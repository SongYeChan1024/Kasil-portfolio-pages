## 진행한 작업

### 1. 튜토리얼 단계 구조 재정리

- 튜토리얼 진행 단계를 1\~6단계로 다시 정리했다.
- 1번은 이동 기본, 2번은 전투 조작 사전 안내, 3번은 전투 실습, 4번은 상자/아이템 루팅, 5번은 상자 내부 아이템/아티팩트 설명, 6번은 포탈/탈출로 분리했다.
- 5번은 물리 콜라이더가 아니라 실제 상자 UI가 열린 시점의 이벤트 기반 단계로 정의했다.
- 씬 트리거는 <code>Trigger_TutorialStep1</code>, <code>Trigger_TutorialStep2</code>, <code>Trigger_TutorialStep3</code>, <code>Trigger_TutorialStep4</code>, <code>Trigger_TutorialStep6</code> 구조로 맞췄다.

### 2. JSON 기반 튜토리얼 안내 데이터 구성

- <code>TutorialGuide.json</code>을 기준으로 안내 문구, 열림 조건, 클리어 조건, 다음 안내 ID를 관리하도록 했다.
- <code>TutorialGuideData</code>를 통해 JSON 한 행을 코드에서 다룰 수 있게 했다.
- <code>LocalJsonTutorialGuideRepository</code>가 <code>Resources/JSON/TutorialGuide.json</code>을 읽어 튜토리얼 데이터를 로드하도록 했다.
- <code>TutorialConditionTypes</code>에 조건 문자열과 이벤트명을 상수로 정리했다.
- 기획 데이터에서 문구와 조건을 조정할 수 있도록 코드와 텍스트 데이터를 분리했다.

### 3. TutorialManager 흐름 확장

- 기존 카탈로그 기반 단순 팝업 구조에서 JSON 조건 기반 진행 구조로 확장했다.
- 콜라이더 진입은 <code>NotifyTriggerEnter()</code>로 받고, 상자 열림/적 처치/탈출 성공 같은 행동 이벤트는 <code>NotifyEvent()</code>로 받도록 했다.
- 현재 팝업이 떠 있을 때 다음 안내가 들어오면 큐에 보관했다가 순서대로 출력하도록 했다.
- 이미 출력된 안내는 <code>openedGuideIds</code>로 중복 출력되지 않게 했다.
- <code>PrevGuideClosed</code>, <code>NextButton</code>, <code>Event</code>, <code>TriggerEnter</code> 조건을 구분해 튜토리얼이 순서대로 진행되도록 했다.

### 4. 상자 루팅 / 아이템 설명 흐름 분리

- 상자 근처에 접근했을 때는 F 상호작용 안내를 띄운다.
- 실제 상자를 열면 <code>ItemBoxOpened</code> 이벤트를 통해 상자 UI 내부 안내가 이어진다.
- 상자 UI 내부에서는 아이템 슬롯 확인, 마우스 오버 툴팁, 더블클릭/드래그 앤 드롭, 퀵슬롯/아티팩트 장착 설명으로 이어지게 구성했다.
- 위치 도달과 실제 행동 완료를 분리해 튜토리얼 조건의 의미가 더 명확해졌다.

### 5. 탈출 후 결과창 흐름 정리

- 튜토리얼 탈출 성공 시 바로 로비로 이동하던 흐름을 제거했다.
- 인게임과 동일하게 탈출 성공 후 결과창이 먼저 표시되고, 결과창의 로비 버튼을 눌렀을 때 로비로 이동하도록 정리했다.
- <code>TutorialManager</code>와 <code>TutorialCompletionTrigger</code>는 이제 <code>isTutorialCompleted</code> 저장만 수행한다.
- 로비 이동은 <code>ResultUI</code>의 기존 <code>OnGoToLobbyScene</code> 흐름에 맡겼다.

### 6. 인트로 튜토리얼 진입 옵션 정리

- <code>IntroSceneController</code>의 <code>useTutorialScene</code> 옵션으로 튜토리얼 씬 사용 여부를 제어한다.
- 개발 테스트용으로 <code>resetTutorialCompletedOnIntro</code> 옵션을 추가했다.
- 이 옵션이 켜져 있으면 인트로 진입 시 <code>SaveFile.json</code>의 <code>isTutorialCompleted</code>만 false로 되돌린다.
- 세이브 파일 전체 삭제 없이 튜토리얼 반복 테스트가 가능해졌다.

### 7. 베타 병합 후 로컬 변경 원인 분석

- 베타 브랜치에서 커밋 사항이 새로 생긴 것처럼 보이는 상태를 확인했다.
- 분석 결과, 정상적인 새 작업이라기보다 이미 머지된 튜토리얼 구현을 로컬 변경이 되돌리는 형태였다.
- <code>TutorialGuide.json</code>, <code>TutorialGuideData.cs</code>, <code>TutorialConditionTypes.cs</code>, <code>LocalJsonTutorialGuideRepository.cs</code>가 삭제로 잡히는 것을 확인했다.
- <code>TutorialManager.cs</code>도 JSON 기반 구조에서 이전 카탈로그 기반 구조로 돌아가는 diff가 생겨 있었다.
- 이 상태를 그대로 커밋하면 팀원 작업과 이미 머지된 튜토리얼 구현을 되돌릴 위험이 있어, 커밋하지 말고 상태를 확인해야 한다고 판단했다.

## 이슈 / 주의할 점

- <code>resetTutorialCompletedOnIntro</code>는 개발 테스트용이므로 빌드 전에는 반드시 꺼야 한다.
- 튜토리얼 메시지 JSON의 <code>OpenConditionValue</code>와 씬 트리거의 <code>triggerValue</code>가 정확히 일치해야 한다.
- 상자 내부 설명은 상자 UI가 실제로 열려야 진행되므로 <code>ItemBoxOpened</code> 이벤트 연결이 유지되어야 한다.
- 탈출 성공 후 결과창이 뜨기 전에 로비로 넘어가면 안 된다.
- 베타 브랜치에서 대량 삭제 diff가 생기면 Unity 자동 저장으로 단정하지 말고 <code>git diff --stat</code>과 삭제 파일 목록을 먼저 확인해야 한다.

## 배운 점


튜토리얼은 단순한 팝업 모음이 아니라, 위치 도달 조건과 실제 행동 완료 조건을 함께 다루는 작은 진행 시스템이다. 위치는 콜라이더로, 행동은 이벤트로 분리하면 흐름이 훨씬 자연스럽고 디버깅하기 쉬워진다.


- 완료 저장과 씬 이동은 같은 일이 아니다. 저장은 상태 기록이고, 이동은 UI/씬 흐름의 책임이다.
- 인게임과 튜토리얼의 결과창 흐름이 다르면 테스트 중에는 괜찮아 보여도 나중에 세션 정산이나 멀티 확장 시 문제가 될 수 있다.
- 세이브 파일 전체 삭제보다 특정 플래그만 리셋하는 개발 옵션이 훨씬 안전하다.
- 노션 문서는 캘린더 DB의 날짜 속성에 들어가야 실제 일정/기록 뷰에서 보인다.
