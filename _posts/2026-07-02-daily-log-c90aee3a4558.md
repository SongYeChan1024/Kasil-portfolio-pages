## ✅ 완료한 작업

### 1) 포화/부분 이동 테스트 체크리스트를 재현 절차로 구체화

- <b>내용</b>
  - 케이스를 “시작 상태 → 조작 → 기대 결과”로 통일해서, 누락 없이 테스트할 수 있도록 문장화했습니다.
  - 특히 ‘부분 이동’은 정상 동작인데도 버그로 오해되기 쉬워서, 기대 결과에 “남은 수량이 어디에 보존되는지”까지 포함시켰습니다.
- <b>결과</b>
  - QA/자체 테스트에서 같은 상황을 반복 재현할 수 있는 형태로 정리되어, 구현 변경 후 회귀 테스트가 쉬워졌습니다.
- <b>체크리스트(요약)</b>
  1. 인벤토리 100% 포화 + 합칠 스택 없음 → 이동 시도 → <b>실패</b>, 원본 유지, UI 메시지(공간 부족)
  2. 인벤토리 포화 + 일부 스택 합치기 가능 → 이동 시도 → <b>부분 성공</b>, 일부 수량만 이동, 잔여는 원본 유지
  3. 체스트 100% 포화 + 합칠 스택 없음 → 이동 시도 → <b>실패</b>, 원본 유지
  4. 체스트 포화 + 일부 스택 합치기 가능 → 이동 시도 → <b>부분 성공</b>, 일부 수량만 이동

---

### 2) 이동 결과별 UI 피드백 최소 규칙 초안 확정

- <b>내용</b>
  - 이동 함수의 반환 결과를 <code>성공/부분성공/실패</code>로 분기해, UI는 “결과만 받아서” 메시지/강조를 수행하도록 규칙을 정리했습니다.
  - 실패 원인은 우선 “공간 부족”으로 통일하고(세부 원인 노출은 추후), 출발지/목적지 슬롯 강조로 보조 피드백을 주는 방향으로 잡았습니다.
- <b>결과</b>
  - UI 피드백이 로직 디테일에 과도하게 의존하지 않게 되어, 로직 리팩터링이 들어와도 UX가 무너지지 않는 구조가 됐습니다.
