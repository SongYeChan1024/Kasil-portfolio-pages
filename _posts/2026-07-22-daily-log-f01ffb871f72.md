### 8. 에너미 소음 감지 로직 점검

- 에너미가 의도보다 소음에 둔감하고 조사 행동이 늦게 발생하는 원인을 확인했습니다.
- 현재 <code>EnemyPerception.CanHear()</code>는 다음과 같이 유효 반경을 계산합니다.

```cs
float effectiveRadius = Mathf.Min(hearingRange, Mathf.Max(0.0f, stimulus.Radius));
```

- 현재 판정은 중심 간 거리 <code>d ≤ min(에너미 청각 반경, 소음 반경)</code>일 때만 통과합니다.
- 따라서 두 원의 테두리가 서로 겹쳐 교집합이 생겨도, 에너미 또는 소음 중심이 작은 반경 안으로 들어오지 않으면 조사하지 않습니다.
- 다크 스피릿 프리팹의 실제 청각 반경은 20입니다.
- 상자 소음 반경이 30이어도 현재는 중심 간 거리 20 이내에서만 반응합니다.
- 기획 의도는 두 범위에 교집합이 생기는 순간 조사하는 것이므로 필요한 판정은 <code>d ≤ 청각 반경 + 소음 반경</code>입니다.
- 예를 들어 청각 반경 20, 소음 반경 30이면 의도상 최대 중심 거리 50에서 범위가 맞닿고 감지가 시작되어야 합니다.
- 현재 벽 차폐 <code>Linecast</code> 판정은 거리 판정 뒤에 별도로 존재하므로, 반경 합산 방식으로 바꾸더라도 벽 너머 소리를 차단하는 규칙은 유지할 수 있습니다.
- 이 항목은 오늘 코드로 수정하지 않았으며 팀원 협의가 필요한 설계·구현 불일치로 기록합니다.

  - 꿈식자는 플레이어 본체가 아니라 감지 조건을 통과한 앵커 좌표를 조사 목표로 사용합니다.

## 이슈 및 주의할 점

- 소음 감지 수식을 합산 방식으로 바꾸면 기존보다 조사 발동 범위가 크게 증가합니다.
- 총성, 걷기, 달리기, 상자, 흔적 등 모든 <code>NoiseStimulus</code>에 같은 합산 방식을 적용할지 합의가 필요합니다.
- 반경 합산 후에는 에너미 청각 반경과 소음별 반경을 다시 플레이 테스트하고 밸런싱해야 합니다.
- 벽 차폐를 유지할지, 소음 종류나 우선순위에 따라 벽을 통과하게 할지도 별도 결정이 필요합니다.
- <code>GlobalEventBus.cs</code>는 오늘 직접 커밋 사이에 팀원의 심상 기록 기능 변경이 함께 들어왔으므로 전체 파일 차이와 개인 변경 범위를 구분해야 합니다.
- 정적 코드·Git 비교는 완료했지만 Unity 플레이 모드에서 ESC, 정산, 튜토리얼 상자 흐름의 회귀 테스트는 별도로 필요합니다.

## 배운 점

- 두 원의 감지 영역을 표현하는 기획이라도 실제 판정이 중심 거리와 작은 반경을 사용하면 체감은 전혀 다르게 나타납니다.
- 범위의 교집합을 판정하려면 두 중심 사이 거리와 두 반경의 합을 비교해야 합니다.
- 기즈모가 두 범위를 모두 그려도 실제 코드 수식이 다르면 디버그 시각화가 잘못된 직관을 줄 수 있습니다.
- 입력 차단은 단일 bool보다 소유권을 분리해야 여러 UI 시스템이 서로의 상태를 안전하게 보존할 수 있습니다.
- ESC처럼 여러 UI가 공유하는 입력은 닫기 우선순위와 키 해제 시점을 함께 관리해야 입력 관통을 막을 수 있습니다.
- 게임 포기는 단순 씬 이동이 아니라 결과 사유, 인벤토리 정산, 저장 데이터, 결과 UI까지 하나의 세션 종료 흐름으로 처리해야 합니다.

- [ ] 벽 차폐 규칙과 소음 우선순위·추적 중단 규칙 유지 여부 확인
- [ ] 반경 합산 적용 후 걷기·달리기·총성·상자 소음의 수치 재조정
- [ ] 다크 스피릿 청각 반경 20이 최종 밸런스에 적절한지 플레이 테스트
- [ ] 두 감지 원이 외곽에서 맞닿는 경계값 테스트
- [ ] 벽이 있는 경우와 없는 경우의 조사 발동 비교
- [ ] 인게임 ESC 메뉴와 인벤토리 닫기 우선순위 회귀 테스트
- [ ] 게임 포기 시 소지품·장착 아티팩트·퀵슬롯 정산 확인
- [ ] 튜토리얼 상자 오픈 직후 안내·Chest·Inventory UI 동시 표시 확인
