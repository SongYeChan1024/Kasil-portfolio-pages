<b>Unity 적 AI 시야 기반 추적 시스템 구현</b> 2026-03-04

## 요약

### 학습 목표 및 구현 사항

- [ ] 적 캐릭터가 거리가 아닌 시야로 플레이어를 감지하도록 AI 개선하기  
- [ ] 배럴과 박스 장애물 뒤에 있을 때 총알 발사 방지하기  
- [ ] Unity Editor 클래스(DrawWireDisc, DrawSolidArc)를 활용한 시야각 시각화 구현하기  
- [ ] 내비게이션 메시 베이킹으로 장애물 회피 경로 설정하기  

### 장애물 설정 및 배치

사이버 박스 3D 모델을 Unity Asset Store에서 다운로드하고 프로젝트에 추가했습니다.   모델의 셰이더가 누락되어 Legacy Shader의 Bumped Specular로 설정했습니다.   사이버 박스의 크기를 0.45\~0.5로 조정하고   씬에 4개를 배치했습니다.  

박스에 Box Collider를 추가하고   "Box"라는 새 레이어를 생성하여 할당했습니다.   Cinemachine Virtual Camera의 Obstacle Detection 설정에 Box 레이어를 추가하여 카메라가 장애물을 감지하고 당겨지도록 구성했습니다.  

### 내비게이션 메시 베이킹

Window > AI > Navigation을 통해 Navigation 창을 열었습니다.   사이버 박스 프리팹을 선택하고 Lighting 옵션에서 Static을 "Everything"으로 설정했습니다.   

Navigation 설정을 조정했습니다:

- Agent Radius: 0.3  
- Agent Height: 1 
- Drop Height: 0.3\~0.4  
- Jump Distance: 3\~5  

베이킹 후 NavMesh가 생성되어 적들이 장애물을 회피하는 경로가 만들어졌습니다.   플레이어 발이 바닥에 약간 빠지는 문제는 Agent Radius를 조정하여 해결했습니다.  

### 레이캐스트 기반 발사 조건 개선

기존 문제: 플레이어가 배럴이나 박스 뒤에 있어도 적이 거리만으로 판단하여 총을 발사했습니다.   

해결 방법: <code>TPSFireUnderbar_M.cs</code> 스크립트를 수정하여 레이캐스트로 장애물을 감지하도록 구현했습니다.  

- Barrel Layer와 Box Layer를 추가로 정의했습니다   
- Layer Mask에 Enemy, Swat, Barrel, Box를 모두 포함시켰습니다   
- 레이캐스트가 충돌한 오브젝트의 태그가 "Enemy" 또는 "Swat"일 때만 발사하도록 조건을 추가했습니다  
- isInputFiring 변수를 활용하여 최종 발사 조건을 단순화했습니다  

테스트 결과, 장애물 뒤에 숨으면 총알이 발사되지 않는 것을 확인했습니다.   

### 적 AI 시야각 시스템 설계

거리 기반 추적의 문제점: 적이 등 뒤에 있어도 거리만으로 판단하여 추적했습니다.  

Unity Editor 클래스 활용: 시야각 시각화를 위해 DrawWireDisc(원형)와 DrawSolidArc(부채꼴)를 사용합니다.   

<b>Editor 클래스 특징:</b>  

- Unity IDE를 구성하는 API(함수의 집합)입니다
- 런타임 실시간에서는 다른 스크립트에서 참조할 수 없습니다
- 디자인 시점에서만 사용 가능하며, 사용자 정의 Window나 Inspector UI를 확장할 수 있습니다

### 수학적 기초: Unity 각도 체계

일반 수학 각도와 Unity 각도의 차이를 이해해야 합니다.  

<b>Unity 각도 체계:</b> 

- 0도: 정면(Z축 양의 방향)
- 90도: 오른쪽
- 180도: 뒤
- 270도: 왼쪽

<b>좌표계:</b>

- X축 = sin(각도)
- Z축 = cos(각도)
- Y축은 수평 회전에서는 사용하지 않음  

### 시야각 구현 준비

Enemy 폴더에 <code>EnemyFOV.cs</code> 스크립트를 생성했습니다.   

각도를 라디안으로 변환하는 함수를 작성했습니다:

- <code>Mathf.Sin</code>과 <code>Mathf.Cos</code>를 사용합니다 
- <code>Mathf.Deg2Rad</code>로 일반 각도를 라디안으로 변환합니다   
- 반지름 1인 단위원 기준으로 X축은 sin, Z축은 cos로 계산됩니다

<b>시야각 시각화</b>  

- <code>Handles.DrawWireDisc</code>로 전체 원형 범위를 흰색으로 표시  
- <code>Handles.DrawSolidArc</code>로 부채꼴 시야각을 회색 반투명으로 표시  
- <code>Handles.Label</code>로 시야각 텍스트를 forward 방향 2.0 위치에 표시  

<b>부채꼴 각도 계산</b>  

- <code>Vector3 fromAnglePos = fov.CirclePoint(-fov.viewAngle * 0.5f)</code>
- 부채꼴의 시작점 각도는 <code>-viewAngle / 2</code>, 종료점 각도는 <code>+viewAngle / 2</code>
- viewAngle이 120도일 때 0.5를 곱하면 60도가 됨 
- 마이너스로 시작하는 이유: 사인/코사인 좌표계에서 시작점이 음수 각도에 위치  

<b>각도 변환</b>  

- <code>Deg2Rad</code> = π × 2 / 360도
- 디그리(degree)를 라디안(radian)으로 변환하는 상수
- 원의 둘레(2πr)에서 360도로 나눈 값 

### 적 추적 및 시야 감지 시스템

- <code>Physics.OverlapSphere</code>로 Enemy 위치에서 15 범위 내 Player 레이어 객체 검색
- 플레이어 방향 벡터 계산: <code>(playerPos - enemyPos).normalized</code>  
- <code>Vector3.Angle</code>로 Enemy forward와 플레이어 방향 사이의 각도 계산 
- 각도가 <code>viewAngle * 0.5</code>보다 작으면 시야각 내에 있음

- 3D 지오메트리에서 직접 광원과 다른 물체에 반사된 간접 조명 및 그림자를 렌더링하는 것 
- 전역 조명의 연산 처리는 많은 부하를 주기 때문에 하드웨어 성능에 따라 실시간 연산이 거의 불가능한 경우가 있음 
- Unity는 실시간 전역 조명(Realtime GI)과 미리 계산된 전역 조명(Precomputed Realtime GI)을 처리하는 기능을 제공 

### 조명 모드 (Lighting Modes)

<b>Realtime 모드</b>   

- 실시간 조명으로 설정하여 씬에 직접 광원을 적용
- 매 프레임마다 조명 연산을 해서 화면을 업데이트
- 연산 부하가 큼

<b>Mixed 모드</b>  

1. <b>Baked Indirect</b>  
   - 간접 광원만 미리 계산해서 베이크하며 그림자는 베이크 대상에서 제외됨
   - Mixed 모드로 설정된 조명은 씬에서 실시간 조명 기능을 유지
   - 중급 사양의 PC나 고성능 모바일 디바이스에 적합
2. <b>Subtractive</b>   
   - 정적인 객체의 직접, 간접 광원과 그림자를 모두 베이크
   - 모바일 디바이스 환경에 적합
   - 이 프로젝트에서는 모바일이라고 가정하고 Subtractive 모드 사용
3. <b>Shadow Mask</b>  
   - 직접 광원은 실시간 조명으로 처리
   - 간접 광원과 Light Probe는 Light Map에 저장 (이미지로 저장해서 카메라에서 믹싱 후 렌더링)
   - 그림자는 별도의 텍스처인 Shadow Mask에 저장

### 라이트 맵핑 (Light Mapping) - 정적인 객체

<b>개념</b>   

- 씬에 배치된 모든 3D 모델에 영향을 미치는 직접 조명, 간접 조명 및 그림자를 텍스처로 미리 만드는 과정
- 정적인 객체(움직이지 않는 벽, 박스, 배럴 등)에만 적용

<b>설정 과정</b>

1. <b>모델 설정</b>    
   - 각 모델(Stair, Barrel, Damage, Box 등)의 모델 설정에서 Generate Lightmap UV 체크
   - Apply를 눌러 적용
2. <b>Static 설정</b>     
   - 스테이지의 각 오브젝트에서 Static > Contribute to GI 체크
   - Everything을 체크하거나 원하는 것만 선택 가능
   - Barrel, Box, Floor, Wall 등 모든 정적 오브젝트에 적용     
3. <b>Lighting 설정</b>    
   - Window > Rendering > Lighting으로 이동
   - Environment Lighting의 Source를 Skybox에서 Color로 변경
   - 색상을 검은색(0, 0, 0)으로 설정하여 어둡게 만듦
   - Skybox Resolution을 256으로 설정 
4. <b>Scene 설정</b>   
   - Realtime Global Illumination 체크 해제 (실시간 전역 조명 사용 안 함)
   - Mixed Lighting 체크
   - Lighting Mode를 Subtractive로 선택
5. <b>라이트 매퍼 설정</b>   
   - CPU 또는 GPU 선택 (그래픽카드가 좋으면 GPU, 아니면 CPU)
   - Lightmap Resolution 조정
   - Lightmap Size를 512로 설정
6. <b>조명 배치</b>    
   - 빈 Object 생성하여 "Lightmapping"으로 명명
   - Point Light 추가 및 플레이어 머리 위쪽으로 이동
   - Mode를 Baked로 설정 (Realtime은 사용 안 함)
   - Range 30, Intensity 2.5 설정
   - Shadow Type 설정 가능
7. <b>추가 조명 배치</b>      
   - Ctrl + D로 Point Light 복제
   - 다양한 색상(노란색, 파란색, 빨간색 등)으로 변경
   - 군데군데 적절한 위치에 배치
   - Pixel Light Count를 20으로 설정하여 빛이 잘 보이도록 함 (Editor > Project Settings > Quality)
8. <b>베이킹 실행</b>    
   - Auto Generate 체크 해제 (자동 베이킹 방지)
   - Generate Lighting 버튼 클릭
   - 베이킹 완료까지 2-3분 대기

<b>베이킹 결과 확인</b>   

- Point Light를 모두 꺼도 조명이 남아있으면 성공
- 메인 씬에 라이트 맵핑 이미지가 생성됨
- Play 모드에서 확인 시 정적 객체는 조명이 잘 적용되지만, 움직이는 물체(플레이어, 에너미)는 베이킹이 안 됨

### 라이트 프로브 (Light Probe) - 동적인 객체

<b>개념</b>    

- 스테이지에서 조명이 있는 곳 주변에 라이트 프로브를 배치
- 라이트 맵을 베이킹할 때 라이트 프로브 주변부의 광원 데이터를 저장
- 근처를 지나가는 동적 오브젝트에 해당 광원 데이터를 전달하고 오브젝트 색상과 보간
- 마치 실시간 조명과 같은 효과를 내는 방식
- 씬에 배치한 프로브 지점에서 베이크된 간접 조명(GI) 정보를 샘플링
- 이동하는(동적인) 오브젝트가 주변 환경의 조명 색과 밝기를 자연스럽게 받도록 함

<b>설정 과정</b>

1. <b>Light Probe Group 생성</b>     
   - 빈 Object 생성하여 "LightProbe Group"으로 명명
   - Light Probe Group 컴포넌트 추가
   - 바닥에 배치하고 Y를 1 정도로 올림 
2. <b>Light Probe 복제 및 배치</b>        
   - Exit Light Probe Editing 클릭
   - Select All 선택
   - Duplicate Selected로 복제
   - 옆으로 이동
   - 이 과정을 반복하여 공간 전체에 배치
3. <b>프로브 조정</b>     
   - Alt + 마우스 좌클릭으로 시점 조정
   - 벽 밖으로 나간 프로브는 드래그하여 선택 후 Delete Selected로 제거
   - 비어있는 부분에는 추가로 프로브 배치
4. <b>최종 베이킹</b>     
   - Point Light 모두 켜기
   - Window > Rendering > Lighting으로 이동
   - Generate Lighting 클릭하여 재베이킹

### 주요 기술 사항

- 정적 오브젝트는 Lightmap에, 동적 오브젝트는 Light Probe에 저장된 조명 정보를 사용 
- 오브젝트 위치에 따라 주변 여러 프로브 값을 보간해 적용
- 한 번 베이킹 후 다시 베이킹하면 속도가 빨라짐 
- 추가 조명 배치 후 재베이킹 가능  

## 메모

라이트 맵핑 LightMapping 정적인 객체<br />씬에 배치된 모든 3D 모델에 영향을 미치는 직접조명 간접조명 및 그림자를 텍스처로 미리 만드는 과정을 의미한다.<br />동적인 객체의 조명 효과는 LightProbe 를 통해 적용한다.

전역 조명 : 3D 지오메트리에서 직접 광원과 다른 물체에 반사된 간접 조명 및 그림자를 렌더링 하는 것을 말한다.

전역 조명의 연산처리는 많은 부하를 주기 때문에 하드웨어의 성능에 따라서 실시간 연산이 거의 불가능한 경우가 있다.

따라서 유니티는  실시간 전역조명(Realtime GI) 미리계산된 전역 조명 (Precomputed Realtime GI)을 처리하는 기능을 제공한다.

조명모드<br />Realtime 모드 : 실시간 조명으로 설정하는 것 으로 씬에 직접 광원을 적용하며 매 프레임마다 조명 연산을 해서 화면을 업데이트한다. 연산 부하가 크다.<br />Mixed 모드 : <br />1. Baked Indirect : 간접 광원만 미리 계산해 베이크 하며 그림자는 베이크 대상에서 제외 된다. Mixed모드로 설정된 조명은 씬에서 실시간 조명 기능을 유지 중급 사양의 PC나 고성능 모바일 디바이스에 적합<br />2. Subtractive : 정적인 객체의 직·간접 광원과 그림자를 모두 베이크한다, 모바일 디바이스의 환경에 적합하다.<br />3.ShadowMask : 직접 광원은 실시간 조명으로 처리하고 간접광원과 LightProbe 는 LightMap 에 저장한다(이미지로 저장해서 카메라에서 믹싱후 렌더링) , 그림자는 별도의 텍스처인 섀도우 마스크에 저장한다.<br />

라이트 프로브 LightProbe 동적인 객체

Light Probe는 씬에 배치한 <b>프로브 지점에서 베이크된 간접 조명(GI) 정보</b>를 샘플링해, <b>이동하는(동적인) 오브젝트가 주변 환경의 조명 색과 밝기를 자연스럽게 받도록</b> 해주는 Unity의 조명 시스템이다.

- 정적 오브젝트는 Lightmap에, 동적 오브젝트는 주로 Light Probe에 저장된 조명 정보를 사용한다.
- 오브젝트 위치에 따라 주변 여러 프로브 값을 보간해 적용한다.

스테이지에서 조명이 있는 곳 주변에 라이트 프로브를 배치하고, 라이트 맵을 베이킹할 때 라이트 프로브 주변부의 광원 데이터를 저장해 둔다. 이후 근처를 지나가는 동적 오브젝트에 해당 광원 데이터를 전달하고 오브젝트 색상과 보간해, 마치 실시간 조명과 같은 효과를 내는 방식이다.

# Light Mapping (라이트 맵핑)

<b>Light Mapping</b>은 <b>정적인 객체(Static Object)</b> 의

직접 조명, 간접 조명, 그림자 정보를 <b>텍스처로 미리 계산하여 저장하는 과정</b>을 의미한다.

씬에 배치된 모든 <b>3D 모델(지오메트리)</b> 에 영향을 미치는 조명 정보를 <b>LightMap 텍스처로 생성</b>한다.

동적인 객체의 조명 효과는 <b>Light Probe</b> 를 통해 적용한다.

---

# 전역 조명 (Global Illumination)

<b>전역 조명(Global Illumination, GI)</b> 은

3D 지오메트리에서

- <b>직접 광원(Direct Light)</b>
- <b>간접 조명(Indirect Light)</b>
- <b>그림자(Shadow)</b>

를 모두 포함하여 <b>장면 전체의 조명 효과를 계산하는 방식</b>을 의미한다.

---

# 전역 조명의 특징

전역 조명 계산은

- 빛의 반사
- 그림자
- 간접 조명

까지 모두 계산하기 때문에 <b>연산 부하가 매우 크다.</b>

따라서 하드웨어 성능에 따라 <b>실시간 연산이 어려운 경우가 많다.</b>

---

# Unity의 전역 조명 처리 방식

Unity는 전역 조명을 처리하기 위해 다음 기능을 제공한다.

- <b>Realtime GI (실시간 전역 조명)</b>
- <b>Precomputed Realtime GI (미리 계산된 전역 조명)</b>

이를 통해 <b>실시간 조명과 베이크 조명을 혼합하여 성능을 최적화한다.</b>

---

# 조명 모드 (Lighting Mode)

Unity의 Light는 <b>3가지 조명 모드</b>를 제공한다.

---

## 1. Realtime Mode

실시간 조명 모드

특징

- 씬에 직접 광원을 적용
- 매 프레임마다 조명 연산을 수행
- 화면을 실시간으로 업데이트

단점

- <b>연산 부하가 매우 크다</b>

---

## 2. Mixed Mode

실시간 조명과 베이크 조명을 <b>혼합해서 사용하는 방식</b>

Mixed Mode에는 <b>3가지 옵션</b>이 있다.

---

### 1. Baked Indirect

- <b>간접 조명만 미리 계산하여 베이크</b>
- <b>직접 조명은 실시간으로 처리</b>
- <b>그림자는 베이크 대상에서 제외</b>

특징

- Mixed 모드에서 실시간 조명 기능을 유지
- <b>중급 사양 PC</b>
- <b>고성능 모바일 디바이스</b>

에 적합하다.

---

### 2. Subtractive

- <b>정적인 객체의 직접 조명과 간접 조명을 모두 베이크</b>
- <b>그림자도 베이크</b>

특징

- 실시간 조명 계산이 거의 없음
- <b>모바일 디바이스 환경에 적합</b>

---

### 3. ShadowMask

- <b>직접 조명은 실시간 처리</b>
- <b>간접 조명과 Light Probe는 LightMap에 저장</b>
- <b>그림자는 ShadowMask 텍스처에 저장</b>

특징

- 베이크 조명과 실시간 조명을 <b>혼합하여 렌더링</b>

---

# 핵심 정리

Light Mapping

→ 정적인 객체의 조명을 <b>텍스처로 미리 계산하는 기술</b>

Global Illumination

→ <b>직접 조명 + 간접 조명 + 그림자</b>를 포함한 전체 조명 시스템

Lighting Mode

- <b>Realtime</b> : 모든 조명 실시간 계산
- <b>Mixed</b> : 실시간 + 베이크 혼합
- <b>Baked</b> : 모든 조명 미리 계산
