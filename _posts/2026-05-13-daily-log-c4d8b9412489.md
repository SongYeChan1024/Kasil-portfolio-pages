## 기본 정보

- 날짜: 2026-05-13
- 프로젝트: ThunderBolt (Unity) — 탱크 조작/포탑·포신 제어 + 레이캐스트 발사
- 작성자: 작성자

## 오늘 한 일(요약)

- Input System으로 <b>탱크 이동/차체 회전/마우스 휠/발사 입력</b>을 연결했다.
- 마우스 위치를 기준으로 <b>포탑(터렛) 회전</b>이 타겟을 따라가도록 구현했다.
- 마우스 휠로 <b>포신 상하각 조절 + 각도 제한(Clamp)</b> 을 적용했다.
- 발사 이벤트로 <b>레이저(Line Renderer) + Raycast 명중 처리 + 히트 이펙트</b>를 연동했다.
- 디버깅 과정에서 포탑 Y축 무한 회전/스크롤 입력 타입 오류/TrackAnim·URP 경고를 정리해 안정성을 올렸다.

## 오늘 진행한 내용(상세)

### 1) 입력(Input System) 연결

- 이동/차체 회전/발사/스크롤 입력을 Input Action으로 묶고, 각 컨트롤 스크립트에서 이벤트/값을 받아 처리했다.

### 2) 포탑(터렛) 회전: 마우스 위치 추적

- 마우스 위치를 Ray로 쏴서 월드 타겟 포인트를 잡고, 포탑이 그 방향을 보도록 회전시켰다.
- 이때 “부모(차체)와 분리된 회전”이 필요해서 회전 기준을 정리했고, 결과적으로 <b>Y축이 계속 돌아가던 현상</b>을 수정했다.

### 3) 포신 상하각: 스크롤 기반 조절 + 각도 제한

- 스크롤 입력은 <code>Vector2</code>로 들어오는 케이스가 있어서, <b>y 값만 사용</b>하도록 수정해 오동작을 해결했다.
- 포신의 상하각은 제한 범위를 두고 Clamp해서, 과도하게 꺾이거나 뒤집히지 않게 만들었다.

### 4) 발사: 레이저 + 명중 처리 + 이펙트

- 발사 시 Line Renderer로 레이저를 짧게 보여주고,
- Raycast로 명중 판정 후 히트 이펙트를 재생하는 형태로 연결했다.

## 이슈/버그 → 해결

- 포탑이 Y축으로 계속 회전함
  - 원인: 회전 기준/좌표계가 섞여서 누적 회전이 생김
  - 해결: 회전 기준을 월드(또는 일관된 기준)로 통일해 수정
- 마우스 스크롤 입력 오류
  - 원인: Scroll 입력이 <code>Vector2</code>인데 그대로 쓰면서 오동작
  - 해결: <code>Vector2.y</code>만 사용하도록 변경
- TrackAnim / URP 설정 관련 경고
  - 조치: 경고 원인 확인 및 프로젝트 설정 점검

## 내일(다음) 할 일

- 발사 로직을 “레이저(즉시 히트)” 외에 <b>투사체(Projectile) 방식</b>과 비교해보고 상황별로 선택
- 히트 이펙트/사운드/피격 처리(HP 등)까지 묶어서 전투 루프를 더 명확히 만들기
- 입력/회전 관련 코드를 컴포넌트 단위로 정리(터렛/포신/차체 책임 분리)

## 짧은 버전

ThunderBolt 탱크 구현 2일차로, Input System으로 이동/회전/발사/스크롤을 연결하고 마우스 위치 기반 포탑 회전, 휠 기반 포신 각도 제한을 구현했다. 발사는 레이저(Line Renderer) + Raycast 명중 처리 + 히트 이펙트를 연동했으며, 포탑 Y축 무한 회전/스크롤 입력 타입 오류와 TrackAnim·URP 경고를 정리했다.
