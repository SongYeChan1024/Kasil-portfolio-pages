## 2. QA-PM-003 순찰·추적 AI 재설계

### 2-1. 기존 문제

기존 구조에서는 에너미가 플레이어를 감지한 뒤 시야에서 놓쳐도 인식이 오래 유지되었다. 에너미별 활동 범위와 자기 순찰 루트의 개념이 약했기 때문에 다음 문제가 함께 발생했다.

- 순찰 포인트가 겹치는 에너미들이 같은 목적지를 선택해 무리처럼 움직임
- 외곽에 스폰된 에너미가 건물 내부 패트롤 포인트로 이동
- 플레이어를 쫓아 자기 담당 영역에서 지나치게 멀리 이탈
- 추적 종료 후 공통 지점으로 복귀하거나 부자연스럽게 뭉침
- 시야가 잠깐 끊겼을 때 바로 복귀하거나 반대로 너무 오래 추적

### 2-2. 수정한 구조

에너미는 스폰될 때 자신에게 연결된 패트롤 루트와 시작 인덱스를 전달받는다. 순찰 중에는 자기 루트의 포인트를 기준으로 배회하고, 추적 종료 후에는 현재 위치에서 가장 가까운 자기 패트롤 포인트로 복귀한다.

추적 범위는 한 개의 경계가 아니라 히스테리시스 구조로 분리했다.

| 구간 | 거리 | 동작 |
| --- | --- | --- |
| 정상 추적 구간 | 패트롤 루트 기준 16m 이내 | 시야 확보 시 어그로 회복 및 추적 유지 |
| 완충 구간 | 16m 초과 24m 이하 | 새 추적 위치를 저장하지 않고 어그로를 빠르게 감소 |
| 강제 복귀 구간 | 24m 초과 | 남은 어그로와 관계없이 추적 종료 후 자기 루트로 복귀 |

히스테리시스는 진입 기준과 이탈 기준을 다르게 두는 방식이다. 경계 하나만 사용하면 플레이어가 경계선을 오갈 때 추적과 복귀 상태가 반복 전환될 수 있다. 완충 구간을 두면 상태가 안정된다.

청각 거리는 다크 스피릿 기준 30으로 조정했다. 소음은 모든 에너미가 아니라 소음 반경 안에 있고 장애물 판정을 통과한 가까운 에너미만 반응한다.

### 2-3. 순찰과 스폰 정합성

- 외곽, 건물 내부, 로비 등 공간별 패트롤 루트를 분리
- 스폰 포인트가 자기 영역의 패트롤 루트를 참조하도록 연결
- 총 14개 스폰 포인트 기준으로 배치와 루트 연결 정리
- 복귀 목적지는 공통 Transform이 아니라 자기 루트의 가장 가까운 지점으로 계산
- NavMesh 위에서만 목적지를 선택하도록 보정
- 강제 어그로도 활동 반경 제한을 우회하지 못하도록 방어

## 3. 근접 교전과 공격 안정화

플레이어가 에너미 주위를 빠르게 돌면 시야각 바깥으로 잠시 벗어나게 된다. 기존에는 이 상황을 시야 상실로 처리해 공격을 중단하고 어그로를 감소시켰다.

수정 후에는 최초 발견과 이미 시작된 근접 교전을 분리한다.

- 최초 발견은 기존 시야 거리, 시야각, 장애물 검사를 모두 사용
- 이미 교전한 대상은 근접 유지 거리 안에서 시야각을 제외
- 단, 벽과 같은 실제 장애물이 있으면 근접 타깃을 유지하지 않음
- 공격 선딜 중에는 제한된 속도로 플레이어 방향을 계속 추적
- 공격 시작 거리와 실제 타격 거리를 분리
- 실제 대미지 직전에도 거리와 장애물을 다시 확인

이 구조의 핵심은 감지 조건을 무조건 넓힌 것이 아니라, 최초 감지와 교전 유지 조건의 책임을 분리한 것이다.

## 4. 이동 벡터와 애니메이션 방향 동기화

AI 판단 주기의 목적지 방향을 애니메이션에 그대로 사용하면 NavMeshAgent가 장애물을 피해 코너를 도는 실제 방향과 스프라이트 방향이 달라질 수 있다.

수정 후에는 매 프레임 NavMeshAgent의 실제 이동 벡터와 속도를 사용한다.

```txt
AI 목적지
→ NavMesh 경로 계산
→ 실제 이동 벡터 계산
→ 걷기 여부와 상하좌우 방향값 갱신
```

좌우 플립과 위·아래 정면/뒷면 값도 실제 이미지 기준으로 반전했다. 그 결과 왼쪽으로 움직이면서 오른쪽을 바라보거나, 아래로 내려오면서 뒷모습이 출력되는 문워크 현상을 수정했다.

## 5. 게임 종료 상태 처리

### 5-1. 문제의 공통 원인

사망이나 탈출 후 결과 UI만 열리고, 전투와 입력 시스템은 계속 살아 있었다. 컴포넌트를 비활성화하는 것만으로는 다른 스크립트가 메서드를 직접 호출하는 상황까지 막을 수 없다.

따라서 한곳만 고치는 대신 다음 경계에서 각각 방어했다.

| 파일 | 책임 |
| --- | --- |
| PlayerStatus.cs | 종료 후 TakeDamage 진입 차단과 입력·이동 잠금 |
| TimeLimitController.cs | 종료 후 기본 시간 흐름과 외부 시간 패널티 차단 |
| GameManager.cs | 플레이타임과 결과 정산을 최초 한 번만 실행 |
| InventoryPresenter.cs | 인벤토리·상자·툴팁 강제 종료와 재오픈 차단 |

### 5-2. 종료 흐름

```txt
사망 또는 탈출 확정
→ IsSessionEnded 활성화
→ 추가 피격 무시
→ 제한시간과 시간 패널티 중단
→ 플레이타임 최초 값 고정
→ 인벤토리 계열 UI 강제 종료
→ 플레이어 입력과 이동 비활성화
→ 결과 UI 출력
```

탈출 채널링 중에는 아직 세션 종료가 확정되지 않았기 때문에 피격을 정상 처리한다. 따라서 피격으로 탈출 채널링이 취소되는 기존 게임 규칙은 유지된다.

중요한 학습 포인트: 입력을 막는 것과 기능 실행을 막는 것은 다르다. 입력 컴포넌트를 꺼도 이벤트나 다른 객체가 메서드를 직접 호출할 수 있으므로 TakeDamage, ApplyTimePenalty, OpenInventoryUI 같은 실제 진입점에도 상태 검사가 필요하다.

## 6. 사망한 플레이어의 에너미 타깃 해제

플레이어 측에서 대미지만 무시하면 에너미는 여전히 죽은 플레이어를 타깃으로 보유한다. 멀티플레이에서는 이 때문에 살아 있는 다른 플레이어를 탐색하지 않고 시체 주변에 머무를 수 있다.

이를 막기 위해 PlayerStatus에 CanBeTargeted 판정을 두고 감지, 추적, 공격이 같은 기준을 사용하게 했다.

```cs
public bool CanBeTargeted =>
    !IsSessionEnded &&
    nowState != livingState.gameover &&
    hpCurrent > 0.0f;
```

적용 지점은 다음과 같다.

1. EnemyPerception에서 사망한 플레이어를 신규 감지 후보에서 제외
2. EnemyBrain에서 현재 타깃이 무효가 되면 어그로와 추적 기억 제거
3. 같은 AI 틱에서 다른 생존 플레이어 탐색
4. EnemyCombat에서 선딜, 공격 애니메이션, 돌진 후, 대미지 직전에 타깃 재검사
5. 늦게 도착한 애니메이션 이벤트가 죽은 타깃을 공격하지 않도록 차단
6. 다른 생존 대상이 없으면 기존 자기 패트롤 루트로 복귀

비플레이어 강제 어그로 오브젝트는 기존 기능을 유지하도록 PlayerStatus가 있는 대상만 생존 상태를 검사했다.

## 8. 이번 작업에서 익혀야 할 설계 원칙

### 단일 책임

감지, 판단, 이동, 전투, 기억을 분리하면 한 기능을 수정할 때 다른 기능에 미치는 영향을 줄일 수 있다.

### 경계에서 검증

대미지, 시간 패널티, UI 열기, 실제 공격처럼 상태를 변경하는 진입점에서 조건을 검사해야 한다.

### 단일 기준 재사용

CanBeTargeted처럼 공통 판정을 하나로 만들면 감지와 공격이 서로 다른 기준을 사용해 발생하는 버그를 줄일 수 있다.

### 상태 전환에는 완충 구간 사용

추적 거리처럼 값이 경계를 오가는 시스템은 한 개의 임계값보다 진입·유지·이탈 기준을 분리하는 것이 안정적이다.

### 이벤트 구독과 해제는 한 쌍

OnEnable에서 구독한 이벤트는 OnDisable에서 반드시 해제해야 중복 호출과 메모리 누수를 막을 수 있다.

### 멀티플레이 확장 시 주의

현재 OnEscapeRequest는 플레이어 ID가 없는 전역 세션 이벤트다. 실제 멀티플레이 전환 시에는 아래처럼 의미를 분리해야 한다.

```txt
OnPlayerEliminated(int playerID)
OnSessionEnded(bool extractionResult)
```

## 9. 검증 결과와 회귀 테스트

- dotnet build 기준 컴파일 오류 0개
- 기존 프로젝트 경고 4개는 이번 변경과 무관
- 신규 로직과 변경 조건에는 역할과 이유를 설명하는 주석 추가

### Unity 플레이 모드 확인 항목

- [ ] 14개 에너미가 연결된 자기 패트롤 루트 안에서 움직이는지 확인
- [ ] 외곽 에너미가 건물 내부 루트로 들어가지 않는지 확인
- [ ] 16m 안에서는 정상 추적하고 완충 구간에서 어그로가 감소하는지 확인
- [ ] 24m를 넘으면 가장 가까운 자기 루트로 복귀하는지 확인
- [ ] 벽 뒤 소음에 가까운 에너미만 반응하는지 확인
- [ ] 플레이어가 에너미 주변을 돌아도 공격이 비정상적으로 끊기지 않는지 확인
- [ ] 사망 직후 추가 공격이 HP, 시간, 플레이타임을 변경하지 않는지 확인
- [ ] 탈출 성공 후 인벤토리와 상자 UI가 열리지 않는지 확인
- [ ] 사망한 플레이어를 에너미가 즉시 타깃에서 제외하는지 확인
- [ ] 멀티플레이 테스트 환경에서 다른 생존 플레이어로 타깃을 전환하는지 확인
