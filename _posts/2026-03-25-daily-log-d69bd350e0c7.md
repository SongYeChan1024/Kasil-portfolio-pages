## 오늘 한 일(요약)

- Ep.3-2 리듬 퍼즐의 전체 플레이 흐름을 구현하고, 오디오/BPM 기반 비트 생성 구조를 정리함
- 발판 순환 생성, 정답 판정, 이펙트 연동, 겹침 방지, 생성 실패 대응까지 포함해 플레이 로직을 안정화함

---

## 구현한 것(핵심)

### 1) RhythmAudioManager

- AudioClip/AudioSource, BPM, Start Offset 기반으로 런타임 비트맵(비트 이벤트) 생성
- <code>beatsPerPlatformSpawn</code> 추가: “몇 박마다 발판을 생성할지” 인스펙터에서 조절 가능

### 2) RhythmPuzzleManager

- 초기 3개 발판 그룹 생성
- 최대 5개 유지 + 앞 발판부터 순환 제거(큐처럼 회전) 구조
- 정답 발판 판정 + 오답/미스/콤보/점수 처리 구현
- 발판 생성 실패 시 퍼즐 전체가 멈추지 않도록 “비트 스킵” 처리 추가

### 3) PlatformSpawner

- 발판 오브젝트 풀링 구조 적용
- 발판 간 최소 거리 검사 추가
- 전체 활성 발판 기준 콜라이더 겹침 검사 추가
- 겹침 발생 시 같은 위치만 재시도하지 않고 다른 오프셋으로 재시도하도록 개선

### 4) RhythmEffectManager

- 정답 표시 이펙트/성공 이펙트 풀링 구조 정리
- OnDisable 시 부모 변경(SetParent) 문제를 피하도록 안정화
- Y 오프셋 대신 회전 오프셋(180도) 기준으로 이펙트 방향 보정

### 5) RhythmPlatform

- 발판 인덱스/비트 인덱스/정답 여부 상태 보관
- 플레이어가 밟았을 때 퍼즐 매니저로 “밟음 이벤트” 전달 → 매니저가 최종 판정하는 구조로 정리

---

## 배운 것(메모)

- Unity에서 <code>SerializeField</code> 값은 코드 기본값보다 인스펙터 값이 우선 적용됨
- BPM 기반 자동 생성만으로는 플레이 감각이 부족할 수 있어, 다음 보정이 함께 필요
  - 생성 주기, 판정 시간, 초기 생성 수/최대 유지 수, 겹침 방지 로직
- OnDisable 타이밍에 자식 오브젝트를 SetParent 하면 런타임 에러가 날 수 있어 “비활성화 중 재부모화”는 피하는 편이 안전
- 발판 랜덤 배치는 거리 검사 + 콜라이더 검사 + 재시도 로직을 함께 써야 안정적

---

## 이슈/버그

### 문제

- 발판 생성 중 겹침이 발생하면 특정 비트에서 발판 생성 실패 후 퍼즐 진행이 멈추는 문제가 있었음

### 원인/가설

- 생성 실패 비트 그룹이 등록되지 않음
- 퍼즐 매니저가 “존재하지 않는 비트 그룹”을 계속 기다리는 구조

### 해결/시도

- 생성 실패 시 전체 로직이 정지하지 않도록 “비트 스킵” 처리 추가
- 같은 오프셋 실패 시 다른 오프셋으로 재생성 시도
- 전체 활성 발판 기준 콜라이더 겹침 검사를 적용

### 다음 액션

- 비트 스킵 방식이 게임플레이에 적절한지 테스트
- 필요 시 “최소 1개 발판은 반드시 생성”하는 fallback 로직 추가 검토
