## 진행한 작업

### 1. 튜토리얼 UI 구조 확장

- 새 튜토리얼 기획서 기준으로 기존 6단계 구조를 유지하되, UI 표현 방식을 확장했다.
- 단순 안내 팝업, 관제사 무전, 유안 대사, 조작 툴팁을 구분하는 방향으로 정리했다.
- 무전/대화 계열은 별도의 Next 버튼 대신 패널 클릭으로 다음 대사로 넘어갈 수 있게 구성했다.
- 유안 대사창에는 캐릭터 스탠딩 이미지를 배치할 수 있도록 UI 구조를 나눴다.
- 관제사 무전은 유안 대사창과 같은 형태가 아니라 중앙 무전 안내에 가깝게 분리하는 방향으로 정리했다.

### 2. 튜토리얼 데이터 갱신

- <code>TutorialGuide.xlsx</code>를 추가하고, 이를 기반으로 <code>TutorialGuide.json</code>을 갱신하는 흐름을 잡았다.
- 튜토리얼 안내 데이터에 무전 대사와 조작 가이드 성격을 함께 담을 수 있도록 확장했다.
- 문구, 출력 순서, 출력 조건, 다음 가이드 연결을 데이터에서 조정할 수 있게 했다.
- 튜토리얼 문구가 깨져 보이는 문제는 TMP 폰트 설정과 UI 텍스트 컴포넌트 참조 문제로 보고 점검했다.

### 3. 튜토리얼 입력 차단 보강

- 튜토리얼 안내창의 확인/클릭 입력이 게임 조작 입력으로 함께 전달되는 문제를 확인했다.
- 안내창이 열린 동안 공격, 이동, 발사 입력이 새지 않도록 일시정지 또는 입력 차단 흐름을 보강했다.
- UI 클릭과 플레이어 조작이 같은 프레임에 동시에 처리되는 문제를 줄이는 방향으로 정리했다.

### 4. 창고 → 인게임 퀵슬롯 반영 문제 수정

- 창고에서 퀵슬롯 등록 후 인게임에 들어갔을 때 UI가 바로 반영되지 않는 현상을 점검했다.
- 원인은 퀵슬롯 복원 이벤트가 <code>GamePlayUI</code> 생성보다 먼저 발생해 UI가 이벤트를 놓칠 가능성이 높은 것으로 판단했다.
- <code>QuickSlotGroupUI.SyncFromInventory()</code>를 추가해 <code>GamePlayUI</code> 초기화 후 현재 <code>PlayerInventory.quickSlots</code>를 직접 읽어 1회 반영하도록 했다.
- 이벤트 기반 갱신 구조는 유지하고, 씬 진입 타이밍 문제만 보정했다.

### 5. 창고 슬롯 UI 레어리티 표시 보강

- 창고 인벤토리 슬롯, 퀵슬롯, 아티팩트 슬롯의 레어리티 표시가 서로 다르게 동작하는 문제를 점검했다.
- TID 기준으로 아이템 데이터를 조회하고, 아이템 등급에 따라 레어리티 프레임을 갱신하도록 정리했다.
- 퀵슬롯의 아이템 이미지가 슬롯 밖으로 커지는 문제를 막기 위해 아이콘 최대 크기를 제한했다.
- 비어 있는 퀵슬롯이 Fill 이미지처럼 밝게 보이는 문제를 줄이기 위해 빈 슬롯 색상을 인벤토리 슬롯 톤에 맞췄다.
- 아티팩트 장착 슬롯에 <code>Image-RarityFrame</code>이 없는 경우 런타임에서 생성해 등급 표시가 가능하도록 보완했다.

### 6. 창고 드래그 앤 드롭 규칙 정리

- 퀵슬롯에는 소비 아이템만 등록 가능하도록 제한했다.
- 퀵슬롯끼리는 서로 자리 교환이 가능하게 했다.
- 아티팩트 슬롯은 아티팩트 슬롯끼리 교환 가능하게 했다.
- 아티팩트 장착/해제는 인벤토리와의 흐름을 유지하고, 패널 빈 공간으로 드롭해 해제되는 방식은 제한했다.
- 창고 화면에서는 <code>StorageInventoryUI</code>가 슬롯 간 이동 규칙을 통합 관리하도록 정리했다.

### 7. 에너미 AI 디코이/전투 타겟 분리

- 디코이 수류탄을 던진 뒤 에너미가 플레이어를 공격하지 않고 패트롤 루트로 복귀하거나 이상 이동하는 문제를 점검했다.
- 원인은 디코이 타겟이 플레이어 전투 타겟을 덮어쓰는 구조와 복귀 조건이 충돌할 가능성이 높은 것으로 판단했다.
- <code>currentTarget</code>은 플레이어 전투 타겟, <code>aggroTarget</code>은 디코이 같은 임시 이동 우선 타겟으로 역할을 분리했다.
- 디코이 지속 중에는 이동 목표만 디코이로 바꾸고, 플레이어 전투 타겟은 보존하도록 했다.
- 디코이가 사라지면 보존된 플레이어 타겟으로 자연스럽게 복귀할 수 있게 했다.

### 8. 에너미 근접 교전 안정화

- 너무 가까운 거리에서 에너미가 공격하지 못하거나, 공격 후 굳었다가 이상한 방향으로 이동하는 문제를 점검했다.
- 근접 시야 판정에서 Raycast가 자기 자신의 콜라이더를 먼저 맞아 플레이어를 놓칠 수 있다고 판단했다.
- <code>Physics.RaycastAll()</code>을 사용해 충돌 후보를 모두 확인하고, 자기 자신 또는 자기 자식 콜라이더는 무시하도록 수정했다.
- 공격 직후에는 짧은 시간 동안 직접 추적을 우선하도록 보정 시간을 추가했다.
- 공격 돌진 직후 루트 반경 판정이 너무 빨리 복귀를 유발하지 않도록 임시 여유 거리를 추가했다.

### 9. 탄환 라인 / 수류탄 비주얼 적용

- 플레이어 탄환 라인 렌더러에 사용할 <code>M_BulletLine.mat</code>을 추가했다.
- 맞았을 때와 빗나갔을 때 색상이 다르게 보이는 문제를 점검하고, 둘 다 보라색 계열 비주얼로 보이도록 정리했다.
- 디코이 수류탄 스프라이트를 적용했다.
- 수류탄 체공 중 궤적을 보여주기 위해 TrailRenderer를 추가했다.
- 수류탄 크기가 너무 커 보이는 문제를 줄이기 위해 스프라이트 스케일을 낮췄다.

### 10. 캐릭터 Shadow 포트레이트 겹침 완화

- 적 캐릭터 포트레이트 겹침 문제와 유사하게, 유안 캐릭터의 메인 포트레이트와 Shadow 포트레이트가 겹쳐 보일 가능성을 점검했다.
- 팀 논의상 렌더/카메라 구조 전체를 지금 정리하기 어렵다고 판단해, 임시 안정화로 Shadow 포트레이트 알파값을 낮추는 방식을 적용했다.
- <code>AnimatorShadowSync</code>에서 Shadow AnyPortrait를 비활성화하지 않고 <code>SetMeshAlphaAll()</code>로 렌더 알파만 조절하도록 했다.
- Animator 동기화는 유지해 포즈가 굳는 문제는 피했다.
- 이 방식은 임시 완화이며, 나중에 그림자 연출 문제가 생기면 카메라/레이어/렌더 구조를 다시 정리해야 한다.

## 이슈 / 주의할 점

- <code>SampleSceneProfile.asset</code> 변경이 남아 있으므로, 커밋 전 의도된 그래픽 설정 변경인지 확인해야 한다.
- 캐릭터 Shadow 포트레이트 알파 0 처리는 임시 대응이다. 그림자 연출이 필요해지면 구조적으로 다시 고쳐야 한다.
- 튜토리얼 UI 이미지의 나인슬라이스 적용은 아직 최종 확정이 필요하다.
- 창고 슬롯 레어리티 프레임은 프리팹 연결과 런타임 보완이 함께 작동하므로, 실제 플레이 화면에서 다시 확인해야 한다.
- 에너미 AI는 디코이 종료 후 재교전 흐름을 장시간 테스트해야 한다.
- 수류탄 TrailRenderer의 굵기와 지속 시간은 플레이 테스트 후 조정 여지가 있다.

## 배운 점

- UI 이벤트는 생성 순서에 따라 쉽게 누락될 수 있으므로, 씬 진입 초기화에서는 이벤트 기반 갱신과 직접 동기화를 함께 두는 편이 안전하다.
- 창고, 퀵슬롯, 인벤토리, 아티팩트 슬롯은 모두 아이템을 보여주는 UI지만 규칙이 다르다. 따라서 표시 로직과 이동 규칙을 분리해서 생각해야 한다.
- AI에서 디코이 같은 임시 타겟을 전투 타겟과 같은 변수로 다루면, 우선순위가 바뀌는 순간 전투 흐름이 깨질 수 있다.
- 포트레이트 겹침 문제는 컴포넌트를 끄는 방식보다 알파만 조절하는 방식이 안전할 때가 있다. 특히 Animator나 AnyPortrait 업데이트가 계속 필요한 경우 그렇다.
- 임시 수정은 임시 수정이라고 문서에 남겨야 나중에 문제가 생겼을 때 원인을 빠르게 찾을 수 있다.
