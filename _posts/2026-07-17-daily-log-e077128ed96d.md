## 진행한 작업

### 1. 전투 실습 구간 진행 차단

- Step3 전투 실습 트리거의 자식으로 배치된 CombatCollider를 스크립트에서 수집하도록 했다.
- 플레이어가 전투 실습 안내를 실제로 시작한 뒤 앞·뒤 차단 콜라이더를 활성화하도록 했다.
- 전투 실습 적을 처치하기 전에는 구간을 빠져나갈 수 없게 했다.
- <code>GlobalEventBus.OnEnemyDead</code> 이벤트를 받아 적 처치 후 차단 콜라이더를 해제하도록 연결했다.
- 트리거가 초기화될 때 차단 콜라이더 상태도 함께 초기화되도록 했다.

### 2. Step2와 Step3 시작 조건 분리

- 초기 구현에서는 전투 차단이 너무 빨리 켜져 플레이어가 진행 방향을 잃거나 바닥 아래로 떨어질 수 있었다.
- CombatCollider 활성화 시점을 단순 접촉 시점이 아니라 안내 데이터가 실제로 처리된 시점으로 변경했다.
- TutorialGuide.json의 TID 2007 열림 조건을 <code>PrevGuideClosed / 2006</code>에서 <code>TriggerEnter / TutorialScene_Step3_CombatPractice</code>로 변경했다.
- Step2에서는 총과 스킬을 시험하고, Step3에 진입했을 때 전투 실습을 시작하는 흐름으로 정리했다.

### 3. 튜토리얼 UI 중 플레이어 입력 차단

- <code>LocalInputReader</code>에 <code>isGameplayInputBlocked</code> 상태를 추가했다.
- 이동, 공격, 스킬, 상호작용, 조준, 인벤토리, 퀵슬롯, 달리기, 구르기 입력을 공통으로 차단했다.
- 입력 차단이 시작되면 이동 벡터를 0으로 보내고 달리기 상태를 해제하도록 했다.
- 팝업을 닫은 클릭이 곧바로 총 발사로 이어지지 않도록, 액션맵 복귀와 게임플레이 입력 해제를 서로 다른 프레임에 처리했다.

### 4. 튜토리얼 UI를 인스펙터 기준으로 전환

- <code>TutorialPopup</code>이 런타임에 RectTransform 위치와 크기를 덮어쓰던 처리를 제거했다.
- 패널 위치, 크기, 캐릭터 이미지 위치는 TutorialSystem 프리팹과 인스펙터 설정을 기준으로 사용하도록 했다.
- 분리 패널의 BackgroundImage가 연결돼 있으면 인스펙터에서 지정한 Sprite, Color, Type을 우선 보존하도록 했다.
- 레거시 배경 스프라이트가 캔버스에 직접 설정한 이미지를 덮지 않도록 우선순위를 조정했다.
- ConfirmButton 참조가 비어 있을 경우 자식 Button에서 자동 탐색하도록 보강했다.
- 분리된 패널이 열릴 때 레거시 제목과 본문 텍스트가 함께 겹쳐 보이지 않도록 숨김 처리했다.

### 5. 튜토리얼 HUD 흐림 처리

- <code>GlobalEventBus.OnGameplayHUDAlphaRequested</code> 이벤트를 추가했다.
- <code>GamePlayUI</code>에 CanvasGroup 기반 HUD 알파 조절 기능을 연결했다.
- 튜토리얼 팝업이나 무전이 표시되는 동안 HUD 알파를 0.3으로 낮추고, 종료 시 1.0으로 복구하도록 했다.
- 튜토리얼 대사창과 인게임 HUD가 겹칠 때 안내 UI가 더 잘 보이도록 했다.

### 6. 튜토리얼 사망 방지와 관제사 무전

- TutorialScene이 로드된 상태에서 치명 피해를 받으면 플레이어 HP를 1로 고정하도록 했다.
- 일반 게임오버와 로비 이동 대신 피격 VFX, 피격 애니메이션, 피격 사운드를 유지했다.
- HP 1 방지 시 관제사 무전으로 “에너미를 죽여야 해!”와 “정신차려 유안!”을 번갈아 출력하도록 했다.
- 무전이 표시되는 동안 TimeScale을 0으로 만들고 플레이어 입력을 차단했다.
- 기존 튜토리얼 가이드가 열려 있었다면 무전 종료 후 기존 가이드를 복구하도록 했다.
- 이 사망 방지는 TutorialScene 로드 여부로 한정해 일반 인게임 사망 흐름에는 영향을 주지 않도록 했다.

### 7. Objective 패널 닫기와 목표 완료 분리

- Objective 패널의 클릭은 목표 완료가 아니라 화면에서 안내를 접는 기능으로 처리했다.
- 실제 목표 완료는 <code>EnemyDead</code>, <code>ItemBoxOpened</code>, <code>EscapeSucceeded</code> 같은 이벤트 조건이 계속 담당하도록 했다.
- 플레이어가 안내창을 닫아도 목표 추적 상태는 유지되도록 역할을 분리했다.

### 8. 에너미 HP 조정

- <code>EnemyStatus.Awake()</code>의 기본 HP 최대값을 100에서 50으로 변경했다.
- 공통 EnemyStatus를 수정했기 때문에 이 스크립트를 사용하는 모든 에너미에 적용될 가능성이 있다.
- 다크 스피릿 한정 조정이 목적이라면 프리팹 또는 데이터 기반 수치로 분리할 필요가 있다.

### 9. Notion 기록 정리

- 팀 전체 변경이 섞였던 <code>코드 변경 사항 기록//0717</code>을 사용자 작성 커밋 기준으로 다시 작성했다.
- 전체 스크립트 비교 문서를 사용자가 직접 수정한 8개 스크립트만 남도록 교정했다.
- 각 스크립트를 이전 상태, 변경 설명, 현재 상태, 정합성 확인 순서로 정리했다.

## 오늘의 핵심 결정

- 전투 차단 콜라이더는 Step3 안내가 실제로 처리된 뒤 활성화한다.
- 전투 실습 완료는 적 사망 이벤트로 판단하고 앞·뒤 차단을 해제한다.
- 튜토리얼 UI가 열리면 시간 정지, 액션맵 전환, 게임플레이 입력 차단을 함께 적용한다.
- UI 종료 시 확인 클릭이 공격으로 새지 않도록 입력 복구를 프레임 단위로 지연한다.
- 튜토리얼 UI의 위치와 크기는 스크립트가 아니라 프리팹·인스펙터가 담당한다.
- Objective 패널 닫기와 목표 이벤트 완료를 서로 다른 상태로 관리한다.
- 튜토리얼에서는 HP 1을 유지하고 관제사 무전으로 전투 지속을 유도한다.
- 튜토리얼 UI 중 인게임 HUD 알파는 0.3으로 낮춘다.

## 이슈 / 주의할 점

- <code>OnEnemyDead</code>는 현재 특정 튜토리얼 적의 ID를 확인하지 않으므로, 다른 적이 먼저 죽어도 차단이 해제될 가능성이 있다.
- <code>EnemyStatus.hpMax = 50</code>은 공통 스크립트 변경이므로 다크 스피릿 외 에너미에도 적용될 수 있다.
- <code>PlayerInput</code>이 비활성화된 상태에서 액션맵 전환을 호출하면 InputSystem 경고가 발생할 수 있다.
- <code>TutorialPopup.cs</code> 일부 한글 주석은 커밋 diff에서 글자가 깨져 보였으므로 파일 인코딩 확인이 필요하다.
- <code>SampleSceneProfile.asset</code>이 튜토리얼 커밋에 포함되어 있어 전역 렌더 설정 변경이 의도된 것인지 확인해야 한다.
- 런타임 사망 방지 무전이 기존 가이드 위에 반복 표시될 때 가이드 상태와 콜백이 정상 복구되는지 테스트가 필요하다.

## 배운 점

- UI 입력 차단은 TimeScale 정지만으로 해결되지 않는다. 게임플레이 입력 이벤트 자체를 막고, 팝업 종료 프레임의 입력까지 고려해야 한다.
- 트리거 접촉과 튜토리얼 안내 처리 성공은 같은 시점이 아닐 수 있다. 진행 차단 같은 물리 상태 변경은 안내가 실제로 열린 이후에 실행해야 한다.
- 비주얼 조정이 잦은 UI의 RectTransform을 코드에서 강제로 덮으면 인스펙터 작업과 충돌한다. 스크립트는 상태와 데이터, 프리팹은 배치를 담당하도록 분리하는 편이 관리하기 쉽다.
- 목표 안내 패널을 닫는 행위와 실제 목표를 완료하는 행위는 별도 상태로 관리해야 한다.
- Additive 씬 전용 로직은 활성 씬만 보지 않고 해당 씬의 로드 여부를 확인해야 한다.
- 개인 개발 기록은 같은 날짜의 전체 커밋이 아니라 Git 작성자와 직접 수정한 파일을 기준으로 범위를 명확히 해야 한다.
