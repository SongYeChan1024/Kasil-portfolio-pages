## 진행한 작업

### 1. 이동과 카메라

- 우클릭을 누르고 있는 동안 커서의 월드 지점으로 목적지가 계속 갱신되도록 구성했습니다.
- 아이소메트릭 Cinemachine 카메라가 플레이어를 추적하도록 연결했습니다.
- 테스트 지면, 장애물과 충돌 기반을 구성했습니다.

### 2. 정신 집중과 인게임 HUD

- Space 정신 집중은 별도 자원이 아니라 기존 코어 에너지를 비효율적으로 회복하는 수단으로 유지했습니다.
- 별도의 집중 게이지를 제거하고 중앙 하단 코어 에너지 바의 변화만 표시했습니다.
- 활성 HUD를 Canvas/UGUI로 구성하고 Canvas Scaler, 앵커, 레이아웃 그룹과 9-Slice 기준을 적용했습니다.

### 3. 전개 격자

- Tab을 누르면 필드 전체에 옅은 격자가 나타나고 전개 가능한 근접 3×3 영역만 청록색으로 강조됩니다.
- 옅은 격자와 활성 격자는 같은 셀 크기를 사용합니다.
- 근접 직군의 중앙 한 칸은 설계자 위치로 잠갔습니다.
- 2×2 이상의 큰 파츠는 셀 크기를 바꾸지 않고 여러 칸을 합친 점유 영역으로 표시하는 원칙을 정했습니다.

### 4. 빗자루 획득과 청사진 편집

- 테스트용 낡은 빗자루를 G로 획득해 보유 파츠에 추가하도록 했습니다.
- G는 획득만 담당하며, 편집 화면은 Tab HUD의 청사진 편집 버튼으로 진입합니다.
- 보유 파츠 좌클릭 후 격자 좌클릭 방식과 드래그 앤 드롭 방식을 모두 지원합니다.
- 배치된 파츠에 마우스를 올리고 QWERASDF를 눌러 액티브 스킬을 할당합니다.

### 5. 빗자루 스킬 사용

- Input Actions에 Q/W/E/R/A/S/D/F 스킬 입력을 연결했습니다.
- 할당 슬롯, 코어 자원과 재사용 대기를 검증한 뒤 스킬을 실행합니다.
- 스킬 사용 순간에만 빗자루를 임시 손 위치에 생성합니다.
- 내려치기, 쓸어치기, 찌르기를 임시 Transform 모션과 범위 피해 판정으로 구분했습니다.
- 공격이 끝나면 빗자루를 회수하고 이동 제한을 해제합니다.
- 게임플레이 판정과 시각 표현을 분리해 이후 Animator와 Animation Event로 교체할 수 있게 했습니다.

## 오늘의 결정

- G 획득과 청사진 편집 진입은 분리합니다.
- 근접 1레벨 청사진은 3×3이며 중앙은 설계자 위치입니다.
- 정신 집중은 전개 전후 사용할 수 있지만 코어 자동 생성보다 비효율적인 보조 회복 수단입니다.
- 장비형 파츠는 상시 손에 들지 않고 해당 스킬을 사용할 때만 현현합니다.
- 현재 공격 모션과 스킬 수치는 기능 검증용 가안입니다.

## 발생한 문제와 해결

- <b>우클릭 한 번의 목적지만 따라감</b> → 버튼 유지 중 포인터 지점을 계속 읽도록 변경했습니다.
- <b>기존 HUD의 해상도 대응 부족</b> → Canvas Scaler와 앵커 기반 UGUI로 전환했습니다.
- <b>G 획득 직후 편집 화면이 열림</b> → 획득과 편집 책임을 분리했습니다.
- <b>플레이 모드 중 씬 빌더 실행 오류</b> → 플레이 모드를 종료한 뒤 빌더를 다시 실행했습니다.
- <b>빗자루 상시 장착이 파츠 구조와 충돌</b> → 스킬 중에만 임시 생성·회수하도록 변경했습니다.
