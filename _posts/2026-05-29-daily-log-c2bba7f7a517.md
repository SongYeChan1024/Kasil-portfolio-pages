## 구현/작업 내용 (디테일)

- <b>무엇을 했는지</b>
  - 2D 실습 게임에 필요한 <b>HP 시스템</b>과 <b>스코어 시스템</b>을 구현하고, 게임 오버 UI(블랙 패널/게임오버 패널)까지 연결했다.
  - 플레이어 피격 연출을 위해 <b>Idle/Hit 애니메이션 클립</b>을 만들고, <b>Blend Tree</b>로 상태 전환을 구성했다.
  - Firebase Console에서 프로젝트를 만들고, Unity 쪽에서 Android 패키지명(언더바 제거 등)을 정리한 뒤 <b>Android 앱 등록 → google-services.json 적용 → FirebaseDatabase SDK 임포트 → Realtime Database 생성/URL 확보</b>까지 진행했다.
- <b>핵심 포인트 / 내가 결정한 것</b>
  - 실시간 멀티플레이 상태를 Firebase에 “매 프레임” 저장하는 건 과금 리스크가 커서, <b>실시간 동기화는 Photon 같은 네트워크 엔진</b>, Firebase는 <b>최종 결과/유저 데이터/세이브</b> 위주로 역할을 분리하는 방향을 유지하기.
  - Firebase 리스너/비동기 콜백에서 Unity UI나 GameObject를 바로 만지면 스레드 충돌이 날 수 있으니, <b>ContinueWithOnMainThread() / UnityMainThreadDispatcher로 메인 스레드에 넘기는 방식</b>을 기본 규칙으로 잡기.
- <b>관련 링크/파일</b>
  - Realtime Database URL: [https://fir-project-b5f2b-default-rtdb.firebaseio.com/](https://fir-project-b5f2b-default-rtdb.firebaseio.com/)
  - 설정 파일: google-services.json (Assets 최상위 배치)

## 배운 것 / 정리

- 개념:
  - <b>Firebase Spark vs Blaze</b>: Spark는 무료/제한, Blaze는 종량제지만 무료 구간 포함(초과분 과금). 출시/유저 증가/Storage·Functions 필요 시 Blaze 고려.
  - <b>Realtime Database</b>: JSON 트리 구조, 경로 기반 접근(Child 체인). 빠른 상태 동기화에 적합하지만 보안 규칙/과금 관리 필수.
  - <b>싱글턴 패턴</b>: 게임 전체에서 하나만 필요한 매니저(HP/Score 등)에 유용.
  - <b>fillAmount(Image)</b>: 0\~1로 게이지 표현(HP UI에 적합).
  - <b>코루틴(IEnumerator)</b>: 피격 연출처럼 “짧은 시간 유지”가 필요한 상태 변화에 효과적(0.15s 후 원복).
- 새로 알게 된 것:
  - Package Name에 언더바(\_)가 있으면 Firebase 등록에서 문제가 날 수 있어 미리 정리하는 게 안전.
  - 테스트 모드 규칙(.read/.write true)은 개발 편의는 높지만 <b>URL만 알면 누구나 접근 가능</b>이라 배포 전 반드시 강화해야 한다.
- 다음에 다시 볼 키워드:
  - ContinueWithOnMainThread, UnityMainThreadDispatcher, Realtime Database Rules, Spark/Blaze, Presence, Photon vs Firebase 역할 분리

## 이슈 / 트러블슈팅 (원인 → 대응)

- <b>증상</b>
  - (예상/자주 발생) Firebase 콜백 내부에서 UI 텍스트 변경이나 GameObject 제어 시 에러 발생 가능
- <b>원인 가설</b>
  - Firebase 콜백이 Unity <b>메인 스레드가 아닌 백그라운드 스레드</b>에서 실행될 수 있음 → Unity API는 메인 스레드 전용
- <b>해결/대응</b>
  - Task 기반 처리: <code>ContinueWithOnMainThread()</code> 사용
  - 리스너/이벤트 기반 처리: <code>UnityMainThreadDispatcher.Enqueue()</code>로 UI/오브젝트 제어를 메인 스레드로 전달
- <b>회고(재발 방지)</b>
  - “콜백에서는 데이터만 다루고, 화면/오브젝트 갱신은 메인 스레드에서”를 습관화하기.
  - Firebase 규칙/과금(예산 알림 포함)은 초기에 세팅해서 나중에 리스크가 커지지 않게 하기.
