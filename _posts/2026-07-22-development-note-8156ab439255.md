- 원인
  <p>
  기존의 방식은 DataManager에 플레이어 데이터에 대한 객체를 선언하고, 해당 객체 데이터를 인터페이스를 통해 접근하는 방식이였는데 플레이어 데이터를 사용하는 스크립트들이 동일한 플레이어 데이터 객체를 사용하지 않고 있었음. 또한 DataManager에 직접적으로 접근 하기에는 스크립트간의 계층 구조가 이를 불가능하게 함.
  </p>
- 해결
  <p>
  플레이어 데이터를 저장하는 싱글톤 ScriptableObject(이하 SO) 스크립트를 Define 파일에 선언하고 Resources 파일에 SO 에셋을 생성하여 어느 계층의 스크립트에서나 플레이어 데이터에 대한 접근이 용이하게 하는 동시에 참조에 있어 혼동이 없게 함
  </p>
