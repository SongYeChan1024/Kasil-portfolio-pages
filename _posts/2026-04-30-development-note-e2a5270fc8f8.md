<b>VR 개발 기초: Unity 설치와 가상현실 핵심 요소</b> 2026-04-30


## 요약


### 오늘 수업 핵심 요약

- <b>Unity 6.3 LTS 버전</b> 설치 및 VR 개발 환경 구축 방법을 배웠습니다. 
- VR에서 상호작용하기 위한 세 가지 핵심 요소인 <b>트래킹(Tracking)</b>, <b>렌더링(Rendering)</b>, <b>인터랙션(Interaction)</b>의 개념과 역할을 이해했습니다. 
- <b>6DoF(Six Degrees of Freedom)</b> 개념을 통해 VR이 단순한 화면 회전이 아니라 실제 공간 이동까지 추적하는 원리를 배웠습니다. 
- Universal 3D 템플릿으로 VR 프로젝트를 생성하는 과정을 실습했으며, 이는 향후 VR 애플리케이션 개발의 기초가 됩니다. 

---

### 주요 개념 정리

- <b>6DoF (Six Degrees of Freedom / 6자유도)</b> 
  - 설명: VR에서 사용자의 움직임을 추적하는 6가지 자유도를 의미하며, 3축 이동(X, Y, Z)과 3축 회전(Pitch, Yaw, Roll)을 포함합니다. 
  - 예시: VR 헤드셋과 컨트롤러가 사용자의 고개 회전뿐만 아니라 앞뒤 좌우 이동까지 추적하는 것
  - 사용되는 상황: VR 환경에서 사용자의 머리와 손의 위치를 정확하게 파악할 때 
  - 헷갈릴 수 있는 점: 3DoF는 회전만 추적하지만, 6DoF는 이동과 회전을 모두 추적합니다.
- <b>트래킹 (Tracking)</b> 
  - 설명: 가상현실에서 사용자의 머리와 손의 위치를 실시간으로 추적하는 기술 
  - 예시: 사용자가 실제로 몸을 움직이거나 손을 뻗으면 VR 공간에서도 동일하게 반영되는 것 
  - 사용되는 상황: VR 헤드셋과 컨트롤러가 사용자의 움직임을 감지하여 가상 공간에 반영할 때
  - 헷갈릴 수 있는 점: 단순히 화면 방향만 바꾸는 것이 아니라, 실제 공간에서의 이동까지 추적해야 몰입감 있는 VR이 구현됩니다. 
- <b>렌더링 (Rendering)</b> 
  - 설명: 사용자가 VR 공간을 볼 수 있도록 가상 세계를 화면에 그려주는 과정 
  - 예시: 고개를 오른쪽으로 돌리면 VR 화면도 즉시 그 방향으로 바뀌는 것 
  - 사용되는 상황: 사용자의 머리 움직임에 맞춰 화면을 실시간으로 업데이트할 때 
  - 헷갈릴 수 있는 점: 일반 게임보다 VR에서 렌더링이 훨씬 중요한 이유는 지연이나 프레임 저하가 멀미를 유발하기 때문입니다. 
- <b>인터랙션 (Interaction)</b> 
  - 설명: 사용자가 VR 공간 안의 오브젝트와 상호작용하는 것 
  - 예시: 손으로 물건을 잡거나(Grab Interaction), 광선을 쏴서 멀리 있는 UI를 선택하는 것(Ray Interaction) 
  - 사용되는 상황: 총을 잡고 발사하기, 공을 던지기, 문 손잡이를 열기, 버튼 누르기 등 
  - 헷갈릴 수 있는 점: VR에서는 단순히 버튼을 누르는 것이 아니라 실제로 손과 컨트롤러를 움직여 상호작용합니다. 
- <b>LTS (Long Term Support / 롱텀 서포트)</b> 
  - 설명: 2\~4년 동안 최신 버전이 바뀌더라도 안정성을 보장하는 Unity 버전 
  - 예시: Unity 6.3 LTS 버전 
  - 사용되는 상황: 장기 프로젝트를 진행할 때 버전 호환성 문제를 방지하기 위해
  - 헷갈릴 수 있는 점: LTS가 아닌 버전은 최신 기능이 있지만, 버전 업데이트로 인한 오류 위험이 있습니다.

### 수업 흐름별 정리

### 1. Unity 설치 및 버전 선택 

- 설명: Unity Hub를 통해 Unity 6.3 LTS 버전을 설치합니다.
- 중요: LTS(Long Term Support) 버전을 선택하여 2\~4년간 안정성을 보장받습니다. 
- 중요한 이유: LTS 버전은 최신 버전이 나와도 호환성 문제가 발생하지 않도록 지원됩니다.

### 2. 모듈 추가 및 플랫폼 설정 

- 설명: Unity에서 다양한 플랫폼을 지원하기 위해 필요한 모듈을 설치합니다.
- 예시: Android Build Support, iOS Build Support, Windows, WebGL 플랫폼 등 
- 중요한 이유: VR 애플리케이션을 다양한 디바이스에 배포하려면 해당 플랫폼 모듈이 설치되어 있어야 합니다.

### 3. 개발 환경 구성 

- 설명: 코드 에디터로 Microsoft Visual Studio Community 2022 또는 Cursor를 사용합니다.
- 예시: Visual Studio Code, Cursor 등을 Unity와 연동하여 사용 가능 
- 중요: 강사는 Cursor Pro 조합을 최상의 조합으로 추천했습니다. 

### 4. VR 프로젝트 생성 

- 설명: Universal 3D 템플릿을 선택하여 VR 프로젝트를 생성합니다.
- 예시: VR 템플릿도 있지만, 샘플 다운로드로 인해 시간이 많이 걸리고 무거워지므로 Universal 3D를 선택 
- 중요한 이유: VR 설정이 어떻게 구성되는지 이해하기 위해 일반 템플릿에서 시작하여 VR 기능을 추가하는 방식을 학습합니다. 

### 5. VR 핵심 개념 이해 

- 설명: VR에서 상호작용하기 위한 세 가지 핵심 요소를 학습했습니다.
- 예시: 트래킹(사용자 위치 추적), 렌더링(화면 표시), 인터랙션(오브젝트 조작) 
- 중요한 이유: 이 세 가지 요소가 모두 작동해야 몰입감 있는 VR 경험을 제공할 수 있습니다.

### 실습 / 작업 순서

1. Unity Hub를 실행하고 Unity 6.3 LTS 버전을 설치합니다. 
2. "모듈 추가"를 클릭하여 필요한 플랫폼 모듈을 선택합니다. 
3. Android Build Support, iOS Build Support, WebGL, Windows 플랫폼을 체크합니다.

5. 한국어 언어 팩을 선택하고 약관에 동의합니다.

7. 프로젝트 생성 화면으로 이동합니다. 
8. "Universal 3D" 템플릿을 선택합니다. 
9. 프로젝트 이름을 "First VR Project" 등으로 설정합니다. 
10. "프로젝트 생성"을 클릭하여 프로젝트를 생성합니다.

### 예시와 활용 사례

  - 상황: VR 헤드셋을 착용하고 공간을 이동할 때
  - 설명: X축(좌우), Y축(위아래), Z축(앞뒤) 이동과 Pitch(상하 회전), Yaw(좌우 회전), Roll(기울임) 회전을 모두 추적합니다. 
  - 왜 이 예시를 사용했는지: 3DoF(회전만)와 6DoF(이동+회전)의 차이를 명확히 이해하기 위해
- <b>렌더링 중요성 예시</b>
  - 상황: 사용자가 고개를 빠르게 돌릴 때
  - 설명: VR 화면이 즉시 반응하지 않으면 지연이 발생하고 멀미를 유발합니다. 
  - 왜 이 예시를 사용했는지: VR에서 부드러운 렌더링과 낮은 지연 시간이 왜 중요한지 강조하기 위해 
- <b>Grab Interaction 예시</b>
  - 상황: VR에서 총을 잡거나 공을 집어서 던질 때
  - 설명: 손이나 컨트롤러로 오브젝트를 직접 잡는 방식의 상호작용입니다. 
  - 왜 이 예시를 사용했는지: VR 인터랙션의 직관적인 특성을 보여주기 위해
- <b>Ray Interaction 예시</b>
  - 상황: 멀리 있는 UI 버튼을 선택하거나 오브젝트를 가리킬 때
  - 설명: 광선처럼 포인터를 쏴서 멀리 있는 대상을 선택하는 방식입니다. 
  - 왜 이 예시를 사용했는지: 손이 닿지 않는 곳의 상호작용 방법을 이해하기 위해

## 1. 트래킹 Tracking

가상현실에서는 사용자의 <b>머리와 손의 위치</b>를 추적해야 한다.

단순히 어느 방향을 보고 있는지만 아는 것이 아니라, 실제 공간에서 사용자가 어디로 움직이고 있는지도 함께 추적해야 한다.

이때 사용하는 개념이 <b>6DoF</b>이다.

```txt
6DoF = Six Degrees of Freedom
6자유도
```

6DoF는 총 여섯 가지 움직임을 추적한다.

### 3축 이동

```txt
X축: 좌우 이동
Y축: 위아래 이동
Z축: 앞뒤 이동
```

### 3축 회전

```txt
Pitch: 위아래로 고개 움직임
Yaw: 좌우로 고개 돌림
Roll: 고개를 기울임
```

즉, VR에서는 사용자가 <b>고개를 돌리는 것뿐만 아니라 실제로 몸이나 손을 움직이는 것까지</b> 추적할 수 있어야 한다.

---

## 2. 렌더링 Rendering

HMD(Head Mount Display)

렌더링은 사용자가 VR 공간을 볼 수 있도록 <b>가상 세계를 화면에 그려주는 과정</b>이다.

VR에서는 일반 게임보다 렌더링이 더 중요하다.

사용자의 머리 움직임에 맞춰 화면이 즉시 바뀌어야 하기 때문이다.

예를 들어 사용자가 고개를 오른쪽으로 돌리면, VR 화면도 그 방향에 맞게 자연스럽게 바뀌어야 한다.

렌더링에서 중요한 요소는 다음과 같다.

```txt
시야각
프레임 유지
양쪽 눈에 맞는 입체 화면
낮은 지연 시간
```

지연이 심하거나 화면이 끊기면 멀미가 날 수 있기 때문에, VR에서는 부드러운 렌더링이 매우 중요하다.

---

## 3. 인터랙션 Interaction

Grab Ray

인터랙션은 사용자가 VR 공간 안의 오브젝트와 상호작용하는 것이다.

VR에서는 단순히 버튼을 누르는 것뿐만 아니라, 손이나 컨트롤러를 이용해 오브젝트를 직접 잡거나, 던지거나, 멀리 있는 대상을 가리켜 선택할 수 있다.

대표적인 방식은 다음과 같다.

```txt
Grab Interaction: 손으로 오브젝트를 잡는 방식
Ray Interaction: 광선처럼 포인터를 쏴서 멀리 있는 오브젝트를 선택하는 방식
```

예시는 다음과 같다.

```txt
총을 잡고 발사하기
공이나 물건을 집어서 던지기
문 손잡이를 잡고 열기
버튼을 눌러 장치 작동시키기
멀리 있는 UI를 Ray로 선택하기
```

즉, 인터랙션은 사용자가 VR 세계 안에서 <b>직접 행동하고 반응을 얻는 구조</b>라고 볼 수 있다.

<b>Unity VR 환경 설정 및 OpenXR 구성</b> 2026-04-30


## 요약


### 오늘 수업 핵심 요약

- Unity에서 <b>OpenXR</b>을 설치하고 구성하여 VR 개발 환경을 구축하는 방법을 배웠습니다. 
- <b>XR Plugin Management</b>를 통해 PC와 Android 플랫폼에서 OpenXR을 활성화하고 <b>인터랙션 프로파일</b>을 등록하는 과정을 실습했습니다. 
- <b>XR Interaction Toolkit</b>을 설치하여 VR에서 손과 컨트롤러의 입력 및 상호작용을 처리할 수 있는 환경을 만들었습니다. 
- 기존 Main Camera를 <b>XR Origin</b>으로 변환하여 VR 카메라 시스템을 구성하는 방법을 배웠으며, 이는 VR 애플리케이션의 핵심 구조입니다. 

---

### 주요 개념 정리

- <b>OpenXR</b> 
  - 설명: VR, AR, MR 등 다양한 XR 기기를 통합적으로 지원하는 표준 통신 규격 API입니다. 
  - 예시: Meta Quest, Oculus Quest, HTC Vive 등 다양한 VR 기기를 하나의 API로 지원 
  - 사용되는 상황: 여러 VR 기기에서 동작하는 애플리케이션을 개발할 때 
  - 헷갈릴 수 있는 점: OpenXR은 기기를 연결시켜주는 역할이고, XR Interaction Toolkit은 입력과 상호작용을 담당합니다. 
- <b>XR Plugin Management</b> 
  - 설명: Unity에서 XR 관련 플러그인을 관리하고 설치하는 시스템입니다. 
  - 예시: OpenXR 플러그인 설치 및 활성화 
  - 사용되는 상황: VR 개발 환경을 처음 구성할 때 반드시 설치해야 합니다. 
  - 헷갈릴 수 있는 점: 설치 후 PC와 Android 플랫폼 각각에서 OpenXR을 체크해야 합니다. 
- <b>인터랙션 프로파일 (Interaction Profile)</b> 
  - 설명: VR 컨트롤러의 버튼과 입력을 정의하는 설정 파일입니다. 
  - 예시: Meta Quest Touch Controller Profile, Oculus Touch Controller Profile 
  - 사용되는 상황: 특정 VR 기기의 컨트롤러를 Unity에서 인식하고 사용할 때 
  - 헷갈릴 수 있는 점: Meta라고 적힌 프로파일과 Oculus 프로파일을 모두 등록해야 호환성이 좋습니다. 
- <b>XR Interaction Toolkit</b> 
  - 설명: VR에서 손이나 컨트롤러의 입력 및 상호작용을 처리하는 프레임워크입니다. 
  - 예시: 오브젝트 잡기, 텔레포트, UI 버튼 클릭 등 
  - 사용되는 상황: VR 애플리케이션 내부에서 유저 입력이나 인터랙션을 설계할 때 
  - 헷갈릴 수 있는 점: OpenXR은 기기 연결, XR Interaction Toolkit은 입력 처리로 역할이 다릅니다. 
- <b>XR Origin</b> 
  - 설명: VR에서 카메라와 컨트롤러의 위치 기준점이 되는 오브젝트입니다. 
  - 예시: Main Camera가 XR Origin의 자식으로 들어가는 구조 
  - 사용되는 상황: VR 카메라 시스템을 구성할 때 기존 Main Camera를 XR Origin으로 변환합니다. 
  - 헷갈릴 수 있는 점: Main Camera가 XR Origin의 자식으로 들어가야 하며, 바깥으로 빠지면 안 됩니다. 
- <b>Runtime Debug</b> 
  - 설명: VR 기기가 없는 상태에서도 기기가 연결된 것처럼 테스트할 수 있게 해주는 옵션입니다. 
  - 예시: 체크하면 플레이 시 화면이 깜빡이며 VR 모드로 전환됩니다. 
  - 사용되는 상황: VR 기기 없이 개발 및 테스트를 진행할 때 
  - 헷갈릴 수 있는 점: 실제 기기가 연결된 것은 아니며, 시뮬레이션만 가능합니다.

### 수업 흐름별 정리

### 1. OpenXR 패키지 설치 

- 설명: Window > Package Manager에서 OpenXR 패키지를 설치합니다. 
- 예시: Unity Registry에서 XR 검색하여 OpenXR Plugin 찾기 
- 중요한 이유: OpenXR은 다양한 VR 기기를 통합 지원하는 표준 API이므로 VR 개발의 기본입니다. 

### 2. XR Plugin Management 설정 

- 설명: Edit > Project Settings > XR Plug-in Management에서 Install XR Plugin Management를 실행합니다. 
- 중요: 설치 후 OpenXR을 체크하여 활성화해야 합니다. 
- 중요한 이유: XR Plugin Management가 있어야 OpenXR 및 기타 XR 기능을 사용할 수 있습니다. 

### 3. PC 및 Android 플랫폼에서 OpenXR 활성화 

- 설명: XR Plug-in Management에서 PC와 Android 탭 각각에서 OpenXR을 체크합니다. 
- 예시: PC 탭에서 OpenXR 체크, Android 탭에서도 OpenXR 체크 
- 중요한 이유: 각 플랫폼별로 OpenXR을 활성화해야 해당 플랫폼에서 VR이 동작합니다. 

### 4. 인터랙션 프로파일 등록 

- 설명: OpenXR 설정에서 Interaction Profiles에 VR 컨트롤러 프로파일을 추가합니다. 
- 예시: Meta Quest Touch Controller Profile, Meta Quest Touch Plus Controller Profile, Oculus Touch Controller Profile 추가 
- 중요: Meta라고 적힌 프로파일은 모두 추가하는 것이 좋습니다. 
- 중요한 이유: 컨트롤러 프로파일이 등록되어야 VR 컨트롤러 입력을 인식할 수 있습니다. 

### 5. XR Interaction Toolkit 설치 

- 설명: Window > Package Manager에서 XR Interaction Toolkit을 검색하여 Install 합니다. 
- 예시: 손의 입력, 오브젝트 변화, 텔레포트, UI 버튼 클릭 처리 
- 중요한 이유: VR에서 손과 컨트롤러의 상호작용을 구현하는 핵심 프레임워크입니다. 

### 6. Main Camera를 XR Origin으로 변환 

- 설명: Hierarchy에서 Main Camera를 마우스 우클릭하여 XR > Convert Main Camera to XR Rig를 선택합니다. 
- 예시: 기존 Main Camera가 사라지고 XR Origin 하위에 Main Camera가 생성됩니다. 
- 중요: Main Camera는 XR Origin의 자식으로 유지되어야 하며 바깥으로 빠지면 안 됩니다. 
- 중요한 이유: VR 카메라 시스템의 기본 구조를 이해하고 올바르게 구성해야 합니다. 

### 7. Runtime Debug 설정 

- 설명: Edit > Project Settings > XR Plug-in Management > OpenXR에서 Runtime Debugger를 체크합니다. 
- 예시: 플레이 시 화면이 깜빡이며 VR 모드로 전환됩니다. 
- 중요: VR 기기가 없어도 기기가 연결된 것처럼 테스트할 수 있습니다. 

### 8. XR 오브젝트 생성 확인 

- 설명: Hierarchy에서 마우스 우클릭 시 XR 메뉴가 나타나는지 확인합니다. 
- 예시: XR > Room-Scale XR, XR > All-In-One VR 등의 옵션 
- 중요한 이유: XR 메뉴가 보이면 VR 환경 설정이 완료된 것입니다.

- <b>헷갈리는 개념</b>: Main Camera의 위치
- <b>헷갈리는 이유</b>: VR로 변환 후 Main Camera의 위치가 바뀌어서 혼란스러울 수 있습니다.

<b>XR Origin 설정과 컨트롤러 구성</b> 2026-04-30


## 요약


### 오늘 수업 핵심 요약

- <b>XR Origin</b>이 VR에서 <b>트래킹 기능</b>을 수행하며, 이를 <b>HMD(Head Mounted Display)</b>라고 부른다는 것을 배웠습니다. 
- <b>XR Device Simulator</b> 샘플을 설치하여 VR 기기 없이도 키보드로 테스트할 수 있는 환경을 구성했습니다. 
- <b>Left Controller</b>와 <b>Right Controller</b>를 XR Origin의 Camera Offset 하위에 추가하고, <b>Tracked Pose Driver</b>를 설정하여 손의 위치와 회전을 추적하도록 구성했습니다. 
- Starter Assets의 프리팹을 활용하여 VR 컨트롤러를 구성하는 방법과 Input Action Reference 설정 방법을 실습했습니다. 

---

### 주요 개념 정리

- <b>XR Origin (VR)</b> 
  - 설명: VR에서 트래킹 기능을 수행하는 오브젝트로, 사용자의 머리와 손의 위치 및 회전을 추적합니다. 
  - 예시: HMD(Head Mounted Display)의 역할을 담당 
  - 사용되는 상황: VR 헤드셋을 착용하고 시선을 움직일 때 화면도 함께 움직이도록 할 때 
  - 헷갈릴 수 있는 점: XR Origin은 단순히 카메라가 아니라 트래킹을 수행하는 시스템 전체를 의미합니다.
- <b>HMD (Head Mounted Display)</b> 
  - 설명: 머리 부분에 장착하는 디스플레이 장치로, VR 기기에서 머리 부분의 동작을 담당합니다. 
  - 예시: Meta Quest 3, Oculus Quest 등의 VR 헤드셋 
  - 사용되는 상황: 사용자의 시선에 따라 화면 모습이 움직이게 할 때 
  - 헷갈릴 수 있는 점: HMD는 하드웨어를 의미하기도 하지만, Unity에서는 XR Origin이 HMD의 기능을 소프트웨어적으로 구현합니다.
- <b>XR Device Simulator</b> 
  - 설명: VR 기기가 없어도 키보드를 사용하여 VR 동작을 테스트할 수 있게 해주는 도구 
  - 예시: 키보드로 머리와 손의 움직임을 시뮬레이션 
  - 사용되는 상황: VR 기기 없이 개발 및 테스트를 진행할 때 
  - 헷갈릴 수 있는 점: 실제 VR 기기와 완전히 동일하지는 않지만, 기본적인 동작 확인에는 충분합니다.
- <b>Tracked Pose Driver</b> 
  - 설명: OpenXR에서 트래킹 오리진을 파악하여 6DoF 기능을 위한 회전량과 이동을 수행시켜주는 컴포넌트 
  - 예시: Main Camera와 Left/Right Controller에 추가하여 위치 추적 
  - 사용되는 상황: VR에서 머리와 손의 위치 및 회전을 실시간으로 추적할 때 
  - 헷갈릴 수 있는 점: Tracked Pose Driver는 자동으로 생성되지 않으므로 수동으로 추가해야 합니다.
- <b>Input Action Reference</b> 
  - 설명: 컨트롤러 입력을 처리하기 위한 레퍼런스 방식의 설정 
  - 예시: Position Input, Rotation Input, Tracking State Input 등 
  - 사용되는 상황: 컨트롤러의 위치, 회전, 트래킹 상태를 입력받을 때 
  - 헷갈릴 수 있는 점: Action 방식과 Reference 방식이 있는데, 여기서는 Reference 방식을 사용합니다.

### 수업 흐름별 정리

### 1. XR Origin과 HMD 개념 확인 

- 설명: XR Origin이 트래킹 기능을 수행하며, 이를 HMD(Head Mounted Display)라고 부릅니다. 
- 예시: 머리 부분 VR 기기에서 동작하며, 사용자가 움직이면 화면도 함께 움직입니다. 
- 중요한 이유: VR의 기본 구조를 이해하는 데 필수적인 개념입니다.

### 2. XR Interaction Manager와 컨트롤러 구조 파악 

- 설명: XR Origin 하위에 Camera Offset이 있고, 그 아래에 Main Camera, Left Controller, Right Controller가 위치합니다. 
- 예시: 데모 씬에서 Left Controller와 Right Controller가 Camera Offset과 같은 레벨에 있는 구조 확인 
- 중요한 이유: 컨트롤러를 올바른 위치에 배치해야 트래킹이 정상 작동합니다. 

### 3. XR Device Simulator 설치 

- 설명: Window > Package Manager에서 XR Interaction Toolkit의 샘플 중 XR Device Simulator를 설치합니다. 
- 중요: VR 기기가 없어도 키보드로 테스트할 수 있게 해주는 중요한 도구입니다. 
- 중요한 이유: 개발 중 매번 VR 기기를 연결하지 않고도 테스트할 수 있어 효율적입니다. 

### 4. Starter Assets 샘플 확인 

- 설명: XR Interaction Toolkit의 샘플에서 Starter Assets를 임포트하여 컨트롤러 프리팹을 사용할 수 있습니다. 
- 예시: Prefabs 폴더에서 XR Controller Left, XR Controller Right 프리팹 확인 
- 중요한 이유: 직접 처음부터 만들지 않고 제공되는 프리팹을 활용하여 빠르게 개발할 수 있습니다. 

### 5. 컨트롤러 프리팹 구조 이해 

- 설명: Left/Right Controller 프리팹 내부에는 조이스틱, 버튼 A/B, 트리거, 그랩 등이 모델링되어 있습니다. 
- 예시: 트리거는 총을 쏘거나 활을 쏠 때, 그랩은 물건을 잡을 때 사용 
- 중요한 이유: 컨트롤러 애니메이션이 미리 만들어져 있어 바로 사용할 수 있습니다. 

### 6. 컨트롤러를 XR Origin에 추가 

- 설명: XR Controller Left와 XR Controller Right를 Camera Offset 하위에 추가하여 Main Camera와 동일한 레벨에 배치합니다. 
- 중요: 컨트롤러는 반드시 XR Origin의 자식으로 유지되어야 합니다. 
- 중요한 이유: Camera Offset과 같은 위치에 있어야 트래킹이 정상 작동합니다. 

### 7. Tracked Pose Driver 추가 

- 설명: Left Controller와 Right Controller를 모두 선택한 후 Tracked Pose Driver 컴포넌트를 추가합니다. 
- 예시: 두 컨트롤러를 함께 선택하여 한 번에 컴포넌트 추가 가능 
- 중요한 이유: Tracked Pose Driver가 있어야 6DoF 기능으로 위치와 회전을 추적할 수 있습니다. 

### 8. Input Action Reference 설정 

- 설명: Position Input, Rotation Input, Tracking State Input을 Reference 방식으로 설정합니다. 
- 예시: 두 컨트롤러를 모두 선택하고 Use Reference로 변경 
- 중요한 이유: 트래킹을 어떻게 할 것인지 정의하는 중요한 단계입니다. 

### 9. 레퍼런스 위치 확인 

- 설명: Input Action Reference들은 Starter Assets > Samples > XR Device Controller에 위치합니다. 
- 예시: 아무 레퍼런스나 선택하여 위치를 확인할 수 있음 
- 중요한 이유: 나중에 커스터마이징할 때 어디서 수정해야 하는지 알아야 합니다.

### 실습 / 작업 순서

1. Window > Package Manager로 이동합니다. 
2. XR Interaction Toolkit 패키지를 찾습니다. 
3. Samples 탭에서 Starter Assets를 Import 합니다. 
4. Samples 탭에서 XR Device Simulator를 Import 합니다. 
5. 경고문이 나타나면 "Fix All"을 클릭합니다. 
6. Edit > Project Settings > XR Plug-in Management > Project Validation에서 모든 이슈를 해결합니다. 
7. Starter Assets > Prefabs 폴더에서 XR Controller Left와 XR Controller Right 프리팹을 찾습니다. 
8. XR Origin의 Camera Offset 하위로 두 컨트롤러 프리팹을 드래그합니다. 
9. Left Controller와 Right Controller를 Main Camera와 같은 레벨에 배치합니다. 
10. 두 컨트롤러를 모두 선택합니다. 
11. Tracked Pose Driver 컴포넌트를 추가합니다. 
12. Position Input, Rotation Input, Tracking State Input을 모두 "Use Reference"로 변경합니다. 
13. 각 입력 항목에 적절한 Input Action Reference를 할당합니다.

### 헷갈릴 수 있는 부분

- <b>헷갈리는 개념</b>: XR Origin의 자식 구조
- <b>헷갈리는 이유</b>: Camera Offset과 Main Camera, Controller의 계층 관계가 복잡합니다.
- <b>구분 방법</b>: XR Origin > Camera Offset > (Main Camera, Left Controller, Right Controller) 순서로, 컨트롤러는 Main Camera와 같은 레벨에 위치해야 합니다. 
- <b>헷갈리는 개념</b>: Input Action Reference vs Action 방식
- <b>헷갈리는 이유</b>: 입력 설정 시 Reference와 Action 두 가지 방식 중 선택해야 합니다.
- <b>구분 방법</b>: 이 수업에서는 Reference 방식을 사용하며, Reference를 선택하면 레퍼런스를 넣을 수 있는 공간이 생깁니다. 
- <b>헷갈리는 개념</b>: 트리거 vs 그랩
- <b>헷갈리는 이유</b>: 두 버튼 모두 컨트롤러에서 손가락으로 누르는 버튼입니다.
- <b>구분 방법</b>: 트리거는 총을 쏘거나 활을 쏠 때 사용하고, 그랩은 물건을 잡을 때 사용합니다.

### 주요 개념 정리

- <b>Camera Offset Y축 회전</b> 
  - 설명: Camera Offset의 Y축 회전값을 조정하여 컨트롤러의 기본 방향을 설정합니다.
  - 예시: Y축을 180도로 설정하면 컨트롤러가 반대 방향을 향하게 됩니다. 
  - 사용되는 상황: 컨트롤러의 초기 방향이 잘못되었을 때 Camera Offset의 회전값으로 보정합니다.
  - 헷갈릴 수 있는 점: Camera Offset과 개별 컨트롤러 중 어디에 회전값을 적용해야 하는지 혼동할 수 있습니다.
- <b>컨트롤러 시각화 오브젝트</b> 
  - 설명: 캡슐이나 다른 3D 오브젝트를 사용하여 컨트롤러의 위치를 화면에 표시합니다.
  - 예시: Left, Right 이름의 캡슐 오브젝트를 Camera Offset 하위에 생성 
  - 사용되는 상황: VR 기기 없이 개발할 때 컨트롤러 위치를 확인하기 위해 사용합니다.
  - 헷갈릴 수 있는 점: 나중에는 실제 손 모델링으로 교체할 예정이므로 임시 오브젝트입니다. 
- <b>Capsule Collider 제거</b> 
  - 설명: 시각화 목적으로만 사용하는 캡슐의 Collider 컴포넌트를 제거합니다.
  - 예시: Capsule Collider를 삭제하여 물리 충돌을 방지 
  - 사용되는 상황: 컨트롤러 표현 오브젝트가 다른 물체와 충돌하지 않도록 할 때
  - 헷갈릴 수 있는 점: Collider가 있으면 다른 오브젝트와 충돌이 발생할 수 있습니다.

### 수업 흐름별 정리

### 1. Camera Offset 회전값 조정 

- 설명: 두 컨트롤러를 선택하여 Camera Offset의 Y축을 180도로 설정합니다. 
- 예시: Camera Offset Y = 180도, 나머지 컨트롤러들은 0으로 설정 
- 중요한 이유: 컨트롤러의 방향이 올바르게 표시되도록 초기 회전값을 설정해야 합니다.

### 2. 키보드로 VR 컨트롤러 테스트 

- 설명: XR Device Simulator를 사용하여 키보드로 컨트롤러 동작을 확인합니다.
- 예시: WASD로 조이스틱, T로 위치 조정, Y로 버튼, 마우스 왼쪽으로 트리거, G로 그랩 테스트 
- 중요: 실제 VR 기기가 없어도 키보드로 모든 입력을 시뮬레이션할 수 있습니다.

### 3. 컨트롤러 시각화를 위한 캡슐 생성 

- 설명: 3D Object > Capsule을 생성하여 Camera Offset 하위에 배치합니다. 
- 예시: Left, Right 이름의 캡슐 두 개를 생성하고 Capsule Collider 제거 
- 중요한 이유: 컨트롤러의 위치를 시각적으로 확인하기 위한 임시 오브젝트입니다.

### 4. 캡슐에 Tracked Pose Driver 추가 

- 설명: Left, Right 캡슐에 Tracked Pose Driver 컴포넌트를 추가합니다. 
- 예시: Copy Component로 한쪽에서 복사하여 다른 쪽에 붙여넣기 
- 중요한 이유: Tracked Pose Driver가 있어야 컨트롤러의 위치와 회전을 추적할 수 있습니다.

### 5. Input Action Reference 설정 

- 설명: Left와 Right 캡슐 모두 선택하여 Use Reference로 변경하고 Input Action을 할당합니다. 
- 예시: Position Input, Rotation Input, Tracking State Input을 각각 XRI 레퍼런스로 설정 
- 중요한 이유: 트래킹 입력을 어떻게 받을지 정의하는 단계입니다.

## 요약


### 오늘 수업 핵심 요약 

- VR 환경에서 <b>버튼, 그립, 트리거, 텔레포트</b> 등 다양한 인터랙션 기능을 직접 테스트하는 방법을 실습했습니다. 
- <b>남서울대 심리학과</b>에서 의뢰한 VR 심리 테스트 프로젝트 사례를 통해 VR이 심리 분석에 어떻게 활용되는지 배웠습니다. 
- VR 시나리오에서 사용자의 첫 행동을 분석하여 심리 상태를 파악할 수 있다는 점을 이해했습니다. 
- VR 기술이 <b>심리 치료, 시뮬레이션, 정신과 진단</b> 등 다양한 분야에서 활용되고 있음을 배웠습니다. 

---

### 주요 개념 정리

- <b>VR 심리 테스트</b> 
  - 설명: VR 환경에서 특정 상황을 제시하고, 사용자의 첫 번째 행동을 관찰하여 심리 상태를 분석하는 기법 
  - 예시: 방 안에 우는 아기, 끓는 물, 어지러운 방이 있을 때 무엇을 먼저 하는지 관찰 
  - 사용되는 상황: 심리학 연구, 정신과 진단, 심리 상태 평가 등 
  - 헷갈릴 수 있는 점: 단순히 VR 체험이 아니라 사용자의 우선순위와 판단을 분석하는 도구입니다.
- <b>VR 심리 치료</b> 
  - 설명: 기존에는 연극을 보여주며 심리 치료를 했지만, 최근에는 VR을 통해 환자에게 상황을 제시하는 방식 
  - 예시: 정신과에서 환자의 심리 상태를 파악하기 위해 VR 콘텐츠를 보여주는 것 
  - 사용되는 상황: 정신과 치료, 심리 상담, 트라우마 치료 등
  - 헷갈릴 수 있는 점: VR은 단순한 게임 기술이 아니라 의료 및 치료 분야에서도 적극 활용되고 있습니다.

- 예시: 버튼 누르기, 잡기(Grab), 그립(Grip), 트리거(Trigger), 텔레포트 등 
- 중요한 이유: 실제로 만들어야 할 VR 콘텐츠의 기능들을 미리 체험하며 구현 방법을 이해하기 위해 

### 2. VR 심리 테스트 프로젝트 사례 소개 

- 설명: 약 3년 전 남서울대 심리학과에서 의뢰한 VR 심리 테스트 프로젝트를 소개했습니다. 
- 예시: 외출 후 집에 돌아왔을 때 방 안의 상황을 VR로 재현하는 프로젝트 
- 중요: 사용자가 VR 공간에 들어가서 첫 번째로 취하는 행동을 통해 심리 상태를 파악할 수 있습니다. 

### 3. VR 심리 테스트 시나리오 구성 

- 설명: 집에 들어갔을 때 여러 문제 상황이 동시에 발생하는 시나리오를 VR로 구현했습니다. 
- 예시: 아기가 울고 있고, 창문이 열려있고, 냄비에 물이 끓고 있고, 방이 지저분하고, 책상이 엎어져 있고, 의자가 넘어져 있는 상황 
- 중요한 이유: 여러 긴급 상황 중 무엇을 우선순위로 처리하는지를 통해 심리 상태를 분석할 수 있습니다. 

### 4. VR의 다양한 활용 분야 

- 설명: VR은 게임뿐만 아니라 시뮬레이션, 심리 치료, 정신과 진단 등에서 많이 활용되고 있습니다. 
- 예시: 기존에는 연극으로 심리 치료를 했지만, 요즘에는 VR을 사용 
- 중요한 이유: VR 개발자로서 게임 외의 다양한 활용 가능성을 이해해야 합니다.

### 기술 서비스: Model Context Protocol

최근 AI 및 소프트웨어 개발 분야에서 급부상하고 있는 규격입니다. 안스로픽(Anthropic)에서 발표한 <b>오픈 표준</b>으로, AI 모델이 데이터 보관소(Google Drive, Slack, GitHub 등)나 로컬 도구에 안전하고 쉽게 연결될 수 있도록 돕는 통신 규약입니다.

- <b>특징:</b> 이전에는 AI가 외부 데이터를 읽으려면 서비스마다 복잡한 커넥터를 따로 만들어야 했지만, MCP를 이용하면 표준화된 방식으로 데이터를 주고받을 수 있습니다.

<b>MCP는 Model Context Protocol의 약자</b>야.

쉽게 말하면 <b>AI가 외부 프로그램, 파일, 도구와 연결되기 위한 표준 연결 방식</b>이야. 공식 문서에서도 MCP를 AI 애플리케이션이 외부 시스템, 데이터 소스, 도구, 워크플로우에 연결되게 해주는 오픈소스 표준이라고 설명해.

조금 쉽게 비유하면:

```txt
MCP = AI용 USB-C 포트
```

USB-C가 노트북과 모니터, 충전기, 외장하드를 연결해주는 공통 규격이라면,

MCP는 <b>AI와 Unity, GitHub, Notion, 파일 시스템, 데이터베이스 같은 도구를 연결해주는 공통 규격</b>이라고 보면 돼.

## MCP가 하는 일

예를 들어 AI에게 이렇게 말한다고 해보자.

```txt
Unity 프로젝트 안의 씬 구조를 읽고,
현재 오브젝트 구성을 바탕으로 기술 문서를 작성해줘.
```

그냥 ChatGPT만 있으면 Unity 프로젝트 내부를 직접 볼 수 없잖아.

그런데 <b>Unity MCP 서버</b>가 연결되어 있으면 AI가 Unity Editor나 프로젝트 정보를 읽을 수 있어.

구조는 대충 이렇게야.

```txt
AI / Antigravity / Claude / ChatGPT
        ↓
      MCP
        ↓
Unity, GitHub, Notion, 파일, DB, 터미널 등
```

Anthropic의 발표에서도 MCP는 AI 도구와 데이터 소스 사이에 안전한 양방향 연결을 만들기 위한 오픈 표준이고, 개발자는 데이터를 MCP 서버로 노출하거나 AI 앱을 MCP 클라이언트로 만들어 연결할 수 있다고 설명하고 있어.

## Client와 Server 개념

MCP에는 보통 두 가지가 있어.

| 구분 | 뜻 | 예시 |
| --- | --- | --- |
| <b>MCP Client</b> | MCP를 통해 도구를 사용하려는 AI 앱 | Antigravity, Claude Desktop, AI IDE |
| <b>MCP Server</b> | AI에게 특정 기능이나 데이터를 제공하는 쪽 | Unity MCP, GitHub MCP, Notion MCP, 파일 시스템 MCP |

예를 들어 <b>Unity MCP</b>라면:

```txt
MCP Client = Antigravity 같은 AI 도구
MCP Server = Unity Editor와 연결된 서버
```

AI가 Unity MCP 서버를 통해 씬 정보, 오브젝트, 컴포넌트 같은 내용을 읽을 수 있는 식이야.

## Unity에서 MCP를 쓰면 좋은 점

Unity 프로젝트 기준으로는 이런 작업에 도움돼.

```txt
- 씬 안의 오브젝트 구조 확인
- 특정 스크립트나 컴포넌트 상태 분석
- 현재 구현된 기능을 바탕으로 기술 문서 작성
- QA 체크리스트 생성
- 기획서와 실제 구현의 차이 비교
```

다만 조심할 점도 있어.

MCP는 AI에게 외부 도구 접근 권한을 주는 구조라서, <b>처음에는 읽기 전용으로 쓰는 게 안전해.</b>

특히 Unity 프로젝트에서는 AI가 씬 파일, 프리팹, <code>.meta</code> 파일을 잘못 수정하면 꼬일 수 있으니까:

```txt
처음에는 읽기 전용
→ 분석과 문서화에 사용
→ 익숙해진 뒤 제한적으로 수정 허용
```

이 순서가 좋아.

### 개요

Unity 6와 Gemini AI를 연동하는 MCP (Model Context Protocol) 서버 설정 방법을 다룬 실습 강의입니다.   강사가 실시간 강의실에 설치 가이드를 공유하고 학생들과 함께 설정 과정을 진행했습니다.  

### Unity MCP 서버 설치 및 설정

- Package Manager에서 Unity MCP (Coplay) 패키지 설치 필요  
- Edit > Project Settings > AI > Unity MCP Server 메뉴로 이동   
- Integrations 섹션에서 Gemini 항목을 찾아 Configure 버튼 클릭 
- Gemini API 키를 입력하고 모델은 반드시 Gemini 1.5 Pro로 선택  
- MCP Bridge 상태가 'Running'으로 표시되는지 확인  

### Cursor 에디터 연동

- Unity Project Settings의 MCP Server 화면에서 Connection Details 또는 Command 경로 복사  
- Cursor 설정 (Ctrl + Shift + J)에서 Features > MCP 탭으로 이동
- Add New MCP Server로 Unity 프로젝트 연결 설정

### 실습 데모

- 강사가 Coplay 윈도우를 통해 "플레이 모드를 실행시켜줘" 명령 테스트  
- AI가 자동으로 플레이 모드 실행 및 신(Scene) 생성 
- GeminiManager 스크립트를 자동 생성하고 API 키 설정  
- 플레이 모드 종료 명령도 성공적으로 실행  
- 마크다운 파일로 기획서 작성 후 Notion에 자동 업로드 기능 시연   

### 강사의 실수 및 팁

- 강사가 실수로 Gemini 1.5 Flash를 사용했지만 Pro를 사용해야 함 
- 나중에 모델 선택 옵션 버튼을 추가할 예정 
- Claude가 Gemini보다 속도가 빠름  

### 개발 도구 조합 권장사항

- 가장 좋은 조합: Cursor + Claude + Gemini Pro/Flash MCP  
- 대규모 프로젝트가 아니므로 Gemini Flash로도 충분 
- Visual Studio Code, Visual Studio 등 다른 에디터 사용 가능  
- 로컬 LLM 사용 가능하지만 비용 발생

Unity 2022에서 MCP 서버 세팅

1. Unity 2022 프로젝트를 연다.
2. Package Manager에서 MCP for Unity 패키지를 설치한다.<br />Git URL:<br />[https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main](https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main)
3. Windows PowerShell에서 Python과 uv 설치 여부를 확인한다.<br />python --version<br />uv --version
4. Unity 상단 메뉴에서 Window > MCP for Unity를 연다.
5. MCP for Unity 창에서 Auto-Setup 또는 Start Server / Start Bridge를 실행한다.
6. MCP Client Configuration에서 Cursor를 선택하고 Configure 또는 Auto Configure를 누른다.
7. Cursor를 열고 Settings > MCP에서 Unity MCP 서버가 등록되었는지 확인한다.
8. Unity MCP 창에서 Connected 또는 Running 상태인지 확인한다.
9. Cursor에서 간단한 명령으로 연결을 테스트한다.<br />예: "Unity 콘솔 로그를 읽고 경고나 오류를 요약해줘."
