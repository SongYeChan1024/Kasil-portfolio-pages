## ✅ 완료한 작업

### 1. 컨테이너 박스 및 인벤토리 양방향 슬롯 이동 연동 분석 및 검증

<ul>
<li>
<b>내용</b>:

- <b><code>ItemBox.cs</code></b><b> 개편</b>: 동적 리스트 형태에서 고정된 슬롯 개수(<code>slotCapacity</code> = 8) 구조로 변경했습니다. 슬롯 자체는 삭제되지 않고 빈칸 상태(<code>CreateEmptyEntry</code>)를 유지하며, 인벤토리로부터의 입력 초과분을 계산하여 반환하는 <code>TryAddItem</code> 및 <code>TryAddToSlot</code>을 구현했습니다.
- <b><code>InventorySlotData.cs</code></b><b> 확장</b>: 원본 데이터인 <code>ItemData</code> 필드를 데이터 스키마에 추가하여 상자와 인벤토리 간 이동 시 스택 상한치(<code>itemMultiple</code>) 등의 속성을 소실 없이 즉각 파악 가능하게 했습니다.
- <b><code>PlayerInventory.cs</code></b><b> 고도화</b>: 단일 지정 슬롯에 대한 타겟 삽입(<code>TryAddToSlot</code>) 및 청소(<code>ClearSlot</code>)를 적용하고, 교환 이벤트 시 <code>itemData</code> 필드도 같이 튜플 스왑되도록 방어 코드를 매핑했습니다.
- <b><code>ChestUI.cs</code></b><b> 정적 최적화</b>: 매 이동 시마다 모든 슬롯 UI를 파괴하고 재생성(Instantiate)하던 방식에서 기존 슬롯 오브젝트 개수가 유지될 시 컴포넌트 정보만 갈아 끼우는 갱신 구조(<code>RefreshAll</code>/<code>RefreshSlot</code>)로 변경해 GC 오버헤드를 감소시켰습니다. 또한, <code>TryMoveToInventorySlot</code>, <code>TryMoveFromInventorySlot</code>을 통해 마우스 드래그 앤 드롭 이동을 지원하는 기반 인터페이스 함수를 완성했습니다.
</li>
<li>
<b>결과</b>: 인벤토리 가득 참 등 예외 상황에서 아이템 초과 수량이 안전하게 유지되며, 상자 UI 슬롯 오브젝트의 정적 갱신을 통해 UI 비동기 로드 시의 비정상 메모리 접근 및 Null Reference 예외 위험성을 원천 차단했습니다.
</li>
<li>
<b>관련 파일</b>:

- ItemBox.cs
- InventorySlotData.cs
- PlayerInventory.cs
- ChestUI.cs
</li>
</ul>

## 🔄 진행 중인 작업

- <b>드래그 앤 드롭(Drag & Drop)</b>: 마우스 드래그 시각 효과와 연동하여 신규 양방향 슬롯 수송 함수(<code>TryMoveToInventorySlot</code>, <code>TryMoveFromInventorySlot</code>)를 호출하는 마우스 포인터 핸들러 조작계 연결.
- <b>바닥 드롭 처리</b>: 상자와 인벤토리가 완전히 가득 찬 상태에서 세션 내 아이템 유실 방지를 위해 월드 바닥에 프리팹 형태로 드롭하는 폴백 메커니즘 설계.

## ❗ 이슈 및 블로커

- <b>이슈</b>: 기존 체스트 UI 비동기 스프라이트 로드 시, 동적 인스턴스 파괴가 겹치면서 <code>Addressables.Release</code> 호출 중 메모리 해제 오류나 깜빡임 현상이 소폭 발견되었습니다.
- <b>해결 방안</b>: 금일 <code>ChestUI.cs</code>에 도입된 정적 슬롯 수 유지 구조와 개별 슬롯 갱신(<code>RefreshSlot</code>) 방식을 통해, 스프라이트 비동기 Completed 콜백 시점에 대상 슬롯 UI가 파괴되지 않고 유효한 상태임을 보장함으로써 해당 오류의 발생 가능성을 원천적으로 제어했습니다.
