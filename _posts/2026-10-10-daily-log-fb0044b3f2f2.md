## 오늘의 목표

## 코드 리뷰 내용

### 데이터가 들어오는 경로

게임 실행 중에는 엑셀 파일을 직접 읽지 않는다. 엑셀에서 정한 수치를 변환 도구로 JSON으로 만든 뒤, Unity가 Resources/Data/DokkaebiGrowth.json을 읽는 구조를 살펴봤다.

- Resources.Load\&lt;TextAsset&gt;("Data/DokkaebiGrowth"): JSON 파일을 텍스트 에셋으로 불러온다.
- JsonUtility.FromJson\&lt;Tables&gt;(asset.text): JSON 텍스트를 Tables 데이터 구조로 변환한다.
- 검증을 통과하면 tables = data로 보관하고, Stage와 Action 등의 조회 함수가 필요한 값을 제공한다.

### 데이터 종류의 차이

- stages: 조합 단계별 해금 타수, 공유 쿨타임, 연계 유예 시간.
- actions: 각 타격의 피해량, 소모 자원, 돌진 거리와 모션.
- recipes·enhancements·branches: 조합 재료, 강화와 진화 분기 데이터.
- 예시로 3타까지 해금되는 정보는 stages, 1타의 돌진 거리 1.4는 actions에 들어 있음을 확인했다.

### 반복 로드와 오류 처리

attempted는 같은 실행 세션에서 파일을 반복해서 읽지 않도록 하는 표시다. Q 입력마다 새로 로드하지 않으며, 로드 실패 후에도 자동 재시도하지 않는다. 데이터 누락이나 잘못된 값은 오류 로그를 남기고, 코드에 고정한 임의의 기본 수치로 대체하지 않는다.

### 데이터와 전투 상태의 책임 구분

DokkaebiGrowthDatabase는 스킬 수치를 제공한다. 현재 연계 타수와 남은 쿨타임은 PrototypeSkillUseController가 담당한다. 데이터를 정의하는 역할과 플레이 중 변하는 상태를 관리하는 역할이 다르다는 점을 정리했다.
