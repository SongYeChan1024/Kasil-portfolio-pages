## 오늘의 한 문장

개별 기능을 시험하던 프로토타입을 이동, 빗자루 획득, 청사진 설정과 첫 전투가 이어지는 실제 튜토리얼 1구간으로 옮겼다.

---

## 오늘의 목표

- [x] 기존 TestMap을 보존한 튜토리얼 전용 씬 생성
- [x] 동굴형 플레이 블록아웃과 한 방향 학습 동선 구성
- [x] 빗자루 획득·청사진 설정·첫 전투 진행 상태 연결
- [x] HUD 튜토리얼 목표 표시
- [x] 전용 NavMesh와 빌드 설정 연결
- [x] 반복 실행 가능한 튜토리얼 씬 빌더 제작
- [x] 비활성 적의 부활 코루틴 오류 수정

## 진행한 작업

### 1. 튜토리얼 전용 동굴 맵

- 기존 <code>TestMap</code>은 원본으로 남기고 <code>Tutorial_Stage01_Awakening</code> 씬을 별도로 생성했습니다.
- 동굴 입구, 푸른 불빛 유도, 낡은 빗자루, 청사진 설정 차단막, 첫 전투 구역과 완료 표식을 순서대로 배치했습니다.
- 바닥, 암벽, 아치, 바위 장애물과 유도등을 블록아웃 자산으로 구성했습니다.
- 튜토리얼 전용 NavMesh를 생성하고 빌드 설정에 씬을 등록했습니다.

### 2. 튜토리얼 진행 상태

- <code>FindBroom → ConfigureBlueprint → DefeatDokkaebi → Completed</code> 네 상태를 구현했습니다.
- 빗자루 보유 여부와 청사진 스킬 할당 여부에 따라 차단막과 적 활성 상태가 바뀝니다.
- 적 처치 후 완료 표식이 켜지고 다음 이동 목표가 HUD에 표시됩니다.
- 목표 제공 인터페이스와 HUD 프레젠터를 분리해 콘텐츠 로직과 화면 표현의 의존 방향을 정리했습니다.

### 3. 반복 생성과 오류 수정

- Unity의 <code>Tools → ERGOSQUARE → Tutorial → Build Stage 01 - Broom Awakening</code> 메뉴에서 씬을 다시 만들 수 있게 했습니다.
- 이미 튜토리얼 이름으로 변경된 오브젝트도 다시 찾도록 빌더를 보완했습니다.
- 처치 이벤트에서 튜토리얼 진행기가 적을 먼저 비활성화하면 테스트 적이 부활 코루틴을 시작하던 오류를 수정했습니다.
- 비활성화 시 코루틴 참조를 초기화하고, 부활 시작 전 활성 상태를 다시 확인하도록 했습니다.

## 오늘의 결정

- 프로토타입 기능은 실제 학습 순서를 가진 별도 튜토리얼 씬으로 옮겨 검증합니다.
- 튜토리얼 1구간은 <code>이동 → 빗자루 획득 → 청사진 설정 → 첫 전투</code>까지만 담당합니다.
- 현재 동굴은 최종 아트가 아니라 거리, 시야, 이동 동선과 학습 순서를 확인하는 블록아웃입니다.
- 튜토리얼 완료로 비활성화된 적은 테스트용 자동 부활을 수행하지 않습니다.

---

## 결과와 검증

- Unity 스크립트 컴파일과 어셈블리 재로드를 통과했습니다.
- 튜토리얼 씬 빌더의 반복 실행을 확인했습니다.
- 전용 NavMesh와 빌드 설정 연결을 확인했습니다.
- 플레이 모드에서 초기 목표 HUD가 정상 표시됐습니다.
- 우클릭으로 빗자루까지 이동하고 <code>G 낡은 빗자루 획득</code> 안내가 표시되는 것을 확인했습니다.
- 수정 후 Unity 콘솔 컴파일 오류는 0건입니다.
- 자동화 입력이 실제 <code>G</code> 입력 전체를 재현하지 못해 획득부터 완료까지의 전 구간은 수동 QA로 남겼습니다.
