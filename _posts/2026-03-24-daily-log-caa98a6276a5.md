## 오늘 한 일(요약)

- 팀 오전 회의에서 현재 진행 상황을 공유하고, 다음 구현 우선순위를 정리했다.
- Episode 3-2 리듬 발판 퍼즐 로직(BeatMap 기반) 구조를 문서화해서 팀과 공유할 수 있는 설계 형태로 정리했다.
- 리듬 발판 퍼즐 로직의 스켈레톤 코드와 로직을 구현하고 파티클 시스템을 만드는 중

## 구현한 것

- Ep.3-2 리듬 발판 퍼즐 설계/로직 정리 (BeatMap 기반)
  - 랜덤 발판 생성(공간 구조) + BeatMap 이벤트(퍼즐 구조) 분리
  - previewTime/judgeTime/judgeWindow/endTime로 점등(연출)과 판정(게임플레이) 분리
  - Wrong(오답) / Miss(미입력)로 실패 유형 분리
  - 중복 판정 방지 상태값 설계(hasJudgedCurrentBeat / wasJudgedThisBeat)
  - 생성 후 Z축 진행 순 정렬로 platformIndex 재부여 → BeatMap이 index를 참조
  - “도달 가능한 랜덤”을 보장하기 위해 점프 거리/높이 제한 기반 재생성 규칙 포함
- 팀 공용 진행 체크리스트(회의 노트 기반) 확인 및 액션아이템 정리
  - 로비/스테이지 전환, 체크포인트 스폰, 플레이어 애니메이션, 공간 퍼즐 연출, 엔딩 전환 흐름 등 우선 작업 항목 합의

## 배운 것(개념/정리)

- 리듬 퍼즐은 ‘점등’과 ‘판정’을 분리해야 억울한 판정이 줄고, 연출/게임플레이 튜닝도 쉬워진다.
- 랜덤 생성 퍼즐은 반드시 “플레이 가능 조건(점프 거리/높이)”을 시스템 규칙으로 고정해야 QA 비용이 줄어든다.
- 팀 협업에서는 플레이어 관련 공통 기능(상호작용/애니메이션/스폰 등)을 한 명이 통합하고, 각 퍼즐 담당이 요구사항을 명확히 전달하는 방식이 효율적이다.

## 이슈/버그

- 내용: 스테이지 선택/전환은 기본 구현됐지만, 체크포인트 선택 후 해당 위치 스폰/상태 연결이 추가로 필요
- 원인/가설: 스테이지 진입과 체크포인트(세이브/스폰) 시스템이 아직 완전히 하나의 흐름으로 묶이지 않음
- 해결/시도: 회의에서 액션아이템으로 정리하고, ‘플레이어 공통 기능 통합’ 원칙으로 진행하기로 합의
- 다음 액션:
  - 체크포인트 선택 → 해당 위치 스폰까지 연결
  - 퍼즐별 필요한 플레이어 조작/애니메이션 요구사항 목록을 정리해서 공유

## 내일 할 일

- 체크포인트 선택 시스템과 스폰 흐름을 실제 플레이 루프에서 끊김 없이 연결(전환/스폰/상태 갱신)
- Ep.3-2 리듬 발판 퍼즐: 1) 발판 생성 → 2) 점등 → 3) 판정 → 4) 점수/콤보/실패 카운트까지 최소 루프 구현
- 공간 퍼즐 맵 연출(성공/실패 피드백, 카메라/사운드/조명) 보강
- 엔딩 씬 전환 및 게임 종료 흐름(타이틀/종료) 1차 구현 + UI 반영 계획 정리
