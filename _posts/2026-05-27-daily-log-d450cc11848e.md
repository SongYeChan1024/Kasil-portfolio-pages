## 기본 정보

- 날짜: 2026-05-27
- 주제: Photon Chat 채팅 UI 구현 + TextMeshPro 한글 폰트(SDF) 세팅 트러블슈팅 + 킬 카운트 분리 기록
- 작성자: 작성자

## 오늘 한 일(요약)

- Photon Chat을 이용해 로비에 <b>채팅 UI(Scroll View + InputField + 전송 버튼)</b>를 구성했다.
- TextMeshPro에서 채팅/입력창 한글이 깨지거나 안 보이던 문제를 해결하기 위해 <b>한글 SDF Font Asset을 만들고 Dynamic 모드로 세팅</b>했다.
- <code>.ttc</code> 폰트의 호환성 이슈를 확인하고, <code>.ttf</code>(예: <code>malgun.ttf</code>, Noto Sans KR) 기반으로 폰트 에셋을 다시 구성해 안정화했다.
- TMP\_InputField는 하위 Text뿐 아니라 <b>InputField 컴포넌트 자체의 Font Asset도 지정</b>해야 한글이 유지된다는 포인트를 정리했다.
- 탱크 게임에서 <b>TankKills / ApacheKills를 분리해 Custom Properties로 기록</b>하고 UI 갱신 로직까지 연결했다.

## 오늘 진행한 내용(상세)

### 1) Photon Chat UI 구성

- Panel을 만들고 Scroll View로 채팅 출력 영역을 구성했다.
- Content 하위에 TextMeshProUGUI를 두고, 메시지가 누적되면 스크롤로 확인할 수 있게 했다.
- 하단에 TMP\_InputField(입력창)와 전송 버튼을 배치해 기본 채팅 인터페이스 형태를 완성했다.

### 2) TextMeshPro 한글화: 폰트 에셋(SDF) 생성

- 채팅처럼 “사용자 입력이 동적으로 바뀌는 UI”는 Atlas Population Mode를 <b>Dynamic</b>으로 두는 게 핵심이다.
- 한글 폰트 에셋 생성 흐름
  - 폰트 파일 import → Create > TextMeshPro > Font Asset → Atlas Population Mode = Dynamic → (필요 시 Atlas 1024x1024)

### 3) 한글 입력이 깨지는 문제 원인/해결

- 원인
  - <code>.ttc</code>(TrueType Collection) 폰트는 Dynamic 모드에서 런타임 Glyph 생성이 실패할 수 있다.
  - TMP\_InputField는 타이핑 시작 시 컴포넌트 자체 설정이 우선되므로, 하위 Text만 폰트를 바꾸면 다시 기본 영어 폰트로 덮여 한글이 깨질 수 있다.
- 해결
  - <code>.ttf</code>(TrueType Font) 기반 폰트 사용(예: <code>C:\\Windows\\Fonts\\malgun.ttf</code>) 후 SDF Font Asset을 새로 생성
  - TextMeshProUGUI + TMP\_InputField(컴포넌트 자체) 모두에 같은 Font Asset을 할당

### 4) Photon 패키지 설치 순서 메모

- Photon Chat과 PUN2는 패키지 충돌이 날 수 있어 <b>Chat 먼저 → PUN2 나중</b> 설치가 안전하다.

### 5) 킬 수 분리 기록(탱크/아파치)

- Custom Properties에 <code>TankKills</code>, <code>ApacheKills</code> 키를 분리해 저장하고,
- 프로퍼티 변경 콜백에서 UI가 갱신되도록 수정했다.

## 이슈/메모

- Photon Custom Properties에서 <code>Hashtable</code> 사용 시 네임스페이스 확인 필요
  - <code>using ExitGames.Client.Photon;</code>

## 내일(다음) 할 일

- 채팅 전송을 Enter 키와 버튼 클릭 둘 다에서 안정적으로 처리(입력 이벤트 OnEndEdit 등)하고, 전송 후 입력창 포커스/초기화 UX 정리
- Photon Chat 패키지 과제 제출(한글화 포함) 마감 체크
- 킬 카운트 UI를 실제 플레이 흐름(PVP/PVE)에서 누락 없이 증가/동기화되는지 테스트
