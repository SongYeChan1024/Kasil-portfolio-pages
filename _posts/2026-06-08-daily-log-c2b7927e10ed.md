## 구현/작업 내용 (디테일)

- <b>무엇을 했는지</b>
  - 기본 템플릿을 그대로 쓰기보다, Pet Bloom Garden 전용 구조/로직이 들어갈 수 있게 프로젝트를 재정리했다.
  - 메인 씬/폴더 구조를 기획서 흐름에 맞게 정리하고, “입구에서 시작 → 이동 → 선택 존 도착 → 펫 선택”의 1일차 플레이 흐름이 보이도록 구성했다.
  - 펫 선택은 선택 존에 들어왔을 때만 UI가 뜨도록 바꾸고, 이미 펫을 가진 상태라면 선택 UI가 다시 뜨지 않게 상태값을 추가했다.
  - 카메라 조작은 PC 테스트에서 제페토 기본 감각(우클릭 드래그 회전)이 살도록 보강 스크립트를 추가했다.
- <b>핵심 포인트 / 내가 결정한 것</b>
  - 1주일 1인 개발이므로 “완벽한 전체 설계”보다 <b>Day 1부터 목표를 쪼개서</b>, 플레이가 ‘보이는’ 상태를 먼저 확보하는 방식으로 간다.
  - 이번 주 핵심 루프(변경 없음):
    - <b>펫 선택 → 펫 상호작용 → 유대 레벨 상승 → 펫 반응 변화 → 포토존 연출</b>
  - 멀티플레이는 이번 주 완성 가능성이 낮아 <b>후순위</b>로 미루고, 초기에는 이벤트 중심 최소 동기화만 고려한다.
  - 제페토 월드는 기능 구현이 TypeScript(ZEPETOScript) 중심이므로, 사람이 읽는 문구만 한국어로 정리하고 식별자는 영어로 유지한다.
- <b>관련 링크/파일</b>
  - 메인 씬: <code>Assets/01_Scenes/Main_PetBloomGarden.unity</code>
  - 폴더 구조 초안: <code>Assets/00_ZEPETO</code>, <code>01_Scenes</code>, <code>02_Scripts</code>, <code>03_Prefabs</code>, <code>04_Art</code>, <code>05_Animations</code>, <code>06_Audio</code>, <code>99_Debug</code>
  - 핵심 구성(1일차): 게임 매니저 / 로컬 플레이어 확인 / 펫 스폰 / 펫 선택 UI / 선택 존 트리거

## 배운 것 / 정리

- 개념:
  - 세팅이 정상이어도 “프로젝트 전용 구조/로직이 없으면” 실제 개발이 시작되지 않는다 → Day 1은 구조부터 잡는 게 맞다.
  - UI 노출은 거리 판정보다 <b>트리거 기반</b>이 의도/디버깅 모두 명확한 편.
- 새로 알게 된 것:
  - 선택 존 감지 안정성을 위해서는 “누가 들어왔는지”를 확실히 해야 한다 → 로컬 플레이어 콜라이더 기준으로 단순화하는 게 효과적.
  - 제페토 기본 조작감을 유지하면서 보강하려면, 완전 커스텀 카메라보다 <b>제페토 카메라 API를 직접 보조</b>하는 방식이 부담이 적다.
- 다음에 다시 볼 키워드:
  - Player Spawn, Entrance Flow, Trigger-based UI, LocalPlayer Collider, Canvas Sorting Order, Zepeto Camera API
