<b>게임 기획 방법론: 상향성과 하향성 기획</b> 2026-05-26


## 요약


### 오늘 수업 핵심 요약

- <b>상향성 기획</b>과 <b>하향성 기획</b>의 개념과 차이점을 학습했습니다. 
- 상향성 기획은 세상에 없는 새로운 것을 만드는 도전적 접근이며, 하향성 기획은 검증된 게임을 모방하되 독보적인 요소를 추가하는 접근입니다. 
- 각 기획 방식의 <b>성공 사례</b>(Hades, Pokémon GO, 배틀그라운드)와 <b>실패 사례</b>(서든어택 2, 메이플스토리 2)를 분석했습니다. 
- 메타버스와 AR 글래스 같은 <b>하드웨어 발전</b>이 콘텐츠 개발에 미치는 영향을 이해했습니다. 
- <b>UI/UX의 중요성</b>을 실제 게임 사례(서든어택 V키, 피망 고스톱)를 통해 배웠습니다. 

이 내용은 게임 개발자로서 기술적 구현뿐만 아니라 산업 트렌드, 사용자 경험, 하드웨어 발전을 함께 고려해야 함을 강조합니다.

---

### 주요 개념 정리

- <b>상향성 기획 (Bottom-up Planning)</b> 
  - 설명: 세상에 없는 것을 만들어내는 창의적이고 도전적인 기획 방식
  - 예시: Hades (로그라이크 장르에 스토리 진행 시스템 접목), 착시 게임, 개원욕
  - 사용되는 상황: IP나 검증된 시스템 없이 새로운 경험을 창조할 때
  - 헷갈릴 수 있는 점: 성공 확률이 낮아(약 1\~10%) 도박에 가깝지만, 성공하면 초대박이 가능함 
- <b>하향성 기획 (Top-down Planning)</b> 
  - 설명: 검증된 게임이나 시스템을 기반으로 모방하되, 독보적인 요소를 추가하는 기획 방식
  - 예시: Pokémon GO (강력한 IP + 위치기반), 배틀그라운드 (FPS + 배틀로얄 규칙)
  - 사용되는 상황: 안정적인 성공을 원하거나 검증된 시장에 진입할 때
  - 헷갈릴 수 있는 점: 단순 모방만으로는 실패하며, 반드시 차별화된 시스템이나 UX가 필요함 
- <b>UI (User Interface)</b> 
  - 설명: 사용자가 게임과 상호작용하는 인터페이스 시스템
  - 예시: 채팅창, 메뉴, 버튼 배치
  - 사용되는 상황: 게임의 기본 시스템 구성 단계
  - 헷갈릴 수 있는 점: UI가 먼저 있어야 사용자가 불편함을 느끼고 UX 개선이 시작됨 
- <b>UX (User Experience)</b> 
  - 설명: 사용자가 실제로 게임을 플레이하며 느끼는 경험과 편의성
  - 예시: FPS 왼손잡이 모드, 서든어택 V키(뒤돌기), 피망 고스톱 하의 표시
  - 사용되는 상황: 게임 출시 후 사용자 피드백을 반영한 개선
  - 헷갈릴 수 있는 점: UX 하나로 시장 판도가 바뀔 수 있음 (피망이 한게임 고스톱 시장의 60% 탈취)

### 수업 흐름별 정리

### 1. 메타버스와 하드웨어 발전 트렌드 

- 설명: 제페토, 로블록스 같은 메타버스가 조악해도 성공하는 이유 분석
- 예시: 제페토는 그래픽이 조악하지만 접근성이 좋고 코로나 시기에 사람들이 모일 수 있는 환경을 제공하여 5억 접속자 확보 
- 중요한 이유: 하드웨어(AR 글래스) 발전이 메타버스의 미래를 결정하며, 구글 글래스가 선글라스 수준까지 발전하면 메타버스 매출이 100배 성장 가능 

### 2. 플랫폼 변화와 산업 전망 

- 설명: 삐삐 → 피처폰 → 스마트폰처럼, 스마트폰 → AR 글래스로 플랫폼이 전환될 것
- 예시: 일론 머스크는 "앞으로 핸드폰이 없어질 것"이라고 예측. 10년 안에 AR 글래스가 주류가 될 전망 
- 중요한 이유: 플랫폼이 바뀌면 UI, UX, 콘텐츠, 하드웨어, 컨트롤러가 모두 바뀌고 새로운 사업 기회가 생김 

### 3. UI/UX의 중요성과 사례 

- 설명: 작은 UX 변화 하나가 게임의 성패를 좌우할 수 있음
- 예시:
  - <b>FPS 왼손잡이 모드</b>: 북미 수출 시 필수 기능. 왼손잡이는 오른손 설정에서 실력의 10%도 발휘 못함 
  - <b>서든어택 V키</b>: 뒤돌기 기능으로 초등학생도 쉽게 플레이 가능. 카운터 스트라이크는 이 기능을 "허접"하다고 보고 제공 안 함 
  - <b>피망 고스톱</b>: 하의(카드 아래 표시) 기능 하나로 한게임 고스톱 시장의 60%를 탈취 
- 중요: UX 하나가 회사를 흥하게도 망하게도 만듦 

### 4. 상향성 기획 성공 사례: Hades 

- 설명: 로그라이크 장르의 반복 플레이 구조를 스토리 진행에 활용
- 핵심 아이디어: 캐릭터가 죽을 때마다 새로운 대화, 캐릭터 관계, 스토리 이벤트 진행 → 실패가 이야기의 일부가 됨
- 성공 요인: 얼리 액세스로 유저 피드백을 반영하여 완성도를 높인 상향성 기획

### 5. 하향성 기획 성공 사례: Pokémon GO 

- 설명: 강력한 IP와 명확한 목표("현실에서 포켓몬 잡기")로 시작
- 핵심 시스템: 위치 기반, AR 기능, 포켓스톱, 체육관
- 성공 요인: IP와 명확한 콘셉트를 먼저 정하고 목표에 맞춰 시스템 구체화. 10억 다운로드 달성

### 6. 하향성 기획 성공 사례: 배틀그라운드 

<ul>
<li>
설명: 하향성 FPS 게임이지만 게임 규칙(배틀로얄)을 바꿔 성공
</li>
<li>
성공 요인: 

- 배틀로얄이라는 새로운 규칙 (50% 기여) 
- 정당한 승리 조건 구현 (밸런스)
- 당시 고사양 그래픽
- 일본 영화 '배틀 로얄' 유행
</li>
<li>
매출: 약 3조 원 
</li>
</ul>

### 7. 하향성 기획 실패 사례: 서든어택 2 

- 설명: 원작 서든어택의 기대에 못 미치고 초고속 실패
- 실패 원인:
  - 언리얼 엔진 사용했지만 최적화 실패 (렉, 버그)
  - 정당한 승리 조건 구현 안 됨 (렉 버그, 렉 저격 등)
  - 유저들이 원한 건 "FPS 골수 게임"이었는데 캐주얼 게임으로 출시
  - 배틀그라운드 출시 시기와 겹침

### 8. 상향성 기획: 마비노기 영웅전 속옷 시스템 

- 설명: 하프라이프 엔진으로 "속옷을 팔기 위해" 게임 기획
- 시스템: 부위별로 갑옷이 파괴되면 속옷이 보임 → 파티 입장 시 특정 룩이 필요 → 속옷 결제 유도
- 가격: 일주일 3,900원 / 보름 9,900원 / 평생 19,800원 
- 결과: 성공 후 다른 게임들도 모두 따라함

  - 왜 이 예시를 사용했는지: 하향성 기획도 목표를 명확히 하면 성공 가능

# 상향성 기획

## 성공 케이스: Hades

Hades는 로그라이크 장르의 반복 플레이 구조를 새롭게 활용한 게임이라고 생각합니다.

기존 로그라이크 게임은 캐릭터가 죽으면 단순히 실패하고 처음부터 다시 도전하는 구조가 많았습니다. 하지만 Hades는 캐릭터가 죽고 다시 돌아올 때마다 새로운 대화와 캐릭터 관계, 스토리 이벤트가 진행되도록 만들었습니다.

이처럼 플레이어의 반복적인 실패 경험을 단순한 리셋이 아니라 이야기 진행의 일부로 바꾸었고, 죽을 때마다 다음 이야기가 궁금해지도록 만든 점이 새로웠습니다.

또한 얼리 액세스 과정에서 유저 반응과 피드백을 반영하며 게임을 다듬어갔기 때문에, 현장의 반응을 바탕으로 완성도를 높인 상향성 기획의 성공 사례라고 생각합니다.

## 실패 케이스: 야생의 땅: 듀랑고

야생의 땅: 듀랑고는 모바일 게임에서 개척형 오픈월드, 생존, 제작, 사회 시스템을 시도한 매우 실험적인 게임이라고 생각합니다.

기존 모바일 게임에서 보기 어려웠던 새로운 구조와 창의적인 시스템을 보여주었지만, 유저 유지와 사업성 면에서는 한계를 보였습니다.

결국 출시 2년을 채우지 못하고 2019년 12월 18일 서비스 종료가 결정되었습니다.

따라서 야생의 땅: 듀랑고는 창의적인 시도와 실험성은 높았지만, 장기적인 유저 확보와 서비스 유지에는 실패한 상향성 기획의 사례라고 생각합니다.

# 하향성 기획

## 성공 케이스: Pokémon GO

Pokémon GO는 포켓몬이라는 강력한 IP와 “현실 세계에서 포켓몬을 잡는다”는 명확한 목표에서 출발한 게임이라고 생각합니다.

먼저 유저에게 어떤 경험을 줄 것인지가 분명했습니다. 플레이어가 실제로 밖을 걸어 다니며 포켓몬을 찾고, 잡고, 수집하는 경험을 하게 만드는 것이 핵심이었습니다.

이 큰 방향성에 맞춰 위치 기반 시스템, AR 기능, 포켓스톱, 체육관 같은 세부 콘텐츠가 설계되었습니다. 또한 Pokémon GO는 10억 다운로드 이상을 기록한 대표적인 성공 모바일 게임으로 평가할 수 있습니다.

따라서 Pokémon GO는 IP와 명확한 콘셉트를 먼저 정하고, 그 목표에 맞춰 게임 시스템을 구체화한 하향성 기획의 성공 사례라고 생각합니다.

## 요약


### 오늘 수업 핵심 요약

- <b>Zepeto Studio</b>에서 3D 아이템(모자, 의상 등)을 Unity로 가져와 커스터마이징하고 <b>Export as Zepeto</b> 기능으로 내보내는 전체 워크플로우를 학습했습니다.
- FBX 파일을 Unity의 <b>Content 폴더</b>에 넣고, <b>Accessory > Headwear</b> 카테고리에서 아이템을 배치하는 방법을 실습했습니다.
- Unity 버전 호환성(3.2.12 버전 사용)과 파일 경로 설정의 중요성을 이해했습니다.
- 취업 준비와 마지막 팀 프로젝트 진행 방식(6명 단일 팀 vs 3명씩 2팀)에 대한 논의가 있었습니다.
- Export 과정에서 간헐적으로 발생하는 오류와 해결 방법을 경험했습니다.

이 내용은 메타버스 아이템 제작의 실무 프로세스를 이해하고, Unity와 Zepeto Studio 간의 연동 작업을 직접 실습하는 데 중요합니다.

### 주요 개념 정리

- <b>Zepeto Studio</b>
  - 설명: Zepeto 메타버스 플랫폼에서 사용할 3D 아이템을 제작하고 판매할 수 있는 Unity 기반 개발 환경
  - 예시: 모자, 의상, 액세서리 등의 아바타 아이템 제작
  - 사용되는 상황: Zepeto 전용 아이템을 만들어 플랫폼에 업로드하고 판매할 때
  - 헷갈릴 수 있는 점: 일반 Unity 프로젝트와 달리 특정 버전(3.2.12)과 파일 구조를 준수해야 함
- <b>Content 폴더</b>
  - 설명: Unity 프로젝트에서 Zepeto 아이템 파일을 저장하는 권장 폴더 위치
  - 예시: FBX 파일, 텍스처, 매트리얼을 Content 폴더에 배치
  - 사용되는 상황: 새로운 3D 모델을 프로젝트에 추가할 때
  - 헷갈릴 수 있는 점: 다른 폴더에 넣어도 작동은 하지만 공식 가이드는 Content 폴더를 권장함
- <b>Export as Zepeto</b>
  - 설명: Unity에서 제작한 아이템을 Zepeto 플랫폼에 업로드할 수 있는 형식으로 변환하는 기능
  - 예시: 오른쪽 마우스 클릭 > Zepeto Studio > Export as Zepeto 선택
  - 사용되는 상황: 아이템 제작 완료 후 Zepeto 스튜디오 웹사이트에 업로드하기 전
  - 헷갈릴 수 있는 점: Play 버튼을 끄고 실행해야 하는 경우와 켠 상태에서 실행해야 하는 경우가 있어 상황에 따라 다름
- <b>FBX 파일</b>
  - 설명: 3D 모델링 데이터를 저장하는 범용 파일 형식
  - 예시: Maya, Max, Blender 등에서 제작한 모델을 FBX로 저장
  - 사용되는 상황: 3D 모델을 Unity로 가져올 때
  - 헷갈릴 수 있는 점: Zepeto 전용 FBX는 무료 사이트에서 제공되기도 하므로 직접 모델링하지 않아도 사용 가능함

### 수업 흐름별 정리

### 1. Zepeto 전용 FBX 파일 소개

- 설명: Maya나 Max 같은 전문 3D 툴 대신 무료로 제공되는 Zepeto 전용 FBX 파일을 활용할 수 있음
- 예시: Zepeto 전용 아이템 사이트에서 모자, 의상 등의 FBX 파일 다운로드
- 중요한 이유: 3D 모델링 학습 시간을 절약하고 원리 이해에 집중할 수 있음

### 2. Unity Content 폴더에 FBX 파일 추가

- 설명: 다운로드한 FBX 파일을 Unity 프로젝트의 Content 폴더에 복사
- 예시: 파일 탐색기에서 FBX 파일을 드래그하여 Unity Content 폴더에 배치
- 중요한 이유: 올바른 폴더 구조를 유지해야 Zepeto Studio에서 정상적으로 인식함

### 3. Accessory 카테고리에서 아이템 배치

- 설명: Unity 에디터의 Accessory 섹션에서 Headwear(모자) 카테고리를 찾아 체크하고 아이템 추가
- 예시: Accessory > Headwear 체크 후 모자 모델을 씬에 배치
- 중요한 이유: 아이템 카테고리를 정확히 지정해야 Zepeto 아바타에 올바르게 장착됨

### 4. 매트리얼로 색상 및 텍스처 변경

- 설명: 매트리얼을 생성하여 아이템의 색상, 패턴, 텍스처를 커스터마이징
- 예시: 매트리얼 생성 후 색상 변경, 또는 포토샵으로 제작한 패턴 이미지 적용
- 중요: 포토샵에서 텍스처에 직접 글자나 디자인을 추가할 수 있음

### 5. Export as Zepeto 실행

- 설명: Play 버튼을 끄고 오른쪽 마우스 클릭으로 "Zepeto Studio > Export as Zepeto" 선택
- 예시: Export 후 저장 여부를 물어보면 선택 (저장 안 해도 되지만 권장)
- 중요한 이유: 이 단계를 통해 Zepeto 플랫폼에 업로드 가능한 파일 형식으로 변환됨

### 6. Zepeto 스튜디오 웹사이트에서 아이템 업로드

- 설명: Zepeto 스튜디오 웹사이트의 "아이템 만들기 > 3D 만들기 > Headwear"에서 내보낸 파일 업로드
- 예시: Export된 파일을 찾아 업로드하면 정식으로 판매 가능한 아이템이 됨
- 중요한 이유: 업로드가 완료되면 실제 사용자들이 구매할 수 있는 상태가 됨

### 7. 취업 지원 및 상담 안내

- 설명: 조기 취업을 원하는 경우 코치에게 개별 연락하여 모의 면접, 자소서 첨삭, 포트폴리오 지원 가능
- 예시: 카카오톡으로 연락하여 취업 관련 상담 요청
- 중요: 요청이 있을 때만 지원하므로 필요하면 적극적으로 연락해야 함

### 8. 마지막 팀 프로젝트 논의

- 설명: 6명 단일 팀 vs 3명씩 2팀 vs 개인 프로젝트 중 어떤 방식으로 진행할지 논의
- 예시: 부산 게임 공모전 대상 팀처럼 7명이 협업했던 사례 언급
- 중요: 코치는 6명 단일 팀을 권장하며, 회사에서 현업자를 멘토로 배정할 예정

### 9. Unity 버전 및 프로젝트 세팅

- 설명: Zepeto Studio는 특정 Unity 버전(3.2.12)을 사용해야 하며, 가이드에서 최신 버전 확인 필요
- 예시: Unity Hub에서 3.2.12 버전 설치, Zepeto Studio 프로젝트 파일 열기
- 중요: 영어권 프로그램이므로 경로에 한글이 들어가면 안 됨

### 10. 아바타 타입 및 체형 설정

- 설명: Type에서 기본 아바타와 애니메이션 아바타 선택 가능, Deformation에서 다양한 체형 선택 가능
- 예시: Type 토글로 기본/애니메이션 전환, Deformation에서 체형 1\~4 선택
- 중요: Convert to Depth Style 기능으로 스타일 변환
