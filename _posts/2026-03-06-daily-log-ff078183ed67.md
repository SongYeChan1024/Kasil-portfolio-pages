- PlayerController Die() 시 GameManager 호출, ScrollingObject가 게임 오버 상태에서 정지하도록 조건 추가 흐름 정리
- 발판(Platform) 충돌 시 점수 증가, 왼쪽 이동(ScrollingObject) 구성 및 장애물 랜덤 생성(1/3 확률) 로직 정리

## 배운 것(개념/정리)

- Canvas Scaler
  - Constant Pixel Size: 해상도/화면 크기가 바뀌어도 UI 요소 크기를 고정 → 디바이스마다 크기/간격이 의도와 달라질 수 있음
  - Scale With Screen Size: 다양한 해상도에서도 UI 비율/배치를 일정하게 유지하는 데 유리
  - Reference Resolution: 640x360(모바일 16:9/16:10 기준)으로 잡고 UI 배치를 맞추면 배율 변화에 자동 대응
- Unity 생명주기
  - Awake → OnEnable → Start → FixedUpdate → Update → LateUpdate
  - Awake/Start는 1회 호출, OnEnable은 활성화될 때마다 호출(오브젝트 풀링에서 중요)
  - LateUpdate는 카메라 추적 등 Update 이후 처리가 필요한 로직에 적합
- Input System
  - Fire 액션에 마우스/터치/게임패드 등 바인딩 가능
  - Send Message로 OnFire 호출 방식 사용 가능
  - isPressed/wasReleasedThisFrame 등으로 입력 상태를 세분화해 처리

## 이슈/버그

## 요약

### 과제

- [ ] 안드로이드로 빌드하여 본인 영어명.apk 파일로 제출  

### 유니티 생명주기 함수

- Awake() → OnEnable() → Start() → FixedUpdate() → Update() → LateUpdate() 순서로 실행됨  
- Awake와 Start는 게임 시작 시 한 번만 호출되며, Awake가 먼저 실행됨  
- OnEnable은 오브젝트가 활성화될 때마다 호출됨 (오브젝트 풀링에서 중요) 
- LateUpdate는 Update 이후에 실행되며, 카메라가 플레이어를 따라가는 로직에 적합함 

### 입력 시스템 구현

- Input System 패키지를 사용하여 마우스 왼쪽 버튼, 터치, 게임패드 등 다양한 입력 지원   
- Fire 액션에 마우스 왼쪽 버튼, 터치 스크린, 게임패드 트리거, VR 컨트롤러 등 연결  
- Send Message 방식으로 OnFire 함수 호출 
- 기존 Update의 입력 처리 로직을 OnFire로 이동  
- isPressed로 버튼 눌림 감지, wasReleasedThisFrame으로 버튼 뗌 감지  

### 발판(Platform) 시스템

- 발판에 OnCollisionEnter2D 이벤트로 플레이어 충돌 감지  
- 발판을 밟았을 때 점수 증가 (GameManager.Instance.AddScore 호출)  
- 발판에 ScrollingObject 컴포넌트 추가하여 왼쪽으로 이동  
- 장애물은 랜덤으로 생성 (Random.Range(0, 3)으로 1/3 확률)  

### 오브젝트 풀링을 이용한 발판 생성기 구현

- 필요한 만큼 오브젝트를 초기에 미리 만들어서 풀에 쌓아두는 방식 
- 새로운 오브젝트를 생성하지 않고 풀에 있는 오브젝트를 가져다 사용 
- 오브젝트를 파괴하지 않고 비활성화하여 풀에 반환 

<b>발판 생성기 구현 과정:</b>   

1. 발판 3개를 화면 밖 구석진 곳(Y: -25)에 미리 배치 
2. 일정 시간 후 1번 발판을 리셋하고 화면 오른쪽에 재배치
3. 일정 시간 후 2번 발판을 리셋하고 화면 오른쪽에 재배치
4. 일정 시간 후 3번 발판을 리셋하고 화면 오른쪽에 재배치
5. 3번 → 1번 → 2번 → 3번 순서로 반복

<b>필요한 변수:</b>      

- 발판 프리팹 (GameObject 배열)
- 발판 개수 (platformCount = 3)  
- 시간 간격 (timeBetSpawn) - 발판 배치 간격  
- 발판 Y축 랜덤 범위 (minY, maxY) - 높낮이 변화  
- 발판 X축 위치 (xPos = 20) - 화면 오른쪽 
- 현재 인덱스 (currentIndex) - 배열 순번 관리  
- 풀 위치 (poolPosition = new Vector3(0, -25, 0)) - 대기 위치  
- 마지막 생성 시간 (lastSpawnTime) 

<b>Start 함수:</b>   

- 발판 개수만큼 게임 오브젝트 생성하여 배열에 할당
- 모든 발판을 풀 위치(Y: -25)에 배치
- lastSpawnTime을 0으로 초기화
- timeBetSpawn을 랜덤 값으로 초기화 

<b>Update 함수:</b>  

- 게임 오버가 아닐 때만 실행
- 현재 시간(Time.time)이 lastSpawnTime + timeBetSpawn보다 크면 발판 생성
- lastSpawnTime을 현재 시간으로 업데이트 
- timeBetSpawn을 새로운 랜덤 값으로 설정 
- Y 좌표를 랜덤하게 설정 (minY \~ maxY 범위)
- 현재 인덱스의 발판을 화면 오른쪽(X: 20)에 배치  
- 발판 활성화 (SetActive(true)) 
- 인덱스 증가, 발판 개수 이상이 되면 0으로 리셋   

### 게임 매니저 및 UI

- GameManager의 scoreText 변수를 public으로 선언하여 외부 접근 가능  
- AddScore 함수에서 점수 증가 시 텍스트 업데이트  
- 게임 오버 시 점수 텍스트 비활성화  

### 안드로이드 빌드 설정

<b>Build Settings:</b>  

- File > Build Settings에서 Android 플랫폼 선택
- Switch Platform 클릭
- Max Texture Size를 512 또는 1024로 설정  

<b>Player Settings:</b>  

- Company Name 설정 (예: Alice)  
- Product Name 확인
- Resolution and Presentation에서 Orientation 설정  
  - Auto Rotation 해제
  - Landscape Right 선택 (홈 버튼이 오른쪽으로)
  - Portrait 옵션 해제 (가로 고정)
- Other Settings > Identification 설정  
  - Override Default Package Name 활성화
  - Package Name 확인 (com.회사명.게임명)
  - Version 1.0 확인
  - Minimum API Level 7.0 이상 설정 (8.0도 가능) 

<b>빌드 실행:</b>   

- Build 버튼 클릭 (Build And Run은 USB로 폰 연결 필요)
- 저장 위치 선택 후 본인영어명.apk로 저장
- 빌드 완료된 .apk 파일 제출

### Canvas Scaler 설정

- <b>Constant Pixel Size (고정 픽셀 크기)</b>: 캔버스 크기가 변해도 UI 요소의 크기를 변경하지 않음  
  - 문제점: 화면 크기가 달라지면 UI 요소의 크기나 간격이 의도와 다르게 나타날 수 있음  
  - 디바이스마다 해상도가 다르기 때문에 발생하는 문제 
- <b>Scale with Screen Size (화면 크기에 따라 스케일)</b>: 다양한 크기와 비율의 화면에서 UI 크기와 배치를 일정하게 유지  
  - 이미지가 깨지지 않고 최종 화면을 강제로 잡아넣는 방식이 아님 
  - 일정한 비율과 크기를 자동으로 유지해줌 
- <b>Reference Resolution 설정</b>: 640x360으로 설정   
  - 모바일 기준 16:9 또는 16:10 비율 사용  
  - 640x360 해상도에서 UI 배치만 신경쓰면 화면 배율이 늘어나도 자동으로 조정됨 

### Text Mesh Pro UI 구성

- <b>Score 텍스트 생성</b>
  - Canvas > UI > Text Mesh Pro 생성 (최초 설치 필요) 
  - 이름: "Score"로 설정  
  - 위치: Top Center 앵커 사용 (Shift+Alt 클릭)  
  - 폰트 사이즈: 30 설정 
  - 가운데 정렬 적용  
  - Outline 설정: 0.1 정도로 적용  
  - <b>주의</b>: Text Mesh Pro는 한글 입력 시 깨짐 현상 발생, 별도 설정 필요 (추후 설명) 
- <b>Game Over 텍스트 생성</b>
  - Legacy Text 사용 (Text Mesh Pro는 폰트가 다양하지 않아서)  
  - 이름: "Game Over"로 설정  
  - 위치: Top Center 앵커 
  - 폰트: Mini Square 등 사용 
  - 폰트 사이즈: 40 설정 
  - 가운데 정렬 및 색상 적용 
  - Shadow, Outline 효과 추가 
  - 초기 상태: 비활성화 (게임 오버 시에만 활성화)  
- <b>Jump to Start 텍스트</b>
  - Game Over 텍스트 복제 (Ctrl+D)  
  - 텍스트: "Jump to Start" 
  - 폰트 사이즈: 30으로 축소 

### 게임 매니저 구현

- <b>싱글톤 패턴 적용</b>
  - 게임 매니저는 하나의 인스턴스만 존재하도록 설계 
  - Awake()에서 싱글톤 체크 로직 구현  
  - <code>if (instance != null) Destroy(this);</code> 로 중복 방지  
  - 손쉬운 접근을 위한 디자인 패턴 
- <b>DontDestroyOnLoad 고려사항</b>
  - 캐주얼 게임에서는 주석 처리 권장  
  - 씬을 재시작할 때 게임 매니저가 중복 생성될 수 있음  
  - 대형 프로젝트가 아니라면 제거하는 것이 정신 건강에 좋음 
- <b>변수 및 메서드</b>
  - <code>public TMP_Text scoreText</code>: 점수 표시 텍스트  
  - <code>public GameObject gameOverUI</code>: 게임 오버 UI 
  - <code>public bool isGameOver = false</code>: 게임 오버 상태 
  - <code>private int score = 0</code>: 점수 변수  
  - <code>AddScore(int point)</code>: 점수 증가 메서드   
  - <code>OnPlayerDead()</code>: 플레이어 사망 시 호출되는 메서드  
- <b>씬 재시작 구현</b>
  - <code>SceneManager.LoadScene(SceneManager.GetActiveScene().name)</code>: 현재 씬 재시작 
  - 다음 씬으로 넘어가는 것이 아닌 현재 씬을 다시 로드 
  - 마우스 버튼 다운으로 재시작 (임시, 추후 OnFire로 변경 예정)   

### 플레이어 및 스크롤링 오브젝트 연동

- <b>PlayerController 수정</b>
  - Die() 메서드에서 <code>GameManager.instance.OnPlayerDead()</code> 호출  
  - 플레이어가 죽으면 게임 매니저의 게임 오버 상태가 true로 변경됨 
- <b>ScrollingObject 수정</b>
  - Update()에서 <code>if (!GameManager.instance.isGameOver)</code> 조건 추가   
  - 게임 오버가 아닐 때만 오브젝트가 움직이도록 설정  

### 플랫폼 시스템 구축

- <b>플랫폼 프리팹 설정</b>
  - 기존에 만들어진 Platform 프리팹 사용 
  - Sprite Renderer 설정: Sorting Layer를 "Middle Ground"로 변경  
  - Box Collider 2D + Is Trigger 설정 확인 
  - Prefab Override 적용: Apply All로 모든 인스턴스에 반영 
- <b>플랫폼 스크립트 생성</b>
  - Scripts 폴더에 "Platform" 스크립트 생성 
  - OnEnable() 메서드 사용 예정 
  - 플랫폼이 화면 밖에서 랜덤한 높이로 등장하여 이동하는 시스템 구현 계획 
  - 에스테로이드(행성) 게임과 유사한 랜덤 스폰 방식 
- <b>점수 시스템 연동</b>
  - 캐릭터가 플랫폼을 밟으면 점수 증가 예정 
  - 플랫폼이 화면 밖으로 나가면 게임 오버
