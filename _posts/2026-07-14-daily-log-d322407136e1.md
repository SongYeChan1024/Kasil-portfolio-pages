## 진행한 작업

### 1. 데이터 기반 VFX 시스템 구축

- GameplayVFXIds에 인게임에서 사용하는 VFX 식별자를 한곳에 정의했다.
- VFXCatalog ScriptableObject에서 ID별 프리팹, 기본 크기, 회전, 수명, 초기 풀 크기를 설정하도록 했다.
- VFXContext를 통해 위치, 회전, 부모, 추가 스케일을 1회 재생 정보로 전달하도록 했다.
- VFXService를 카탈로그 조회와 재생 요청의 단일 진입점으로 구성했다.
- VFXRuntimePool이 프리팹별 인스턴스 대기열을 생성하고 대여·반환하도록 구현했다.
- PooledVFX가 파티클 종료 또는 지정 수명 이후 자동으로 풀에 반환되도록 했다.
- GameplayVFXPresenter가 전역 게임 이벤트를 VFX 재생 요청으로 변환하도록 했다.

### 2. 전체 인게임 이벤트 VFX 연결

- 플레이어 이동, 회피, 피격, 사망, 무기 공격 이벤트를 연결했다.
- 에너미 피격, 공격, 사망 이벤트를 연결했다.
- 아이템 드롭, 습득, 상자 열기, 아티팩트 장착 이벤트를 연결했다.
- 문 상호작용과 탈출 지점 이벤트를 연결했다.
- 기존 게임 로직의 결과가 확정된 위치에서만 VFX를 호출하도록 해 판정 로직과 표현 로직의 정합성을 유지했다.

### 3. 유탄 스킬 VFX 단계 분리

- 유탄을 던지는 순간의 투척체 효과를 독립 항목으로 분리했다.
- 일정 시간 후 발생하는 프리즘 폭발 효과를 별도 항목으로 분리했다.
- 폭발 이후 활성화되는 디코이 효과도 별도 항목으로 분리했다.
- 세 효과가 서로 다른 위치, 수명, 크기, 프리팹을 사용할 수 있도록 카탈로그에서 개별 설정하게 했다.

### 4. VFX 풀 반환 오류 수정

- OnDisable에서 풀 반환을 처리하면서 SetActive(false)를 다시 호출하던 중복 흐름을 제거했다.
- 명시적 반환 요청과 OnDisable 반환 경로의 책임을 분리했다.
- OnDisable에서는 부모 복원과 대기열 등록만 수행하도록 했다.
- 반환 중 상태와 대기열 등록 여부를 검사해 같은 인스턴스가 두 번 반환되지 않도록 했다.
- 상자 열기나 아이템 장착 후 VFX가 사라지지 않던 문제의 원인이 파티클 루프 또는 종료 조건 설정일 수 있어 카탈로그 수명과 파티클 설정을 함께 조정했다.

### 5. VFX 카탈로그 설정 반영

- 플레이 모드에서 직접 조정한 프리팹, 크기, 수명 등의 값을 확인했다.
- 플레이 종료 후 초기화되지 않도록 확정 값을 VFXCatalog 에셋에 저장했다.
- 카탈로그는 설정 원본이고 VFXManager 역할의 VFXService가 이를 읽어 실행하는 구조임을 정리했다.

### 6. 튜토리얼 씬 기본 구성

- LevelDesignScene을 복제한 TutorialScene에서 사용하지 않는 맵 오브젝트를 비활성화하고 도로 중심으로 정리했다.
- 튜토리얼은 별도 씬에서 완성하는 것을 우선 목표로 하되, 일정 부족 시 프리팹을 다른 씬으로 옮길 수 있도록 재사용 가능한 구조로 만들었다.
- 기존 프로젝트의 Additive 씬 구성 원칙에 맞춰 TutorialScene을 콘텐츠 씬으로 사용하도록 했다.
- TutorialScene을 Build Settings에 등록하고 Tutorial 전용 레이어를 추가했다.

### 7. 튜토리얼 팝업과 트리거 구현

- TutorialMessageCatalog에 MOVE, INTERACT, ITEM, ATTACK, SKILL, ESCAPE 메시지를 등록하도록 했다.
- TutorialPopup이 제목, 본문, 확인 버튼을 표시하도록 구성했다.
- TutorialManager가 중복 팝업 차단, timeScale 저장·복원, 입력 맵 전환, 확인 입력을 처리하도록 했다.
- TutorialTrigger가 플레이어의 BoxCollider 진입을 감지해 지정된 메시지를 한 번만 출력하도록 했다.
- TutorialSystem과 TutorialTrigger를 프리팹으로 제작해 씬 밖에서도 재사용할 수 있게 했다.

### 8. 실제 하이라키와 튜토리얼 이벤트 연결

- PlayerSpawnPoint 기준으로 이동 설명 트리거를 배치했다.
- BoxSpawnPointPool 기준으로 상자 상호작용 설명 트리거를 배치했다.
- EnemySpawnPointPool과 EnemyPatrolRoutePool 기준으로 공격 설명 트리거를 배치했다.
- TutorialEventBridge가 상자 열기와 에너미 체력 변경 이벤트를 감지해 후속 튜토리얼을 출력하도록 했다.
- 상자 UI 입력과 튜토리얼 팝업 입력이 충돌하지 않도록 아이템 안내 메시지는 게임을 정지하지 않게 했다.

### 9. TutorialScene 전용 NavMesh 구성

- 복제된 TutorialScene이 LevelDesignScene의 NavMesh 에셋을 공유하지 않도록 분리했다.
- TutorialNavMesh 루트 아래의 Road 오브젝트만 수집하는 NavMeshSurface를 구성했다.
- TutorialScene에 복사되어 있던 다른 NavMeshSurface는 해당 씬 안에서만 비활성화했다.
- `Unity.AI`.Navigation.Editor의 베이크 경로를 사용해 NavMesh-TutorialNavMesh.asset을 생성했다.
- 사라졌던 LevelDesignScene의 원본 NavMesh 에셋을 기존 GUID로 복구하고 기존 씬 참조가 정상임을 확인했다.

### 10. 코드 문서화 및 검증

- 오늘 직접 구현하거나 수정한 29개 스크립트만 기록 대상으로 선별했다.
- VFX 작업은 00489d3에서 5381ff4까지, 튜토리얼 작업은 08f5d21에서 bdef1c6까지를 비교 기준으로 고정했다.
- 각 파일을 이전 전체 코드 → 변경 설명 → 현재 전체 코드 순서로 Notion에 기록했다.
- 같은 날 합쳐진 오디오, 시야각, 그래픽, 리팩터링 등 다른 작업자의 변경은 제외했다.
- Unity 솔루션 빌드에서 컴파일 오류 0개를 확인했다.
- 최종 작업 트리가 clean 상태임을 확인했다.

## 이슈 / 주의할 점

- TutorialScene은 공통 매니저와 플레이어가 있는 베이스 씬과 Additive로 실행해야 전체 흐름을 확인할 수 있다.
- 튜토리얼 팝업이 timeScale을 0으로 만들 때 상자 UI처럼 별도 입력 맵을 쓰는 기능과 충돌하지 않는지 플레이 모드 검증이 필요하다.
- VFX 프리팹의 파티클이 Loop로 설정되어 있으면 파티클 종료 감지만으로 반환되지 않을 수 있으므로 카탈로그 수명 제한을 함께 설정해야 한다.
- VFX 크기는 프리팹 Transform, 파티클 Shape·Size, 카탈로그 기본 스케일이 함께 영향을 주므로 최종 화면 기준으로 조정해야 한다.
- 튜토리얼 씬의 NavMesh는 도로만 포함하도록 구성했지만 에너미 스폰 위치가 베이크 영역 위에 있는지 실제 플레이에서 확인해야 한다.
- LevelDesignScene의 NavMesh는 복구·참조 확인을 마쳤지만 Unity 플레이 모드 회귀 테스트가 필요하다.

## 배운 점


카탈로그는 무엇을 재생할지 정의하는 설정 원본이고, 서비스는 언제 어떻게 재생할지 결정하며, 풀은 인스턴스의 생성과 재사용을 담당한다. 세 책임을 분리하면 효과를 교체하거나 수치를 조정해도 게임 로직을 다시 수정할 필요가 줄어든다.


- Enum이나 상수 ID는 코드 안정성을 높이지만 실제 프리팹·크기·수명은 ScriptableObject 데이터로 분리하는 것이 조정에 유리하다.
- 오브젝트 풀에서는 SetActive(false), OnDisable, 대기열 등록이 서로 연쇄 호출되므로 각 경로의 책임을 명확히 해야 한다.
- 시각 효과는 공격 요청 시점이 아니라 데미지·상호작용·상태 변경이 실제로 확정되는 지점에 연결해야 거짓 피드백을 막을 수 있다.
- 튜토리얼은 UI 하나가 아니라 메시지 데이터, 표시 UI, 진행 제어, 트리거, 게임 이벤트 연결을 분리해야 재사용할 수 있다.
- 복제 씬은 NavMesh와 같은 외부 생성 에셋의 GUID를 공유할 수 있으므로 원본 씬과 신규 씬의 참조를 반드시 확인해야 한다.
- 에디터 설치 도구가 실제 하이라키 이름과 좌표를 기준으로 오브젝트를 생성하면 반복 수정 시 수동 배치 오류를 줄일 수 있다.
