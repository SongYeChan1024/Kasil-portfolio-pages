<b>Unity Photon Chat UI 구현 및 한글화</b> 2026-05-27


## 요약


### 오늘 수업 핵심 요약

- Unity에서 <b>Photon Chat</b>을 활용한 실시간 채팅 UI를 구현하는 방법을 학습했습니다.
- <b>TextMeshPro의 한글 폰트 에셋(SDF)</b>을 생성하여 채팅창에서 한글을 사용할 수 있도록 설정하는 과정을 배웠습니다.
- Photon Chat 패키지와 Photon PUN2의 설치 순서가 중요하며, 잘못된 순서로 설치 시 오류가 발생할 수 있다는 점을 학습했습니다.
- UI 구성요소인 Scroll View, Input Field, Button을 조합하여 채팅 인터페이스를 완성했습니다.
- 개발에서 AI 도구 활용의 중요성과 한계, 그리고 개발자가 반드시 알아야 할 핵심 개념에 대해 논의했습니다.

---

### 주요 개념 정리

- <b>Photon Chat</b>
  - 설명: Photon Engine에서 제공하는 실시간 채팅 서비스 SDK
  - 사용되는 상황: 멀티플레이어 게임에서 플레이어 간 텍스트 채팅 구현
  - 헷갈릴 수 있는 점: Photon PUN2와는 별도의 패키지이며, 설치 순서가 중요함
- <b>TextMeshPro SDF (Signed Distance Field) Font Asset</b>
  - 설명: Unity에서 고품질 텍스트 렌더링을 위한 폰트 에셋 포맷
  - 예시: 한글 폰트를 TextMeshPro에서 사용하려면 SDF 형태로 변환 필요
  - 사용되는 상황: UI 텍스트, 특히 다양한 언어(한글 등)를 표시할 때
- <b>Atlas Population Mode</b>
  - 설명: 폰트 아틀라스 생성 방식을 결정하는 설정
  - Dynamic vs Static: Dynamic은 실시간으로 필요한 글자를 생성, Static은 미리 정해진 글자만 사용
  - 사용되는 상황: 채팅처럼 사용자 입력이 동적으로 변하는 경우 Dynamic 모드 사용
- <b>IChatClientListener 인터페이스</b>
  - 설명: Photon Chat 서버에서 오는 각종 이벤트(접속, 메시지 수신 등)를 처리하는 인터페이스
  - 사용되는 상황: 채팅 매니저 스크립트에서 상속받아 채팅 이벤트 처리
- <b>Scroll View 구조</b>
  - 설명: Unity UI에서 스크롤 가능한 콘텐츠 영역을 만드는 컴포넌트
  - 구성요소: Scroll Rect, Content, Scrollbar Vertical
  - 헷갈릴 수 있는 점: 예전에는 수동으로 Scroll Rect를 추가했지만, 현재는 Scroll View 프리팹으로 자동 생성됨

### 수업 흐름별 정리

### 1. 채팅 UI 패널 기본 구조 생성

- 설명: Canvas Lobby에 Photon Chat용 패널 생성
- 작업 내용:
  - Panel Photon Chat 생성 및 크기 조정 (600x500)
  - 위치 조정 및 중앙 정렬 (Middle Center)
  - 배경 이미지 설정 (sf-window-singleBorder-window)
- 중요한 이유: 채팅 인터페이스의 기본 프레임 역할

### 2. Scroll View를 활용한 채팅 출력창 구성

- 설명: 채팅 메시지가 표시될 스크롤 가능한 영역 생성
- 작업 내용:
  - UI > Scroll View 생성
  - Horizontal Scrollbar 삭제 (세로 스크롤만 필요)
  - Scroll View를 패널에 맞게 확장
  - 배경 색상 설정 (Alpha 200 정도)
  - Anchor를 Top Left로 설정
- 중요한 이유: 채팅 메시지가 누적되면서 스크롤할 수 있도록 함

### 3. 채팅 출력 텍스트 설정

- 설명: Scroll View의 Content 안에 채팅 메시지를 표시할 TextMeshPro 추가
- 작업 내용:
  - Content 하위에 TextMeshPro 생성
  - 폰트 크기 15로 설정
  - 정렬 설정 (Left, Top)
  - 텍스트 색상 흰색으로 설정
- 중요: 이 단계에서는 한글이 표시되지 않음 (폰트 에셋 미설정)

### 4. 한글 폰트 에셋 생성 (중요)

- 설명: TextMeshPro에서 한글을 표시하기 위한 SDF 폰트 에셋 제작
- 작업 내용:
  - Noto Sans KR 폰트 다운로드 (저작권 문제 없음)
  - Fonts 폴더 생성 및 폰트 파일 import
  - 폰트 파일 선택 > 우클릭 > Create > TextMeshPro > Font Asset
  - Atlas Population Mode를 Dynamic으로 설정
  - Width, Height를 1024, 1024로 설정
- 중요한 이유: 상용화 시 저작권 문제가 없는 폰트 사용 필수
- 헷갈릴 수 있는 점: 오래된 블로그 글(2018년 버전)의 한글화 방법은 현재와 다르므로 따라하면 안 됨

### 5. 폰트 에셋 적용 및 테스트

- 설명: 생성한 한글 폰트 에셋을 채팅 출력 텍스트에 적용
- 작업 내용:
  - Text Chat Output의 Font Asset에 생성한 Noto Sans KR 에셋 할당
  - 테스트로 한글 입력 확인
- 주의사항: 특정 글자만 표시되지 않는 경우가 있을 수 있음

### 6. 채팅 입력 필드 생성

- 설명: 사용자가 채팅을 입력할 Input Field 구성
- 작업 내용:
  - Panel Photon Chat 하위에 Input Field TextMeshPro 생성
  - 이름을 InputChat으로 변경
  - 하단에 배치 및 크기 조정
  - Source Image 클리어 (배경 투명)
  - Text Component에 생성한 폰트 에셋 할당
  - Placeholder 설정 (흰색, 15 크기)

### 7. 전송 버튼 생성

- 설명: 채팅 메시지를 전송할 버튼 추가
- 작업 내용:
  - UI > Button - TextMeshPro 생성
  - 버튼 텍스트를 "전송"으로 변경
  - 버튼 텍스트에 폰트 에셋 할당
  - 텍스트 굵게 설정, 색상 파란색, 가운데 정렬
  - 소스 이미지 설정
- 기능: 전송 버튼 또는 Enter 키로 메시지 전송 가능하도록 구현 예정

### 8. Photon Chat 패키지 설치

- 설명: Photon 관리 화면에서 Chat 앱 생성 및 Unity 패키지 설치
- 작업 내용:
  - Photon Engine 웹사이트 접속 > 관리 화면 이동
  - 새 어플리케이션 만들기 > Chat 선택
  - 어플리케이션명 입력 (예: ThunderBolt)
  - App ID 복사 (Ctrl+C)
  - Unity의 Window > Asset Store에서 Photon Chat 검색
  - Photon Chat 다운로드 및 Import
- 중요: <b>설치 순서 주의</b> - Photon Chat을 먼저 설치하고 Photon PUN2를 설치해야 오류가 없음
- 오류 발생 시: Photon PUN2를 먼저 설치한 경우 중복 파일로 인한 오류 발생. 이 경우 Photon Chat 삭제 후 재설치, Photon PUN2도 재import하면 해결됨

### 9. Lobby Chat Manager 스크립트 생성

- 설명: 채팅 기능을 관리할 스크립트 생성
- 작업 내용:
  - Network 폴더에 LobbyChatManager 스크립트 생성
  - Panel Photon Chat에 스크립트 컴포넌트 추가
  - 스크립트 열기 및 기본 구조 작성 시작

### 실습 / 작업 순서

#### 한글 폰트 에셋 생성 전체 과정

1. Project 창에서 Fonts 폴더 생성
2. Noto Sans KR 폰트 파일을 Fonts 폴더에 import (또는 구글 폰트에서 다운로드)
3. 폰트 파일 선택 후 우클릭
4. Create > TextMeshPro > Font Asset 선택
5. 생성된 Font Asset 선택
6. Inspector에서 Atlas Population Mode를 <b>Dynamic</b>으로 변경
7. Width와 Height를 <b>1024, 1024</b>로 설정
8. TextMeshPro 컴포넌트의 Font Asset 필드에 생성한 에셋 드래그 앤 드롭
9. 테스트로 한글 입력하여 확인

#### Photon Chat 설치 순서 (중요)

1. Photon Engine 웹사이트 접속
2. 관리 화면 이동 > 앱 섹션
3. 새 어플리케이션 만들기 클릭
4. Photon Type을 <b>Chat</b>으로 선택
5. 어플리케이션명 입력 후 생성
6. 생성된 App ID 복사 (Ctrl+C)
7. Unity에서 Window > Asset Store > Photon Chat 검색
8. Photon Chat 다운로드 및 Import
9. Import 완료 후 App ID 입력

### 헷갈릴 수 있는 부분

- 헷갈리는 개념: Photon PUN2 vs Photon Chat
- 헷갈리는 이유: 둘 다 Photon Engine의 패키지이지만 용도가 다름
- 구분 방법: PUN2는 멀티플레이어 게임 전반, Photon Chat은 채팅 전용
- 헷갈리는 개념: Static vs Dynamic (Atlas Population Mode)
- 헷갈리는 이유: 둘 다 폰트를 표시하지만 생성 방식이 다름
- 구분 방법: Dynamic은 실시간 글자 생성(채팅 등), Static은 미리 정해진 글자만
- 헷갈리는 개념: Photon Chat과 Photon PUN2의 설치 순서
- 헷갈리는 이유: 순서를 바꾸면 중복 파일 오류 발생
- 구분 방법: <b>Photon Chat 먼저 → Photon PUN2 나중에</b> 설치
- 헷갈리는 개념: MonoBehaviour 상속 여부
- 헷갈리는 이유: 채팅 매니저에 MonoBehaviour는 상속받지만 움직임이 없음
- 구분 방법: 움직임이 없어도 채팅 데이터 처리를 위해 필요. IChatClientListener도 함께 상속

- 파이어베이스(Firebase) 학습을 위한 2D 게임 제작 계획과 과제(Photon Chat 패키지 제출)에 대해 안내받았습니다.

### 주요 개념 정리

- <b>TrueType Collection (.ttc)</b>
  - 설명: 여러 폰트가 하나로 묶여있는 폰트 파일 형식
  - 예시: 윈도우 기본 폰트인 돋움체(gulim.ttc)
  - 사용되는 상황: 시스템 폰트로 여러 변형을 포함할 때
  - 헷갈릴 수 있는 점: TextMeshPro Dynamic 모드와 호환되지 않아 런타임에 한글 Glyph 생성 실패
- <b>TrueType Font (.ttf)</b>
  - 설명: 단일 폰트 파일 형식
  - 예시: 맑은 고딕(malgun.ttf), Noto Sans KR
  - 사용되는 상황: TextMeshPro에서 Dynamic 모드로 한글 폰트 생성 시
  - 헷갈릴 수 있는 점: .ttc와 달리 TextMeshPro와 완벽하게 호환됨
- <b>Atlas Population Mode - Dynamic</b>
  - 설명: 게임 실행 중에 필요한 글자를 실시간으로 아틀라스 텍스처에 생성하는 모드
  - 예시: 채팅 입력창처럼 사용자가 다양한 한글을 입력하는 경우
  - 사용되는 상황: 수많은 한글 조합을 미리 만들어둘 수 없을 때
  - 헷갈릴 수 있는 점: Static 모드는 미리 정해진 글자만 사용 가능
- <b>TMP\_InputField Font Asset 설정</b>
  - 설명: InputField 컴포넌트 자체의 Font Asset 속성
  - 예시: TMP\_InputField의 Font Asset 필드에 폰트 에셋 할당
  - 사용되는 상황: 사용자가 입력창에 타이핑할 때
  - 헷갈릴 수 있는 점: InputField의 하위 Text 컴포넌트뿐만 아니라 InputField 자체에도 폰트를 지정해야 함. 그렇지 않으면 타이핑 시작 시 기본 영어 폰트로 덮어씌워져 한글이 깨짐
- <b>Custom Properties (Photon)</b>
  - 설명: Photon에서 플레이어별 커스텀 데이터를 저장하는 해시 테이블
  - 예시: 탱크킬수(TankKills), 아파치킬수(ApacheKills) 분리 저장
  - 사용되는 상황: 멀티플레이어 게임에서 플레이어별 통계 관리
  - 헷갈릴 수 있는 점: 해시 테이블은 탐색 테이블로, 키-값 쌍으로 데이터 저장

### 수업 흐름별 정리

### 1. TextMeshPro 한글 폰트 문제 진단

- 설명: InputField (TMP)에서 영어는 정상 입력되지만 한글이 화면에 나타나지 않거나 깨지는 현상 발생
- 원인: 윈도우 기본 폰트인 돋움체(gulim.ttc)를 Dynamic 모드로 설정했지만, .ttc 파일은 여러 폰트가 묶여있어 TextMeshPro의 Dynamic 폰트 생성 기능과 호환성 문제 발생
- 중요한 이유: 런타임에 사용자가 입력한 새로운 한글 글자의 텍스처를 제대로 생성하지 못하고 투명하게 처리됨

### 2. 해결 방법: .ttf 폰트 파일 사용

- 설명: .ttc 파일 대신 단일 폰트 파일 형식인 .ttf (TrueType Font) 파일 사용
- 예시: 맑은 고딕(malgun.ttf) 폰트 사용 - TextMeshPro와 완벽하게 호환
- 중요한 이유: 원본 경로 <code>C:\Windows\Fonts\malgun.ttf</code>에서 Unity 프로젝트의 <code>Assets/Fonts/</code> 폴더로 복사하여 가져옴

### 3. TMP 폰트 에셋 생성 및 설정

- 설명: Unity 에디터에서 malgun.ttf 파일을 우클릭하여 <code>Create &gt; TextMeshPro &gt; Font Asset</code> 선택, Malgun SDF 폰트 에셋 생성
- 설정: Inspector에서 Atlas Population Mode를 Dynamic으로 변경
- 중요: Dynamic 모드는 게임 실행 중에 필요한 한글 글자를 실시간으로 아틀라스 텍스처에 구워주어, 수많은 한글 조합을 미리 만들어둘 필요가 없게 함

### 4. UI 컴포넌트에 폰트 적용

- 설명: 씬에 있는 모든 TextMeshPro 관련 컴포넌트에 새로 만든 폰트 적용
- 일반 텍스트: <code>TextMeshProUGUI</code> 컴포넌트의 <code>Font Asset</code> 속성에 <code>Malgun SDF</code> 할당
- 입력창: <code>TMP_InputField</code> 컴포넌트의 <code>Font Asset</code> 속성에 <code>Malgun SDF</code> 할당
- 중요: ⚠️ TMP\_InputField 자체의 Font Asset을 지정하지 않으면, 사용자가 타이핑 시작 시 기본 영어 폰트(LiberationSans)로 덮어씌워져 한글이 다시 깨질 수 있음. 반드시 InputField 컴포넌트의 Font Asset도 변경 필요

### 5. 탱크/아파치 킬수 분리 기록

- 설명: 기존에는 탱크끼리만 킬수가 기록되었으나, 아파치도 킬수가 기록되도록 수정
- 수정 내용: KillInfo UI에서 탱크킬수(TankKills)와 아파치킬수(ApacheKills)를 Custom Properties에서 분리 저장
- 중요한 이유: 플레이어별 유닛별 통계를 정확하게 추적

### 6. 코드 수정 작업

- 설명: TankDamage.cs에서 함수명을 명확하게 변경 - <code>NotifyTankKillRPC</code>로 명명
- 수정: <code>setCustomProperties</code>에서 <code>ExitGames.Client.Photon.Hashtable</code>을 사용하여 TankKills 증가 처리
- TankFire.cs 수정: <code>ApacheCrashHit</code>에서 PhotonView의 <code>OwnerActorNr</code>을 매개변수로 전달
- KillInfo.cs 수정: <code>ChangeProperties</code>에서 TankKills와 ApacheKills 중 하나라도 변경되면 UI 업데이트

### 7. 파이어베이스 학습 계획 안내

- 설명: 탱크 게임에서 단순히 킬수만 기록하는 것은 너무 간단하여, 간단한 2D 게임을 만들어서 Firebase를 배우기로 함

- 중요한 이유: Firebase를 통해 킬수, 스코어, 선택한 유닛 등의 데이터를 영구적으로 저장하는 방법 학습

### 헷갈릴 수 있는 부분

- 헷갈리는 개념: .ttc와 .ttf 폰트 파일 형식
- 헷갈리는 이유: 둘 다 폰트 파일이고 시스템에서는 정상 작동하지만 TextMeshPro에서는 차이가 있음
- 구분 방법: .ttc는 여러 폰트 묶음, .ttf는 단일 폰트. TextMeshPro Dynamic 모드는 .ttf만 지원
- 헷갈리는 개념: TextMeshProUGUI vs TMP\_InputField의 Font Asset 설정
- 헷갈리는 이유: 하위 Text 컴포넌트에만 설정하면 될 것 같지만 InputField는 추가 설정 필요
- 구분 방법: InputField는 컴포넌트 자체에도 Font Asset을 설정해야 타이핑 시 한글이 유지됨
- 헷갈리는 개념: Atlas Population Mode의 Dynamic vs Static
- 헷갈리는 이유: 둘 다 폰트를 표시하지만 생성 방식이 다름
- 구분 방법: Dynamic은 런타임에 필요한 글자를 실시간 생성(채팅, 입력창 등), Static은 미리 정해진 글자만 사용
- 헷갈리는 개념: Custom Properties의 Hashtable 구조
- 헷갈리는 이유: 일반 변수처럼 보이지만 키-값 쌍으로 저장하는 탐색 테이블
- 구분 방법: <code>ExitGames.Client.Photon.Hashtable</code>을 사용하여 \{ "키": 값 \} 형태로 저장

## 메모


<b># TextMeshPro 한글 폰트 깨짐/안 보임 현상 해결 방법</b>

<b>## 🚨 문제 현상</b>

유니티 TextMeshPro(TMP)를 사용하여 채팅 입력창(\`InputField (TMP)\`)을 구현했을 때, 영어는 정상적으로 입력되지만

- \*한글을 입력하면 글자가 화면에 나타나지 않거나 깨지는 현상\*\*

이 발생했습니다.

<b>## 🔍 원인 분석</b>

초기에는 윈도우 기본 폰트인 돋움체(\`gulim.ttc\`)를 가져와서 TMP 폰트 에셋을 생성하고 \`Dynamic\`(동적) 모드로 설정했습니다. <br />하지만 \`.ttc\` (TrueType Collection) 확장자를 가진 폰트 파일은 여러 폰트가 하나로 묶여있는 형식이라서,

- \*TextMeshPro의 Dynamic 폰트 생성 기능과 호환성 문제\*\*

를 일으킵니다. <br />이로 인해 런타임에 사용자가 입력한 새로운 한글 글자(Glyph)의 텍스처를 제대로 생성해내지 못하고 투명하게 처리해버린 것입니다.

<b>## 💡 해결 방법</b>

이 문제를 해결하려면 \`.ttc\` 파일 대신 단일 폰트 파일 형식인

- \*\`.ttf\` (TrueType Font)\*\*

파일을 사용해야 합니다.

<b>### 1. 호환되는 \`.ttf\` 폰트 파일 준비</b>

<b>### 3. UI 컴포넌트에 폰트 일괄 적용</b>
