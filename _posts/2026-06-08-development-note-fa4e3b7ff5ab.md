<b>Pet Bloom Garden - ZEPETO 1주일 프로젝트 기획 및 구조 설계</b> 2026-06-08

## 요약

## 오늘 수업 핵심 요약

- <b>Pet Bloom Garden</b>은 1주일 단위 1인 개발 프로젝트로, 프로토타입 완성을 목표로 1일차부터 구체적인 목표를 설정하여 진행한다.
- 핵심 흐름은 <b>펫 선택 → 펫 상호작용 → 유대 레벨 상승 → 펫 반응 변화 → 포토존 연출</b>이며, 이 흐름이 실제로 플레이 가능한 상태까지 만드는 것이 이번 주 목표이다.
- <b>ZEPETO 월드 개발의 가장 중요한 전제</b>는 Unity C# 스크립트가 최종 빌드에 포함되지 않으며, 모든 기능 구현은 <b>ZEPETOScript(TypeScript 기반)</b>로 해야 한다는 점이다.
- Unity <b>2022.3.34f1</b> 버전을 요구하며, 프로젝트 시작 전 Unity 버전 맞추기가 첫 순서이다.
- 프로젝트는 모바일 가로 화면 중심으로 설계하고, 멀티플레이와 저장 기능은 후순위로 미룬다.

## 주요 개념 정리

### <b>ZEPETOScript</b>

- <b>설명</b>: ZEPETO 월드에서 기능 구현에 사용하는 TypeScript 기반 스크립트
- <b>사용되는 상황</b>: Unity C# 스크립트는 최종 패키지 빌드에 포함되지 않으므로, 실제 기능 구현은 <code>.ts</code> 파일 중심으로 작성해야 함
- <b>헷갈릴 수 있는 점</b>: Unity 에디터에서는 C#으로 설계하듯 생각할 수 있지만, 실제 스크립트 파일은 TypeScript로 작성

### <b>NavMeshAgent</b>

- <b>설명</b>: 캐릭터를 따라다니는 펫의 이동을 구현하는 컴포넌트
- <b>예시</b>: 펫이 플레이어를 따라오는 구조
- <b>사용되는 상황</b>: 펫 따라오기 기능 구현 시
- <b>헷갈릴 수 있는 점</b>: 모바일에서는 펫이 벽에 끼거나 땅 아래로 떨어질 수 있으므로 이동 범위 제한 및 안전 위치 재배치 필요

### <b>ZEPETO Multiplay</b>

- <b>설명</b>: 여러 유저가 같은 월드에서 플레이하도록 서버/클라이언트 통신을 제공하는 시스템
- <b>사용되는 상황</b>: 멀티플레이 기능 구현 시
- <b>헷갈릴 수 있는 점</b>: 초기 버전에서는 8명 이하, 위치/애니메이션 실시간 동기화보다 이벤트 중심 처리로 단순화 권장

## 수업 흐름별 정리

### 1. ZEPETO 개발 전제 조건 이해

- <b>설명</b>: ZEPETO 월드 개발은 Unity와 World SDK 기반이며, TypeScript로 기능을 구현해야 함
- <b>중요한 이유</b>: C# 스크립트는 빌드에 포함되지 않으므로 처음부터 TypeScript 기반으로 작업해야 재작업을 피할 수 있음

### 2. 제페토가 제공하는 것과 직접 구현해야 하는 것 구분

- <b>설명</b>: ZEPETO SDK가 제공하는 기능(아바타, 월드 입장, UI 이벤트, NavMeshAgent)과 직접 만들어야 하는 기능(게임 로직, UI 흐름, 이동 범위 제한) 구분
- <b>중요한 이유</b>: 효율적인 개발을 위해 SDK 활용 범위와 직접 구현 범위를 명확히 해야 함

### 3. 프로젝트 폴더 구조 설계

- <b>설명</b>: 처음부터 체계적인 폴더 구조를 설계하여 프로젝트가 흩어지지 않게 관리
- <b>예시</b>: <code>00_ZEPETO</code>, <code>01_Scenes</code>, <code>02_Scripts</code> (Core, Player, Pet, Interaction 등 하위 폴더), <code>03_Prefabs</code>, <code>04_Art</code>, <code>05_Animations</code>, <code>06_Audio</code>, <code>99_Debug</code>
- <b>중요한 이유</b>: 1주일 내 완성을 위해서는 초기 구조가 명확해야 작업 효율이 높아짐

### 4. 핵심 스크립트 목록 작성

- <b>설명</b>: 1주일 안에 끝내기 위해 핵심 스크립트 10\~14개 정도로 시작
- <b>중요한 이유</b>: 너무 세밀하게 쪼개면 일정 내 완성이 어려움

### 5. 기능 구현 순서 수립

- <b>단계별 구현</b>: 월드 기본 세팅 → 펫 선택 → 상호작용과 유대 레벨 → 펫 따라오기 → 포토존
- <b>중요한 이유</b>: 순차적으로 기능을 쌓아가며 매일 동작 가능한 결과물 확보

### 6. 1주일 개발 일정 계획

- <b>설명</b>: Day 1부터 Day 7까지 목표와 결과물을 명확히 설정
- <b>중요한 이유</b>: 일일 목표가 명확해야 프로토타입 완성 가능

### 7. MVP 범위 정의

- <b>설명</b>: 이번 주 필수 MVP와 가능하면 추가할 항목, 후순위 항목을 구분
- <b>중요한 이유</b>: 제한된 시간 내에 핵심 기능 우선 완성

### 8. 1일차 작업 계획

- <b>설명</b>: 오늘은 코딩보다 <b>설계판을 박는 날</b>로 설정

## 실습 / 작업 순서

### 1일차 작업 순서

1. Unity 버전과 ZEPETO World SDK 세팅 확인
2. <code>Main_PetBloomGarden</code> 씬 생성
3. 폴더 구조 생성 (위 구조대로)
4. 펫 프리팹 3개 자리만 만들기
5. <code>PBGGameManager.ts</code>, <code>LocalPlayerFinder.ts</code>, <code>PetSelectionController.ts</code>, <code>PetSpawner.ts</code> 먼저 생성
6. 선택 버튼을 눌렀을 때 펫이 하나 생성되는 것까지 테스트

### 펫 선택 시스템 구현 흐름

```txt
PetSelectionController
→ 선택 버튼 클릭
→ selectedPetId 저장
→ PetSpawner.SpawnPet(selectedPetId)
→ PetInteractionUI 활성화
```

- <b>프리팹만 3개, 로직은 하나</b>로 간다 (강아지, 고양이, 토끼에 별도 AI 불필요)

### 상호작용과 유대 레벨 구현 흐름

```txt
버튼 클릭
→ PetInteractionController.PlayInteraction(type)
→ 펫 애니메이션 실행
→ EffectManager.PlayEffect(type)
→ BondManager.AddExp(value)
→ BondLevelUI.Refresh()
```

### 펫 따라오기 구현

1. NavMeshAgent로 플레이어 따라오기 구현
2. 이동 가능 범위를 산책로와 주요 포토존 중심으로 제한
3. Agent Radius, Height, Step Height를 펫 크기에 맞춰 조정
4. <b>중요: 맵 전체를 펫이 돌아다니게 하지 않음</b> (안전한 길만 다니도록)

### 포토존 구현 흐름

```txt
PhotoZoneTrigger
→ 플레이어 진입
→ PhotoZoneUI 활성화
→ 사용 가능한 포즈 표시
→ 포즈 버튼 클릭
→ 펫 포즈 애니메이션 실행
→ 꽃잎/하트/별빛 이펙트 출력
→ 사진 촬영 안내 문구 표시
```

- 프로토타입에서는 한 가지만 만든 뒤 기능 구현 우선

## 헷갈릴 수 있는 부분

### C# vs TypeScript 혼동

- <b>헷갈리는 이유</b>: Unity 에디터에서는 C#을 사용하지만, ZEPETO 월드에서는 C# 스크립트가 빌드에 포함되지 않음
- <b>구분 방법</b>: 기능 구현은 반드시 <code>.ts</code> 파일(ZEPETOScript)로 작성

### 멀티플레이 우선순위

- <b>헷갈리는 이유</b>: ZEPETO Multiplay 기능이 있지만 1주일 내 완성은 어려움
- <b>구분 방법</b>: 초기 버전은 싱글 플레이 중심, 멀티플레이는 후순위

### 펫 이동 범위

- <b>헷갈리는 이유</b>: NavMeshAgent를 사용하면 맵 전체를 자유롭게 돌아다닐 수 있을 것 같음
- <b>구분 방법</b>: 맵 전체가 아닌 안전한 경로만 설정하여 끼임/낙하 방지

## 메모

Pet Bloom Garden은 1주일짜리 1인 개발이다, 시작 부터 전체적인 구조와 틀을 기획서로 정리해서 하는 것도 좋겠지만 그렇게 해서 1주만에 완성이 가능한 형태가 아니라고 판단해서 1일차부터 목표치를 잡고 움직이기로 했다.

이번 주 목표는 이렇게 잡게 되었다.

<blockquote markdown="1">

<b>펫 선택 → 펫 상호작용 → 유대 레벨 상승 → 펫 반응 변화 → 포토존 연출</b>

이 흐름이 실제로 플레이 가능한 상태까지 가는 것.

</blockquote>

기획서에서도 핵심 흐름을 “월드 입장 → 펫 선택 → 상호작용 → 유대 경험치 → 레벨 상승 → 펫 행동 변화 → 포토존 → 사진 촬영”으로 잡고 있고, 초기 버전 우선 범위도 펫 3종, 선택 UI, 먹이 주기, 쓰다듬기, 놀아주기, 유대 레벨, 펫 따라오기, 포토존 3종, 포즈 3종, 하트/꽃잎/별빛 이펙트, 모바일 가로 UI로 정리돼 있어.

## 1. 가장 먼저 알아야 할 제페토 개발 전제

여기서 중요한 점은 <b>제페토 월드에서는 Unity C# 스크립트가 최종 패키지 빌드에 포함되지 않고, 기능 구현은 ZEPETOScript, 즉 TypeScript 기반으로 해야 한다는 것이다.</b>

<p>
 C#으로 설계하듯이 생각할 수는 있지만, 실제 스크립트 파일은 <code>.ts</code> 중심으로 짜야 한다는 뜻이다.
</p>

<p>
ZEPETO World 개발은 Unity와 World SDK를 기반으로 하고, 현재 설치 가이드에서는 Unity <b>2022.3.34f1</b> 버전을 요구한다고 안내하고 있다.
</p>

프로젝트 시작 전에 Unity 버전부터 맞추는 게 첫 순서 이다.

## 2. 제페토가 해주는 것과 직접 만들어야 하는 것

| --- | --- | --- |
| 플레이어 | 제페토 아바타, 월드 입장, 기본 캐릭터 조작 | 로컬 플레이어 찾기, 펫이 따라갈 대상 연결 |
| 스크립트 | ZEPETOScript 실행 구조, TypeScript 기반 컴포넌트 | 게임 로직 전체. 펫 선택, 유대 레벨, UI 흐름 |
| UI | Unity UI와 Button, Slider 같은 UI 이벤트 사용 가능 | 펫 선택 UI, 상호작용 UI, 유대 레벨 UI, 포토존 UI |
| 펫 이동 | NavMeshAgent를 이용해 캐릭터를 따라오는 구조 구현 가능 | 이동 범위 제한, 끼임 방지, 안전 위치 재배치 |
| 멀티플레이 | ZEPETO Multiplay로 룸, 서버/클라이언트 통신 가능 | 무엇을 동기화할지 결정. 초기에는 이벤트만 최소 동기화 |
| 사진/소셜 | 제페토 기본 촬영, 친구 방문 흐름 활용 | 포토존 트리거, 포즈 버튼, 이펙트 연출, HYPE 안내 UI |

제페토 공식 가이드에서는 Unity UI 이벤트를 ZEPETOScript에서 Button, Slider 등으로 연결하는 방식이 안내되어 있고, 펫처럼 캐릭터를 따라다니는 오브젝트는 NavMeshAgent와 ZEPETO 캐릭터 Transform을 이용하는 예제가 있다. 그래서 <b>UI, 트리거, 펫 따라오기 자체는 충분히 가능</b>하다고 보인다.

<p>
멀티플레이는 이번 주 안에 완성하지 못할 것 같아 후순위로 미룬다.
</p>

ZEPETO Multiplay는 여러 유저가 같은 월드에서 플레이하도록 서버/클라이언트 개발과 로컬 테스트 환경을 제공하지만, 기획서에서도 초기 기준은 8명 이하, 위치나 애니메이션 실시간 동기화보다 이벤트 중심 처리로 잡혀 있다.

## 5. 기능 구현 순서

### 1단계: 월드 기본 세팅

먼저 Unity 버전과 ZEPETO World SDK 세팅을 확인하고, 메인 씬을 하나 만든다. 그다음 입구 광장, 펫 선택존, 케어존, 포토존 1개만 먼저 배치한다. 기획서상 월드는 모바일 가로 화면 중심이고, PC는 개발/테스트 보조 환경으로 잡혀 있으니 UI와 화면 구성은 처음부터 모바일 기준으로 봐야 한다.

### 2단계: 펫 선택

처음에는 강아지, 고양이, 토끼 3종 모두 AI를 따로 만들 필요 없을 것 같다.

<b>프리팹만 3개, 로직은 하나</b>로 간다.

```txt
PetSelectionController
→ 선택 버튼 클릭
→ selectedPetId 저장
→ PetSpawner.SpawnPet(selectedPetId)
→ PetInteractionUI 활성화
```

### 3단계: 상호작용과 유대 레벨

먹이 주기, 쓰다듬기, 놀아주기는 처음엔 구조를 통일하고 이후에 세분화 시킨다.

```txt
버튼 클릭
→ PetInteractionController.PlayInteraction(type)
→ 펫 애니메이션 실행
→ EffectManager.PlayEffect(type)
→ BondManager.AddExp(value)
→ BondLevelUI.Refresh()
```

기획서에서도 상호작용 결과는 펫 애니메이션, 하트/꽃잎 이펙트, 효과음, 유대 경험치 증가, 펫 상태 변화, 포토존 반응 변화로 정리돼 있으므로 이 흐름을 그대로 코드 구조로 옮기면 된다.

### 4단계: 펫 따라오기

펫 따라오기는 NavMeshAgent로 구현할 수 있다. 그러나, 기획서 피드백에도 있었듯이 모바일에서는 펫이 벽에 끼거나 땅 아래로 떨어지는 문제가 생길 수 있으므로, 이동 가능 범위를 산책로와 주요 포토존 중심으로 제한하고, Agent Radius, Height, Step Height를 펫 크기에 맞춰 조정한다.

<p>
여기서 중요한 건 <b>맵 전체를 펫이 돌아다니게 하지 않는 것,</b> 펫은 자유로운 척하지만 사실은 꽃길 위의 철도처럼 안전한 길만 다니게 해야 한다.
</p>

### 5단계: 포토존

프로토타입에서는 포토존을 한 가지만 만들고, 기능 구현을 우선순위에 두어 먼저 완성한다.

```txt
PhotoZoneTrigger
→ 플레이어 진입
→ PhotoZoneUI 활성화
→ 사용 가능한 포즈 표시
→ 포즈 버튼 클릭
→ 펫 포즈 애니메이션 실행
→ 꽃잎/하트/별빛 이펙트 출력
→ 사진 촬영 안내 문구 표시
```

기획서에는 꽃밭, 구름 침대존, 산책길 벤치, 펫 스타일존, 펫 카페, 밤하늘 정원 포토존이 잡혀 있지만, 1주일 버전에서는 이중 하나만 만드는 게 현실적 이다.
