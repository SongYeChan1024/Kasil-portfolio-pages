<b>Unity 오브젝트 풀링과 네트워크 동기화 수업</b> 2026-05-15

## 요약

### 오늘 수업 핵심 요약

- <b>Apache 헬리콥터</b>를 위한 <b>오브젝트 풀링(Object Pooling)</b> 시스템을 <b>Queue</b> 자료구조를 활용하여 구현했습니다.
- <b>싱글턴 패턴(Singleton Pattern)</b>으로 ApacheSpawner를 설계하여 전역 접근이 가능하도록 구현했습니다.
- 랜덤한 위치에서 Apache가 생성되도록 <b>Spawn Point</b> 시스템을 List로 관리하고, <b>초기 스폰 시간 3초</b>, <b>리스폰 시간 5초</b>로 설정했습니다.
- Tank, Turret, Cannon에 <b>Photon View</b>를 추가하여 멀티플레이어 환경에서 <b>네트워크 동기화</b>를 준비했습니다.

---

### 주요 개념 정리

- <b>오브젝트 풀링 (Object Pooling)</b>
  - 설명: 게임 오브젝트를 매번 생성/파괴하지 않고 미리 생성해두고 재사용하는 기법
  - 예시: Apache 헬리콥터를 5대 미리 생성해두고 비활성화 상태로 Queue에 보관, 필요할 때 Dequeue하여 활성화
  - 사용되는 상황: 반복적으로 생성/삭제되는 오브젝트 (적, 총알, 이펙트 등)
  - 헷갈릴 수 있는 점: Enqueue는 "넣기"(반납), Dequeue는 "꺼내기"(사용)
- <b>Queue vs List</b>
  - 설명: Queue는 FIFO(First In First Out) 구조, List는 인덱스 기반 접근
  - 사용되는 상황: 오브젝트 풀링은 Queue와 자료구조가 잘 맞음
  - 헷갈릴 수 있는 점: List는 중간 요소 제거 시 데이터 시프트 발생, 하지만 소량(5개 정도)이면 성능 문제 없음

|  |  |
| --- | --- |
| Queue | FIFO, 먼저 들어간 |
| List | 인 |

- <b>싱글턴 패턴 (Singleton Pattern)</b>
  - 설명: 클래스의 인스턴스가 하나만 존재하도록 보장하는 디자인 패턴
  - 예시: <code>ApacheSpawner.Instance</code>로 어디서든 접근 가능
  - 사용되는 상황: GameManager, Spawner 등 전역 관리 객체
  - 헷갈릴 수 있는 점: <code>DontDestroyOnLoad</code>는 씬 전환 시 유지용 (이번 실습에서는 생략)
- <b>네트워크 동기화 (Network Synchronization)</b>
  - 설명: 멀티플레이어 환경에서 로컬 플레이어의 움직임을 다른 네트워크 유저에게 전송(송신)하고, 다른 유저의 움직임을 받아서(수신) 화면에 표시
  - 예시: Photon View 컴포넌트 추가
  - 사용되는 상황: Tank(몸통), Turret(포탑), Cannon(포신)처럼 움직임이 다른 각 부분마다 별도로 적용
  - 헷갈릴 수 있는 점: 각 오브젝트마다 움직임이 다르면 개별적으로 Photon View 필요

### 수업 흐름별 정리

### 1. Apache 오브젝트 풀링 설계

- 설명: ApacheSpawner 스크립트를 싱글턴 패턴으로 생성하고, Queue를 사용한 오브젝트 풀링 시스템 설계
- 예시: <code>Queue&lt;GameObject&gt; apacheQ = new Queue&lt;GameObject&gt;()</code>
- 중요한 이유: 반복적인 생성/파괴로 인한 성능 저하 방지

### 2. Spawn Point 설정

- 설명: 빈 오브젝트 SpawnPoints를 생성하고 하위에 5개의 SpawnPoint 배치, List로 관리
- 예시: 턴을 주기 위해 바깥쪽 여러 위치에 분산 배치
- 중요한 이유: 랜덤한 위치에서 적이 출현하도록 게임 난이도 조절
- <code>중요:</code> GetComponentsInChildren으로 자동으로 SpawnPoints의 자식 Transform들을 리스트에 담음

### 3. 스폰 타이밍 설정

- 설명: 초기 스폰은 3초 간격, 리스폰은 5초 간격으로 설정
- 예시: <code>initialTime = 3f</code>, <code>respawnTime = 5f</code>
- 중요한 이유: 기획 의도에 맞는 게임 밸런스 조정

### 4. Create Pooling 메서드 구현

- 설명: 풀 사이즈만큼 Apache 프리팹을 Instantiate하여 ApacheSpawner 하위에 생성하고, 비활성화 상태로 Queue에 Enqueue
- 예시: 5대의 Apache를 미리 생성하여 비활성 상태로 대기
- <code>중요:</code> 부모를 <code>this.transform</code>으로 설정하여 ApacheSpawner 하위에 정리

### 5. Spawn Apache 코루틴 구현

- 설명: IEnumerator로 일정 시간마다 Apache를 Dequeue하여 랜덤 Spawn Point에서 활성화
- 예시: <code>WaitForSeconds</code> 사용하여 초기/리스폰 타이밍 조절
- 중요한 이유: 게임 진행 중 지속적으로 적 생성
- <code>중요:</code> While 루프로 계속 스폰하되, GameManager.Instance.isGameOver로 게임 종료 시 중단

### 6. Return Apache 메서드 구현

- 설명: Apache가 파괴될 때 비활성화하고 다시 Queue에 Enqueue하여 재사용
- 예시: <code>apache.SetActive(false)</code>, <code>apacheQ.Enqueue(apache)</code>
- 중요한 이유: 오브젝트 풀링의 핵심인 재사용 구현

### 7. GameManager 싱글턴 생성

- 설명: isGameOver bool 변수로 게임 종료 상태 관리
- 예시: <code>public bool isGameOver = false</code>
- 중요한 이유: 게임 종료 시 Apache 스폰 중지

### 8. Photon View 추가

- 설명: Tank, Turret, Cannon에 각각 Photon View 컴포넌트 추가
- 예시: Add Component → Photon View
- 중요한 이유: 멀티플레이어 환경에서 각 부분의 움직임을 독립적으로 동기화
- <code>중요:</code> 움직임이 다른 각 파트마다 별도의 Photon View 필요

### 실습 / 작업 순서

1. ApacheSpawner 스크립트 생성 및 싱글턴 패턴 구현
2. Queue 선언 및 초기화: <code>Queue&lt;GameObject&gt; apacheQ = new Queue&lt;GameObject&gt;()</code>
3. Apache 프리팹을 Resources 폴더에서 불러와 SerializeField로 연결
4. Hierarchy에서 SpawnPoints 빈 오브젝트 생성, 하위에 SpawnPoint 5개 배치
5. SpawnPoints 위치를 랜덤하게 배치 (바깥쪽, 보이지 않는 곳)
6. List로 SpawnPoint Transform 받기: <code>GetComponentsInChildren&lt;Transform&gt;()</code>
7. CreateApachePulling() 메서드에서 for문으로 풀사이즈만큼 Apache 생성 및 Enqueue
8. Awake에서 CreateApachePulling() 호출하여 초기화
9. SpawnApache() 코루틴 구현: Dequeue → 랜덤 위치 설정 → 활성화
10. <code>SetPositionAndRotation()</code>으로 위치와 회전을 동시에 설정
11. Start에서 StartCoroutine(SpawnApache()) 호출
12. ReturnApache() 메서드 구현: 비활성화 후 Enqueue
13. ApacheCrash 스크립트의 OnTriggerEnter에서 ApacheSpawner.Instance.ReturnApache(gameObject) 호출
14. GameManager 생성 및 isGameOver bool 변수 추가
15. Resources 폴더의 Apache 프리팹 더블클릭하여 Capsule Collider 크기 조정 (Radius: 10, Height: 30)
16. Tank, Turret, Cannon에 각각 Photon View 컴포넌트 추가
17. 테스트: Play 모드에서 Apache가 5대 생성되고, 랜덤 위치에서 스폰되는지 확인

### 예시와 활용 사례

- 예시 1: Apache 오브젝트 풀링
  - 상황: Apache가 5대 미리 생성되어 ApacheSpawner 하위에 비활성 상태로 대기
  - 설명: Hierarchy에서 Apache(Clone) 5개가 보이며, 실행 시 랜덤 위치에서 활성화됨
  - 왜 이 예시를 사용했는지: 오브젝트 풀링이 제대로 작동하는지 시각적으로 확인
- 예시 2: SetPositionAndRotation 사용
  - 상황: Apache를 스폰할 때 위치와 회전을 동시에 설정
  - 설명: <code>apache.transform.SetPositionAndRotation(pt.position, pt.rotation)</code>
  - 왜 이 예시를 사용했는지: position과 rotation을 따로 설정하는 것보다 한 번에 처리 가능
- 예시 3: 랜덤 스폰 포인트 선택
  - 상황: 5개의 스폰 포인트 중 랜덤하게 선택
  - 설명: <code>Transform pt = spawnPoints[Random.Range(0, spawnPoints.Count)]</code>
  - 왜 이 예시를 사용했는지: 게임에 예측 불가능성과 난이도 추가

### 헷갈릴 수 있는 부분

- 헷갈리는 개념: Enqueue vs Dequeue
- 헷갈리는 이유: 둘 다 Queue 관련 메서드지만 반대 동작
- 구분 방법: Enqueue는 "넣기"(반납, SetActive false), Dequeue는 "꺼내기"(사용, SetActive true)
- 헷갈리는 개념: 싱글턴 Instance vs this
- 헷갈리는 이유: Instance는 정적 변수, this는 현재 인스턴스
- 구분 방법: Instance가 null이면 this를 할당, 아니면 Destroy
- 헷갈리는 개념: GetComponentsInChildren (복수형)
- 헷갈리는 이유: GetComponentInChildren (단수형)과 혼동
- 구분 방법: 복수형은 모든 자식의 컴포넌트를 배열로 반환
