<b>게임 기획서 피드백 및 진로 상담 수업</b> 2026-06-04


## 요약


### 오늘 수업 핵심 요약

- 게임 개발 도구인 <b>Pixyz 플러그인</b>을 소개하고, FBX 파일을 손상 없이 Unity로 가져오는 방법을 설명했습니다.
- 게임 개발자의 진로로 <b>경력 쌓기 → 강사/창업</b> 경로를 제시하며, 정책자금 활용법과 NCS 훈련 교육 강사 제도를 안내했습니다.
- 우성혁, 송유찬, 송예찬, 장수영, 김남회 레이서의 <b>게임 기획서를 개별 검토</b>하고 피드백을 제공했습니다.
- 모바일 게임 개발 시 <b>플랫폼 사양, 화면 방향, UI/UX 일관성</b> 등 실무적인 개발 체크포인트를 강조했습니다.
- 게임 기획에서 <b>정당한 승리 조건</b>과 <b>유저 이탈 방지</b>의 중요성을 설명했습니다.

---

### 주요 개념 정리

- <b>Pixyz 플러그인</b>
  - 설명: Unity에서 FBX 파일을 손상 없이 가져올 수 있게 해주는 새로운 툴
  - 예시: AutoCAD, 3DMAX, Maya, Blender에서 작업한 3D 모델을 그대로 Unity로 임포트
  - 사용되는 상황: 기존에는 FBX를 가져올 때 면이나 선이 깨지거나 색깔이 제대로 오지 않는 문제가 있었으나, Pixyz를 사용하면 해결 가능
  - 헷갈릴 수 있는 점: 별도 텍스처나 노멀맵 작업이 필요 없이 원본 상태 그대로 가져올 수 있음
- <b>권장사양/최소사양 명시</b>
  - 설명: 모바일 게임 출시 시 구동 가능한 기기 사양을 명확히 표기해야 함
  - 예시: 갤럭시23 기준, 노트3/노트5 등 구체적인 기종 명시
  - 사용되는 상황: 사양이 낮은 기기에서 게임이 안 되는 경우 개발자가 부당한 비난을 받을 수 있음
  - 헷갈릴 수 있는 점: 사양을 명시하지 않으면 유저가 자신의 기기 문제를 개발자 탓으로 돌릴 수 있음
- <b>정당한 승리 조건 (Fair Victory Condition)</b>
  - 설명: 게임에서 승패가 명확하고 공정하게 결정되어야 유저가 납득할 수 있음
  - 예시: 동점 시 판정 규칙이 복잡하거나 모호하면 유저 불만 발생
  - 사용되는 상황: 투표 시스템이나 경쟁 게임에서 특히 중요
  - 헷갈릴 수 있는 점: 동점 자체를 아예 발생하지 않게 설계하는 것도 하나의 방법
- <b>코어 루프 (Core Loop)와 반복 플레이</b>
  - 설명: 게임의 핵심 반복 구조로, 지루함을 방지하는 설계가 필요
  - 예시: MMORPG의 레벨업, 장비 획득 등 성장 시스템
  - 사용되는 상황: 반복 플레이가 많은 게임에서 유저 이탈을 막기 위함
  - 헷갈릴 수 있는 점: 반복 자체가 문제가 아니라, 만족감이 없는 반복이 문제

### 수업 흐름별 정리

### 1. 도입: Pixyz 플러그인 소개 및 진로 상담

- 설명: Pixyz라는 Unity 플러그인이 FBX 파일을 손상 없이 가져올 수 있게 해준다는 내용을 5년 차 이상 개발자들에게 강연한 경험을 공유
- 예시: 제페토 제작 시 FBX 모델링을 가져와서 텍스처와 노멀맵을 별도로 입혀야 했던 불편함 해소
- 중요한 이유: 실무에서 3D 모델 작업 효율을 크게 높일 수 있음

### 2. 진로 및 창업 안내

- 설명: 게임 개발 경력 → 강사/창업 경로 제시, 정책자금 활용 방법 안내
- 예시: 대한상공회의소, 한국기술신용보증기금 등의 R&D 예산 활용
- 중요한 이유: 기술만으로는 부족하고, 경력을 쌓은 후 다양한 진로를 고려해야 함

### 3. 우성혁 레이서 기획서 피드백

- 설명: 모바일 게임 기획서 검토, 동시접속자 24명 기준
- 피드백 내용:
  - 권장사양/최소사양 명시 필요 (예: 갤럭시23 기준)
  - 화면 방향: 세로보다 <b>가로 모드 강력 추천</b> (몰입감 향상)
  - 오프닝 시네머신이나 로딩 화면 제안
- 중요한 이유: 사양 미명시 시 유저 클레임 발생 가능, UI 일관성 유지 필요

### 4. 송유찬/송예찬 레이서 기획서 피드백

- 설명: 반복 플레이 기반 게임, 지루함 방지 방안 필요
- 피드백 내용:
  - "좋아요" 시스템 API 연동이 어려울 경우 대안 제시
  - 리니지2/와우의 <b>추천 시스템(평판 시스템)</b> 사례 소개
  - 플랫폼(PC/모바일) 명시 필요, 가로/세로 방향 결정
- 중요한 이유: API 연동 실패 시 대안 필요, UI/UX 일관성 유지

### 5. 장수영 레이서 기획서 피드백 (아이돌 키우기 게임)

- 설명: 편의점 배경의 인랑 게임, 투표 시스템 기반
- 피드백 내용:
  - <b>정당한 승리 조건</b> 구현 필요
  - 동점자 판정 규칙을 단순하고 직관적으로
  - 아이온2의 슈고 페스타 사례: 유저들이 아예 게임을 시작하지 않아 전원 0점 사태 발생
- 중요한 이유: 판정 시비가 유저 이탈로 이어질 수 있음

### 6. 김남회 레이서 기획서 피드백 (2D 게임)

- 설명: 제페토 플랫폼에서 2D 게임 제작
- 피드백 내용:
  - 카메라 고정 시 아바타 리깅/외형 변형 가능성 염두
  - <b>플랫폼 사양 오버스펙</b>: RTX 2060은 너무 높은 사양, GTX 1050 수준으로 수정 필요
  - 제페토는 내장 그래픽으로도 구동 가능한 수준
  - 재미의 난이도를 제페토 유저 연령대(10\~20대)에 맞춰 조정
  - 2D와 3D의 괴리감 고려 (레트로 느낌으로 어필할지 결정)
- 중요한 이유: 사양 과다 명시 시 유저 진입 장벽 상승, 플랫폼 특성 고려 필요

### 예시와 활용 사례

- <b>예시 1: Pixyz 플러그인 활용</b>
  - 상황: 제페토에서 FBX 파일을 가져올 때 텍스처와 노멀맵을 별도로 작업해야 했던 문제
  - 설명: Pixyz를 사용하면 AutoCAD, 3DMAX, Maya, Blender에서 작업한 파일을 그대로 가져올 수 있음
  - 왜 이 예시를 사용했는지: 실무 개발자들에게 작업 효율을 높이는 신기술 소개
- <b>예시 2: 리니지2/와우의 추천 시스템</b>
  - 상황: 유저 간 평판을 가시화하는 시스템 필요
  - 설명: 캐릭터 이름 색깔이 하늘색 → 파란색으로 변하며, 추천을 많이 받을수록 신뢰도 상승
  - 왜 이 예시를 사용했는지: API 연동 없이도 유저 평판을 표현할 수 있는 대안 제시
- <b>예시 3: 아이온2 슈고 페스타 실패 사례</b>
  - 상황: 2천억 원을 들여 만든 미니게임인데 유저들이 아무도 시작하지 않음
  - 설명: 유저들이 "배신하지 말고 다 같이 1등 하자"며 단합해서 게임을 플레이하지 않음
  - 왜 이 예시를 사용했는지: 게임 기획 시 예상치 못한 유저 행동 패턴을 고려해야 함을 강조
- <b>예시 4: 당근마켓 온도 시스템</b>
  - 상황: 평판을 시각화하는 방법
  - 설명: 온도가 높을수록 신뢰도가 높아 거래가 원활함
  - 왜 이 예시를 사용했는지: 평판 시스템의 실생활 적용 사례

### 헷갈릴 수 있는 부분

- <b>헷갈리는 개념</b>: 권장사양 vs 최소사양
- <b>헷갈리는 이유</b>: 둘 다 게임 구동 가능 범위지만 명확한 구분이 필요
- <b>구분 방법</b>: 최소사양은 "게임이 켜지는" 수준, 권장사양은 "쾌적하게 플레이 가능한" 수준
- <b>헷갈리는 개념</b>: 세로 모드 vs 가로 모드 (모바일)
- <b>헷갈리는 이유</b>: 개발자 입장에서는 큰 차이가 없어 보일 수 있음
- <b>구분 방법</b>: 가로 모드는 화면이 넓어 몰입감이 높고, 세로 모드는 한 손 조작에 유리
- <b>헷갈리는 개념</b>: API 연동 vs 게임 내 자체 시스템
- <b>헷갈리는 이유</b>: 외부 API가 더 전문적으로 보이지만 구현 난이도가 높음
- <b>구분 방법</b>: 시간이 촉박하거나 기술적 어려움이 있다면 자체 시스템으로 대체 가능

### 주요 개념 정리

- <b>HDRP (High Definition Render Pipeline)</b>
  - 설명: Unity에서 고품질 실사 그래픽을 구현하기 위한 렌더링 파이프라인
  - 예시: 아이온2, 로스트아크2 같은 하이엔드 게임 제작 시 사용
  - 사용되는 상황: RTX 3060 이상의 고사양 그래픽카드를 가진 유저를 대상으로 할 때
  - 헷갈릴 수 있는 점: 모바일에서는 발열 문제로 5분 이상 플레이가 어렵고, GTX 1660 Super 같은 저사양에서는 레이트레이싱 기능이 작동하지 않음
- <b>URP (Universal Render Pipeline)</b>
  - 설명: 경량화된 렌더링 파이프라인으로, 카툰 그래픽이나 모바일 게임에 최적화
  - 예시: 제페토 같은 모바일 플랫폼 게임
  - 사용되는 상황: 저사양 기기나 모바일 게임 개발 시
  - 헷갈릴 수 있는 점: HDRP는 실사 그래픽용, URP는 카툰 그래픽용으로 구분

| 구분 | HDRP | URP |
| --- | --- | --- |
| 용도 | 고품질 실사 그래픽 | 경량화 카툰 그래픽 |
| 플랫폼 | PC (고사양) | 모바일/저사양 |
| 비유 | 벤츠 | 소나타 |

- <b>포스트 프로세싱 (Post Processing)</b>
  - 설명: 카메라 앞에 필터를 달아서 그래픽 효과를 주는 기술, 포토샵의 보정 효과와 유사
  - 예시: 안티앨리어싱, 모션 블러, 블룸, 반사 효과 등
  - 사용되는 상황: 오브젝트 자체에 그래픽 효과를 주기 어려울 때, 리소스를 절약하면서 시각 효과를 높이고 싶을 때
  - 헷갈릴 수 있는 점: HDRP/URP는 오브젝트에 직접 렌더링/쉐이딩을 적용하는 것이고, 포스트 프로세싱은 카메라 필터로 효과를 주는 것으로 완전히 다름
- <b>쉐이더 (Shader)</b>
  - 설명: 그래픽카드가 병렬 연산으로 복잡한 데이터를 독립적으로 처리하는 기술
  - 예시: 물 파도, 바다, 폭포 같은 반복적인 패턴이나 대규모 시뮬레이션
  - 사용되는 상황: 일정한 패턴이 아닌 자연스러운 효과가 필요할 때
  - 헷갈릴 수 있는 점: 데이터가 너무 많으면 병목현상 발생 가능
- <b>역학 애니메이션 (Procedural Animation)</b>
  - 설명: 실측 데이터를 기반으로 실시간 연산을 통해 애니메이션을 생성하는 기술
  - 예시: 롯데타워가 지진으로 무너지는 시뮬레이션, CCTV에서 걸음걸이로 사람 특정
  - 사용되는 상황: 건축 시뮬레이션, 사고 재현, 캐릭터의 걷기/뛰기 패턴 분석
  - 헷갈릴 수 있는 점: 그래픽 디자이너가 프로그래밍을 잘하면 매우 유리한 분야
- <b>반응형 애니메이션 (Reactive Animation)</b>
  - 설명: 총 맞은 부위, 칼 맞은 부위, 공격 각도에 따라 다른 애니메이션을 실행하는 기술
  - 예시: 레퀴엠의 PVP 시스템에서 각도, 무기, 캐릭터 스탯에 따라 다른 데미지와 애니메이션 적용
  - 사용되는 상황: PVP/PK 게임에서 전투의 현실감을 높일 때
  - 헷갈릴 수 있는 점: 뒤에서 맞았는데 뒤로 넘어지면 안 되는 등 방향 로직이 복잡함
- <b>Ragdoll (래그돌)</b>
  - 설명: 충격에 대한 실시간 반응을 물리엔진으로 구현한 애니메이션
  - 예시: GTA6에서 총 맞아 죽을 때의 리얼한 넘어짐 동작
  - 사용되는 상황: 캐릭터가 죽거나 넘어질 때 자연스러운 물리 반응이 필요할 때
  - 헷갈릴 수 있는 점: 각 리깅과 기본 아이들이 존재해야 생성 가능
- <b>NavMesh (내비메시)</b>
  - 설명: 폴리곤 단위로 경로를 인지하여 AI가 자동으로 목표 지점까지 이동하게 하는 시스템
  - 예시: 적이 플레이어를 쫓아오거나, 레이싱 게임의 Bot이 결승선까지 달리는 것
  - 사용되는 상황: AI 기반 NPC 이동, 적 추적, 자동 경로 탐색
  - 헷갈릴 수 있는 점: 옛날에는 C# 노가다로 프레임과 폴리곤 좌표를 일일이 코딩했지만, 지금은 NavMesh로 간편하게 구현 가능
- <b>강화학습 (Reinforcement Learning)</b>
  - 설명: AI가 개발자가 정한 패턴만 따르는 것이 아니라, 스스로 학습하여 가장 효율적인 행동을 선택하는 기술
  - 예시: 검은사막의 NPC가 자기 맘대로 퇴근 시간을 정하거나, 로스트아크의 NPC가 친밀도에 따라 다른 반응을 보이는 것
  - 사용되는 상황: Unity ML Agent Toolkit을 사용한 AI 강화학습 구현
  - 헷갈릴 수 있는 점: 기존 AI는 정해진 패턴만 따랐지만, 강화학습은 AI가 스스로 판단함
- <b>보안 기술 (Security)</b>
  - 설명: 클라이언트-서버 간 통신을 해킹하거나 위변조하는 것을 막기 위한 기술
  - 예시: Eclipse 같은 패킷 분석 프로그램으로 프리서버를 만드는 것 방지, 앰플가드/핵실드 같은 보안 프로그램
  - 사용되는 상황: 온라인 게임에서 DDoS, 클라이언트 위변조, 핵 사용 방지
  - 헷갈릴 수 있는 점: 마음먹고 해킹하면 막을 방법이 없지만, 법적으로 지켜야 할 의무는 방어해야 함
- <b>LOD (Level of Detail)</b>
  - 설명: 카메라 시점에 따라 멀리 있는 오브젝트는 폴리곤을 줄이고, 가까이 가면 다시 늘리는 최적화 기법
  - 예시: 검은사막에서 자체 엔진으로 구현한 거리별 렌더링 최적화
  - 사용되는 상황: 네트워크 게임에서 렌더링 부하를 줄이고 프레임을 안정화할 때
  - 헷갈릴 수 있는 점: 카메라에 안 보이는 것은 아예 렌더링하지 않음
- <b>오브젝트 풀링 (Object Pooling)</b>
  - 설명: 폭발, 물 효과, 폭포 같은 반복 생성 오브젝트를 미리 생성해두고 재사용하여 과부하를 줄이는 기법
  - 사용되는 상황: 대규모 파티클이나 반복 생성되는 오브젝트가 많을 때
  - 헷갈릴 수 있는 점: 프로그래밍 영역이라 현재 단계에서는 깊이 다루지 않음

### 수업 흐름별 정리

### 1. HDRP와 그래픽 기술 소개

- 설명: Unity의 HDRP 기술은 언리얼 엔진을 따라잡기 위해 도입된 고품질 렌더링 기술로, 물리 기반 렌더링(PBR), 레이트레이싱 등을 지원
- 예시: 광원, 쉐이더, 렌더링이 극강으로 구현되지만 PC 사양이 받쳐줘야 함
- 중요: HDRP는 RTX 3000번대 이상의 그래픽카드에서 레이트레이싱 기능을 사용할 수 있으며, 차이가 최대 10배까지 남

### 2. HDRP의 한계와 주의사항

- 설명: HDRP는 모바일에서 발열 문제가 심각하며, 저사양 유저는 프레임 드랍과 결손 현상 발생
- 예시: VR 성인 콘텐츠가 5분 이상 플레이 불가능하게 제작된 이유가 발열 때문
- 중요: 제페토 같은 게임에는 HDRP가 불필요하며, 사용자들이 고사양을 요구하지 않음

### 3. URP 소개

- 설명: URP는 경량형 렌더링 파이프라인으로, 카툰 그래픽과 모바일에 최적화
- 예시: 모바일 게임 출시 시 프로젝트를 URP로 시작하면 최적화에 유리하지만, 요즘 핸드폰은 사양이 좋아서 굳이 안 써도 됨
- 중요: HDRP를 벤츠로 비유하면 URP는 소나타 정도의 수준

### 4. 포스트 프로세싱

- 설명: 카메라 앞에 필터를 달아서 그래픽 효과를 주는 방식으로, 오브젝트 자체를 수정하지 않고도 시각 효과 향상 가능
- 예시: 안티앨리어싱, 모션 블러(마비노기 영웅전에서 많이 사용), 반사 효과
- 중요: URP/HDRP가 리소스 100을 잡아먹는다면, 포스트 프로세싱은 20% 정도만 사용하므로 효율적

### 5. 쉐이더와 렌더링

- 설명: 쉐이더는 그래픽카드가 병렬 연산으로 복잡한 데이터를 처리하는 기술로, 물 파도나 대규모 시뮬레이션에 사용
- 예시: OpenGL은 40년 된 엔진이지만 저사양에서 3D 게임을 가장 잘 구현함
- 중요: 데이터가 너무 많으면 병목현상 발생 가능

### 6. 애니메이션 블렌딩

- 설명: 노드 기준으로 캐릭터나 오브젝트의 애니메이션을 구현하는 방식
- 예시: 유니티에서 애니메이터 블렌드 트리를 사용한 애니메이션 전환
- 중요: 많이 만들어보는 방법밖에 없으며, 평생 해도 헷갈리므로 자주 쓰는 건 포스트잇으로 메모 추천

### 7. 역학 애니메이션

- 설명: 실측 데이터를 기반으로 시뮬레이션 연산을 통해 애니메이션을 생성하는 기술
- 예시: 롯데타워가 지진으로 무너지는 과정을 1만분의 1 축소 모델로 시뮬레이션
- 중요: 건축 분야에서 수요가 많으며, 3D 모델링과 프로그래밍을 모두 잘하면 매우 유리함

### 8. 반응형 애니메이션과 Ragdoll

- 설명: 총 맞은 부위, 칼 맞은 부위, 각도에 따라 다른 애니메이션을 실행하는 기술과 물리 기반 넘어짐 효과
- 예시: GTA6의 리얼한 죽음 장면, 레퀴엠의 PVP 데미지 차별화
- 중요: 충격에 대한 실시간 반응을 물리엔진으로 구현한 것이 Ragdoll

### 9. NavMesh와 AI

- 설명: 폴리곤 단위로 경로를 인지하여 AI가 자동으로 이동하는 시스템
- 예시: 적이 플레이어를 쫓아오거나, 레이싱 게임의 Bot이 결승선까지 달리는 것
- 중요: 옛날에는 C# 노가다로 프레임과 폴리곤 좌표를 일일이 작업했지만, 지금은 NavMesh로 간편하게 구현

### 10. 강화학습

- 설명: AI가 스스로 학습하여 가장 효율적인 행동을 선택하는 기술
- 예시: 검은사막의 NPC가 퇴근 시간을 자기 맘대로 정하거나, 로스트아크의 NPC가 친밀도에 따라 특별 아이템 제공
- 중요: Unity ML Agent Toolkit으로 강화학습 구현 가능

### 11. 보안 기술

- 설명: 클라이언트-서버 간 통신을 보호하기 위한 기술로, Eclipse 같은 패킷 분석 프로그램으로 프리서버 제작을 방지
- 예시: 믹스마스터는 앰프가드에 연간 6천만원을 지불하여 클라이언트 위변조와 핵 사용 방지
- 중요: 마음먹고 해킹하면 막을 방법은 없지만, 법적 의무는 지켜야 함

### 12. 네트워크 최적화

- 설명: 채팅 도배 방지, 분산 서버 기술, 네트워크 부하 감소 기법
- 예시: 롤에서 채팅 글자 수 제한과 반복 단어 금지로 서버 부하 방지
- 중요: Photon, Fusion 같은 Unity 네트워크 최적화 기법 활용

### 13. LOD와 렌더링 최적화

- 설명: 카메라 시점에 따라 멀리 있는 오브젝트는 폴리곤을 줄이고, 가까이 가면 다시 늘리는 기법
- 예시: 검은사막의 자체 엔진이 LOD 기법을 매우 잘 구현함
- 중요: 네트워크 지연을 최소화하고 프레임을 안정화할 수 있음

### 14. 서버-클라이언트 역할 분리

- 설명: 고스톱 게임에서 그림은 클라이언트에 저장하고, 패킷 신호만 서버에서 보내는 방식
- 예시: 승패 판정이나 데이터베이스 스키마는 무조건 서버에 보관하여 위변조 방지
- 중요: HTTPS 프로토콜 통일로 보안 표준 유지

### 15. 프로파일링과 메모리 최적화

- 설명: 렉이나 프레임 저하의 원인을 찾는 프로파일링 도구 활용
- 예시: 그래픽카드의 비디오 메모리(VRAM)를 활용하여 CPU 부하를 GPU로 분산
- 중요: 리소스 압축(JPG 방식)과 텍스처 최적화로 메모리 절약

### 16. 스크립트 최적화와 코루틴

- 설명: 코드를 최소화하고 싱글톤 패턴을 사용하여 연산 속도 향상
- 예시: 구구단을 3\~4줄로 짤 수 있는데 천 줄로 짜면 안 되는 것처럼, 코드가 길수록 연산 속도가 느려짐
- 중요: 반복 작업은 코루틴으로 타이밍 호출을 간소화
