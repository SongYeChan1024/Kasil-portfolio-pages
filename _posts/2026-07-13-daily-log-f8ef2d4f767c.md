## 진행한 작업

### 1. 다크 스피릿 순찰·추적 AI 재설계

- 에너미마다 자기 패트롤 루트와 활동 범위를 갖도록 구조를 정리했다.
- 순찰 포인트별 랜덤 배회 목적지를 NavMesh 위에서 선택하도록 변경했다.
- 추적 종료 후 공통 위치가 아니라 자기 루트에서 가장 가까운 포인트로 복귀하게 했다.
- 정상 추적 16m, 완충 구간 16m 초과 24m 이하, 강제 복귀 24m 초과로 추적 경계를 분리했다.
- 시야가 끊기거나 완충 구간에 들어오면 어그로가 단계적으로 감소하도록 수정했다.
- 강제 어그로가 자기 활동 반경 제한을 우회하지 못하게 했다.
- 다크 스피릿 청각 거리를 30으로 조정하고 장애물 판정을 통과한 가까운 에너미만 소음에 반응하도록 정리했다.

### 2. 스폰과 패트롤 루트 정합성 수정

- 외곽, 건물 내부, 로비 등 공간별 패트롤 루트를 분리했다.
- 각 스폰 포인트가 자기 영역의 패트롤 루트를 참조하도록 연결했다.
- 총 14개 에너미 스폰을 기준으로 스폰 위치와 패트롤 루트를 동기화했다.
- 외곽에 생성된 에너미가 건물 내부 루트로 진입하거나, 로비 에너미들이 같은 루트를 따라 뭉치는 현상을 줄였다.

### 3. 에너미 이동 애니메이션 방향 수정

- AI 목적지 방향 대신 NavMeshAgent의 실제 이동 벡터를 매 프레임 사용하도록 변경했다.
- 장애물 회피와 코너 이동 중에도 이동 방향과 스프라이트 방향이 일치하도록 했다.
- 왼쪽 이동 중 오른쪽을 보거나, 아래로 내려오면서 뒷모습이 출력되던 좌우·상하 방향값을 이미지 기준으로 보정했다.

### 4. 근접 전투 안정화

- 플레이어가 에너미 주위를 돌 때 잠깐 시야각 밖으로 나가더라도 근접 교전 상태를 유지하도록 했다.
- 최초 감지에는 기존 시야각을 적용하고, 교전 유지에는 근접 거리와 실제 장애물 여부를 사용했다.
- 공격 선딜 중 플레이어 방향을 제한된 회전 속도로 따라가도록 수정했다.
- 공격 시작 거리와 실제 피해 거리를 분리하고, 피해 직전에도 거리와 장애물을 다시 검사한다.

### 5. 게임 종료 후 후속 처리 차단

- 사망 또는 탈출 확정 시 PlayerStatus에 세션 종료 상태를 기록하도록 했다.
- 종료 이후 추가 TakeDamage 호출을 차단해 HP, 피격 애니메이션, 루시드 낙인, 시간 패널티가 다시 실행되지 않도록 했다.
- TimeLimitController가 종료 이벤트를 받으면 기본 시간 흐름과 외부 시간 패널티를 모두 중단하도록 했다.
- GameManager가 플레이타임과 결과 정산을 최초 종료 이벤트에서 한 번만 처리하도록 했다.
- 게임 종료 시 인벤토리, 상자, 툴팁을 강제로 닫고 이후 재오픈을 차단했다.
- 탈출 채널링 중 피격으로 탈출이 취소되는 기존 규칙은 유지했다.

### 6. 사망한 플레이어의 에너미 타겟 해제

- PlayerStatus에 CanBeTargeted 공통 판정을 추가했다.
- EnemyPerception이 사망하거나 탈출한 플레이어를 신규 감지 후보에서 제외하도록 했다.
- EnemyBrain이 무효 타겟의 어그로와 추적 기억을 제거하고 다른 생존 플레이어를 다시 탐색하도록 했다.
- EnemyCombat이 공격 선딜, 애니메이션, 돌진, 실제 피해 단계마다 타겟 상태를 다시 확인하도록 했다.
- 공격 중 타겟이 사망하면 남은 콤보를 취소하고 공격 상태와 NavMeshAgent를 정상 복구하도록 했다.

### 7. 코드 문서화 및 검증

- 신규 및 변경 로직에 역할과 수정 이유를 설명하는 주석을 추가했다.
- Unity 솔루션 빌드 결과 컴파일 오류 0개를 확인했다.
- 오늘 직접 수정한 12개 스크립트의 이전 전체 코드, 변경 설명, 현재 전체 코드를 비교 문서로 작성했다.

## 이슈 / 주의할 점

- 현재 OnEscapeRequest는 플레이어 ID가 없는 전역 세션 이벤트다. 실제 멀티플레이 전환 시에는 개별 플레이어 탈락과 전체 세션 종료 이벤트를 분리해야 한다.
- NavMesh 기반 순찰과 장애물 회피가 정상 작동하려면 레벨 디자인 씬의 NavMesh와 Wall 레이어 설정이 정확해야 한다.
- 프리팹 기본값뿐 아니라 씬에 저장된 직렬화 값과 스폰 포인트의 루트 참조도 함께 확인해야 한다.
- 코드 빌드는 통과했지만 실제 에너미 배치, 경계 거리, 공격 타이밍은 Unity 플레이 모드 회귀 테스트가 필요하다.

## 배운 점


입력을 끄는 것만으로 기능 실행이 완전히 중단되지는 않는다. 외부 이벤트나 다른 컴포넌트가 메서드를 직접 호출할 수 있으므로 TakeDamage, ApplyTimePenalty, OpenInventoryUI, 실제 공격 판정 같은 상태 변경 진입점에서도 종료 상태를 검사해야 한다.


- 추적과 복귀처럼 경계값 주변에서 상태가 반복될 수 있는 기능에는 완충 구간이 필요하다.
- 감지, 판단, 이동, 기억, 전투 책임을 분리하면 수정 범위를 좁히고 회귀 오류를 줄일 수 있다.
- CanBeTargeted처럼 공통 판정을 사용하면 감지에서는 죽은 플레이어를 제외했지만 공격에서는 계속 때리는 식의 기준 불일치를 방지할 수 있다.
- 프리팹과 씬 데이터는 코드와 별도로 직렬화되므로 수치 변경 시 양쪽 정합성을 확인해야 한다.
