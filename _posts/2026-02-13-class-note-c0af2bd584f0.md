## 📊 Draw Call이란?

Draw Call은 CPU가 GPU에게 "이 오브젝트를 화면에 그려라"라고 명령을 내리는 것을 의미합니다.

### ✔ Draw Call의 기본 구조

- <b>CPU:</b> 렌더링할 데이터를 준비하고 GPU에 명령을 전달
- <b>GPU:</b> CPU로부터 받은 명령에 따라 실제 렌더링 수행

### ✔ Draw Call이 많아지면 생기는 문제

오브젝트가 많아질수록 Draw Call 수가 증가하고, CPU가 GPU에 명령을 전달하는 과정에서 병목 현상(Bottleneck)이 발생할 수 있습니다.

- 프레임 드롭 발생
- 게임 성능 저하

### ✔ Draw Call 최적화 방법

- <b>Batching:</b> 여러 오브젝트를 하나의 Draw Call로 묶어서 처리
- <b>GPU Instancing:</b> 동일한 메시를 여러 번 그릴 때 효율적으로 처리
- <b>Occlusion Culling:</b> 카메라에 보이지 않는 오브젝트는 렌더링하지 않음
- <b>LOD (Level of Detail):</b> 거리에 따라 오브젝트의 디테일 수준 조절

## 📌 Built-in과 URP의 주요 차이점

### ✔ Draw Call 처리 방식

<b>Built-in Render Pipeline:</b>

- 광원 개수만큼 Draw Call이 발생
- 예: 광원 5개 = Draw Call 5번 발생
- 광원이 많아질수록 성능 저하가 심해짐

<b>Universal Render Pipeline (URP):</b>

- 여러 광원을 한 번의 Draw Call로 처리
- 예: 광원 5개여도 Draw Call 1번만 발생
- 성능 최적화에 유리

### ✔ URP를 사용하는 이유

- <b>성능 향상:</b> Draw Call 수를 크게 줄여 게임이 더 가볍고 빠르게 실행됨
- <b>모바일 최적화:</b> 모바일 플랫폼에서도 원활한 성능 제공
- <b>현대적인 렌더링:</b> 최신 렌더링 기법과 효율적인 리소스 관리

### ✔ 정리

Built-in은 광원마다 Draw Call이 발생하지만, URP는 여러 광원을 묶어서 처리하기 때문에 Draw Call이 적게 발생합니다. 이것이 URP를 사용하는 가장 큰 이유입니다.

## 🔄 CrossFade(크로스페이드)란?

CrossFade는 애니메이션 전환 시 이전 동작과 현재 동작을 부드럽게 섞어주는 기법입니다.

### ✔ CrossFade의 작동 원리

- <b>블렌딩(Blending):</b> 두 애니메이션을 동시에 재생하면서 가중치를 조절
- <b>전환 시간:</b> 지정된 시간 동안 이전 애니메이션에서 새 애니메이션으로 자연스럽게 전환
- <b>부드러운 움직임:</b> 애니메이션 간 끊김 없이 자연스러운 동작 구현

[System.Serializable] //Attribute 개발자가 적으면 컴파일할때 유니티에서 실행해준다.
                      //인스펙터에서 클래스를 보이게 만들어 줌
public class PlayerAnimationClips //애니메이션 동작 클립을 정리해서 모아둔 클래스
{
    public AnimationClip idle;
    //아이들 애니메이션 클립

    //앞으로 달리기 애니메이션 클립
    public AnimationClip RunB;
    //뒤로 달리기 애니메이션 클립
    public AnimationClip RunL;
    //왼쪽 달리기 애니메이션 클립
    public AnimationClip RunR;
    //오른쪽 달리기 애니메이션 클립
    public AnimationClip SprintF;
    //앞으로 전력질주 애니메이션 클립
}
public class PlayerCTRL : MonoBehaviour
//플레이어 움직임과 애니메이션을 제어하는 클래스
{
    public PlayerAnimationClips playerClips;
    //애니메이션 클립들을 모아둔 클래스 변수
    public Animation _animation;
    //애니메이션 컴포넌트 정의
    [SerializeField] private TPSInput input;
    //TPSInput 스크립트 변수

    //Transform 컴포넌트 변수
    public float moveSpeed = 6f;
    //플레이어 이동 속도
    public float rotSpeed = 60f;
    //플레이어 회전 속도

    {
        input = GetComponent<TPSInput>();

        _animation = GetComponent<Animation>();
        //Animation 컴포넌트 정의
    }


    void FixedUpdate() //고정프레임 물리적인 것을 구현 할 때, 정확한 시간안에 무언가를 구현할 때 사용한다.
                       //Update는 프레임마다 호출되지만,
                       //FixedUpdate는 일정한 시간 간격으로 호출된다.
                       //따라서 물리적인 움직임이나 애니메이션을 구현할 때는 FixedUpdate를 사용하는 것이 좋다.
    {
        Move();
        //플레이어 움직임 처리

    }

    private void Move()
    //플레이어 움직임 처리
    {
        if (input.moveDir != Vector3.zero)
        //움직임 입력이 있다면

            rb.MovePosition(rb.position + (tr.forward * input.moveDir.z + tr.right * input.moveDir.x)

            //이 두 벡터를 더하여 플레이어의 이동 방향을 계산한다.
            //그 후, moveSpeed와 Time.fixedDeltaTime을 곱하여 이동 거리를 계산하고,
            //현재 위치(rb.position)에 더하여 새로운 위치를 계산한다.
            //이렇게 하면 플레이어가 입력에 따라 부드럽게 이동하게 된다.
        }
    }

    private void Update()
    {
        Rotate();
        //플레이어 회전 처리
        UpdateAnimation();
        //애니메이션 처리
    }

    //플레이어 회전 처리를 함수로 묶은 것
    {
        float MouseX = input.lookDir.x;
        tr.Rotate(Vector3.up * MouseX * rotSpeed * Time.deltaTime);

    }

           //움직임 입력이 없다면

        if (input.moveDir.x > 0.1f)
           //오른쪽으로 움직임 입력이 있다면
        {
            _animation.CrossFade(playerClips.RunR.name, 0.2f);
            //오른쪽 달리기 애니메이션으로 0.2초 동안 부드럽게 전환
        }
        else if (input.moveDir.x < -0.1f)
            //왼쪽으로 움직임 입력이 있다면
        {
            _animation.CrossFade(playerClips.RunL.name, 0.2f);
            //왼쪽 달리기 애니메이션으로 0.2초 동안 부드럽게 전환
        }
        else
        {
            if (input.moveDir.z > 0.1f)
            //앞으로 움직임 입력이 있다면
            {
                _animation.CrossFade(playerClips.RunF.name, 0.2f);
                //앞으로 달리기 애니메이션으로 0.2초 동안 부드럽게 전환
            }
            else if (input.moveDir.z < -0.1f)
                  //뒤로 움직임 입력이 있다면
            {
                _animation.CrossFade(playerClips.RunB.name, 0.2f);
                //뒤로 달리기 애니메이션으로 0.2초 동안 부드럽게 전환
            }
        }
    }
}

### ✔ CrossFade vs Play의 차이

<b>Play():</b> 즉시 애니메이션을 전환 (끊김 발생 가능)

<b>CrossFade():</b> 지정된 시간 동안 부드럽게 전환 (자연스러운 움직임)

### ✔ 활용 상황

- Idle에서 Walk로 전환할 때
- Walk에서 Run으로 전환할 때
- 공격 동작에서 이동 동작으로 전환할 때

CrossFade를 사용하면 게임 캐릭터의 움직임이 훨씬 자연스럽고 부드러워집니다.

### LOD

LevelOfDetail

1.카메라가 시야에서 멀어지면 해상도를 낮추고 가까워지면  해상도를 높이는 기능

### ✔ LOD란?

<b>LOD (Level of Detail)</b>는 카메라와의 거리에 따라 오브젝트의 디테일을 조절하는 최적화 기법입니다.

### ✔ LOD의 작동 원리

- <b>거리 기반 품질 조절:</b> 카메라에서 가까운 오브젝트는 높은 품질로, 먼 오브젝트는 낮은 품질로 렌더링
- <b>여러 단계의 메시:</b> LOD0 (최고 품질) → LOD1 → LOD2 (최저 품질) 순으로 폴리곤 수를 줄인 메시를 준비
- <b>자동 전환:</b> 설정된 거리에 따라 자동으로 적절한 LOD 단계로 전환

### ✔ LOD의 장점

- 렌더링 부하 감소
- 프레임 레이트 향상
- Draw Call 최적화
- 먼 거리의 오브젝트에 불필요한 디테일 제거

### ✔ Physics Manager란?

물리엔진의 속성 결정

Physics Manager는 Unity에서 물리 엔진의 전역 설정을 관리하는 시스템입니다. Edit → Project Settings → Physics에서 접근할 수 있습니다.

### ✔ 주요 설정 항목

- <b>Gravity:</b> 중력 값 설정 (기본값: -9.81)
- <b>Default Material:</b> 물리 머티리얼이 없는 콜라이더의 기본 설정
- <b>Bounce Threshold:</b> 튕김 효과가 발생하는 최소 속도
- <b>Sleep Threshold:</b> Rigidbody가 휴면 상태로 전환되는 기준
- <b>Default Contact Offset:</b> 충돌 감지 거리
- <b>Queries Hit Triggers:</b> Raycast가 Trigger를 감지할지 여부

### ✔ Layer Collision Matrix

어떤 레이어끼리 충돌할지 설정하는 매트릭스입니다. 불필요한 충돌 연산을 줄여 성능을 최적화할 수 있습니다.

### ✔ 최적화 팁

- 불필요한 레이어 간 충돌 비활성화
- Fixed Timestep 조정으로 물리 연산 빈도 제어
- Sleep Threshold 값을 조정하여 정적인 오브젝트의 연산 줄이기

### ✔ 활용 예시

<b>Player 레이어와 Enemy 레이어 간 충돌만 활성화:</b> 총알은 적과만 충돌하도록 설정

<b>Gravity 조정:</b> 달 환경이나 우주 배경의 게임에서 중력 값 변경

### const 와 readonly 의 차이

<b>유니티(C#)에서 코딩을 하다 보면 “변하지 않는 값”을 만들 때 const와 readonly 사이에서 고민하게 되죠. </b>

<b>둘 다 값을 수정할 수 없게 만들지만, 값이 결정되는 시점과 사용 방식에서 큰 차이가 있습니다.</b>

<b>한마디로 요약하자면, const는 “태어날 때부터 정해진 운명”이고, </b>
