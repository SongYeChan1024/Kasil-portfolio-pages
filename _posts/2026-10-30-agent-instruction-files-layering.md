프로젝트가 늘면서 코딩 에이전트에게 주는 지침 파일도 저장소마다 하나씩 생겼다. Claude Code는 `CLAUDE.md`, Codex는 `AGENTS.md`를 읽는데, 둘을 번갈아 쓰다 보니 같은 규칙이 여기저기 조금씩 다르게 복사되어 있었다. 오늘 이 파일들을 한 구조로 정리하면서 두 도구가 지침을 **어디서, 어떤 순서로** 읽는지 공부한 내용을 남겨 둔다.

## 정리 전 상태

| 위치 | 읽는 도구 | 문제 |
| --- | --- | --- |
| `~/.codex/AGENTS.md` (전역) | Codex만 | 한국어 사용·외부 반영 전 확인 같은 공통 규칙이 여기에만 있음 |
| 저장소별 `CLAUDE.md` | Claude Code만 | 공통 규칙이 저장소마다 복사됨 |
| 일부 저장소의 `AGENTS.md` | Codex만 | `CLAUDE.md`만 있는 저장소에서는 Codex가 규칙을 못 읽음 |
| 작업 폴더 루트 | 없음 | 어떤 프로젝트가 어디 있는지 매번 다시 찾아야 함 |

규칙이 같은 내용인데 파일이 다르면, 한쪽만 고치고 다른 쪽은 잊어버린다. 실제로 한 저장소의 지침에는 다른 PC의 경로가 그대로 남아 있었다.

## 두 도구가 지침을 읽는 방식

정리하기 전에 각 도구의 읽기 규칙부터 확인했다. 이걸 모르면 파일을 어디에 둘지 정할 수 없다.

### Claude Code — `CLAUDE.md`

- **전역:** `~/.claude/CLAUDE.md` — 모든 프로젝트에서 읽는다.
- **실행 위치와 그 위:** 실행한 폴더부터 위로 올라가며 만나는 `CLAUDE.md`를 모두 읽는다. 그래서 `C:\GitHubProjects\After_Seconds`에서 실행하면 `C:\GitHubProjects\CLAUDE.md`도 함께 읽힌다.
- **가져오기:** 파일 안에 `@경로`를 쓰면 그 파일 내용을 끼워 넣는다. `@README.md`, `@~/.codex/AGENTS.md`처럼 쓸 수 있다.

### Codex — `AGENTS.md`

- **전역:** `~/.codex/AGENTS.md`.
- **프로젝트:** Git 저장소 루트부터 실행 폴더까지 내려오며 만나는 `AGENTS.md`를 이어 붙인다.
- **위로는 Git 루트에서 멈춘다.** 그래서 저장소 바깥 폴더(`C:\GitHubProjects`)의 `AGENTS.md`는 저장소 안에서 실행하면 읽지 않는다.
- **`@` 가져오기가 없다.** `CLAUDE.md`에 `@README.md`라고 써 둬도 Codex 입장에서는 그냥 글자일 뿐이다.

이 차이 두 가지(위로 올라가는 범위, `@` 지원 여부)가 구조를 정하는 기준이 됐다.

## 정리한 구조

```text
~/.codex/AGENTS.md            전역 공통 규칙 — 원본은 여기 하나
~/.claude/CLAUDE.md           └ "@~/.codex/AGENTS.md" 한 줄로 가져오기
C:\GitHubProjects\CLAUDE.md    작업 공간 지도 (프로젝트 목록 · 먼저 읽을 문서)
C:\GitHubProjects\AGENTS.md    └ "CLAUDE.md를 따른다"
<저장소>\CLAUDE.md             프로젝트 규칙 — 원본
<저장소>\AGENTS.md             └ "CLAUDE.md(와 README 등)를 먼저 읽는다"
```

원칙은 하나다. **규칙의 원본은 한 곳에만 두고, 나머지는 가리키기만 한다.**

### 1. 전역 규칙: Codex 파일을 원본으로

Codex는 `@` 가져오기를 못 하지만 Claude Code는 할 수 있다. 그래서 원본을 Codex 쪽(`~/.codex/AGENTS.md`)에 두고, Claude Code 전역 파일은 그걸 가져오기만 하게 했다.

```markdown
# 전역 지침 (Claude Code)

공통 규칙은 Codex와 같은 파일 하나로 관리합니다. 여기서 고치지 말고 아래 파일을 고칩니다.

@~/.codex/AGENTS.md
```

반대로 했다면(Claude 쪽이 원본) Codex는 그 파일을 가져올 방법이 없어서 내용을 복사해야 했을 것이다.

전역 규칙에 넣은 것은 **모든 프로젝트에 똑같이 적용되는 것**만이다.

- 한국어로 대화하고, 짧은 진행 안내도 한국어로 쓴다.
- push · PR · 외부 문서 수정 · 비용이 드는 생성은 대상과 내용을 먼저 보여 주고 확인받는다.
- 문서 작성자는 내 이름으로 적고 도구 이름을 적지 않는다.
- 이어서 작업할 때는 `git pull --ff-only` 후 인수인계 문서와 현재 코드를 확인한다. 과거 채팅을 현재 상태로 단정하지 않는다.
- "연결 설정이 있다"와 "실제로 연결됐다"를 구분해서 보고한다.

### 2. 작업 공간 지도: 루트 `CLAUDE.md`

이전에는 새 대화를 열 때마다 "어느 폴더가 무슨 프로젝트고, 인수인계 문서는 어디 있는지"를 다시 찾게 했다. 이걸 루트 파일 하나에 표로 적었다.

| 폴더 | 내용 | 기준 브랜치 | 먼저 읽을 것 |
| --- | --- | --- | --- |
| `After_Seconds` | 개인 · 1인칭 퍼즐 액션 | `main` | `CLAUDE.md` → 이어하기 문서 |
| `Project_DOB` | 4인 팀 프로젝트 | `main`은 PR로만 | `CLAUDE.md` → `README.md` |
| `Kasil_DevLog` | 이 블로그 | `main` push 시 배포 | `README.md` |
| … | | | |

Claude Code는 하위 저장소에서 실행해도 이 파일을 함께 읽으니, 어느 프로젝트에서 시작하든 전체 지도를 갖고 시작한다. Codex는 Git 루트에서 멈추기 때문에 루트에서 실행했을 때만 읽는다. 이 차이도 파일 안에 적어 두었다.

### 3. 저장소: `CLAUDE.md`가 원본, `AGENTS.md`는 안내판

저장소별 규칙은 이미 `CLAUDE.md`에 잘 정리되어 있었다. 그래서 `AGENTS.md`에는 내용을 복사하지 않고 한두 줄만 적었다.

```markdown
# Project_DOB — Codex 작업 안내

이 저장소의 작업 규칙은 CLAUDE.md와 팀 규칙의 기준인 README.md를 따릅니다.
작업 전에 두 문서를 읽습니다(CLAUDE.md의 `@` 가져오기는 Codex가 자동으로 읽지 않습니다).
```

여기서 놓치기 쉬운 점이 있다. `CLAUDE.md`가 `@README.md`, `@PROJECT_CONTEXT.md`처럼 **다른 파일을 가져오고 있으면**, Codex에게는 그 파일들도 직접 읽으라고 이름을 적어 줘야 한다. "CLAUDE.md를 따른다"만 쓰면 Codex는 정작 핵심 규칙이 담긴 README를 놓친다.

## 정리하면서 만난 함정

**커밋되지 않은 지침 파일이 pull을 막았다.** 한 저장소에서 `git pull`이 이렇게 멈췄다.

```text
error: The following untracked working tree files would be overwritten by merge:
	AGENTS.md
```

다른 PC에서 `AGENTS.md`를 새로 커밋해 올렸는데, 이 PC에도 커밋하지 않은 옛 버전이 있었던 것이다. 두 파일을 비교해 보니 원격이 더 새 버전(V0.04, 로컬은 V0.01)이었고, 로컬에만 있던 문장은 이미 다른 지침에 들어 있었다. 그래서 로컬 파일은 따로 백업하고 원격 버전을 받았다. **지침 파일도 코드처럼 바로 커밋해 두지 않으면 PC 사이에서 충돌한다.**

**같은 저장소를 가리키는 폴더가 둘이었다.** 블로그 저장소의 이름을 바꾸기 전에 만든 폴더와 바꾼 뒤에 만든 폴더가 둘 다 남아 있었다. 확인해 보니 하나가 다른 하나의 `git worktree`였다. worktree에서는 이미 다른 폴더가 체크아웃한 브랜치로 바꿀 수 없다.

```text
fatal: 'main' is already used by worktree at '.../Kasil-portfolio-pages'
```

이런 사정은 코드만 봐서는 알 수 없으니, 루트 지도에 "블로그는 `origin/main`에서 새 브랜치를 만들어 작업한다"고 적어 두었다.

**PC마다 다른 경로.** 학원 PC에서 쓴 지침에는 학원 PC의 사용자 폴더 경로가 박혀 있었다. 경로는 PC마다 다르니 두 경로를 함께 적고, 공통 안내를 따르게 바꿨다.

## 배운 것

- 지침 파일을 어디에 둘지는 **도구가 어디까지 올라가며 읽는지**로 정해진다. Claude Code는 실행 폴더 위로 계속 올라가고, Codex는 Git 루트에서 멈춘다.
- 원본을 한 곳에 두고 나머지는 가리키게 하면, 규칙을 바꿀 때 한 파일만 고치면 된다. `@` 가져오기를 지원하는 쪽이 지원하지 않는 쪽의 파일을 가져오게 하는 게 방향이다.
- 가리키기만 하는 파일에는 **실제로 읽어야 할 파일 이름**을 빠짐없이 적는다. 가져오기를 못 하는 도구는 링크를 따라가지 않는다.
- 팀 저장소는 예외다. 팀원도 같은 규칙을 봐야 하므로 공통 규칙이라도 저장소 안 README에 남겨 둔다.
- 지침도 코드처럼 버전 관리한다. 커밋하지 않은 지침은 다른 PC에서 만든 지침과 충돌한다.
