# 1. 퍼즐 목표

Episode 3-2는 음악 리듬(오디오 재생 시간)에 맞춰 <b>정답 발판을 판정 윈도우 안에서 밟는</b> 리듬 퍼즐 스테이지다.

- 플레이어에게 리듬 기반 입력 경험 제공
- 진행(점프/이동)과 시각 연출(점등/이펙트/장식)의 결합
- 점수/콤보/오답/미스 기반의 긴장감 형성
- Episode 3 전체 결과 집계(엔딩 판정) 구조와 연동

# 2. 퍼즐 진행 방법

## 2-1. 퍼즐 구성

- 겉보기에는 발판이 랜덤하게 배치되지만, 내부적으로는 <b>BeatMap(비트 이벤트) 데이터</b>를 기준으로 ‘해당 시점의 정답 발판’이 정해진다.
- 퍼즐은 비트(BeatEvent) 단위로 진행되며, 각 비트는 점등/판정 타이밍을 가진다.

BeatEvent(비트) 핵심 정보

- previewTime: 정답 표시(예고) 시작
- judgeTime: 실제 판정 시작
- judgeWindow: 판정 허용 범위
- endTime: 비트 종료
- targetPlatformIndex: 정답 발판 인덱스

진행 흐름(루프)

1. 퍼즐 시작 시 초기 비트 그룹/발판 그룹 생성
2. 오디오 재생 시작(오디오 시간 기준으로 비트 진행)
3. 현재 시간 기준으로 정답 발판 점등(필요 시 예고 점등 포함)
4. 플레이어가 발판을 밟으면 ‘밟음 이벤트’를 매니저로 전달
5. 판정 윈도우 안에서 정답 발판을 밟으면 정답 처리
6. 오답 발판을 밟으면 오답 처리, 입력 없이 윈도우 종료 시 미스 처리
7. 다음 비트 그룹 생성 및 오래된 그룹 제거(순환)
8. 모든 비트가 끝나면 퍼즐 종료 및 결과 보고

## 2-2. 플레이어 상호작용

- 플레이어는 점프/이동으로 발판을 선택해 밟는다.
- 발판은 충돌을 감지하고, 최종 판정은 매니저가 수행한다(역할 분리).
- 판정 결과는 점수/콤보/오답/미스 카운트 및 연출로 피드백된다.

# 3. 퍼즐 구성

## 3-1. 공간 구조

- 전방(Z축) 진행을 기준으로 “길”처럼 인지되는 흐름형 배치를 유지한다.
- 비트 그룹 단위로 발판이 순환 생성/제거되며, 플레이어 시야에 항상 일정량의 발판이 보이도록 유지한다.
  - 시작 시 초기 3개 비트 그룹 생성
  - 최대 5개 비트 그룹 유지
  - 새 비트 추가 시 가장 오래된 그룹부터 제거

## 3-2. 오브젝트 구성

- 발판(Platform)
  - 랜덤 생성 + 풀링 적용
  - 각 발판은 생성 후 정렬을 통해 <code>platformIndex</code>를 부여
- 정답 표시/성공 이펙트(Effect)
  - 표시 이펙트(정답 발판 가독성)
  - 성공 이펙트(보상 피드백)
- (선택) 장식 오브젝트(Deco)
  - 비트 그룹 주변에 랜덤 스폰 후, 해당 그룹 제거 시 함께 제거

## 3-3. 발판 생성/정답 지정 구조

핵심 원칙

- 발판은 랜덤이되, 판정은 데이터(BeatMap) 기반으로 명확해야 한다.

인덱스 재부여(중요)

- 발판 생성 후 <b>Z축 진행 순으로 정렬</b>
- 정렬 후 <code>platformIndex</code> 재부여
- BeatMap은 이 인덱스를 기준으로 정답 발판을 참조

도달 가능한 랜덤(플레이 가능 보장)

- 발판 간 거리는 플레이어 최대 점프 거리 이내
- 높이 차는 플레이어 최대 점프 높이 이내
- 조건 초과 시 배치 폐기/재생성

## 3-4. 퍼즐 판정 조건

판정 결과

- 정답(Success): 정답 발판을 판정 윈도우 안에서 밟음
- 오답(Wrong): 정답이 아닌 발판을 밟음
- 미스(Miss): 정답 발판을 밟지 못하고 윈도우 종료

중복 판정 방지(안정성)

- 퍼즐 전체: <code>hasJudgedCurrentBeat</code>
- 발판 단위: <code>wasJudgedThisBeat</code>

실패 조건(예시)

- Wrong + Miss 누적이 기준치를 넘으면 실패(초기 버전은 ‘누적 실패형’ 권장)

## 3-5. 퍼즐 완료 결과

- 퍼즐 종료 시 3-2 결과는 Episode 3 매니저에 보고된다.
  - 퍼즐 점수
  - 힌트 사용량
  - AI 상호작용 횟수
  - 수집 태그
  - 클리어 여부
- Episode 3 전체 결과 합산 및 진엔딩/노멀 엔딩 판정 조건에 반영된다.

# 4. 연출 요소

가독성/체감 핵심: ‘점등’과 ‘판정’을 분리한다.

- 예고 점등(previewTime): 플레이어가 미리 준비할 시간 제공
- 판정 시작(judgeTime) + 판정 허용(judgeWindow): 입력 판정

필요 연출

- 정답 발판 점등/예고 점멸
- 성공 시 발광 강화/파티클
- Wrong 시 붉은 반응/흔들림/꺼짐
- Miss 시 약한 소멸 연출
- 비정답 발판은 상대적으로 어둡게 유지

(선택) 장식 연출

- 비트 그룹 단위로 장식이 함께 생성/제거되어 ‘환경이 함께 살아 움직이는’ 느낌을 제공

# 5. 핵심 시스템 요약

- <b>BeatMap(비트 이벤트) 기반 정답 지정 + 오디오 시간 동기화</b>
- <b>비트 그룹 순환 스폰(초기 3개 / 최대 5개 유지)</b>
- <b>점등(연출)과 판정(게임플레이) 분리</b>
- <b>정답/오답/미스 판정 + 점수/콤보/카운트 관리</b>
- <b>중복 판정 방지 상태값(hasJudgedCurrentBeat/wasJudgedThisBeat)</b>
- <b>겹침 방지/생성 실패 방어(스킵/대체(fallback) 구조)</b>
- <b>이펙트/장식 오브젝트 풀링 기반 연출</b>
- <b>Episode 3 결과 집계 및 엔딩 판정과 연동</b>

# 6. 구현/연동 메모(업데이트)

## 6-1. 시스템 구성 요약

핵심 런타임 구성(현재 기준)

- RhythmPuzzleManager: 퍼즐 전체 진행 제어
- RhythmAudioManager: 오디오 재생 및 런타임 비트맵 생성
- PlatformSpawner: 발판 생성/배치/풀링 + 겹침 방지
- RhythmPlatform: 발판 단위 상태 + 밟힘 이벤트 전달
- (선택) RhythmBeatWindowManager: 비트 그룹 생성/유지/제거(프로젝트 구조에 따라 분리)
- (선택) RhythmScoreManager: 점수/콤보/오답/미스 관리(프로젝트 구조에 따라 분리)
- RhythmEffectManager: 정답/성공 이펙트 관리
- (선택) DecoRandomSpawn: 비트 연동 장식 스폰
- Ep3\_2Manager: 3-2 시작/종료, 결과 집계, 다음 씬 연결

## 6-2. 후속 작업 항목

- 팀 작업 맵 병합 이후 최종 동선 테스트
- 인스펙터 값 기준 난이도 밸런싱
- Easy/Normal/Hard 프리셋 분리 여부 확정
- 성공/실패 UI 또는 후속 연출 보강
- 장식 스폰 및 발판 배치의 시각적 밸런스 최종 조정
- (프로젝트 상황에 따라) 3-3 씬 병합/빌드 등록 및 씬 전환 임시 처리
