## 오늘의 목표

AI가 작성한 코드를 직접 이해하고 수정할 수 있도록 데이터 입력, 상태 소유, 호출 관계, 씬 간 상태 인계와 스킬 실행 순서를 실제 소스 기준으로 공부했습니다. 특히 빗자루 Q 연계의 공유 쿨타임과 다음 타격 대기 시간을 구분했습니다.

## 작업 내용

### 데이터 로드와 상태 소유

<code>DokkaebiGrowthDatabase.cs</code>에 Excel → 변환 도구 → JSON → Unity 데이터 조회 흐름, 조합 단계와 타격 데이터의 차이, 최초 로드·검증·실패 처리와 캐시 역할을 상세히 설명했습니다. 자료형과 C# 문법도 함께 풀어 썼습니다.

공통 수치는 데이터베이스, 개체별 성장·유대는 개체 성장 상태, 배치와 키 할당은 청사진 로드아웃, 현재 자원·체력은 각 상태 컴포넌트가 소유합니다. 연계 타수와 쿨타임은 <code>PrototypeSkillUseController</code>가 관리하며 연출 클래스가 피해나 쿨타임을 결정하지 않습니다.

### Q1 → Q2 → Q3 실행 순서

<code>PrototypeSkillUseController.cs</code>에 입력 처리부터 타격·연출 종료까지 상세 주석을 추가하고 실제 코드 순서대로 리뷰했습니다.

1. <code>GameplayInputReader</code>가 Q 입력을 0번 슬롯 요청으로 전달합니다. 입력 자체가 스킬 사용 승인은 아닙니다.
2. 컨트롤러가 슬롯 소유 개체, 연계 상태, 사용 가능 여부와 자원을 확인합니다.
3. Q1 사용이 승인되고 자원이 지불되면 개체별 공유 쿨타임과 다음 타격 대기 시간을 설정합니다.
4. 실행 중 일반 이동을 제어하고 돌진·타격 시점·피해 판정을 처리합니다. 시작·타격·종료 이벤트로 연출과 연결됩니다.
5. 이전 동작이 끝나면 다음 타격을 받을 상태로 넘어갑니다. Q2·Q3는 공유 쿨타임 때문에 막히지 않지만 실행 중 동작과 자원 조건은 확인합니다.
6. 마지막 타격이 승인되면 연계 상태는 초기화되지만 해당 타격의 동작은 계속 실행되고 공유 쿨타임은 유지됩니다.

기본 데이터 기준 공유 쿨타임은 Q1 승인 시점부터 10초입니다. Q2는 Q1 승인부터 6초, Q3는 Q2 승인부터 새로 6초 안에 이어야 합니다. 연계 만료는 연계 상태만 초기화하며 이미 시작한 공유 쿨타임을 지우지 않습니다.

동작 종료 직전 0.18초의 입력 버퍼는 다음 요청 하나를 보관하는 장치입니다. 버퍼 입력 순간이 아니라 실제 다음 타격 승인 시점에 연계 대기 시간이 갱신됩니다. 이 수치들은 기존 구현을 설명한 것이며 이번 작업에서 변경하지 않았습니다.

### 함께 주석을 보강한 연결 스크립트 12개

- 입력: <code>GameplayInputReader.cs</code>
- 아이템 정의·개체: <code>PartDefinition.cs</code>, <code>ActiveSkillDefinition.cs</code>
- 배치·키 할당·보유 파츠: <code>PrototypeBlueprintLoadout.cs</code>, <code>PrototypePartInventory.cs</code>
- 자원: <code>CoreResourcePool.cs</code>
- 스킬 실행·피해·반응: <code>PrototypeSkillExecution.cs</code>, <code>PrototypeDamageReceiver.cs</code>, <code>PrototypeHitData.cs</code>
- 이동: <code>PlayerNavMotor.cs</code>
- 연출: <code>PrototypeBroomSkillPresenter.cs</code>
- 씬 인계: <code>TutorialSessionTransfer.cs</code>

각 클래스의 역할, 상태 소유자, 호출 흐름과 문제 발생 시 확인할 위치를 설명했습니다. 전체 프로젝트의 모든 스크립트에 주석을 완료한 것은 아닙니다.

### 저장과 씬 간 상태 인계 구분

<code>TutorialSessionTransfer</code>는 실행 중 메모리로 상태를 다음 씬에 한 번 전달하는 구조이며 디스크 저장·로드가 아닙니다. 인벤토리 → 배치 → 키 할당 순서와 자원·체력·내구도 복원을 설명했습니다. 현재 스킬 쿨타임과 연계 타이머는 이 스냅샷으로 전달하지 않습니다.
