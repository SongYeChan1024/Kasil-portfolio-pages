인벤토리와 인게임 메뉴가 중첩된 상태에서 X·ESC 입력, 관제실 씬 전환 또는 외부 프로그램으로 포커스 이동 후 게임으로 복귀

</td>

① 인게임 진입 → ② Tab으로 인벤토리 출력 → ③ ESC로 인게임 메뉴 출력 → ④ 관제실로 돌아가기 → ⑤ 관제실에 남은 UI 확인 → ⑥ 다시 인게임에 진입해 동일 과정 반복
</td>

</td>

</td>
</tr>
<tr>
<td>
기대 결과
</td>
<td>
씬 전환 시 인게임 전용 팝업이 모두 닫혀야 한다. X와 ESC 입력은 현재 최상위 팝업만 닫아야 하며 HP·MP·퀵슬롯 등 기본 GamePlayUI는 유지되어야 한다.
</td>
</tr>
<tr>
<td>
실제 결과
</td>
<td>
관제실 복귀 후 설정 팝업이 남거나 인벤토리가 열린 상태로 관제실에 진입한다. X 버튼을 누르면 인게임 메뉴가 닫히지 않고 설정 팝업이 열리며, 특정 순서로 ESC를 입력하면 인게임 전체 UI가 비활성화된다.
</td>
</tr>
<tr>
<td>
영향 범위
</td>
<td>
인게임 HUD 확인 불가, 팝업 조작 불가, 관제실과 인게임 사이 UI 상태 오염, 정상적인 테스트 진행 방해
</td>
</tr>
<tr>
<td>
원인
</td>
<td>
HUD인 GamePlayUI까지 팝업 스택에 포함되어 반복 ESC 입력 시 함께 닫힐 수 있었으며, 인벤토리·게임 메뉴·튜토리얼이 동일한 입력 차단 상태를 독립적으로 변경해 다른 시스템의 차단을 해제할 수 있었다. 씬 전환 시 인게임 전용 UI와 입력 상태를 정리하는 처리도 부족했다.
</td>
</tr>
<tr>
<td>
수정 내용
</td>
<td>
GamePlayUI를 루트 UI로 분리하고 튜토리얼과 게임 메뉴의 입력 차단 소유권을 구분했다. ESC 메뉴가 열리면 시간은 유지하되 플레이 입력과 하위 UI Raycast를 차단하도록 변경했다. 인벤토리가 열려 있으면 ESC로 인벤토리를 먼저 닫고, 씬 전환 시 인게임 UI·스택·입력 상태를 일괄 초기화하도록 보강했다.
</td>
</tr>
