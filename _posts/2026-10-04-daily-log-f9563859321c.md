## 데일리로그 요약

### 오늘의 목표

동굴 전체의 이동 길을 읽기 쉽게 만들고, 초가집 앞 언월도 보스와 실제 전투 흐름을 연결합니다. 전개된 코어와 빗자루를 지켜야 하는 대상으로 만들며, 환경용 도깨비불과 청사진 회수·재설치의 피드백을 보강합니다.

### 완료한 작업

- 동굴 입구부터 코어·후속 연습 구간까지 환경 외형을 확장하고 암벽에 가려진 통로를 보정했습니다.
- 별도 초가집 보스존과 언월도 도깨비 이미지, 전조·체력 UI, 씬 이동과 상태 인계를 구성했습니다.
- 일반 근접 적과 보스의 상태 머신, 전조와 실제 피해 판정, 처치·패배·재도전 흐름을 연결했습니다.
- 전개 코어의 피격·파괴·자원 생성 중단과 내구도 바·피격 점멸·피해 숫자를 연결했습니다.
- 환경용 도깨비불을 눈 없는 푸른 불꽃과 광원으로 분리하고, 넓어진 부유·좌우 이동·소멸·랜덤 재등장을 구현했습니다.
- 필드에 전개된 빗자루에 내구도와 적·보스 피격을 연결했습니다.
- Tab의 역전개 버튼으로 회수 후 이동하여 재설치할 수 있도록 흐름을 다듬었습니다.

### 주요 결정

- 환경 도깨비불에는 눈을 넣지 않습니다. 물건에 깃든 개체용 귀여운 도깨비불과 구분합니다.
- 장식의 이동판정 제외는 태그 이름만으로 처리하지 않습니다. Collider/NavMeshObstacle이 없는 시각물과 Ignore Raycast 레이어를 사용합니다.
- 스킬 때 잠깐 나타나는 빗자루는 연출 전용입니다. 내구도와 적의 피격 대상 등록은 실제 설치된 파츠에만 적용합니다.
- 일반 회수·재설치는 수리가 아닙니다. 편성·스킬 배정·자원·남은 내구도를 보존합니다.
- 체크포인트 재도전의 복구는 튜토리얼 테스트용 예외입니다. 최종 허브 복구·영구 사망 규칙을 대체하지 않습니다.

## 일일개발일지

### 1. 동굴 전체 외형과 통로 가림

기존 굴곡 바닥·충돌·NavMesh의 윤곽을 유지하면서 입구 이후 구간까지 암벽과 바닥 외형을 연결했습니다. 카메라에서 암벽 이미지가 이동 바닥을 덮는 문제는 동굴 단면과 바닥 투영을 이용하는 통로 노출 재질로 보정했습니다. 장식만 보정하며 이동용 Collider/NavMesh와 사용자 맵 배치를 임의로 다시 저장하지 않습니다.

통로 검사는 13개 시점에서 가려진 바닥 샘플 291개가 다시 보이는 것을 확인했습니다. 이는 모든 카메라 각도에서 가림 문제가 없다는 최종 승인을 뜻하지 않습니다.

### 2. 초가집 앞 언월도 보스존

별도 씬 Tutorial\_Stage02\_Woldo에 초가집 이미지, 언월도 병사형 도깨비 이미지, 동굴 경계와 전투 공동, 보스 체력·목표·재도전 UI를 구성했습니다. 초가집의 점유 면적은 이동 경로에서 제외했습니다.

첫 맵 끝 푸른 표식의 G 상호작용으로 보스 씬으로 이동하는 경로를 연결했습니다. 장비, 같은 옵션의 파츠 인스턴스, 청사진 편성, 스킬 할당, 플레이어 체력, 코어 에너지와 남은 코어 내구도를 인계합니다. 보스 씬을 직접 열었을 때만 검·빗자루·코어와 테스트 에너지 50을 준비합니다. 정상 이동의 자원을 50으로 초기화하지 않습니다.

현재 첫 맵의 코어 이후 연습 전투와 끝 표식은 유지됩니다. 처음 구상한 ‘코어 획득 직후 즉시 보스존 이동’으로 학습 구간을 모두 제거한 것은 아닙니다.

### 3. 몬스터 AI와 전투 흐름

일반 근접 적은 대기 → 발견·추격 → 전조 → 타격 → 후딜을 기본으로, 경직·귀환·처치 상태를 분리했습니다. 장애물 시야, NavMesh 경로, 추격 한계와 메뉴/패배 입력 차단을 연결했습니다. 코어 학습 구간의 적은 보이는 전개 코어를 우선 목표로 삼습니다.

보스는 접근 후 추격 → 전조 → 타격 → 빈틈을 반복하며 횡베기·내려찍기·돌진 세 패턴을 순환합니다. 전조 때 방향을 고정하고 같은 기하 규칙으로 피해를 판정하며 한 공격에서 같은 대상이 반복 피격되지 않게 합니다. 체력 단계에 따라 일부 전조·후딜이 줄고 2단계 이상 돌진은 설치 코어를 겨냥할 수 있습니다. 군진·영혼 사슬 등 기획서의 모든 최종 패턴을 구현한 것은 아닙니다.

보스 처치 후 결박핵 G 정화까지 연결했습니다. 플레이어 패배 시 공격·이동·메뉴를 정리하고 재도전 시 입장 체크포인트를 복원합니다. 이후 본편 이동과 완성된 시네마틱은 아직 아닙니다.

### 4. 코어 피격과 직관적인 내구도 표시

전개된 코어를 실제 피해 대상으로 등록했습니다. 일반 적과 보스의 공격 범위에 포함되면 내구도가 줄어들고, 0이면 자원 생성과 가용 상태가 중단됩니다.

월드 내구도 바, 숫자, 감소 잔상, 붉은 피격 점멸과 피해 숫자를 추가했습니다. 파괴 상태도 표시합니다. 원래 손상된 코어를 회수했다 다시 전개해도 자동 수리되지 않게 기존 내구도를 유지합니다.

### 5. 환경 도깨비불

눈 없는 투명 불꽃 이미지, 실제 Point Light, 가산광 번짐과 바닥광을 분리했습니다. 동굴 11개와 보스존 5개 환경 불빛에 적용하며 물건 도깨비 이미지와 원본은 보존했습니다.

현재 튜닝값은 위아래 진폭 0.55m, 좌우 진폭 1.1m, 재등장 중심 반경 2.2m입니다. 6\~10초간 보이며 0.9초 페이드, 1\~2.5초 소멸 후 주변 위치에서 다시 밝아집니다. 모두 프로토타입 가안이며 물건·전투 수치가 아닙니다.

재등장 후보는 바닥과 장애물을 검사하고 각 불빛의 주기는 분산합니다. 불꽃·광원·빛 번짐이 함께 사라지며 장식용 난수는 Unity의 아이템 드롭 난수와 분리했습니다. 조명 자체에는 이동을 막는 Collider나 NavMeshObstacle을 만들지 않았습니다.

### 6. 빗자루 피격과 내구도 보존

실제로 전개된 빗자루에 PrototypeDeployedPartTarget을 붙여 소유자와 실제 PartInstanceData를 연결했습니다. 일반 적·보스의 타격 범위에 들어오면 한 공격당 한 번 피해를 받습니다. 적이 빗자루를 별도 우선 추격하는 어그로 시스템까지 추가한 것은 아닙니다.

아이템의 CurrentDurability에 손상을 기록하고 내구도 바·피해 숫자를 표시합니다. 파손되면 콜라이더를 끄고 스킬을 사용하지 못하게 하며, 시전 중 파손되어도 실제 피해는 발생하지 않습니다. 미리보기와 일시적인 스킬 빗자루는 피해 대상에서 제외합니다.

일반 회수로 내구도가 회복되지 않습니다. 전투 패배 후 재도전할 때만 체크포인트 진입 시 내구도로 복원합니다. 별도의 수리·복구 메뉴는 아직 구현하지 않았습니다.

### 7. 역전개와 다른 위치 재설치

사용 흐름: Tab → ‘역전개 · 청사진 회수’ → 우클릭으로 이동 → 좌클릭 재설치.

수동 회수는 코어와 빗자루의 월드 설치·피격 대상을 함께 정리하고 전개 미리보기는 열린 상태로 유지합니다. 편성, 스킬 배정, 에너지, 남은 내구도는 유지합니다. 전개 중심에서 수평 거리 12m를 넘으면 기존 자동 회수를 사용하며 이때는 미리보기도 닫습니다.

버튼 문구를 역전개로 명확히 하고 실제 EventSystem 레이캐스트로 다른 HUD가 클릭을 가리지 않는지 검사했습니다. 설치 외곽선이 생성 첫 프레임에 굵은 흰 선으로 보이는 초기값도 보정했습니다.

## 검증 결과와 한계

검증은 사용자 편집 씬과 분리된 Unity 6000.3.7f1 프로젝트에서 진행했습니다.

- 동굴 통로 노출: 67개 검사, 13개 시점·가려진 바닥 샘플 291개 복원.
- 저장 굴곡 맵 진행 회귀: 54개 검사. 장비·처치·빗자루·코어 진행 API 확인.
- 일반 근접 AI: 55개 검사.
- 최종 후속 실행: 부유·빗자루 피격·역전개 42개, 코어 피드백 회귀 36개, 보스 회귀 67개, 환경 불꽃 77개 통과.
- 마지막 네 모듈의 검사 수 합계는 222개입니다. 중복되는 모듈·단계가 있으므로 독립 기능 222개 또는 실제 입력으로 완주한 통합 QA 222개로 해석하지 않습니다.
- 회수 버튼의 실제 UI 레이캐스트, 회수·재설치, 일반 적·보스의 빗자루 타격, 파손 스킬 차단, 거리 자동 회수와 체크포인트 복구를 검사했습니다.
- 마지막 후속 작업에서는 두 저장 씬의 해시가 그대로인 것을 확인했습니다. 열어 둔 사용자 Unity 씬의 미저장 편집 상태를 저장·재조립하지 않았습니다.
