## 요약

### 애니메이션 시스템 복습

- 애니메이션은 정적인 객체에 시간축에 따라 연속적인 움직임을 부여하여 살아있는 것처럼 보이게 만드는 기술 
- <b>키프레임과 인터폴레이션(보간)</b>: 부드러운 애니메이션을 위해 프레임 간 값을 계산하여 연속적인 움직임 표현  
  - Lerp (Linear Interpolation): 선형 보간 방식 
  - Slerp (Spherical Linear Interpolation): 회전 시 사용하는 구면 선형 보간, Quaternion과 함께 사용  

### Legacy vs Mecanim 애니메이션 비교

<b>Legacy Animation</b> 

- 초기 Unity에서 사용하던 방식으로 Animation 컴포넌트 사용
- 단점: 다른 캐릭터의 애니메이션 클립을 가져올 수 없고 유연성이 부족함
- 애니메이션 간 전환 개념이 없어 재생 중단 후 새로 시작해야 함 
- 간단한 애니메이션에는 여전히 사용 가능 

<b>Mecanim Animation</b> 

- 현재 Unity에서 주로 사용하는 방식
- Animation Controller를 통해 조건과 파라미터에 따라 애니메이션 전환 가능 
- FSM (Finite State Machine, 유한상태머신) 기반으로 동작  
- 장점: 상태 전환 관리가 용이하고 자동 전환 지원 
- 단점: 트랜지션이 많아지면 복잡해지고 가독성이 떨어질 수 있음 

### Mecanim 주요 컴포넌트

<b>Animation Clip</b> 

- 가장 작은 단위의 애니메이션 (걷기, 달리기, 공격 등)
- Loop Time: 반복 동작 설정 (Walk, Run, Attack은 체크, Die는 체크 해제) 
- Root Transform 설정으로 애니메이션 위치와 방향 조절 가능 

<b>Animation Controller</b> 

- 노드 기반으로 상태와 전환을 시각적으로 구성
- Entry: 시작점
- Any State: 어느 상태에서든 전환 가능
- Exit Time: 전환 시 대기 시간 설정 

<b>Animator Component</b> 

- 게임 오브젝트에 추가되어 애니메이션 실행
- Avatar: 본(Bone) 데이터를 담고 있는 리깅 정보  
- Apply Root Motion: 체크 시 캐릭터의 위치와 회전을 애니메이션이 제어, 해제 시 스크립트로 제어  
- Update Mode: Normal (Update), Animate Physics (FixedUpdate), Unscaled Time (타임스케일 무시)  
- Culling Mode: 애니메이션 계산 최적화 관련 설정  

### 아바타 시스템

<b>Humanoid Avatar</b> 

- 인간형 캐릭터를 위한 아바타 (2족 보행)
- 휴머노이드 캐릭터 간 애니메이션 공유 가능 (리타게팅) 
- 단, 뼈 구조가 어느 정도 일치해야 함 
- T-Pose: 양팔을 수평으로 벌린 기본 자세, Unity 표준  
- A-Pose: 양팔을 내린 자세, 관절 왜곡 최소화에 유리  

<b>Generic Avatar</b> 

- 비인간형 캐릭터 (4족 보행, 동물, 로봇 등)
- 특정 캐릭터의 독특한 뼈대 구조에 맞게 애니메이션 설정 
- 캐릭터 간 애니메이션 공유 불가능 

<b>리타게팅 (Retargeting)</b> 

- 하나의 캐릭터에서 제작된 애니메이션을 다른 캐릭터에서 재사용하는 기능
- 작업 시간과 비용 절감 
- 캐릭터의 신체 비율이 달라도 자동으로 조절됨  
- Mecanim 개발자가 만든 기능 

<b>Avatar 설정</b> 

- Model 클릭 후 Rig 탭에서 Humanoid 선택 및 Apply
- Configure 버튼으로 본 매핑 상태 확인 가능 
- 초록색 원: 필수 본, 성공적으로 매핑됨 
- 빨간색 원: 매핑 실패 
- Optimize Game Object: 체크 시 장착한 무기만 표시하여 최적화 (적이 여러 마리일 때 성능 향상)  

### 데이터 저장 및 불러오기 (Data Save/Load)

<b>저장 방식</b> 

- 파일에 기록하는 방식 (로컬 저장 - 하드디스크/SSD)
- 별도의 데이터 서버에 저장하는 방식 (원격 저장) 

<b>PlayerPrefs 방식</b>  

- Unity에서 제공하는 가장 간편한 데이터 관리 클래스
- int, float, string, bool 타입 저장 가능
- 주요 함수:
  - <code>SetInt()</code>, <code>SetFloat()</code>, <code>SetString()</code>: 키-값 쌍으로 데이터 저장  
  - <code>GetInt()</code>, <code>GetFloat()</code>, <code>GetString()</code>: 저장된 값 불러오기  
  - <code>HasKey()</code>: 키 존재 여부 확인
  - <code>DeleteKey()</code>, <code>DeleteAll()</code>: 키 삭제
  - <code>Save()</code>: 변경사항을 물리적 공간에 저장

<b>단점 및 주의사항</b> 

- 보안에 매우 취약 - 데이터가 암호화되지 않음
- 사용자가 값을 직접 수정 가능
- 복잡한 구조의 데이터(클래스, 리스트 등) 저장 어려움
- 중요한 데이터는 암호화하거나 JSON 파일 저장 방식 사용 권장 
- 싱글 게임의 로컬 저장에 적합 

<b>실습 예제: 킬 카운터 구현</b> 

- UI Panel과 Text로 킬 수 표시 화면 구성  
- GameManager에서 킬 카운트 관리
- <code>LoadGameData()</code>: PlayerPrefs.GetInt("Kill\_Count", 0)로 저장된 킬 수 불러오기  
- <code>IncreaseKillCount()</code>: 적 처치 시 킬 수 증가 및 PlayerPrefs.SetInt()로 저장 
- 적이 죽을 때 Enemy AI에서 GameManager.Instance.IncreaseKillCount() 호출  
- Unity 종료 후 재시작해도 킬 수가 유지됨 

### 향후 학습 예정

<summary>스크립트 구현</summary>

```cs
using System.Collections;
using System.Collections.Generic;
using UnityEngine;
using System.IO; //파일 입출력 관련 네임스페이스
using System.Runtime.Serialization.Formatters.Binary; //바이너리 포멧터 관련 네임스페이스
using DataInfo; //GameData, Item 클래스가 포함된 네임스페이스

public class DataManager : MonoBehaviour
{
    [SerializeField] private string dataPath; //데이터가 저장되는 파일 경로
    public void Initialize() //데이터 매니저 초기화 메서드
    {
        dataPath = Application.persistentDataPath + "/gameData.dat"; //데이터 파일 경로 설정
        //Application.persistentDataPath 는 Unity 에서 제공하는 경로로,
        //어플리케이션의 데이터를 저장 할 수 있는 위치.
        //공용 폴더에 저장됨.
    }
    public void Save(GameData gameData) // 게임 데이터를 저장하는 메서드
    {
        BinaryFormatter bf = new BinaryFormatter(); //바이너리 포멧터 객체 생성

        FileStream file = File.Create(dataPath); //물결 혹은 물길 지정된 경로에 파일로 저장하거나 그 파일을 불러올 때 왔다갔다 하는 경로를 Stream 이라고 한다.
        //파일 스트림 생성, 지정된 경로에 파일 생성
        
        GameData data = new GameData(); //파일에 저장할 클래스에 데이터 할당
        data.killCount = gameData.killCount;
        data.hp = gameData.hp;
        data.speed = gameData.speed;
        data.equipItem = gameData.equipItem;
        //어떤 아이템이 장착되어 있는지 저장

        bf.Serialize(file, data);
        //파일에 데이터를 직렬화 하여 저장
        //float, int, List<item> 등 다양한 타입의 데이터를
        //binary(byte)형식으로 변환하여 저장 할 수 있음.
        file.Close(); //파일 스트림 닫기
    }
    public GameData Load() 
    {
        if (File.Exists(dataPath)) //지정한 경로에 파일이 존재하는지 확인
        {
            BinaryFormatter bf = new BinaryFormatter(); //바이너리 포맷터 객체 생성
            FileStream file = File.Open(dataPath, FileMode.Open); //파일스트림 열기
            GameData data = (GameData)bf.Deserialize(file);
            //파일에서 데이터를 역직렬화 하여 GameData 객체로 변환
            file.Close(); //파일 스트림 닫기
            //로드된 데이터를 사용하여 게임 상태를 복원하는 로직을 여기에 추가 할 수 있음
            return data; // 로드된 GameData 객체 반환
        }
        else
        {
            GameData data = new GameData(); //파일이 존재하지 않는 경우, 기본값을 가진 GameData 객체를 반환
            return data; //새로운 게임을 시작할 때 기본값으로 사용할 수 있음
        }
    }
}

```

<summary>1\.  Player Preference 방식 (PlayerPrefs)</summary>

PlayerPrefs를 활용 한 데이터 저장

PlayerPrefs 클래스는 유니티에서 가장 간편히 사용할 수 있는 데이터 관리 클래스이다.

PlayerPrefs 클래스는 int, float, string bool 타입의 변수를 저장하고 로드하는 기능을 제공한다.

PlayerPrefs 클래스 에는 다음 함수들 이 있다.

1. DeleteAll() : 모든 키 값을 삭제
2. DeleteKey() : 특정 키 값을 삭제
3. GetFloat() : 지정 한 float타입의 키 값을 로드한다.
4. GetInt() :  지정한 int타입의 키 값을 로드한다.
5. GetString() :  지정한 string타입의 키 값을 로드한다.
6. HasKey() : 해당 키가 존재하는 여부를 반환한다.
7. Save() : 변경 된 모든 키 값을 물리적인 공간에 저장한다.
8. SetFloat() : 지정한 키로 float타입의 값을 저장한다.
9. SetInt() : 지정한 키로 int타입의 값을 저장한다.
10. SetString() : 지정한 키로 string타입의 값을 저장한다.

</details>

<b>Unity 데이터 관리: Binary 파일 저장 방식</b> 2026-02-27

## 요약

### PlayerPreferences 기능 복습

- <code>DeleteKey</code> 메서드를 사용하여 특정 키값 삭제 가능   
- <code>DeleteAll</code> 메서드로 저장된 모든 데이터 삭제 가능 (게임 종료 시 사용)  
- <code>SetInt</code>, <code>GetInt</code>, <code>GetFloat</code>, <code>GetString</code> 등의 메서드로 데이터 관리 
- <code>HasKey</code> 메서드로 해당 키 존재 여부 확인 가능 
- PlayerPreferences는 Unity에서 제공하는 가장 간편한 데이터 관리 클래스 

### Binary 파일 저장 방식 개념

- 두 번째 데이터 저장 방식으로 Binary(이진 데이터) 파일 저장 소개   
- 하드디스크(SSD)에 물리적으로 저장되는 방식   
- 데이터를 0과 1(이진 데이터) 형태로 변환하여 저장  
- 이미지, 사운드, 동영상 등 바이너리 데이터 처리에 활용 
- PlayerPreferences보다 복잡하지만 더 전문적인 방식  

### 직렬화(Serialization)와 역직렬화(Deserialization)

- <b>직렬화</b>: int, float, string 등의 자료형을 byte 단위로 변환하여 저장하거나 전송하는 과정    
  - 하드디스크 공간에 물리적으로 저장하기 위해 필요 
  - 서버와 데이터 통신 시 byte 단위로 재배열하여 전송  
- <b>역직렬화</b>: byte 형태의 데이터를 다시 int, float, string 등으로 변환하는 과정    
  - 하드디스크에서 데이터 로드 시 사용  
  - 서버에서 클라이언트로 데이터 전송 시 사용  

### 데이터 관리 흐름

- <b>Initialize()</b>: 저장 경로(dataPath)와 파일명 지정  
  - <code>Application.persistentDataPath</code> 사용하여 플랫폼에 맞는 안전한 저장 위치 설정  
  - PC, Android, iOS에서 공용 폴더에 저장  
- <b>Save()</b>: 게임 데이터를 직렬화하여 파일로 저장  
- <b>Load()</b>: 저장된 파일을 역직렬화하여 데이터 복원  

### GameData 및 Item 클래스 구조

- <code>GameData</code> 클래스 생성 (MonoBehaviour 상속 제거)   
  - <code>namespace DataInfo</code> 안에 관련 클래스들 그룹화   
  - <code>[System.Serializable]</code> 속성으로 직렬화 가능하도록 설정  
  - 변수: <code>killCount</code>, <code>hp</code>, <code>damage</code>, <code>speed</code>  
  - <code>List&lt;Item&gt; equipItem</code>으로 장착한 아이템 관리  
- <code>Item</code> 클래스 구조  
  - <code>ItemType</code> enum: HP, Speed, Grenade, Damage   
  - <code>ItemCalc</code> enum: Value, Percent (아이템 계산 방식)  
  - 변수: <code>itemType</code>, <code>itemCalc</code>, <code>itemName</code>, <code>itemDesc</code>, <code>itemValue</code>   

### ItemInfo 및 아이템 데이터 설정

- 각 아이템 슬롯에 <code>ItemInfo</code> 컴포넌트 추가  
- 아이템별 데이터 설정:
  - <b>Item HP</b>: HP 타입, "HP UP", "Increase +10 HP", Value 10    
  - <b>Item Speed</b>: Speed 타입, "Speed UP", "Increase +10%", Percent 0.1    
  - <b>Item Grenade</b>: Grenade 타입, "Grenade UP", "Increase +2 Grenade", Value 2  
  - <b>Item Shock</b>: Damage 타입, "Damage UP", "Increase +5% Damage", Percent 0.05   

### DataManager 구현

- 필요한 네임스페이스 추가  
  - <code>using System.IO</code> (파일 입출력)
  - <code>using System.Runtime.Serialization.Formatters.Binary</code> (직렬화)  
  - <code>using DataInfo</code> (GameData 클래스 접근) 
- <code>BinaryFormatter</code>와 <code>FileStream</code> 사용  
  - FileStream: 데이터가 하드디스크와 왔다 갔다 하는 가상의 통로   
  - 버퍼링 개념: 데이터를 모아뒀다가 한꺼번에 전송  
- <code>Save()</code> 메서드 구현  
  - BinaryFormatter로 직렬화 수행
  - FileStream으로 파일 생성 및 데이터 저장
  - 저장 후 <code>FileStream.Close()</code> 필수 (리소스 해제)   
- <code>Load()</code> 메서드 구현  
  - 파일 존재 여부 확인 (<code>File.Exists</code>)
  - FileStream으로 파일 열기 (`FileMode.Open`)
  - BinaryFormatter로 역직렬화 수행  
  - GameData 객체로 변환하여 반환  

### GameManager 통합

- GameManager에 DataManager 컴포넌트 추가  
- <code>Awake()</code>에서 DataManager 초기화 
  - <code>dataManager.Initialize()</code> 호출하여 경로 설정
  - <code>gameData = dataManager.Load()</code> 호출하여 데이터 로드  
  - 로드된 데이터로 killCount, hp, damage, speed 값 설정  
- <code>OnApplicationQuit()</code>에서 자동 저장   
  - 게임 종료 시 <code>dataManager.Save(gameData)</code> 호출

### 데이터 적용 및 테스트

- TPS Damage 스크립트에서 게임 시작 시 hp 값 적용  
- TPS Controller에서 walkSpeed 값 적용 (초기값 6으로 설정)   
- Bullet Controller에서 damage 값 적용 (초기값 25로 설정)  
- 킬 카운트 증가 테스트 성공   
  - 게임 종료 후 재시작해도 킬 카운트 값 유지 확인

### File Stream 및 버퍼링 개념

- FileStream은 유니티 스크립트와 하드디스크 사이의 데이터 통로  
- 버퍼링: 데이터를 바로 전송하지 않고 모아뒀다가 한꺼번에 전송  
- 버퍼링 발생 이유: 네트워크 연결 끊김 등으로 데이터 수신 불가 시  
- FileStream 사용 후 반드시 Close() 호출하여 리소스 해제 필요  

### 저장 경로 확인

- <code>Application.persistentDataPath</code> 경로 확인 방법   
- Windows의 경우: 사용자/AppData/Local/DefaultCompany/UnityTPS    
- Android/iOS의 경우: 각 플랫폼의 공용 폴더에 저장

        //Application.persistentDataPath 는 Unity 에서 제공하는 경로로,
        //어플리케이션의 데이터를 저장 할 수 있는 위치.
        //공용 폴더에 저장됨.
    }
    public void Save(GameData gameData) // 게임 데이터를 저장하는 메서드
    {
        BinaryFormatter bf = new BinaryFormatter(); //바이너리 포멧터 객체 생성

        FileStream file = File.Create(dataPath); //물결 혹은 물길 지정된 경로에 파일로 저장하거나 그 파일을 불러올 때 왔다갔다 하는 경로를 Stream 이라고 한다.
        //파일 스트림 생성, 지정된 경로에 파일 생성
        
        GameData data = new GameData(); //파일에 저장할 클래스에 데이터 할당
        data.killCount = gameData.killCount;
        data.hp = gameData.hp;
        data.speed = gameData.speed;
        data.equipItem = gameData.equipItem;
        //어떤 아이템이 장착되어 있는지 저장

        bf.Serialize(file, data);
        //파일에 데이터를 직렬화 하여 저장
        //float, int, List<item> 등 다양한 타입의 데이터를
        //binary(byte)형식으로 변환하여 저장 할 수 있음.
        file.Close(); //파일 스트림 닫기
    }
    public GameData Load() 
    {
        if (File.Exists(dataPath)) //지정한 경로에 파일이 존재하는지 확인
        {
            BinaryFormatter bf = new BinaryFormatter(); //바이너리 포맷터 객체 생성
            FileStream file = File.Open(dataPath, FileMode.Open); //파일스트림 열기
            GameData data = (GameData)bf.Deserialize(file);
            //파일에서 데이터를 역직렬화 하여 GameData 객체로 변환
            file.Close(); //파일 스트림 닫기
            //로드된 데이터를 사용하여 게임 상태를 복원하는 로직을 여기에 추가 할 수 있음
            return data; // 로드된 GameData 객체 반환
        }
        else
        {
            GameData data = new GameData(); //파일이 존재하지 않는 경우, 기본값을 가진 GameData 객체를 반환
            return data; //새로운 게임을 시작할 때 기본값으로 사용할 수 있음
        }
    }

하드디스크(SSD)에서 물리적으로 저장 되는 형태

바이너리 파일 저장 방식은

데이터를 <b>0과 1(이진 데이터)</b> 형태로 변환하여

하드디스크(SSD)에 물리적으로 저장하는 방식이다.

텍스트(JSON 등)처럼 사람이 읽을 수 있는 형태가 아니라

컴퓨터가 효율적으로 처리할 수 있는 형태로 저장된다.

- 직렬화(Serializable)

객체를 저장 또는 전송할 수 있도록

byte 단위의 연속된 데이터 형태로 변환하는 과정

우리는 C# 클래스 에서 int float string 등등의 자료형을 통해서 데이터를 다루고 있는데 <br />지금처럼 하드디스크(SSD) 공간에 물리적으로 저장 하고자 할 때는 위의 int, float, string 등 을 byte로 변환 시켜서 저장해야 한다. 이 과정을 직렬화 라고 한다.<br />클라이언트에서 서버로 데이터 전송을 할 때도  int, float, string 등을 byte 단위로 전송 하기 좋게 재배열하는 과정을 말한다.

- 역직렬화(Deserializable)

하드디스크(SSD)에 있는 byte 형태의 자료를 다시 Load 할 때 byte를 float, int, string 등의 우리가 알아들을 수 있는 자료형의 형태로 변환하는 과정을 역직렬화 라고 한다.

서버의 데이터를 클라이언트 에게 보낼 때 byte 자료형을 다시 유저가 알 수 있는 자료형으로 변환하는 과정을 말한다.

### 직렬화가 필요한 이유

- 파일로 저장하기 위해
- 네트워크를 통해 서버로 전송하기 위해
- 시스템 간 데이터를 공유하기 위해

클라이언트에서 서버로 데이터를 전송할 때도

int, float, string 등을 그대로 보내는 것이 아니라

byte 단위로 재배열하여 전송한다.

이 역시 직렬화 과정이다.

## 전체 흐름 정리

1. 객체 생성
2. 직렬화 → byte 변환
3. 파일 저장 또는 서버 전송
4. byte 데이터 수신
5. 역직렬화 → 객체 복원

<summary>데이터 관리 흐름</summary>

데이터를 관리 하려면 반드시 Initialize() 경로를 지정하고 경로명을 지정<br />Save() 데이터 저장 직렬화 Serailization<br />Load() 데이터 불러오기 Deserailization

### 1) Initialize()

- 데이터를 저장/불러오기 전에 <b>저장 경로(dataPath)</b> 와 <b>파일명</b>을 미리 정한다.
- 보통 <code>Application.persistentDataPath</code>를 사용해 플랫폼에 맞는 안전한 저장 위치를 잡는다.

### 2) Save()

- 게임 데이터를 파일로 저장한다.
- 저장할 객체를 <b>직렬화(Serialization)</b> 해서 byte 형태로 변환한 뒤 파일에 기록한다.

### 3) Load()

- 저장된 파일에서 데이터를 읽어온다.
- 파일의 byte 데이터를 다시 객체로 복원하는 <b>역직렬화(Deserialization)</b> 과정을 거친다.

인벤토리 시스템에서 아이템을 추가하고 삭제할 때 GameData 클래스의 equipItem에 반영하고, 아이템 변화 시 이벤트를 발생시켜 실제 변수 값을 업데이트하는 로직을 구현하였다. 

### 이벤트 시스템 구현

- onItemChanged 델리게이트를 사용하여 아이템 변경 이벤트 시스템 구성  
- 반환형이 void이고 매개변수가 없는 함수에 대해 이벤트 발생 
- 아이템이 추가되거나 삭제될 때 언제든지 쉽게 접근하여 변경사항을 반영할 수 있도록 델리게이트 활용 

### 아이템 추가 구현

- AddItem 함수 작성 
- 리스트의 Contains 메서드를 사용하여 같은 아이템이 있는지 확인  
- 중복 확인을 위해 리스트 자료구조 사용 
- GameData.equipItem에 아이템 추가 
- 추가 완료 후 onItemChanged?.Invoke() 호출하여 이벤트 발생  

### 아이템 삭제 구현

- RemoveItem 함수 작성 
- GameData.equipItem에서 아이템 제거
- 삭제 완료 후 onItemChanged?.Invoke() 호출  

### 아이템 계산 방식

두 가지 계산 방식을 구현하였다:

<b>값 방식 (Value)</b>  

- 아이템 밸류 값을 그대로 증가/감소
- 예: HP에 아이템 밸류만큼 더하거나 빼기

<b>퍼센트 방식 (Percent)</b>  

- 기존 값에 비율을 곱하여 계산
- 증가 시: 현재값 + (현재값 × 아이템밸류)   
- 감소 시: 현재값 ÷ (1 + 아이템밸류)   

<b>계산 예시</b>

- 스피드 6.0에서 10% 증가: 6.0 + (6.0 × 0.1) = 6.6  
- 스피드 6.6에서 10% 감소: 6.6 ÷ 1.1 = 6.0  
- HP 120에서 10% 증가: 120 + (120 × 0.1) = 132 
- HP 132에서 10% 감소: 132 ÷ 1.1 = 120  

### 스위치문을 통한 속성별 처리

각 아이템 타입(HP, Speed, Damage, Grenade)에 대해 스위치문으로 분기 처리  

- HP, Speed, Damage는 값/퍼센트 방식 모두 구현  
- Grenade는 복잡도 때문에 생략 

### 드롭 시스템 연동

- 드롭 시 아이템이 인벤토리에 추가되도록 구현 
- DraggingItem의 ItemInfo에서 아이템 데이터를 가져와서 GameManager.Instance.AddItem 호출  
- 슬롯에서 빠져나올 때 부모가 InventoryTR이 되면 삭제 처리   

### 업데이트 셋업 등록

각 UI 컴포넌트에서 OnEnable 시 GameManager의 onItemChanged 이벤트에 UpdateSetup 함수를 등록  

<b>등록된 컴포넌트들:</b>

- TPSCity (플레이어 스탯 UI)  
- TPSDamage (데미지 UI)  
- BulletScript (총알 관련) 

이를 통해 아이템이 추가되거나 삭제될 때마다 자동으로 UI가 갱신된다. 

### 데이터 로드 시스템

게임 데이터 로드 시 보유한 아이템을 인벤토리에 복원하는 로직 구현 

<b>구현 방식:</b>

- 이중 반복문 사용  
- 외부 루프: 보유한 아이템 개수만큼 반복 
- 내부 루프: 모든 슬롯을 순회하여 빈 슬롯 찾기   
- ChildCount가 0보다 크면 continue로 건너뛰기  
- 빈 슬롯을 찾으면 아이템 오브젝트의 부모를 해당 슬롯으로 설정  
- ItemInfo에 게임 데이터의 equipItem 값 설정 
- break로 내부 루프 탈출하여 다음 아이템으로 이동  

### 테스트 및 검증

<b>테스트 과정</b>  

1. 플레이 모드에서 HP 아이템을 인벤토리에 추가: 120 → 130으로 변경 확인   
2. 아이템 제거: 130 → 120으로 복원 확인 
3. 스피드 아이템 추가: 6.0 → 6.6으로 변경 확인 
4. 데미지 아이템 추가: 25 → 26.25로 변경 확인 
5. 게임 종료 후 재시작: 변경된 값들이 유지되는지 확인 

<b>데이터 초기화</b>

- 테스트 중 데이터가 꼬인 경우 게임 데이터 파일 삭제하여 초기화   
- 경로: 게임 매니저에서 확인 가능 

### 슬롯 시스템 설정

- GameManager에 SlotList 할당 
- 아이템 오브젝트 4개 등록 (HP, Speed, Damage, Grenade)    

### 중요 개념 정리

<b>Continue vs Break</b>   

- Continue: 현재 반복을 건너뛰고 다음 반복으로 이동
- Break: 반복문을 완전히 탈출

<b>Null 조건 연산자 (?.)</b>  

- null이 아니면 호출하라는 의미
- 예: onItemChanged?.Invoke() → onItemChanged가 null이 아닐 때만 Invoke 호출

### 데이터 저장 방식 비교

강의 마지막에 Unity 데이터 저장 방식들을 정리하였다:  

<b>PlayerPrefs 방식</b>  

- 가장 쉬운 방법이지만 보안성이 없음
- 암호화되지 않은 상태로 저장
- 출시 게임에서는 반드시 암호화 필요

<b>Binary 방식</b>  

- 하드디스크/SSD에 물리적으로 저장
- Serialization(직렬화) / Deserialization(역직렬화) 사용  

<b>서버 저장 방식</b> 

- 원격 데이터 서버에 저장
- 추후 학습 예정

<b>데이터 관리 필수 요소</b> 

- 경로 지정
- 경로명 지정
- Initialize, Save, Load 구현

    public void AddItem(Item item) //인벤토리에 아이템을 추가 되었을 때 데이터 정보를 업데이트 하는 함수

                    gameData.damage += item.value; //데미지 증가                
                else                
                    gameData.damage += gameData.damage * item.value; //데미지 증가                
                break;
        }

    }

    public void OnPauseClick()
    {
        isPaused = !isPaused; //토글 방식으로 일시정지 상태 변경
        Time.timeScale = (isPaused ? 0.0f : 1.0f);
        //Time.timeScale을 0으로 설정하면 게임이 일시정지되고, 1로 설정하면 게임이 정상적으로 진행

        // 플레이어가 전혀 움직이지 못하게 플레이어의 스크립트들을 비활성화
        var player = GameObject.FindGameObjectWithTag("Player");
        //GameObject.FindGameObjectWithTag("PLAYER") 메서드를 사용하여 "PLAYER" 태그가 지정된 게임 오브젝트를 찾아 player 변수에 할당
        MonoBehaviour[] scripts = player.GetComponents<MonoBehaviour>();
        //GetComponents<MonoBehaviour>() 메서드를 사용하여 플레이어 게임 오브젝트에 연결된 모든 MonoBehaviour 스크립트를 배열로 가져옴
        foreach (MonoBehaviour script in scripts)
        //foreach 루프를 사용하여 배열에 있는 각 스크립트에 대해 반복하면서,
        //script.enabled 속성을 isPaused의 반대값으로 설정하여 일시정지 상태에 따라 스크립트를 활성화하거나 비활성화
        {
            script.enabled = !isPaused; //일시정지 상태에 따라 스크립트 활성화/비활성화
        }
        var canvasGroup = GameObject.Find("Panel-Weapon").GetComponent<CanvasGroup>();
        canvasGroup.blocksRaycasts = !isPaused; //일시정지 상태에 따라 UI의 상호작용 가능 여부 설정
