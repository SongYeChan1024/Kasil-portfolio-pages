<b>멀티플레이어 네트워킹 기초와 로비 구현</b> 2026-03-12


## 요약


### Photon 설정 및 초기 구성

- Photon Unity Networking SDK 다운로드 및 설치 진행    
- App ID를 입력하여 프로젝트 셋업 완료  
- Server Settings에서 프로토콜과 지역 설정  

### 네트워크 프로토콜

<b>UDP vs TCP</b> 

- <b>UDP</b>: 속도가 빠르지만 일부 데이터 손실 가능, 게임에서 주로 사용
- <b>TCP</b>: 신뢰성 높은 통신, 데이터 손실 없음, 속도 느림

### 서버 지역(Region) 설정

- 한국 서버: <code>kr</code>
- 일본 서버: <code>jp</code>  
- Dev Region 설정을 통해 접속할 서버 지역 선택 

### RPC (Remote Procedure Call)

- 네트워크에 있는 다른 클라이언트에서 함수를 실행시키는 기능 
- 원격 함수 호출을 통한 멀티플레이어 통신 구현

### 멀티플레이어 게임 오브젝트 구조

<b>4인 멀티플레이어 게임의 오브젝트 수</b>  

- 총 16개의 플레이어 오브젝트 생성 (4명 × 4대 컴퓨터)
- 각 컴퓨터에서 4명의 플레이어 캐릭터를 모두 생성하여 관리  

<b>Local Object vs Remote Object</b>   

- <b>Local Object</b>: 자기 자신이 직접 조종하는 캐릭터, 주도권이 본인에게 있음   
  - 키보드/마우스 입력 처리
  - 이동 처리
  - 카메라 연결
- <b>Remote Object</b>: 다른 플레이어의 캐릭터, 주도권이 네트워크 너머의 타인에게 있음  
  - 네트워크 데이터로 움직임
  - 위치 동기화만 수신

<b>예시</b>: A 컴퓨터에서는 플레이어 A가 Local, 나머지 B, C, D는 Remote   

### 네트워크 동기화

- Local Object가 움직이면 모든 컴퓨터의 해당 Remote Object도 동시에 움직여야 함    
- A 컴퓨터에서 캐릭터 A를 이동시키면, B, C, D 컴퓨터에서도 캐릭터 A가 동일하게 이동  
- 이것이 네트워크 동기화의 핵심 개념 

### 서버/클라이언트 개념

<b>기본 개념</b>  

- <b>서버</b>: 주인, 공간을 제공하는 역할 (호스트)
- <b>클라이언트</b>: 손님, 서버에 요청하는 역할
- 클라이언트가 서버에 요청하면 서버가 응답 

### 서버 방식의 종류

<b>1. Dedicated Server (전용 서버)</b>   

- 게임 전용 서버가 따로 존재하는 방식
- 중앙 서버가 모든 게임 데이터를 관리
- <b>장점</b>: 보안 강력, 핵 방지 효과적, 안정적 
- <b>단점</b>: 서버 운영 비용 높음, 전문 인력 필요 
- <b>적합한 장르</b>: MMORPG, 대규모 FPS (검은사막, 배틀그라운드 등)  

<b>2. Listen Server (리슨 서버)</b>   

<ul>
<li>
플레이어 중 한 명의 PC가 서버 역할 수행 
</li>
<li>
방장 개념이 존재 
</li>
<li>
<b>장점</b>: 서버 비용 절감, 구현 비교적 쉬움 
</li>
<li>
<b>단점</b>: 

- 호스트의 네트워크 상태가 모든 플레이어에게 영향  
- 방장이 나가면 게임 중단 
- Host advantage 존재 
</li>
<li>
<b>적합한 장르</b>: Co-op 게임, 소규모 FPS 
</li>
</ul>

<b>3. P2P (Peer to Peer)</b>   

- 중앙 서버 없이 모든 플레이어가 서로 직접 연결 
- <b>장점</b>: 서버 비용 거의 없음, 1:1에서 응답속도 매우 빠름 
- <b>단점</b>: 보안 취약, 핵 방지 어려움, 대규모 확장 어려움 
- <b>적합한 장르</b>: 격투 게임, RTS, 1:1 스포츠 게임  

### 프로젝트 서버 구조

<b>좀비 서바이벌 멀티플레이어 구현 방식</b>   

- <b>Listen Server 방식</b> 사용  
- <b>매치메이킹</b>과 <b>로비 접속</b>은 Photon 전용 클라우드 서버 이용  
- 방을 만들고 찾는 과정에서만 전용 서버 사용, 게임 진행은 Listen Server  

<b>호스트 권한 관리</b>  

- 게임 승패, 스코어, 레벨 상승 등은 모두 호스트에 위임  
- 클라이언트의 변조/위조 행위 방지 목적 
- 예: 플레이어가 적을 처치해도 즉시 반영되지 않고 호스트에서 판단 후 반영 

### 조작 설정

<b>입력 매핑</b>     

- 카메라 회전: 마우스 X축 
- 전진: 위 방향키 
- 발사: 마우스 왼쪽 버튼 
- 룸 나가기: ESC 키  

<b>Exit 기능 구현</b>     

- Input Manager에 "Exit" 추가 (키: ESC)   
- PlayerController에 OnExit 이벤트 추가 
- ESC 입력 시 로비로 이동하도록 구현 예정 (바로 종료하지 않음) 

### 로비 씬(Scene) 구현

<b>씬 생성</b>  

- 새로운 Scene 생성: "Lobby" 
- UI Canvas 추가 (이름: "Canvas - Lobby")   

<b>UI 요소 구성</b>   

- <b>Panel BG</b>: 배경 패널, 알파값 255로 설정, InputField Background 스프라이트 사용    
- <b>타이틀 텍스트</b>: "좀비 서바이벌"   
  - 폰트: 케네디체  
  - 크기: 50 (이후 70으로 조정)  
  - 색상: 빨간색 
  - 효과: Shadow 컴포넌트 추가 (offset: -2, -2)  
- <b>Connection Info 텍스트</b>: "Connection info here" 
  - 크기: 25 
  - 정렬: 가운데 
  - 너비: 300 
- <b>Join 버튼</b>   
  - 크기: 너비 300, 높이 60 
  - 텍스트: "JOIN", 크기 25  
  - 배경색: 회색 

<b>로비 매니저 생성</b>   

- 빈 GameObject 생성: "LobbyManager" 
- LobbyManager 스크립트 생성 및 연결   

### 로비 매니저 스크립트 구조

<b>네임스페이스 및 상속</b>     

- <code>using Photon.Pun;</code> - Photon Unity Networking 기능
- <code>using Photon.Realtime;</code> - Photon 서비스 관련 기능 
- <code>MonoBehaviourPunCallbacks</code> 상속   
  - 기존 MonoBehaviour 기능 유지하면서 네트워크 콜백 함수 사용 가능  
  - 네트워크 이벤트 처리 가능

<b>주요 역할</b> 

- 마스터 서버 접속 관리
- 매치메이킹 처리
- 로비 연결 관리

# 6️⃣ Local Object vs Remote Object

## Local Object

내가 직접 조종하는 캐릭터

예

```txt
내 키보드 입력
내 마우스 입력
```

특징

- 이동 처리
- 입력 처리
- 카메라 연결

---

## Remote Object

다른 플레이어 캐릭터

특징

- 내가 조종하지 않음
- 네트워크 데이터로 움직임
- 위치 동기화만 받음

# 1️⃣ Dedicated Server (구분 전용 서버)

<b>게임 전용 서버가 따로 존재하는 방식</b>

특징

- 중앙 서버가 모든 게임 데이터를 관리
- 플레이어는 서버에 접속해서 게임 진행
- 서버가 게임 상태를 결정

장점

- 보안 강함
- 치트(핵) 방지 좋음
- 안정적

단점

- 서버 운영 비용 높음

적합한 장르

- MMORPG
- 대규모 FPS
- 온라인 RPG

예

- 월드 오브 워크래프트
- 배틀필드

---

# 2️⃣ Listen Server (리슨 서버)

<b>플레이어 중 한 명이 서버 역할을 하는 방식</b>

특징

- 중앙 서버 있음 (하지만 플레이어 PC가 서버 역할)
- 방장이 서버 역할

장점

- 서버 비용 적음
- 구현 비교적 쉬움

단점

- 방장이 나가면 게임 종료
- 방장이 유리할 수 있음 (Host advantage)

적합한 장르

- Co-op 게임
- 소규모 FPS

예

- Left 4 Dead
- 일부 Co-op 게임

---

# 3️⃣ P2P (Peer to Peer)

<b>모든 플레이어가 서로 직접 연결하는 방식</b>

특징

- 중앙 서버 없음
- 플레이어끼리 직접 통신

장점

- 서버 비용 거의 없음
- 구조 단순

단점

- 보안 취약
- 핵 사용 가능성 높음
- 동기화 어려움

적합한 장르

- 격투 게임
- RTS
- 1:1 스포츠 게임

예

- 일부 격투 게임
- 스타크래프트 초기 버전

| 구조 | 중앙 서버 | 비용 | 보안 | 적합 장르 |
| --- | --- | --- | --- | --- |
| Dedicated | 있음 (전용 서버) | 높음 | 매우 강력 | MMORPG, 대규모 FPS |
| Listen | 있음 (플레이어 PC) | 낮음 | 보통 | Co-op, 소규모 FPS |
| P2P | 없음 | 매우 낮음 | 취약 | 격투, RTS, 1:1 스포츠 |

좀비 서바이벌 멀티 플레이어는 Listen Server 방식으로 구현 할 예정

다만 매치 메이킹 과정에서는 포톤(Photon)에서 제공 하는 전용 클라우드 서버를 이용 할 예정

## 요약


### 프로젝트 목표

- 싱글 플레이어 좀비 서바이버 게임을 최대 4인 멀티플레이어로 포팅 
- 플레이어들이 협동하여 좀비를 처치하는 게임 구현
- 사망한 플레이어는 5초 후 자동 부활  
- 매치메이킹 시스템: 로비에서 자동으로 빈 룸 찾아 참가  

### Photon 라이브러리 구조

- <b>Photon.Realtime</b>: 실시간 네트워크 게임 개발용 C# 라이브러리 (범용)  
- <b>Photon.Pun</b>: Unity 전용 컴포넌트로, Photon.Realtime을 포함하여 Unity에서 게임 오브젝트 형태로 사용 가능하게 만든 라이브러리  
- Unity 개발 시 Photon.Pun과 Photon.Realtime을 함께 사용해야 함  
- Unreal Engine 사용 시에는 Photon.Realtime만 사용 

### 마스터 서버 접속 및 룸 생성

- <code>PhotonNetwork.ConnectUsingSettings()</code>로 마스터 서버 접속 시도  
- 접속 성공 시 <code>OnConnectedToMaster()</code> 콜백에서 Join 버튼 활성화  
- 접속 실패 시 재접속 시도 
- <code>PhotonNetwork.JoinRandomRoom()</code>으로 빈 방에 랜덤 입장 시도 
- 빈 방이 없을 경우 <code>OnJoinRandomFailed()</code> 콜백에서 새 방 생성

- <code>IsVisible = false</code>로 설정 시 비밀방처럼 목록에서 숨김 
- 기본적으로 로비에서 방 생성 

### PhotonNetwork.LoadLevel의 동작

- 방장이 <code>PhotonNetwork.LoadLevel()</code>을 실행하면 다른 플레이어들도 자동으로 같은 씬 로드 
- <code>SceneManager.LoadScene()</code>과 달리 네트워크 정보 유지  
- <code>SceneManager.LoadScene()</code>은 이전 씬의 모든 게임 오브젝트가 파괴되어 로비 씬의 네트워크 정보가 유지되지 않음 

### PhotonView 컴포넌트

- <b>역할</b>: 로컬 오브젝트의 움직임을 송신하고 리모트 오브젝트의 움직임을 수신받는 컴포넌트  
- 로컬과 리모트 오브젝트를 구분하고 네트워크 동기화 및 RPC 호출 관리
- View ID로 각 오브젝트 식별 가능

### 플레이어 캐릭터 설정

- 플레이어 캐릭터 프리팹을 Resources 폴더에 저장 (네트워크 게임에서의 Prefab 폴더)   
- PhotonView 컴포넌트 추가  
- PhotonTransformView 추가: Position과 Rotation 동기화   
- PhotonAnimatorView 추가: 애니메이션 동기화  
- Observed Components에서 관찰할 컴포넌트 지정 (Manual 모드)  

### 카메라 셋업

- 네트워크 상에서 각 플레이어의 카메라가 자신의 캐릭터만 따라가도록 설정  
- <code>PhotonView.IsMine</code>으로 로컬 플레이어 판별  
- 자신의 캐릭터일 경우에만 Virtual Camera가 Follow하도록 구성  

### 플레이어 입력 및 이동 제어

- <code>PhotonView.IsMine</code>이 false인 경우 입력 및 이동 스크립트에서 return하여 원격 플레이어 조작 방지   
- PlayerInput, PlayerMovement, PlayerShooter 등 모든 입력 관련 스크립트에서 동일하게 적용  

### 체력 및 데미지 시스템 (호스트 권한 방식)

- <b>핵심 원칙</b>: 모든 게임 로직은 호스트(방장)에서 처리하고 결과를 클라이언트에 전달  
- <code>PhotonNetwork.IsMasterClient</code>로 호스트 판별  
- 체력 관리, 데미지 처리, 사망 처리는 호스트에서만 권한 보유  

<b>LivingEntity 스크립트:</b>

```cs
[PunRPC]
void ApplyUpdatedHealth(float newHealth, bool newDead) {
    health = newHealth;
    dead = newDead;
}
```

  

- 호스트에서 체력 감소 처리 후 <code>RPC(RPCTarget.Others)</code>로 다른 클라이언트에 전달  
- 체력 회복도 동일한 방식으로 호스트에서 처리  

### RPC (Remote Procedure Call) 개념

- <b>정의</b>: 원격에 있는 다른 클라이언트의 함수를 실행할 수 있는 기능   
- <code>[PunRPC]</code> 어트리뷰트로 선언된 메서드는 다른 클라이언트에서 원격 실행 가능  
- <b>RPC Target 옵션</b>:
  - <code>All</code>: 자신 포함 모든 클라이언트 
  - <code>Others</code>: 자신을 제외한 다른 클라이언트  
  - <code>AllBuffered</code>: 모든 클라이언트 + 이후 접속자에게도 전달  
  - <code>MasterClient</code>: 호스트(방장)만 

### 총기 발사 시스템

<b>발사 처리 순서:</b>

1. 클라이언트 B가 Shot() 메서드 실행  
2. Shot()에서 <code>ShotProcessOnServer()</code> RPC 호출 → 호스트 A에서 실행  
3. 호스트 A에서 실제 발사 처리 (적중 판정, 총알 감소 등)  
4. <code>ShotEffectProcessOnClient()</code> RPC로 모든 클라이언트에 발사 이펙트 재생  

   

<b>Gun 스크립트 동기화:</b>

- PhotonView 컴포넌트 추가  
- <code>OnPhotonSerializeView()</code> 인터페이스 구현으로 탄창/총알 정보 동기화   
- 스트림으로 남은 탄창 수, 탄알 수, 재장전 상태 전송  

### 네트워크 프로토콜 설정

- <b>Reliable Delta Compressed</b>: TCP/IP 방식 - 패킷 손실 시 재전송, 데이터 무결성 중요한 경우 사용  
- <b>Unreliable</b>: UDP 방식 - 패킷 손실 무시하고 빠른 전송, FPS/TPS 게임에서 주로 사용  
- <b>OnReliableChange</b>: 상황에 따라 자동으로 TCP/UDP 전환   
- 기본값은 Unreliable (UDP) 

### 좀비 AI 설정

- 좀비에도 PhotonView, PhotonTransformView, PhotonAnimatorView 추가  
- Auto Find All 옵션으로 자동으로 컴포넌트 탐지  
- LivingEntity 스크립트에서 <code>PhotonNetwork.IsMasterClient</code> 체크  
- AI 동작은 호스트에서만 활성화, 다른 클라이언트는 동기화된 정보만 수신   

### 플레이어 리스폰 시스템

- 사망 후 5초 뒤 <code>DoRespawn()</code> 함수 호출  
- <code>Invoke("DoRespawn", 5f)</code>로 지연 실행 (코루틴 대신 사용 가능) 
- <code>PhotonView.IsMine</code> 체크로 자신의 캐릭터만 리스폰  

### 아이템 사용 시스템

- 아이템 사용도 호스트에서 처리 후 모든 클라이언트에 동기화  
- 한 플레이어가 아이템 획득 시 다른 모든 플레이어도 해당 정보 공유 필요

# Photon 멀티플레이 핵심 구조

Photon 멀티플레이는 기본적으로

\*\*“누가 이 오브젝트의 주인인지 구분하고, 생성하고, 동기화하고, 필요하면 원격 함수(RPC)를 호출하는 구조”\*\*로 되어 있다.

---

# 1. Local Object

<b>현재 내 컴퓨터에서 직접 조종하는 오브젝트</b>

즉, 내가 키보드와 마우스로 움직이는 내 캐릭터이다.

특징

- 입력을 직접 받음
- 이동, 회전, 발사 등 직접 실행
- 자신의 상태를 네트워크에 송신

예시

```txt
내 플레이어 캐릭터
```

---

# 2. Remote Object

<b>다른 플레이어가 조종하는 오브젝트</b>

즉, 내 컴퓨터에서는 직접 조종하지 않고

네트워크를 통해 받은 데이터로 움직이는 캐릭터이다.

특징

- 입력을 직접 받지 않음
- 위치, 회전, 애니메이션을 수신
- 다른 사람의 Local Object가 내 화면에서는 Remote Object가 됨

예시

```txt
다른 유저의 캐릭터
```

---

# 3. PhotonView

<b>네트워크 오브젝트를 식별하고, 소유권을 판단하며, 동기화와 RPC의 기준이 되는 컴포넌트</b>

쉽게 말하면 <b>네트워크 신분증</b>이다.

역할

- 이 오브젝트가 누구 것인지 구분
- Local / Remote 판별 기준 제공
- RPC 호출 기준 제공
- View ID를 통해 네트워크 오브젝트 식별

즉, 멀티플레이 오브젝트에는 거의 반드시 붙는 핵심 컴포넌트이다.

---

# 4. photonView.IsMine

<b>이 오브젝트가 내 것인지 확인하는 속성</b>

<code>true</code>면 내가 조종하는 Local Object

<code>false</code>면 다른 사람이 조종하는 Remote Object

예시 코드

```txt
usingPhoton.Pun;
usingUnityEngine;

publicclassPlayerMove :MonoBehaviourPun
{
voidUpdate()
    {
if (photonView.IsMine)
        {
floath=Input.GetAxis("Horizontal");
floatv=Input.GetAxis("Vertical");

transform.Translate(newVector3(h,0,v)*Time.deltaTime*5f);
        }
    }
}
```

설명

- <code>photonView.IsMine == true</code>
  <p>
  → 내 캐릭터라서 입력 처리
  </p>
- <code>photonView.IsMine == false</code>
  <p>
  → 남의 캐릭터라서 입력 처리 안 함
  </p>

이게 없으면

<b>모든 캐릭터가 내 입력으로 같이 움직이는 대참사</b>가 열릴 수 있다.

---

# 5. PhotonNetwork.Instantiate

<b>네트워크 상에서 플레이어 오브젝트를 생성하는 함수</b>

일반 <code>Instantiate()</code>는 내 컴퓨터에만 오브젝트를 만든다.

하지만 <code>PhotonNetwork.Instantiate()</code>는 <b>모든 플레이어의 컴퓨터에 같은 오브젝트를 생성</b>한다.

예시 코드

```txt
PhotonNetwork.Instantiate("Player",Vector3.zero,Quaternion.identity);
```

의미

- <code>"Player"</code> 프리팹을
- 지정한 위치와 회전값으로
- 네트워크 전체에 생성

즉, 멀티플레이 캐릭터는 보통 이 방식으로 생성해야 한다.

---

# 6. RPC (Remote Procedure Call)

<b>다른 클라이언트에서도 같은 함수를 실행시키는 기능</b>

예를 들어 내가 총을 쐈을 때

다른 플레이어 화면에서도 발사 이펙트가 보여야 한다.

그럴 때 RPC를 사용한다.

예시 코드

```txt
[PunRPC]
voidPlayFireEffect()
{
Debug.Log("발사 이펙트 실행");
}
```

호출 예시

```txt
photonView.RPC("PlayFireEffect",RpcTarget.All);
```

의미

- 나만 실행하는 게 아니라
- 모든 클라이언트에서 같은 함수 실행

---

# 7. View ID

<b>PhotonView가 가진 고유 번호</b>

멀티플레이에서는 같은 프리팹이 여러 컴퓨터에 복제되어 존재하기 때문에

어떤 오브젝트가 어떤 오브젝트인지 구분할 번호가 필요하다.

그 번호가 View ID이다.

역할

- 네트워크 오브젝트 식별
- RPC 대상 구분
- 동기화 대상 구분

즉, PhotonView는 View ID를 가지고 있고

Photon은 그 번호를 기준으로 오브젝트를 찾는다.

---

# 8. Network Synchronization

<b>오브젝트의 상태를 네트워크를 통해 서로 같게 유지하는 것</b>

동기화 대상 예시

- 위치
- 회전
- 애니메이션
- 체력
- 상태값

예를 들어 내 캐릭터가 앞으로 걸어가면

그 위치 데이터가 다른 플레이어에게 전달되어

다른 사람 화면에서도 같은 움직임이 보이게 된다.

---

# 전체 흐름

멀티플레이 캐릭터는 보통 이런 흐름으로 작동한다.

```txt
1. PhotonNetwork.Instantiate()로 플레이어 생성
2. 생성된 오브젝트에는 PhotonView가 붙어 있음
3. PhotonView의 View ID로 각 오브젝트를 식별
4. photonView.IsMine으로 내 캐릭터인지 확인
5. 내 캐릭터(Local Object)만 입력 처리
6. 움직임과 상태를 네트워크로 동기화
7. 다른 플레이어 캐릭터는 Remote Object로 수신만 함
8. 필요할 때 RPC로 함수 실행
```

---

# 구조도

## 1단계: 플레이어 생성

```txt
PhotonNetwork.Instantiate("Player")
        ↓
네트워크 전체에 Player 프리팹 생성
        ↓
각 플레이어의 컴퓨터에 Player 오브젝트 생성
```

---

## 2단계: 오브젝트 식별

```txt
Player 오브젝트
   └─ PhotonView 부착
         └─ View ID 보유
```

PhotonView가 붙어 있어야

이 오브젝트가 네트워크 오브젝트로 인식된다.

---

## 3단계: 로컬 / 리모트 판별

```txt
photonView.IsMine == true  → Local Object
photonView.IsMine == false → Remote Object
```

---

## 4단계: 입력 처리

```txt
Local Object
   └─ 이동 입력 처리
   └─ 회전 처리
   └─ 발사 처리
   └─ 상태 송신

Remote Object
   └─ 입력 처리 안 함
   └─ 네트워크 데이터 수신
   └─ 위치/회전/애니메이션 반영
```

---

## 5단계: 동기화와 RPC

```txt
내 캐릭터 이동
   ↓
Network Synchronization
   ↓
다른 플레이어 화면에서도 같은 위치 반영

내가 발사
   ↓
RPC 호출
   ↓
다른 플레이어 화면에서도 발사 효과 실행
```

---

# 한 장으로 보는 Photon 구조도

```txt
[PhotonNetwork.Instantiate]
        ↓
[네트워크 플레이어 생성]
        ↓
[PhotonView 부착]
        ↓
[View ID로 식별]
        ↓
[photonView.IsMine 판별]
     ┌───────────────┴───────────────┐
     ↓                               ↓
[Local Object]                   [Remote Object]
- 입력 처리                       - 입력 처리 안 함
- 이동/회전                       - 데이터 수신
- 상태 송신                       - 위치/회전 반영
- RPC 호출 가능                   - RPC 수신 가능
     └───────────────┬───────────────┘
                     ↓
         [Network Synchronization]
                     ↓
          [모든 클라이언트 상태 일치]
```

# 짧은 정리

## PhotonView

네트워크 오브젝트를 식별하고 소유권, 동기화, RPC의 기준이 되는 컴포넌트

## photonView.IsMine

해당 오브젝트가 내가 조종하는 Local Object인지 판별하는 속성

## PhotonNetwork.Instantiate

네트워크 전체에 플레이어 오브젝트를 생성하는 함수

## Local Object

내가 직접 조종하는 오브젝트

## Remote Object

다른 플레이어가 조종하는 오브젝트

## RPC

다른 클라이언트에서도 동일한 함수를 실행시키는 기능

## View ID

PhotonView가 가진 고유 식별 번호

## Network Synchronization

오브젝트의 상태를 네트워크로 동기화하여 모든 플레이어에게 동일하게 보이게 하는 과정

---

# 실전용 예제 코드

목표

```txt
방 입장
→ PhotonNetwork.Instantiate()로 플레이어 생성
→ photonView.IsMine 이면 내 캐릭터만 입력 처리
→ IPunObservable / OnPhotonSerializeView 로 위치, 회전 동기화
→ RPC로 점프 이펙트 같은 단발성 동작 실행
```

Photon 공식 문서 기준으로, 네트워크 오브젝트는 <code>PhotonView</code>가 필요하고 <code>PhotonNetwork.Instantiate()</code>로 생성하며, 동기화는 <code>IPunObservable</code>의 <code>OnPhotonSerializeView()</code>에서 송수신하고, RPC는 <code>[PunRPC]</code>와 <code>photonView.RPC(...)</code>로 호출합니다. 또 <code>OnPhotonSerializeView()</code>가 호출되려면 해당 스크립트가 <code>PhotonView</code>의 Observed 컴포넌트로 등록되어 있어야 합니다.

```txt
}
```

## 2) NetworkPlayerController.cs

내 캐릭터만 입력받고, 다른 캐릭터는 네트워크 데이터를 받아 부드럽게 따라오게 만드는 핵심 스크립트입니다.

```txt
usingPhoton.Pun;
usingUnityEngine;

[RequireComponent(typeof(PhotonView))]
publicclassNetworkPlayerController :MonoBehaviourPun,IPunObservable
{
    [Header("Move")]
    [SerializeField]privatefloatmoveSpeed=5f;
    [SerializeField]privatefloatrotateSpeed=180f;

    [Header("Remote Sync")]
    [SerializeField]privatefloatpositionLerpSpeed=10f;
    [SerializeField]privatefloatrotationLerpSpeed=10f;

privateVector3networkPosition;
privateQuaternionnetworkRotation;

privatevoidStart()
    {
networkPosition=transform.position;
networkRotation=transform.rotation;
    }

privatevoidUpdate()
    {
if (photonView.IsMine)
        {
HandleInput();

// 예시: Space를 누르면 모두에게 점프 이펙트 RPC 호출
if (Input.GetKeyDown(KeyCode.Space))
            {
photonView.RPC(nameof(PlayJumpEffect),RpcTarget.All);
            }
        }
else
        {
// 리모트 오브젝트는 네트워크로 받은 값으로 보간
transform.position=Vector3.Lerp(
transform.position,
networkPosition,
Time.deltaTime*positionLerpSpeed
            );

transform.rotation=Quaternion.Lerp(
transform.rotation,
networkRotation,
Time.deltaTime*rotationLerpSpeed
            );
        }
    }

privatevoidHandleInput()
    {
floath=Input.GetAxis("Horizontal");
floatv=Input.GetAxis("Vertical");

Vector3move=newVector3(h,0f,v);

// 이동
transform.position+=move.normalized*moveSpeed*Time.deltaTime;

// 이동 방향이 있으면 회전
if (move.sqrMagnitude>0.001f)
        {
QuaterniontargetRot=Quaternion.LookRotation(move);
transform.rotation=Quaternion.RotateTowards(
transform.rotation,
targetRot,
rotateSpeed*Time.deltaTime
            );
        }
    }

// 단발성 이벤트는 RPC가 잘 맞음
    [PunRPC]
privatevoidPlayJumpEffect()
    {
Debug.Log($"{photonView.ViewID} 점프 이펙트 실행");
// 여기서 파티클 재생, 애니메이션 트리거 등을 넣으면 됨
    }

// 상태 동기화
publicvoidOnPhotonSerializeView(PhotonStreamstream,PhotonMessageInfoinfo)
    {
if (stream.IsWriting)
        {
// 로컬 오브젝트: 내 상태를 보냄
Vector3pos=transform.position;
Quaternionrot=transform.rotation;

stream.SendNext(pos);
stream.SendNext(rot);
        }
else
        {
// 리모트 오브젝트: 남이 보낸 상태를 받음
networkPosition= (Vector3)stream.ReceiveNext();
networkRotation= (Quaternion)stream.ReceiveNext();
        }
    }
}
```

## 3) SimpleLauncher.cs

연결하고, 로비 들어가고, 룸 생성 또는 참가까지 해주는 최소 예제입니다.

```txt
usingPhoton.Pun;
usingPhoton.Realtime;
usingUnityEngine;

publicclassSimpleLauncher :MonoBehaviourPunCallbacks
{
    [SerializeField]privatestringgameVersion="1.0";
    [SerializeField]privatebytemaxPlayersPerRoom=4;

privatevoidStart()
    {
PhotonNetwork.AutomaticallySyncScene=true;
PhotonNetwork.GameVersion=gameVersion;
PhotonNetwork.ConnectUsingSettings();
    }

publicoverridevoidOnConnectedToMaster()
    {
Debug.Log("마스터 서버 접속 완료");
PhotonNetwork.JoinRandomRoom();
    }

publicoverridevoidOnJoinRandomFailed(shortreturnCode,stringmessage)
    {
Debug.Log("참가할 룸이 없어서 새로 생성합니다.");
RoomOptionsroomOptions=newRoomOptions {MaxPlayers=maxPlayersPerRoom };
PhotonNetwork.CreateRoom(null,roomOptions);
    }

publicoverridevoidOnJoinedRoom()
    {
Debug.Log("룸 참가 완료");
// 현재 씬에 PlayerSpawner가 있으면 Start에서 자동 생성됨
    }
}
```

Photon 공식 문서에서도 <code>PhotonNetwork.Instantiate()</code>는 룸 안의 클라이언트가 네트워크 오브젝트를 만들 때 쓰며, <code>PhotonView</code>는 오브젝트와 소유자 식별, Observed 컴포넌트 관리, ViewID 보유 역할을 합니다. <code>photonView.IsMine</code>은 내가 제어 중인 오브젝트인지 판단할 때 사용하는 핵심 기준입니다.

## 구조가 어떻게 굴러가냐

### 내 캐릭터

<code>photonView.IsMine == true</code>

- 입력 처리
- 이동/회전 실행
- <code>OnPhotonSerializeView()</code>에서 위치/회전 송신
- 필요하면 RPC 호출

### 남 캐릭터

<code>photonView.IsMine == false</code>

- 입력 처리 안 함
- <code>OnPhotonSerializeView()</code>에서 위치/회전 수신
- <code>Lerp</code>로 부드럽게 반영
- RPC 수신해서 효과 재생

이 흐름이 Photon 멀티플레이의 뼈대입니다. Photon 문서에서도 <code>OnPhotonSerializeView()</code>는 로컬 쪽이 쓰고, 리모트 쪽이 읽는 구조로 설명합니다.

## 자주 터지는 실수

### 1. Player 프리팹 이름 불일치

```txt
PhotonNetwork.Instantiate("Player", ...)
```

면 프리팹 이름도 정확히 <code>Player</code>여야 합니다.

### 2. PhotonView 없음

네트워크 오브젝트에는 <code>PhotonView</code>가 필요합니다.

### 3. Observed 등록 안 함

<code>IPunObservable</code>를 구현했어도 <code>PhotonView</code>가 그 스크립트를 observe하지 않으면 직렬화가 안 돕니다.

### 4. 모든 캐릭터가 내 입력으로 움직임

<code>if (photonView.IsMine)</code> 조건이 빠진 경우입니다.

### 5. Start/Awake에서 IsMine 체크 타이밍 꼬임

Photon 문서에 따르면 룸에 들어가기 전 씬 오브젝트에서는 <code>Awake()</code> 시점의 <code>IsMine</code>이 유효하지 않을 수 있습니다.

### \[PunRPC\]

<code>[PunRPC]</code>는 Photon에서 <b>해당 메서드를 원격 호출(Remote Procedure Call)할 수 있도록 지정하는 특성(Attribute)</b> 이다.

이 특성이 붙은 메서드는 <b>PhotonView.RPC() 함수를 통해 다른 클라이언트에서도 실행할 수 있다.</b>

\[PunRPC\]로 선언된 메서드는 다른 클라이언트에서 원격 실행이 가능하게 해준다<br />Ex) Dosomething() 이라는 메서드가 \[PunRPC\] 로 선언이 되어 있다면<br />클라이언트 A는 자신의 월드에서 Dosomething() 을 실행 하지 않고<br />클라이언트 B에 있는 Dosomething()을 원격 실행 할 수 있다.<br />즉, A자신을 포함한 모든 클라이언트에서 Dosomething()을 실행 시킬 수 있다.

\[PunRPC\]는 Photon에서 해당 메서드를 원격 호출(RPC)할 수 있도록 지정하는 특성(Attribute)이다.

이 특성이 붙은 메서드는 PhotonView.RPC()를 통해 다른 클라이언트에서도 실행할 수 있다.

## 주의할 점

Photon 공식 문서 기준으로 몇 가지 규칙이 있다.

- RPC 메서드는 보통 <code>void</code>로 만드는 것이 권장됨
- <code>static</code> 메서드는 RPC로 사용할 수 없음
- RPC 메서드는 <code>PhotonView</code>가 붙은 <b>같은 오브젝트</b>에 있어야 함
- 메서드 이름은 고유하게 쓰는 것이 좋음
- 오버로드는 피하는 것이 좋음

<b>예: 클라이언트 A, B, C가 존재 A가 호스트라고 가정 했을 때</b>

- 클라이언트 B(컴퓨터)의 로컬플레이어 b의 총에서 Shot()메서드 실행2.Shot()에서 photonView.RPC(“ShotProcessOnServer”, RpcTarget.MasterClient) 실행3.실제 사격 처리를 하는 ShotProcessOnServer()에서호스트 클라이언트 A에서만 실행
