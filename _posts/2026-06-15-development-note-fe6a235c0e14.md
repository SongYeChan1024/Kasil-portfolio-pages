## 1. 프로토타입 목적

본 1차 프로토타입의 목적은 《침몽도시: 루시드 다이버》의 전체 콘텐츠를 구현하는 것이 아니라, 게임의 가장 기본적인 플레이 흐름이 실제로 작동하는지 검증하는 것이다.

이번 프로토타입에서는 <b>진입 → 이동 → 전투 → 회수 → 탈출 → 결과 확인</b>으로 이어지는 최소 플레이 루프를 우선 구현한다.

이를 통해 모바일 2.5D 실시간 협동 익스트랙션 슈팅 RPG의 핵심 기반이 되는 조작감, 전투 반응성, 아이템 회수, 탈출 구조, 결과 출력이 하나의 세션 안에서 끊기지 않고 연결되는지 확인한다.

---

## 2. 프로토타입 핵심 검증 목표

| 검증 항목 | 확인 내용 |
| --- | --- |
| 이동 검증 | 플레이어가 2.5D 테스트 맵에서 자연스럽게 이동할 수 있는가? |
| 조준 / 공격 검증 | 플레이어가 기본 공격을 사용하고 적에게 피해를 줄 수 있는가? |
| 적 AI 검증 | 적이 플레이어를 인식하고 추적할 수 있는가? |
| 회수 검증 | 플레이어가 아이템을 획득하고 획득 상태가 UI 또는 데이터로 반영되는가? |
| 탈출 검증 | 플레이어가 탈출 지점에 도달하면 세션이 종료되는가? |
| 결과 검증 | 탈출 성공 여부와 획득 아이템이 결과창에 표시되는가? |
| 감각 피드백 검증 | 공격, 피격, 획득, 탈출 순간이 최소한의 연출로 구분되는가? |

---

## 3. 핵심 플레이 루프

1차 프로토타입에서 검증할 플레이 흐름은 다음과 같다.

```txt
1. 플레이어가 테스트 맵에 진입한다.
2. 플레이어가 맵 위에서 이동한다.
3. 테스트 아이템 위치로 이동해 아이템을 획득한다.
4. 테스트 몬스터가 플레이어를 인식하고 추적한다.
5. 플레이어가 기본 공격으로 몬스터를 공격한다.
6. 몬스터를 처치하거나 회피한다.
7. 플레이어가 탈출 전화부스에 도달한다.
8. 탈출 성공 결과창이 출력된다.
```

본 루프가 1회 이상 끊기지 않고 반복 가능하면 1차 프로토타입의 기본 검증은 성공으로 본다.

## 4. 포함 기능

| 구분 | 기능 | 우선순위 |
| --- | --- | --- |
| 플레이어 | 이동 | Must |
| 플레이어 | 조준 및 기본 공격 | Must |
| 전투 | 적 피격 판정 | Must |
| 전투 | 적 체력 및 사망 처리 | Must |
| AI | 적 인식 및 추적 | Must |
| 아이템 | 테스트 아이템 획득 | Must |
| 탈출 | 탈출 전화부스 접촉 처리 | Must |
| UI | 획득 아이템 카운트 표시 | Must |
| UI | 탈출 성공 결과창 | Must |
| 연출 | 공격 / 피격 / 획득 / 탈출 기본 피드백 | Should |

## 5. 제외 기능

1차 프로토타입에서는 핵심 루프 검증을 우선하므로 아래 기능은 제외한다.

| 제외 기능 | 제외 이유 |
| --- | --- |
| 2인 멀티플레이 | 최소 루프 안정화 이후 검증 |
| 보스전 | 기본 전투 구조 확인 이후 추가 |
| 루시드 공명 시스템 | 협동 확장 기능이므로 후순위 |
| 지원 캐릭터 호출 | 1차 루프 검증에 필수 아님 |
| 각성 보존 슬롯 세부 규칙 | 탈출 / 실패 구조 검증 이후 추가 |
| 복잡한 인벤토리 | 아이템 획득 여부만 우선 확인 |
| 다수 몬스터 | 적 1종으로 AI와 전투 흐름 먼저 검증 |
| 상가 구역 전체 구현 | 30m x 30m 테스트맵으로 기능 검증 후 확장 |

## 6. 테스트 맵 구성

1차 프로토타입은 대형 테마 맵이 아니라, 최소 기능 검증을 위한 단일 평면 테스트맵에서 진행한다.

| 항목 | 내용 |
| --- | --- |
| 맵 형태 | 30m x 30m 단일 평면 샌드박스 |
| 플레이어 스폰 | 맵 남단 중앙 |
| 테스트 아이템 | 맵 북서쪽 |
| 테스트 몬스터 | 맵 북동쪽 |
| 탈출 지점 | 맵 북단 중앙 |
| 장애물 | 중앙 기둥 2개 |
| 외곽 제한 | 맵 밖으로 나가지 못하도록 외벽 또는 펜스 배치 |

### 기본 동선

```txt
플레이어 스폰
→ 아이템 획득
→ 몬스터 조우
→ 전투 또는 회피
→ 탈출 전화부스 접촉
→ 결과창 출력
```

---

## 7. 시스템별 완료 기준

| 시스템 | 완료 기준 |
| --- | --- |
| 플레이어 이동 | 입력에 따라 캐릭터가 맵 내부에서 이동한다 |
| 카메라 | 플레이어를 따라가며 테스트맵 진행에 문제가 없다 |
| 기본 공격 | 공격 입력 시 투사체 또는 공격 판정이 발생한다 |
| 적 피격 | 공격이 적에게 닿으면 적 체력이 감소한다 |
| 적 사망 | 적 체력이 0이 되면 적이 사라지거나 비활성화된다 |
| 적 AI | 적이 일정 거리 안의 플레이어를 감지하고 추적한다 |
| 아이템 획득 | 아이템 접촉 시 아이템이 사라지고 획득 카운트가 증가한다 |
| 탈출 처리 | 탈출 지점 접촉 시 세션 성공 처리된다 |
| 결과창 | 탈출 성공 여부와 획득 아이템 개수가 표시된다 |

## 8. 테스트 시나리오

### 정상 성공 시나리오

```txt
1. 플레이어가 테스트맵에 진입한다.
2. 플레이어가 북서쪽 아이템 위치로 이동한다.
3. 아이템을 획득한다.
4. 북동쪽 몬스터와 조우한다.
5. 기본 공격으로 몬스터를 처치하거나 회피한다.
6. 북단 중앙 탈출 전화부스로 이동한다.
7. 탈출 지점에 접촉한다.
8. 결과창에서 탈출 성공과 획득 아이템을 확인한다.
```

### 실패 / 예외 확인 시나리오

| 상황 | 확인 내용 |
| --- | --- |
| 아이템 미획득 후 탈출 | 결과창에 획득 아이템 0개로 표시되는가? |
| 몬스터에게 피격 | 플레이어 체력 또는 의식 안정도가 감소하는가? |
| 적을 처치하지 않고 탈출 | 회피 플레이가 가능한가? |
| 맵 외곽 이동 시도 | 외곽 Collider에 막히는가? |
| 탈출 지점 반복 접촉 | 결과창이 중복 출력되지 않는가? |

## 9. 리스크 및 확인 사항

| 리스크 | 영향 | 대응 방향 |
| --- | --- | --- |
| 조작감이 둔함 | 전투 재미 저하 | 이동 속도, 가속, 감속 수치 조정 |
| 공격 판정이 불명확함 | 타격감 부족 | 피격 플래시, 사운드, 체력 감소 UI 추가 |
| 적 추적이 불안정함 | 전투 흐름 깨짐 | 감지 거리와 추적 상태 단순화 |
| 아이템 획득 피드백 부족 | 회수 재미 약화 | 획득 사운드, 아이콘 카운트 적용 |
| 탈출 성공 느낌 부족 | 익스트랙션 장르성 약화 | 전화벨, 화면 전환, 결과창 연출 추가 |
| 맵이 너무 복잡함 | 테스트 목적 흐려짐 | 1차는 30m x 30m 단일 평면 유지 |

## 10. 1차 프로토타입 성공 기준

1차 프로토타입은 아래 조건을 만족하면 성공으로 판단한다.

```txt
플레이어가 테스트맵에 진입해 이동하고,
아이템을 획득하고,
적과 전투하거나 회피한 뒤,
탈출 전화부스에 도달해,
결과창에서 탈출 성공 여부와 획득 결과를 확인할 수 있다.
```

본 단계에서는 그래픽 완성도보다 핵심 루프의 작동 여부와 조작 / 전투 / 회수 / 탈출 피드백의 명확성을 우선한다.
