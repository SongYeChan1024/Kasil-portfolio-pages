<b>VR 인터랙션 시스템 (Climb, Haptic, Gaze)</b> 2026-05-07


## 요약


### 오늘 수업 핵심 요약

- <b>Climb Interactable</b>을 활용한 사다리 오르기 기능을 구현하는 방법을 배웠습니다. 
- <b>Teleportation Anchor</b>와 <b>Teleportation Multi Anchor Volume</b>을 사용하여 사다리 오르기 시 위치 이동을 관리하는 원리를 이해했습니다. 
- <b>XR Interaction Toolkit</b>의 다양한 컴포넌트와 인터랙터 시스템을 활용하여 VR 상호작용을 구현하는 방법을 학습했습니다. 
- VR 게임 개발에서 Haptic(진동), Gaze(시선 처리) 등 다양한 인터랙션 요소를 다루는 방법을 배웠으며, 이를 바탕으로 개인 VR 게임을 제작할 예정입니다. 

---

### 주요 개념 정리

- <b>Climb Interactable</b>
  - 설명: VR에서 사다리나 벽을 오르는 기능을 구현하는 컴포넌트 
  - 사용되는 상황: 사다리 오르기, 암벽 등반 등 수직 이동이 필요한 경우 
  - 헷갈릴 수 있는 점: Climb Interactable을 추가하면 Rigidbody가 자동으로 생성됨 
- <b>Teleportation Anchor</b>
  - 설명: 텔레포트 이동 시 정확한 위치와 방향을 지정하는 기능 
  - 예시: 목표물 앞이나 옆의 특정 위치로 이동하도록 설정 
  - 사용되는 상황: 플레이어가 특정 위치로 정확하게 이동해야 할 때
- <b>Teleportation Multi Anchor Volume</b>
  - 설명: 사다리 오르기처럼 여러 앵커 위치를 관리하며, 가장 가까운 지점으로 이동하게 하는 시스템 
  - 예시: Bottom Anchor, Middle Anchor, Top Anchor를 관리하여 사다리의 각 위치로 이동 
  - 사용되는 상황: 사다리 오르기처럼 연속적인 위치 이동이 필요한 경우 
- <b>XR Interactable Affordance State Provider</b>
  - 설명: 인터랙션이 가능한 오브젝트의 상태를 감지해서 시각적으로 알려주는 역할 
  - 사용되는 상황: 오디오 피드백, 시각적 UI 효과, Haptic 진동 등을 구현할 때 
  - 헷갈릴 수 있는 점: 기능을 직접 실행하는 것이 아니라 중재자 역할만 함 
- <b>Near-Far Interactor</b>
  - 설명: 가까이 있으면 Grab으로 동작하고, 멀리 있으면 Ray로 동작하는 인터랙터 
  - 사용되는 상황: 거리에 따라 상호작용 방식을 자동으로 전환해야 할 때

---

### 수업 흐름별 정리

### 1. Teleportation Anchor 복습 및 활용

- 설명: 이전 수업에서 배운 Teleportation Anchor를 활용하여 원하는 위치로 이동하는 방법을 복습했습니다. 
- 예시: Anchor 안에 빈 오브젝트를 만들고, Transform을 원하는 위치로 설정 
- 중요한 이유: Climb 기능 구현 시 위치 이동 관리의 기본이 됨

### 2. Climb Interactable 기본 구조 이해

- 설명: 사다리 프리팹을 통해 Climb 시스템의 구조를 분석했습니다. 
- 예시: Ladder 프리팹에는 Bottom Anchor, Middle Anchor, Top Anchor가 있으며, 각 앵커가 텔레포트 위치를 관리 
- 중요한 이유: 사다리 오르기는 실제로 텔레포트를 활용한 위치 이동임을 이해 

### 3. Handles와 Climb Interactable 설정

- 설명: 사다리의 Handles(손잡이)에 Climb Interactable 컴포넌트를 추가하여 오르기 기능을 구현 
- 예시: Left Side와 Right Side 밑에 여러 실린더 오브젝트를 배치하고, 각각에 Climb Interactable 추가 
- 중요: Interactable이 작동하려면 Interactor가 필요함 

### 4. XR Interactable Affordance State Provider 이해

- 설명: 인터랙션 상태를 감지하여 시각적/청각적 피드백을 제공하는 컴포넌트의 역할을 학습 
- 예시: Ignore Hover, Ignore Select 등의 설정으로 특정 상태만 시각적으로 표시 
- 중요한 이유: UI 효과, 색상 변경, Haptic 피드백 등 다양한 상호작용 효과 구현에 활용

### 5. Color Affordance와 Material Property 설정

- 설명: 오브젝트의 색상을 변경하여 상호작용 가능 여부를 시각적으로 표시 
- 예시: 실린더에 Color Material Property Affordance Receiver와 렌더링 기능 추가 

### 6. Near-Far Interactor 복사 및 설정

- 설명: Near-Far Interactor를 XR Origin에서 복사하여 Controller에 추가 
- 예시: Sample 프리팹 폴더에서 Near-Far Interactor를 찾아 컨트롤러에 붙여넣기 
- 중요한 이유: Climb 기능이 작동하려면 적절한 Interactor가 필요

---

### 실습 / 작업 순서

1. 빈 오브젝트를 Anchor 안에 생성하고 원하는 위치로 이동 
2. Anchor의 Teleportation Anchor 컴포넌트에서 Transform 지정 
3. Sample 프리팹 폴더에서 Ladder 프리팹 찾기 
4. Ladder 프리팹을 씬에 배치 
5. Multi Floor Ladder도 씬에 추가 
6. Ladder 구조 분석: Handles > 실린더들 > Climb Interactable 확인 
7. XR Origin > Sample > 프리팹 폴더에서 Near-Far Interactor 찾기 
8. Near-Far Interactor를 복사하여 Controller 하위에 붙여넣기 
9. 테스트 진행

### 예시와 활용 사례

- 예시 1: Teleportation Anchor 활용
  - 상황: 목표물 앞으로 정확하게 이동하고 싶을 때 
  - 설명: Anchor Transform을 목표물 앞이나 옆으로 설정하여 정확한 위치로 이동
  - 왜 이 예시를 사용했는지: Area나 Anchor를 적절히 활용하면 게임에서 다양한 이동 방식 구현 가능 
- 예시 2: 사다리 구조 분석
  - 상황: Ladder 프리팹의 내부 구조 이해 
  - 설명: Bottom/Middle/Top Anchor로 3개의 앵커 위치 관리, Left Side/Right Side에 각각 Handles 배치
  - 왜 이 예시를 사용했는지: 사다리가 아닌 암벽 등 다른 오르기 시스템을 만들 때도 같은 원리 적용 가능 
- 예시 3: XR Interaction Toolkit의 암기 방식
  - 상황: 다양한 컴포넌트와 시스템이 있어 복잡함 
  - 설명: 각 컴포넌트가 무엇을 하는지 종목만 알고, 응용하는 방식으로 학습
  - 왜 이 예시를 사용했는지: XR Interaction Toolkit은 거의 암기가 필요하며, 기본 개념을 알면 응용 가능

### 헷갈릴 수 있는 부분

- 헷갈리는 개념: Climb Interactable과 Simple Interactable 
- 헷갈리는 이유: 처음에 Simple Interactable을 추가했다가 Remove Component 함
- 구분 방법: 사다리 오르기는 Climb Interactable을 사용해야 함
- 헷갈리는 개념: XR Interactable Affordance State Provider의 역할 
- 헷갈리는 이유: 이름이 복잡하고 직접적인 기능을 수행하는 것처럼 보임
- 구분 방법: 실제 기능을 수행하는 것이 아니라 상태를 감지해서 시각적으로 알려주는 중재자 역할만 함
- 헷갈리는 개념: 사다리 오르기와 텔레포트의 관계 
- 헷갈리는 이유: 겉으로는 기어서 올라가는 것처럼 보임
- 구분 방법: 실제로는 텔레포트를 이용해서 가까운 앵커 지점으로 순차적으로 이동하는 방식

## 1. XR Climb Interactable 구현

<b>좋음. 거의 맞음.</b>

다만 “컨트롤러 변화량만큼 XR Origin을 이동한다”보다 <b>컨트롤러 이동의 반대 방향으로 XR Origin을 이동한다</b>고 쓰면 더 정확해.

Unity 공식 문서에서도 Climb locomotion은 Climb Interactable을 Select 중인 Interactor의 움직임에 대해 <b>XR Origin을 반대로 이동</b>시키는 방식이며, 실제 XR Origin 이동은 <b>Climb Provider</b>가 처리한다고 설명해.

다듬으면 이렇게:


<blockquote markdown="1">


플레이어가 컨트롤러로 손잡이나 사다리 같은 <code>XR Climb Interactable</code>을 Select하면, 해당 Interactable을 잡은 Interactor의 이동량이 등반 입력으로 사용된다.

손이 아래로 움직이면 몸은 위로 올라가야 하므로, <code>Climb Provider</code>는 컨트롤러 이동 방향의 반대 방향으로 <code>XR Origin</code>을 이동시킨다.

즉 <code>XR Climb Interactable</code>은 등반 가능한 대상과 기준 Transform을 제공하고, <code>Climb Provider</code>는 실제 플레이어 리그인 <code>XR Origin</code>의 위치를 변경하여 등반 이동을 구현한다.

## 2. XR Grab Interactable Attach Transform

<b>핵심은 맞는데, 원인 설명이 부족해.</b>

지금 답안은 “해결법” 위주라서, 문제에서 요구한 <b>Snap movement의 원인</b>을 더 써야 해.

<code>Attach Transform</code>을 설정하지 않으면 Unity는 해당 Interactable 오브젝트의 Transform 위치를 기본 부착점으로 사용해. 그래서 오브젝트의 피벗이나 중심점이 실제 손잡이 위치와 다르면, 잡는 순간 컨트롤러의 Attach 지점에 맞춰 물체가 갑자기 이동하거나 회전하는 Snap이 생길 수 있어. <code>Attach Ease In Time</code>은 이 부착 전환을 부드럽게 만드는 시간값이야.

다듬으면 이렇게:


<blockquote markdown="1">


<code>XR Grab Interactable</code>에서 <code>Attach Transform</code>을 지정하지 않으면, 오브젝트 자신의 Transform 위치가 기본 부착점으로 사용된다.

이 위치가 실제 손으로 잡아야 하는 그립 위치와 다르면, 물체를 Select하는 순간 컨트롤러의 Attach 위치에 맞춰 물체가 갑자기 이동하거나 회전하는 Snap movement가 발생한다.

이를 해결하기 위해 물체의 자식으로 빈 GameObject를 만들고, 손잡이로 잡히길 원하는 위치와 회전에 배치한 뒤 <code>Attach Transform</code> 필드에 연결한다.

필요하면 <code>Attach Ease In Time</code>을 조절해 잡히는 순간의 스냅 느낌을 완화할 수 있으며, 카메라를 가리는 경우에는 Attach 위치와 회전을 조정해 물체가 손에 자연스럽게 잡히도록 보정한다.

</blockquote>


여기서 네가 쓴 \*\*“Attach용 빈 오브젝트 만들기”\*\*는 아주 좋은 포인트야.

다만 “Z축을 조정한다”보다는 <b>위치와 회전을 조정한다</b>가 더 안전한 표현이야.

## 3. XR UI Interaction Canvas 설정

<b>좋음. 거의 제출해도 됨.</b>

<code>Tracked Device Graphic Raycaster</code> 정답도 맞아.

조금 더 완성하려면 <code>World Space Canvas</code>, <code>XR UI Input Module</code>, <code>XR Ray Interactor의 UI Interaction</code>까지 같이 적어주면 좋아. XRI에서 XR UI는 World Space Canvas에 <code>Tracked Device Graphic Raycaster</code>를 추가해 3D 트래킹 디바이스가 UI를 하이라이트하고 선택할 수 있게 하며, Event System에는 XR 입력을 처리할 Input Module이 필요해.

다듬으면 이렇게:


<blockquote markdown="1">


VR 환경에서 월드 스페이스 Canvas와 상호작용하려면 기존 <code>Graphic Raycaster</code> 대신 <code>Tracked Device Graphic Raycaster</code>를 사용한다.

이 컴포넌트는 XR 컨트롤러나 손처럼 3D 공간에서 추적되는 디바이스가 쏘는 레이를 Canvas의 UI 요소에 대한 Raycast로 처리한다.

이후 Event System의 <code>XR UI Input Module</code>을 통해 Hover, Select, Click 같은 UI 이벤트로 전달되어 버튼, 슬라이더, 토글 등을 조작할 수 있다.

또한 <code>XR Ray Interactor</code> 쪽에서는 UI Interaction 옵션이 활성화되어 있어야 한다.

</blockquote>

## 4. Interaction Layer Mask 활용

<b>방향은 맞는데, 중요한 주의점 하나가 필요해.</b>

<code>Interaction Layer Mask</code>는 일반 Unity Layer나 Physics Layer랑 다른 개념이야. Interactor와 Interactable이 <b>같은 Interaction Layer를 하나 이상 공유할 때만 Hover/Select가 가능</b>해져. 공식 문서도 Interaction Layer Mask는 Hover/Select 같은 상호작용 상태를 필터링한다고 설명하고, 일반 GameObject Layer와는 별개라고 말해.

다듬으면 이렇게:


<blockquote markdown="1">


<code>Interaction Layer Mask</code>를 사용하면 Interactor와 Interactable 사이의 Hover, Select 가능 여부를 상호작용 종류별로 분리할 수 있다.

예를 들어 <code>Climb</code> Interaction Layer를 만들고, 등반 가능한 오브젝트의 <code>XR Climb Interactable</code>과 등반에 사용할 Interactor에만 해당 Layer를 설정하면 그 오브젝트는 등반 상호작용에만 반응하게 만들 수 있다.

반대로 UI는 Ray 상호작용만 받도록 Ray Interactor의 UI Interaction 설정과 Canvas의 <code>Tracked Device Graphic Raycaster</code>를 사용하고, Grab이나 Direct Interactor에서는 해당 UI용 Interaction Layer를 제외한다.

이렇게 하면 Ray, Grab, Climb, Poke 같은 상호작용이 서로 잘못 반응하는 문제를 줄이고, 씬 안의 상호작용 규칙을 명확하게 관리할 수 있다.

</blockquote>


추가로 기억하면 좋은 점:

> <code>Interaction Layer Mask</code>는 XRI 상호작용 필터이고, <code>Raycast Mask</code>나 GameObject의 Layer는 실제 물리 Raycast/Collider 감지 범위에 영향을 준다.

이 문장 넣으면 점수 방어력이 올라가. 방패에 광택 코팅한 느낌이야. 🛡️

## 5. Hand Tracking + UI Poke

<b>기본 방향은 맞지만, 답안이 조금 짧아.</b>

<code>Hover</code>와 <code>Select</code>를 나누는 건 맞고, 여기에 <code>Poke Hover Radius</code>, <code>Poke Interaction Offset</code>, <code>XR Poke Filter</code>, UI 버튼 반응 방식을 넣으면 좋아.

<code>XR Poke Interactor</code>는 가까운 대상에 대해 찌르기 동작을 수행하는 Interactor이고, <code>Poke Hover Radius</code>는 Hover 판정 반경, <code>Poke Interaction Offset</code>은 찌르기 Select가 더 쉽게 발생하도록 하는 오프셋 역할을 해. Debug Visual에서는 Hover와 Select 구간이 서로 다른 구체로 표시돼.

또한 XRI는 Poke 기반 UGUI 상호작용을 지원하므로, 일반 UI 버튼도 별도 Collider나 Interactable 없이 누르기, 슬라이더, 토글 같은 UI 조작이 가능하다고 설명돼.

다듬으면 이렇게:


<blockquote markdown="1">


Hand Tracking으로 UI를 조작할 때는 손가락 끝, 보통 검지 끝 위치에 <code>XR Poke Interactor</code>를 배치하여 찌르기 입력을 감지한다.

<code>Poke Hover Radius</code>는 손가락이 UI에 가까워졌을 때 Hover로 판정되는 범위를 정하고, <code>Poke Interaction Offset</code>이나 <code>XR Poke Filter</code>는 특정 방향과 깊이로 충분히 눌렀을 때 Select가 발생하도록 보정한다.

사용자가 손가락을 UI 버튼 가까이에 가져가면 Hover 상태가 되고, 버튼 표면을 일정 깊이 이상 찌르면 Select 또는 Click 이벤트가 발생한다.

이 이벤트는 <code>Tracked Device Graphic Raycaster</code>와 <code>XR UI Input Module</code>을 통해 Unity UI Button의 Highlight, Pressed, OnClick 반응으로 연결된다.

</blockquote>

1. <b>XR Climb Interactable 구현의 핵심 원리</b>
   <p>
   <b>Unity 6의 XRI 3.0에서 </b><b><code>XR Climb Interactable</code></b><b>을 사용하여 등반 시스템을 구축할 때, 사용자의 컨트롤러 이동량을 실제 플레이어 캐릭터(XR Origin)의 위치 변화로 변환하기 위해 필요한 물리적 메커니즘과 Climb Provider의 역할에 대해 설명하시오.</b>
   </p>

   <p>
   플레이어가 손(컨트롤러)로 손잡이를 <b>잡고(Select)</b> 컨트롤러를 위/아래로 움직이면  XR Climb Interactable이 현재 잡은 손잡이를 기준으로 컨트롤러의 변화량을 추적하고 Climb Provider가 그 변화량 만큼 <b>XR Origin의 위치를</b> 변환해서 몸이 올라가는 것을 구현한다.
   </p>
2. <b>XR Grab Interactable의 Attach Transform 최적화</b>
   <p>
   <b><code>XR Grab Interactable</code></b><b> 컴포넌트에서 Attach Transform 필드를 명시적으로 설정하지 않았을 때, 런타임에서 물체를 잡는 순간 발생하는 현상(Snap movement)의 원인과 이를 해결하여 자연스러운 ‘그립(Grip)’ 위치를 지정하는 방법을 기술하시오.</b>
   </p>

   <p>
   <b>Attach용 빈 오브젝트를 만들어 Z축 등 위치를 조정한다.</b>
   </p>

   <p>
   카메라 가림 문제가 있으면 <b>Attach를 뒤로 배치</b>해서 해결한다.
   </p>

   <p>
   Attach Ease In Time으로 잡히는 속도(스냅 느낌 완화)도 조절한다.
   </p>
3. <b>XR UI Interaction을 위한 Canvas 설정</b>
   <p>
   <b>VR 환경에서 월드 스페이스(World Space)에 배치된 Canvas와 상호작용하기 위해, 기존의 </b><b><code>Graphic Raycaster</code></b><b> 대신 반드시 추가해야 하는 컴포넌트의 명칭을 쓰고, 해당 컴포넌트가 XR Ray Interactor의 신호를 어떻게 처리하는지 설명하시오.<br /><br />Tracked Device Graphic Raycaster</b>
   </p>

   <p>
   기존 Graphic Raycaster는 “마우스/일반 포인터” 중심이라 XR 디바이스(트래킹된 컨트롤러/레이) 입력을 제대로 받기 어려우므로 Tracked Device Graphic Raycaster 를 사용해서  XR Ray Interactor 같은 <b>트래킹 디바이스 포인터</b>가 쏘는 레이를 UI hit test에 사용해서 Event System으로 전달해 <b>Hover/Click(Select) 같은 UI 이벤트</b>가 발생하도록 한다.
   </p>
4. <b>Interaction Layer Mask의 활용</b>
   <p>
   <b>특정 레이어에 있는 물체는 등반(Climb)만 가능하고, 다른 레이어에 있는 UI 요소는 레이(Ray)로만 선택 가능하게 구분하려고 합니다. 이때 </b><b><code>Interaction Layer Mask</code></b><b>를 사용하여 상호작용 유형을 필터링하는 기술적 이점과 설정 과정을 설명하시오.</b>
   </p>

   <p>
   각 Interactor(Climb용, Ray용, Direct/Grab용)에 <b>Interaction Layer Mask</b>를 다르게 설정해서 특정 레이어는 Climb만 반응 UI 레이어는 Ray만 반응 하게 만든다.<br />이런 방식으로 만들게 되면 불필요한 충돌이나 오작동을 방지 할 수 있다.
   </p>
5. <b>Hand Tracking과 UI 상호작용의 결합</b>
   <p>
   <b>Unity 6 XR에서 컨트롤러가 아닌 Hand Tracking을 사용하여 UI를 조작할 때, 손가락의 ‘찌르기(Poke)’ 동작을 감지하기 위해 필요한 XR Poke Interactor의 물리적 트리거 범위 설정(Hover vs. Select)과 UI 버튼의 대응 방식에 대해 기술하시오.</b>
   </p>

   <p>
   XR Poke Interactor는 손가락 끝(또는 poke 포인트)에 콜라이더/트리거를 두고<br />Hover(근접)와 Select(임계값 이상 눌림/진입) 구간을 구분해서 Hover 와 Select를 구분하게 만든다.<br />
   </p>
