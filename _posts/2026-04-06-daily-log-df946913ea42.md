## 기본 정보

- 날짜: 2026-04-06
- 프로젝트:팀 모으미 / Moz.A.I.c (EP.3 사운드 시스템 + EP.3-3 연출/흐름)
- 작성자: 작성자

## 오늘 한 일(요약)

- 사운드 시스템 구조를 역할별로 정리하고(씬/플레이어/UI/오브젝트), 적용 흐름을 문서화했다.
- 플레이어 사운드 구조를 분리/안정화하고, 씬별 설정을 주입하는 방식으로 정리했다.
- EP.3-3 최종 연출 흐름에서 각 매니저/스크립트 책임을 재분리하고 연결 구조를 점검했다.

## 구현한 것

- 사운드 시스템 역할 분리 구조 정리
  - 씬 기본 사운드: <code>SoundProfile + SoundController</code>
  - 플레이어 사운드: <code>PlayerSound</code> (감지는 <code>PlayerMovement</code>, 재생은 <code>PlayerSound</code>)
  - UI 사운드: <code>UISoundTrigger</code>
  - 오브젝트 상호작용: <code>SoundTrigger</code>
  - 실제 재생/클립 등록: <code>SoundManager</code>
- 플레이어 사운드 안정화
  - 걷기/달리기 간격에 따라 발소리 타이밍 분리
  - 이동 잠금/슬라이딩 상태에서 발걸음 미재생 처리
  - 시작 직후 착지음 오작동 방지(초기 바닥 판정/타이머 초기화 쪽 보완)
- 씬별 플레이어 사운드 주입 구조 확장
  - <code>SoundProfile</code>에 플레이어 발걸음/점프/착지 설정값 추가
  - <code>SoundController</code>가 씬 시작 시 <code>PlayerSound</code>에 주입하도록 연결
- EP.3-3 최종 흐름 책임 재정리
  - <code>FinalPianoInteraction</code>: 피아노 상호작용 시 2곡 중 랜덤 재생, 중복 실행 방지/1회 실행/저장데이터 반영, 음악 종료 후 UnityEvent 호출 구조 정리
  - <code>FinalDialogueController</code>: “이벤트 종료 여부 + 출구 콜라이더 개방/제어” 중심으로 단순화(다른 책임과 분리)
  - <code>Ep3_3Manager</code>: 3-3 진행 기록/결과 보고 후 엔딩 판정 흐름 연결 재확인
  - <code>Ep_3Manager</code>: 3-1\~3-3 결과 누적 → 기억 재구성률/필수 태그로 노멀/진엔딩 판정 구조 재확인

## 배운 것(개념/정리)

- 사운드는 단순 재생 기능이 아니라, “씬 단위/플레이어/상호작용/UI”처럼 <b>역할을 분리한 구조 설계</b>가 유지보수와 확장에 핵심이다.
- 프리팹은 기능(컴포넌트)만 유지하고, 씬마다 달라지는 값은 <code>SoundProfile</code> 같은 외부 설정으로 <b>주입하는 패턴</b>이 프로젝트 규모가 커질수록 안정적이다.
- 기능 구현보다도 스크립트의 책임을 명확히 쪼개야(예: 출구 개방 vs 결과/엔딩 판정) 연결 흐름이 단순해지고 디버깅이 쉬워진다.
- Unity에서는 코드 로직뿐 아니라 인스펙터 연결/UnityEvent 호출 순서까지 포함해 “실제 동작 흐름”을 설계해야 한다.

## 이슈/버그

- 내용: 인스펙터 세팅(클립 등록/이벤트 연결) 항목이 많아지면서 반복 세팅 시간이 크게 늘고, 연결 실수 가능성이 커졌다.
- 원인/가설: SFX/풋스텝 enum 및 항목 증가로 관리 포인트가 급증했고, 씬별/오브젝트별로 연결해야 하는 레퍼런스가 많아졌다.
- 해결/시도: 역할 분리를 더 명확히 하고(가이드 문서화 포함), 씬 시작 시 주입 구조(SoundProfile→SoundController→PlayerSound)로 “변경 지점”을 한 곳으로 모으는 방향으로 정리했다.
- 다음 액션: EP.3-3은 <code>FinalPianoInteraction.onMusicFinished</code>에 연결할 함수/순서(예: 출구 개방, 스테이지 완료 보고 등)를 확정하고, 씬에서 플레이 테스트로 중복 호출/타이밍 문제를 검증한다.

## 내일 할 일

- EP.3-3 씬에서 UnityEvent 연결(특히 <code>onMusicFinished</code>) 함수 목록/순서 고정하고 실제 플레이 테스트
- 출구 개방 타이밍/중복 호출/엔딩 연출 타이밍 문제 발생 여부 확인 및 수정
- 풋스텝 사운드: 씬 기본 발소리 → (가능하면) 바닥 재질 분기/전환 방식 구현 방향 구체화
