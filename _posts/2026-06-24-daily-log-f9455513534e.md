## 🎯 개발 비전 (Vision)

플레이어의 피드백과 편의성을 극대화하기 위해 기존의 단순 드롭 방식 상자에서 컨테이너 인터페이스 방식으로 전환하고, 인게임 파밍 프로세스의 기획 완성도를 높여 코어 루프의 게임플레이 경험을 프리미엄하게 완성하는 것을 비전으로 삼습니다.

---

## 📌 오늘의 목표

- [x] <code>ItemBox</code> 상호작용 및 파밍 구조 변경 (<code>드롭 박스 -&gt; 컨테이너 박스</code> 구조로 개편)
- [x] 상자 내부 아이템 저장을 위한 <code>BoxItemEntry</code> 데이터 구조 도입
- [x] 가중치 기반 랜덤 아이템 생성을 위한 <code>BoxLootOption</code> 구조 설계 및 구현
- [x] <code>ChestUI</code> 및 <code>ChestSlotUI</code> 신규 추가 및 레이아웃(좌측: 인벤토리 / 우측: 체스트) 연동
- [x] 우클릭 입력을 통한 상자 슬롯 아이템의 플레이어 인벤토리 자동 이동 기능 구현
- [x] <code>InventoryPresenter</code>가 상자 UI와 인벤토리 UI를 함께 제어할 수 있도록 중재 로직 연동
- [x] 입력 액션맵(<code>Player</code> ↔ <code>UI</code>) 전환 시스템 구축
- [x] <code>PlayerInventory.AddItem()</code> 메서드 개선 (실제 습득 수량 차감 및 초과 잔여분 보존 반환 처리)

## ✅ 완료한 작업

### 1. <code>ItemBox</code> 역할 변경 및 데이터 저장 구조화

<ul>
<li>
<b>내용</b>: 

- 플레이어가 상자와 상호작용할 때 즉시 바닥에 아이템을 생성하고 상자가 파괴되던 기존 로직을 제거했습니다.
- 상자 내부에 아이템 데이터(<code>BoxItemEntry</code>)를 리스트 형태로 직접 보유하여 유지되도록 변경하였습니다.
</li>
<li>
<b>결과</b>: <code>List&lt;BoxItemEntry&gt; items</code> 구조를 채택하여 상자가 사라지지 않고 내부 보관함 역할을 수행하는 컨테이너 구조의 기반을 확보했습니다.
</li>
</ul>

### 2. 상자 아이템 데이터 및 랜덤 루팅 옵션 분리

- <b>내용</b>:
  - <b><code>BoxItemEntry</code></b><b> 클래스</b>: 상자 내부의 특정 슬롯 1칸을 표현하는 데이터 클래스로, <code>ItemData</code> 에셋 레퍼런스와 아이템 수량(<code>amount</code>)을 포함합니다.
  - <b><code>BoxLootOption</code></b><b> 클래스</b>: 인펙터에서 상자 생성 시 랜덤 획득 후보군(아이템 에셋, 등장 가중치, 최소/최대 수량)을 조정할 수 있는 설정 클래스입니다.
- <b>결과</b>: 상자 생성 시점(<code>useRandomLoot == true</code>)에 <code>lootOptions</code>의 가중치를 계산하여 내부 <code>items</code> 데이터를 자동으로 빌드하는 <code>GenerateRandomItems()</code> 기능 처리가 가능해졌습니다.

### 3. 체스트 UI (<code>ChestUI</code> & <code>ChestSlotUI</code>) 신규 구현

- <b>내용</b>:
  - 상자의 보유 아이템을 시각적으로 렌더링하고 유저 입력을 처리하는 UI 프레임워크를 개발했습니다.
  - 상자 내부의 아이템 종류 수에 맞춰 동적으로 <code>ChestSlotUI</code>를 생성하고, 개별 아이템 아이콘 및 수량을 새로고침(<code>RefreshAll()</code>)하도록 연동했습니다.
- <b>결과</b>: 좌측 인벤토리, 우측 체스트 UI의 이중 배치 레이아웃 구현 및 비주얼 피드백 시스템을 준비했습니다.

### 4. 우클릭 이동 로직 및 <code>PlayerInventory.AddItem()</code> 고도화

- <b>내용</b>:
  - 체스트 슬롯 우클릭 감지 시 <code>ChestUI.TryMoveToInventory(slotIndex)</code>를 실행합니다.
  - <code>PlayerInventory.AddItem()</code>이 아이템 스택 누적 및 빈 슬롯 삽입 후 <b>실제로 인벤토리에 들어가지 못하고 남은 수량</b>을 정확하게 반환하도록 로직을 수정했습니다.
- <b>결과</b>: 인벤토리가 가득 찰 경우 수용 가능한 만큼만 인벤토리로 이동하고, 남은 수량은 상자에 그대로 유지되는 정밀한 파밍 이동 처리를 구현했습니다. 아이콘 비동기 로드 이후에도 UI 갱신 이벤트가 올바르게 재전파됩니다.

### 5. <code>InventoryPresenter</code> 및 입력 액션맵 제어 통합

- <b>내용</b>:
  - <code>InventoryPresenter</code>가 상자 오픈 이벤트(<code>OnItemBoxOpened</code>)를 구독하여 상자 UI와 인벤토리 UI를 동시에 개폐 및 동기화하도록 중재자 패턴을 확장 적용했습니다.
  - 상자가 열렸을 때 <code>LocalInputReader</code>를 통해 액션맵을 <code>UI</code> 모드로 전환하여 조작계 혼선을 차단하고, 닫힐 때 다시 <code>Player</code> 액션맵으로 복귀시킵니다.
- <b>결과</b>: UI 연동 상태에서의 마우스 커서 활성화 및 플레이어 조작 잠금 처리를 안정적으로 수행합니다.

## 🔄 진행 중인 작업 (아직 남아 있는 작업)

- <b>드래그 앤 드롭(Drag & Drop)</b>: 마우스 드래그를 이용한 인벤토리 ↔ 체스트 슬롯 간 직접적인 아이템 이동 기능 구현.
- <b>인벤토리 포화 시 바닥 드롭 처리</b>: 상자와 인벤토리가 모두 가득 찬 상태에서 아이템 이동 시, 초과분이 월드 바닥에 프리햅 형태로 드롭되는 예외 처리.
- <b>단축키 UI 닫기 바인딩</b>: <code>F</code> 키 또는 <code>ESC</code> 키 입력 시에도 UI 액션맵 바인딩을 통해 통합 UI 창이 정상적으로 닫히도록 입력 매핑 검증.
- <b>테스트용 상자 프리셋 설정</b>: 인스펙터 상에서 <code>items</code> 또는 <code>lootOptions</code>에 드롭 프리팹(<code>_Drop.prefab</code>) 대신 <code>ItemData</code> 에셋(<code>testHealMedicine.asset</code> 등)이 올바르게 할당되도록 점검 및 조율.

## ⚠️ 주의 사항 및 핵심 규칙


<b>아이템 데이터 레퍼런스 규칙</b><br />

- 상자 내부에 직접 설정하는 데이터는 월드 드롭용 프리팹(예: <code>testHealMedicine_Drop.prefab</code>)이 절대 아니어야 합니다.<br />
- 반드시 데이터 정보만을 담고 있는 <b><code>ItemData</code></b><b> ScriptableObject 에셋(예: </b><b><code>testHealMedicine.asset</code></b><b>, </b><b><code>testManaPiece.asset</code></b><b>, </b><b><code>testMemoryPiece.asset</code></b><b>)</b>을 직접 바인딩해야 정상 작동합니다.
