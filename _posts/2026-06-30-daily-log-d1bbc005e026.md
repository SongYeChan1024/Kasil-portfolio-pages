## ✅ 완료한 작업

### 1) 퀵슬롯 유지(세션 전환) 관점에서 데이터 파이프라인 점검

- <b>내용</b>
  - 로비 → 인게임 → 결과창으로 상태가 이동할 때, 퀵슬롯 구성이 어디에서 “진실(SoT)”로 관리되는지(저장 시점/로드 시점/중간 캐시)를 기준으로 흐름을 다시 확인했습니다.
  - UI에서 슬롯 설정이 바뀌는 순간과, 실제 인게임에서 소비/사용되는 순간 사이의 갭(동기화 타이밍)을 리스크로 보고 체크 포인트를 정리했습니다.
- <b>결과</b>
  - “세션 경계(씬 전환/결과창 진입/로비 복귀)마다 <b>명시적으로 Save/Load가 한번씩 일어나야 안정적</b>”이라는 기준을 다시 세웠습니다.
- <b>관련 파일(점검 대상)</b>
  - GameManager.cs
  - ResultManager.cs
  - (퀵슬롯 UI/데이터) Quickslot 관련 스크립트들

---

### 2) 인벤토리/체스트 UI 오픈 상태에서 입력 처리 안전성 체크

- <b>내용</b>
  - 상자 UI가 열릴 때/닫힐 때 액션맵(Player ↔ UI) 전환과 커서 상태, 플레이어 조작 잠금이 “항상 되돌아오는지”를 중심으로 흐름을 점검했습니다.
  - 인벤토리/체스트 이동 함수들이 예외 상황(부분 이동/실패)에서도 UI 갱신이 일관되게 일어나도록, Refresh 단위(전체/슬롯 단위) 적용 기준을 메모했습니다.
- <b>결과</b>
  - 입력/상태 전환은 “닫힐 때 복구”가 누락되면 연쇄 버그가 나기 쉬우므로, 닫기 트리거(ESC/F/버튼/거리 이탈 등)를 모두 동일한 Close 경로로 묶는 게 핵심이라고 정리했습니다.
- <b>관련 파일(점검 대상)</b>
  - InventoryPresenter.cs
  - ChestUI.cs
  - LocalInputReader.cs (또는 입력 전환 담당)
