## 요약

### 실습 과제

- [ ] 시네머신을 이용한 카메라 쉐이크 구현  
- [ ] 에너미 패트롤(순찰) 기능 구현  
- [ ] Assembly Definition 파일 설정 및 컴파일 최적화  
- [ ] A\* Pathfinding 알고리즘 프로젝트 실습  
- [ ] 2D/3D Pathfinding 프로젝트 분석  

### 드럼통 폭파 카메라 쉐이크 구현

- 시네머신을 이용한 카메라 쉐이크 구현으로 이전 방식(카메라 직접 흔들기)보다 간단해짐 
- Virtual Camera에 Cinemachine Impulse Listener 추가 
  - Extensions에서 Cinemachine Impulse Listener 선택
  - Noise 설정, Channel Mask를 Everything으로 설정 
  - Reaction Settings에서 6D Shake 선택 (6방향 흔들림)  
  - Amplitude Gain, Frequency Gain, Duration 값 조정 (Duration은 5 정도)  
- Barrel 프리팹에 Cinemachine Impulse Source 추가  
  - 진동을 발생시키는 컴포넌트 역할
  - Channel을 Everything으로 설정 
- Barrel Script에서 Hit Count가 3이 되었을 때 Impulse 실행 

### 에너미 패트롤 시스템

- Patrol Area와 Patrol Point 설정으로 순찰 경로 구성   
- Enemy Move Agent 스크립트 생성 및 구현  
- NavMeshAgent를 이용한 길찾기 구현  
  - Auto Braking을 false로 설정 (목적지 근처에서 속도 감소 방지) 
  - Agent Speed를 1.5로 설정 (Animator의 Blend Tree 설정과 동일)  
- Patrol Point 데이터 수집 방법  
  - GameObject.Find로 Patrol Area 찾기
  - GetComponentsInChildren으로 하위 Transform 수집
  - List를 사용하여 Waypoint 관리
  - 첫 번째 요소(부모) 제거: <code>wayPoints.RemoveAt(0)</code>  

### Assembly Definition 파일

- <b>사용 이유</b>: 스크립트가 많아질수록 컴파일 시간이 길어지는 문제 해결  
  - 대규모 프로젝트에서 스크립트가 400\~800개 이상일 때 변수 하나만 수정해도 전체 재컴파일로 인한 시간 소요
  - 폴더별로 분리하여 수정된 어셈블리만 재컴파일 
- <b>구현 방법</b>  
  - Common, Enemy, Player, Stage 폴더별로 Assembly Definition 생성
  - 각 폴더에 .asmdef 파일 생성 (예: CommonAD, EnemyAD, PlayerAD, StageAD)
- <b>의존성 설정</b>  
  - Assembly Definition Reference에 필요한 패키지 추가
  - PlayerAD: Unity.InputSystem 추가  
  - StageAD: Cinemachine.Runtime 추가  
- DLL(Dynamic Linked Library) 형태로 컴파일되어 Library/ScriptAssemblies에 저장  

### AI Navigation 주요 용어

- <b>Geometry(지오메트리)</b>: 지형을 의미   
- <b>Walkable Area</b>: 장애물을 판단하여 지나갈 수 있는 영역 
- <b>NonWalkable Area</b>: 장애물을 판단하여 지나갈 수 없는 영역
- <b>OffMeshLink</b>: 끊어진 메시를 연결, 점프 기능 구현에 사용  
- <b>Bake</b>: 네비게이션 메시 구축 과정  
- <b>Polygon → 3D Mesh</b>: 폴리곤이 3D 메시로 변환   

### A\* Pathfinding 알고리즘

- 실시간(런타임)으로 최단 거리를 계산할 때 사용하는 알고리즘    
- Asset Store에서 관련 프로젝트 학습 권장  
  - A\* Pathfinding Project (무료)
  - 2D Grid Pathfinding
  - 3D Flexible Pathfinding
- 포트폴리오 면접 시 경험 여부 질문 가능성 있음  

### 스크립트 구조 정리

- Scripts 폴더를 Enemy, Player, Stage, Common으로 분류

스크립트 컴파일과 어셈블리 정의 컴파일

유니티는 해당 프로젝트의 스크립트 관리는 어셈블리 (Managed Assembly)에 컴파일한다.

유니티는 프로젝트의 C# 스크립트를 컴파일하여 .NET 관리 코드(Managed) 어셈블리(DLL)로 만든다.

스크립트의 개수가 많아질수록 컴파일 시간이 길어진다.

즉 아주 빈번하게 수정되는 조그만 스크립트 하나 때문에 매번 컴파일 시간이 길어진다.대규모 프로젝트에서는 매누 치명적인 단점 중 하나였다

이를 개선하기 위해서 어셈블리 정의 파일을 사용해서 별도의 어셈블리로 분리할 수 있는 기능을 제공한다.

어셈블리 정의 파일(Assembly Definition files)

Unity는 기본적으로 프로젝트의 모든 C# 스크립트를

하나의 기본 어셈블리(<code>Assembly-CSharp.dll</code>)로 컴파일한다.

그래서

- 스크립트 수가 많아질수록
- 코드 의존성이 복잡해질수록
- 작은 파일 하나만 수정해도

<p>
 전체 어셈블리가 다시 컴파일된다.
</p>

즉, 아주 작은 스크립트 하나를 자주 수정하더라도

프로젝트 전체가 다시 컴파일되기 때문에

대규모 프로젝트에서는 빌드 대기 시간이 매우 길어지는 문제가 있었다.

---

<h3>
 해결 방법: 어셈블리 정의 파일(Assembly Definition)
</h3>

이를 개선하기 위해 Unity는

<b>Assembly Definition File(.asmdef)</b> 기능을 제공한다.

이 기능을 사용하면:

- 스크립트를 여러 개의 별도 어셈블리로 분리할 수 있고
- 특정 어셈블리만 독립적으로 컴파일되도록 만들 수 있다.

그 결과,

✔ 수정된 어셈블리만 재컴파일

✔ 전체 컴파일 시간 단축

✔ 의존성 관리 명확화

✔ 대규모 프로젝트 구조 개선

### NavMesh Agent와 Waypoint 순환 시스템

- Next IDX를 증가시켜 웨이포인트를 순환하는 방식 구현 
- Remaining Distance를 체크하여 목적지 도착 판단  
- 목적지에 가까워지면 Next IDX를 증가시킴  
- 모듈로(%) 연산자를 사용하여 인덱스 순환 처리  
  - 웨이포인트 카운트가 10개일 때, 인덱스가 10이 되면 다시 0으로 순환  
  - 나머지 연산으로 배열 범위를 초과하지 않도록 처리
- Distance 체크를 통한 목적지 도착 판단 방법도 가능하나 자원을 더 소모함  

### Required Component 사용법

- <code>[RequireComponent(typeof(NavMeshAgent))]</code> 속성을 사용하여 필수 컴포넌트 지정  
- NavMeshAgent가 없으면 스크립트가 작동하지 않도록 설정
- 실수로 필수 컴포넌트를 삭제하는 것을 방지  
- 개발 중 실수를 방지하기 위한 안전장치 
- Animator도 Required Component로 지정  

### Enemy AI 상태 시스템 구현

- Enum을 사용한 상태 정의: Patrol(0), Trace(1), Attack(2), Die(3)  
  - 숫자 대신 Enum을 사용하여 가독성 향상 
- 상태에 따른 애니메이션 재생  
  - Patrol: 걷기 애니메이션
  - Trace: 달리기 애니메이션
  - Attack: 총 쏘는 애니메이션
  - Die: 죽는 애니메이션
- 기본 상태는 Patrol로 설정 

### 거리 기반 상태 전환 로직

- 플레이어와 적 사이의 거리를 계산하기 위해 Transform 변수 필요  
  - Player Transform과 Enemy Transform 저장
- 공격 거리(Attack Distance): 5미터 설정  
- 추적 거리(Trace Distance) 설정  
- 거리가 공격 범위 안에 들면 Attack 상태로 전환 
- 거리가 추적 범위 안에 들면 Trace 상태로 전환 
- 범위 밖이면 Patrol 상태 유지  

### 태그와 레이어 설정

- Player 태그 설정  
- Enemy 태그와 레이어 생성   
- 자식 오브젝트까지 레이어 적용 (Yes, change children) 
- 충돌 감지 매트릭스 설정  
  - Player, Bullet, Enemy, Wall 등과의 충돌 설정

### Coroutine을 활용한 최적화

- CheckState와 Action을 별도의 코루틴으로 분리  
- CheckState: 0.3초마다 상태 체크   
  - <code>yield return ws</code> (Wait for seconds)로 제어권 반환
  - 메모리와 제어권을 효율적으로 관리
- Action: 0.4초 대기 후 실행 
  - CheckState는 0.3초 안에 실행, Action은 0.4초 후 실행으로 분산 처리 
- IsDie 체크를 통해 사망 시 로직 중단   
  - 죽은 상태에서 계속 추적하는 버그 방지

### Unity Lifecycle 메서드

- Awake와 Start는 한 번만 호출됨 
- OnEnable은 오브젝트가 활성화될 때마다 호출  
- OnDisable은 비활성화될 때 호출 
- 오브젝트 풀링에서 OnEnable/OnDisable 활용 

### 초기화 설정

- Awake에서 Wait for Seconds 한 번만 생성  
  - 코루틴 실행 시마다 new로 생성하지 않고 재사용
- FindWithTag로 플레이어 찾기 
- Enemy Transform은 자기 자신으로 설정 
- OnEnable에서 CheckState 코루틴 시작
