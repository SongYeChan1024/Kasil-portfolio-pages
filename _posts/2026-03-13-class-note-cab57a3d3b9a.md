### 2) Unity + Photon: 좀비 서바이벌 네트워킹 구현

<b>실습 준비</b>

- ColorSerializationClass 다운로드 후 Scripts 폴더에 추가
- 다음 수업 준비 안내 확인 및 자료 다운로드

<b>Photon 핵심 개념</b>

- Photon 라이브러리: Unity ↔ 서버 통신 통로
- SDK: 클라이언트 통신 규칙/기능 묶음
- 데이터가 오가는 방식(통신 구조) 이해가 핵심

<b>마스터 클라이언트</b>

- 방 만든 사람이 마스터 클라이언트
- 마스터만 적을 생성하고, 나머지는 정보를 받는 구조로 최적화
- 마스터가 “남은 적 수/웨이브 수” 등 핵심 데이터를 관리해 송신

<b>직렬화/역직렬화 (ColorSerialization)</b>

- 직렬화: Color → byte 배열 변환 후 전송
- 역직렬화: byte → Color 복원
- 레벨 변경 등으로 색이 바뀔 수 있어 동기화 필요

<b>구현 체크 포인트</b>

- EnemySpawner:
  - 마스터만 Update 실행
  - 코루틴으로 일정 시간 후 <code>PhotonNetwork.Destroy</code> 처리
- 생성:
  - <code>PhotonNetwork.Instantiate</code> 사용
  - Prefab은 Resources 폴더에 있어야 함
  - RPC 타겟은 All로 보내 모두 동기화
- GameManager:
  - PlayerHealth Find/이벤트 등록은 Instantiate 이후에 (순서 중요: “태어나기 전에 찾으면 오류”)
- Awake:
  - Color 타입(128) 직렬화/역직렬화 등록 + 에러 체크

<b>빌드/테스트</b>

- Build Settings: 로비 씬을 맨 위, 메인 씬 그 다음
- 로비에서 시작해야 토큰 생성 + 마스터 서버 연결
- 빌드 실행파일 + 유니티 에디터 동시 실행으로 멀티 테스트

<b>설계 포인트: LivingEntity 상속</b>

- 플레이어/적 공통 로직(데미지/HP/사망) 중복 제거
- 공통 기능은 LivingEntity로 올리고, 각 클래스는 고유 기능만 처리

### AI 게임 적용 사례 분석

강사는 게임에서의 AI 활용 사례로 DeepSeek을 언급하며, GPT보다 기능이 부족하지만 대화형 AI를 기반으로 구성했다고 설명했다.   

<b>아이온2의 전투 시스템 분석</b>:  

- PVP와 PVE 전투 시스템이 프로그래머의 뛰어난 구현 능력으로 완성되었다
- 파티 구성에 따라 보스의 기믹과 패턴이 달라지는 시스템 
- 직업군(탱커, 힐러, 버퍼 등)에 따른 차별화된 전투 경험 

<b>어그로 시스템</b>:   

- 힐러를 보호하기 위한 전략적 시스템
- 과거에는 수동적이었으나 현재는 기믹과 패턴 형태로 자동화
- 특정 던전에서는 힐러의 부활 스킬만 작동하도록 설계되어 힐러의 중요성 강조 

### AI 활용 게임 개발 사례

<b>앵그리버드 8시간 재현 프로젝트</b>:  

- ChatGPT, Gemini, Claude 등 AI 도구만으로 게임 재현 
- Unity 엔진과 AI를 활용하여 포토샵이나 일러스트 없이 개발 
- 그래픽 에셋, 스프라이트 처리, 코딩까지 모두 AI가 처리  

<b>밸로란트 맵 AI 구현</b>: 

- 해외 틱톡커가 AI로 밸로란트 맵(펄, 스플릿, 로터스, 선셋)을 구현
- AI로 생성된 맵에 비 효과를 추가하여 높은 완성도 달성

### 프로젝트 AI 적용 방안

<b>추천 AI 기능</b>:  

- 튜토리얼 시스템에 AI 적용
- 대화형 AI를 통한 플레이 방법 안내 (음성 또는 텍스트)
- ChatGPT나 Gemini API 연동을 통한 간단한 구현도 가능
- 학습된 AI를 통한 맞춤형 가이드 제공 

<b>NPC AI 봇 시스템</b>:  

- 1인 게임 플레이어를 위한 AI 파티원 제공
- 카운터 스트라이크처럼 난이도 조절 가능한 AI 봇  
- 파티 압박감을 느끼는 유저들을 위한 솔루션  
- GPT 기반 대화 기능 탑재 가능 

<b>AI 튜토리얼 및 가이드</b>:  

- 던전 패턴과 기믹 설명 제공
- 텍스트 또는 음성으로 실시간 안내
- 특정 패턴 발동 시 대화 및 음성 가이드 
- 초보자도 쉽게 접근할 수 있는 상세한 튜토리얼  

### 프로젝트 요구사항 및 기대 수준

<b>필수 요구사항</b>:  

- 이전 컴투스 공모전 수상작 이상의 비주얼과 게임 시스템
- Unity 기능의 75-80% 활용 수준

- AI에 과도하게 집중하지 말고 전체적인 게임 완성도에 초점

<b>장르 권장사항</b>:

### 개발 프로세스 및 팀워크

<b>팀 협업 중요성</b>:

### 개발 도구 및 자료

### Photon 네트워킹 기본 개념

- <b>Exit Games Client Photon 라이브러리 역할</b>: Unity 게임 엔진과 Photon 서버 사이에서 데이터를 주고받는 통로 역할   
- <b>SDK (Software Development Kit)</b>: Photon Fusion 설치 시 포함된 C# 라이브러리 클라이언트로, 서버와의 직접적인 통신 규칙을 정의  
- <b>데이터 통신 방식</b>: 게임과 서버 사이에서 데이터가 왔다갔다 하는 통로 

### 마스터 클라이언트 시스템

- <b>마스터 클라이언트 개념</b>: 처음 방을 만든 사람이 마스터 클라이언트가 됨 
- <b>데이터 전송 방식</b>: 마스터 클라이언트가 남은 적 수와 현재 웨이브 수 정보를 가지고 있다가 다른 클라이언트들에게 송신 
- <b>적 생성 최적화</b>: 마스터 클라이언트만 적을 생성하고 나머지는 정보를 받는 방식으로 구현  

### 직렬화/역직렬화 (ColorSerialization)

- <b>직렬화 (Serialization)</b>: Color 데이터를 byte 배열로 변환하여 네트워크로 전송   
- <b>역직렬화 (Deserialization)</b>: byte 데이터를 다시 Color로 변환하여 수신  
- <b>필요성</b>: 레벨이 변경되면 색깔도 변경될 수 있어 네트워크를 통해 색깔 정보를 주고받아야 함 
- <b>Color 타입 코드</b>: 128 (바이트 단위로 변환)  
- <b>패킷 단위</b>: 1024 바이트가 1 패킷 

### EnemySpawner 스크립트 수정사항

- <b>Start 메소드</b>: <code>StartCoroutine</code>을 사용하여 Enemy GameObject를 5초 후에 <code>PhotonNetwork.Destroy</code>로 네트워크상에서 제거  
- <b>Update 메소드</b>: 마스터 클라이언트만 직접 실행하도록 조건 추가  
- <b>UpdateUI 메소드</b>: Enemy 카운터와 리스트 정보 업데이트 

### CreateEnemy 메소드 수정

- <b>RPC 타겟</b>: RPC 타겟을 All로 설정하여 모든 클라이언트에 전달 
- <b>Photon Instantiate 사용</b>: 게임 오브젝트 생성 시 <code>PhotonNetwork.Instantiate</code> 사용 
- <b>리소스 폴더 필수</b>: Player Prefab은 반드시 Resources 폴더에 있어야 <code>PhotonNetwork.Instantiate</code>가 찾을 수 있음 

### GameManager 스크립트 중요 수정

- <b>Start 메소드 순서 주의</b>: PlayerHealth를 찾아서 이벤트 등록하는 코드가 <code>PhotonNetwork.Instantiate</code>보다 아래에 위치해야 함   
- <b>오류 발생 이유</b>: PlayerHealth 컴포넌트를 찾는 코드가 인스턴스 생성보다 먼저 실행되면 찾을 수 없어 오류 발생   
- <b>코드 순서의 중요성</b>: 순서도 중요하며, 태어나기 전에 찾으려고 하면 오류 발생 

### Awake 메소드 추가

- <b>ColorSerialization 등록</b>: Awake에서 Color 타입(128)에 대한 직렬화/역직렬화 메소드 등록   
- <b>에러 체크</b>: 자동완성이 안되거나 빨간줄이 생기면 잘못된 것 

### 빌드 및 테스트

- <b>빌드 세팅</b>: 로비 씬을 맨 위로, 메인 씬을 그 다음으로 배치  
- <b>시작 위치</b>: 로비에서 시작해야 토큰이 생성되고 마스터 서버와 연결됨  
- <b>멀티플레이 테스트</b>: 빌드한 실행파일과 Unity 에디터에서 동시에 실행하여 멀티플레이 테스트  
- <b>Player Character Clone 확인</b>: 양쪽 모두에서 Player Character Clone이 생성되어 만남  

### 핵심 개념: LivingEntity 상속

- <b>코드 중복 문제</b>: 플레이어와 적 모두 데미지 받고, HP 깎이고, 죽는 로직이 중복됨  
- <b>해결 방법</b>: LivingEntity 클래스를 만들어 공통 기능을 상속받고, 각 클래스에서는 고유 기능만 처리   
- <b>PlayerHealth 예시</b>: 기본 기능은 상속받고, UI 슬라이더만 별도로 처리 
- <b>이전 프로젝트 개선</b>: Unity TPS 게임의 코드 중복을 IDamageableInterface 상속과 MovingEntityClass 상속으로 해결 가능
