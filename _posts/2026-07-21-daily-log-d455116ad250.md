## 진행한 작업

### 1. 에너미 피격 플래시 적용

- <code>EnemyStatus</code>에 개체 단위 실제 피해 이벤트를 추가했습니다.
- <code>EnemyVisible</code>이 피격된 다크 스피릿의 AnyPortrait 색상만 밝은 보라색으로 바꾸도록 구현했습니다.
- 공유 머티리얼을 수정하지 않아 다른 에너미나 캐릭터의 렌더링에 영향을 주지 않게 했습니다.
- 현재 시야 알파를 유지해 숨어 있던 적이 피격 순간 잘못 노출되지 않도록 했습니다.
- 연속 피격과 비활성화 시 남아 있는 플래시 코루틴과 색상을 정리하도록 구성했습니다.

### 2. 피격 경직과 공격 중 히트 스톱 분리

- 일반 행동 중 피격되면 NavMeshAgent 이동과 AI 목적지 갱신을 잠시 멈추도록 했습니다.
- 공격 중에는 공격 상태, 콤보, 돌진을 취소하지 않고 애니메이터 재생만 짧게 정지시켰습니다.
- <code>EnemyMovement</code>의 피격 정지 요청을 <code>EnemyPresenter</code>가 <code>EnemyAnimator</code>에 전달하도록 역할을 분리했습니다.
- 애니메이터 정지는 <code>unscaledTime</code>을 사용해 게임 시간 배율과 관계없이 종료되도록 했습니다.
- 연속 피격 재적용 간격을 두어 에너미가 무한 경직되는 상황을 방지했습니다.
- 코드 기본값은 일반 경직 0.08초, 공격 히트 스톱 0.04초입니다.
- 현재 다크 스피릿 프리팹의 실제 값은 피격 플래시 0.1초, 일반 경직 0.3초, 공격 히트 스톱 0.1초, 재적용 간격 0.1초입니다.

### 3. 피격 시 플레이어 인식과 상태 정합성 보강

- 에너미가 실제 피해를 받으면 활동 반경 안에서 가장 가까운 유효 플레이어를 즉시 전투 타겟으로 등록하도록 했습니다.
- 피해 이벤트에 공격자 정보가 없는 현재 구조를 고려해 런타임 플레이어 목록에서 가장 가까운 대상을 찾습니다.
- 디코이 이동 타겟과 플레이어 전투 타겟을 분리했습니다.
- 디코이가 활성화된 동안에는 디코이 우선순위를 유지하고, 디코이가 끝나면 저장된 플레이어 타겟으로 복귀합니다.
- 피격 반응이 활동 반경과 복귀 규칙을 무시하지 않도록 추격 범위 조건을 유지했습니다.
- 공격 중 피격된 경우 공격 코루틴을 유지하며, 비공격 상태에서만 Chase 상태를 즉시 갱신합니다.

### 4. 다수 에너미 겹침 현상 완화

- 플레이어 주변에 여러 접근 슬롯을 만들고 개체 ID를 기준으로 서로 다른 슬롯을 선택하도록 했습니다.
- 접근 지점은 NavMesh 샘플, 완전 경로, 벽 차단, 활동 반경 조건을 통과한 경우에만 사용합니다.
- 공격 거리 안에 들어온 에너미가 플레이어 중심점까지 계속 파고들지 않도록 정지 조건을 추가했습니다.
- 개체 고유값을 기준으로 NavMeshAgent의 <code>avoidancePriority</code>를 분산했습니다.
- 다크 스피릿 프리팹은 접근 반경 3.5, Agent Radius 0.7, 회피 우선순위 40\~60을 사용합니다.
- 랜덤 배회, 디코이, 마지막 확인 위치, 순찰·복귀 목적지에는 분산 접근 지점을 섞지 않았습니다.

### 5. 에너미 처치 보상 상자 구현

- <code>SpawnManager</code>가 스폰된 각 에너미의 로컬 사망 이벤트를 한 번만 구독하도록 했습니다.
- 확률 판정을 통과하면 에너미 사망 위치를 NavMesh 지면으로 보정한 뒤 <code>ItemBox_Enemy</code>를 생성합니다.
- 생성된 상자는 에너미가 속한 씬으로 이동시켜 Additive 씬 구조와 정합성을 유지합니다.
- 현재 씬별 실제 드롭 확률은 다음과 같습니다.
  - <code>DemoScene</code>: 25%
  - <code>DemoScene Additive</code>: 25%
  - <code>DemoScene Patrol</code>: 20%
  - <code>DemoScene Tutorial</code>: 비활성
- <code>ItemBox_Enemy</code>는 3\~5종을 생성합니다.
- 카테고리 가중치는 Memory/Consume/Artifact 40/40/20입니다.
- 아티팩트 등급 가중치는 40/30/15/10/5로 기본 상자보다 고등급 보상을 강화했습니다.

### 6. 튜토리얼 확정 보상 상자 구현

- <code>ItemBox</code>에 랜덤 보상과 분리된 <code>FixedLootOption</code> 구조를 추가했습니다.
- 확정 목록은 아이템 TID와 수량을 JSON 저장소에서 찾아 상자 슬롯에 채웁니다.
- <code>ItemBox_Tutorial</code>은 랜덤 생성을 사용하지 않습니다.
- 현재 확정 지급 목록은 다음과 같습니다.
  - TID 301 × 5
  - TID 302 × 5
  - TID 401 × 1
  - TID 1001 × 1
- 튜토리얼 데모 씬의 기존 박스를 튜토리얼 전용 프리팹으로 교체했습니다.
- 튜토리얼에서는 적 사망 상자 드롭을 비활성화해 확정 학습 보상과 랜덤 보상이 섞이지 않게 했습니다.

### 7. 아이템 카테고리 직렬화 정합성 보강

- <code>itemCategory</code>의 각 값을 0\~6으로 명시했습니다.
- 열거형 선언 순서가 바뀌더라도 기존 씬, 프리팹, ScriptableObject의 카테고리 값이 밀리지 않도록 했습니다.
- 기본 상자와 테스트 아이템 데이터의 기존 직렬화 값을 현재 열거형 번호에 맞게 동기화했습니다.

- 캐릭터 수집·해금·감상 흐름, UI 이미지 리소스 개선 방향 등 본인 담당이 아닌 범위는 제외했습니다.
- 개발 상세 화면에는 현재 Unity 소스와 개인 커밋을 확인해 다음 핵심 코드를 발표용 코드 패널로 정리했습니다.
  - NavMesh 도달 가능 지점만 사용하는 꿈식자 랜덤 순찰
  - 튜토리얼 이벤트 진행과 팝업 종료 후 입력 복구
  - 튜토리얼 UI·월드 대상 하이라이트
  - 인벤토리 장착 가능 슬롯 하이라이트
  - 총구 VFX와 짧은 실시간 Light를 함께 사용하는 머즐 플래시
- 기본 FSM은 기존 기반 확장, AI 모듈 분리·2연격은 공동 영역, 튜토리얼은 기획안 기반 구현으로 기여 범위를 명시했습니다.
- <code>[PM]송예찬_02_에너미AI_인터랙티브.html</code>은 스폰 시작부터 순찰·감지·조사·추격·공격·탐색·복귀까지 상태별 설명을 확인하는 대표 결과물 페이지로 정리했습니다.
- 두 발표 HTML의 연결 파일, 상세 항목 수, 이미지 경로와 JavaScript 문법을 확인했습니다.
- 현재 변경은 발표 자료 피드백을 위한 로컬 문서 작업이며, 별도 Git 커밋으로 확정하지 않았습니다.

## 이슈 및 주의할 점

- 에너미 상자 드롭은 코드 기본값 20%와 별개로 주력 Demo 씬 두 곳에 25%가 직렬화되어 있습니다.
- 다크 스피릿의 경직·히트 스톱도 코드 기본값보다 프리팹 직렬화 값이 크게 설정되어 있으므로 실제 플레이 감각은 프리팹 값을 기준으로 판단해야 합니다.
- 접근 슬롯은 벽, 좁은 통로, 활동 반경 경계에서 직접 추격으로 fallback될 수 있습니다.
- 에너미 보상 상자는 현재 Instantiate 방식이며, 반복 전투에서 생성 비용이 문제가 되면 오브젝트 풀 연결을 검토해야 합니다.
- 아티팩트 해제는 특정 인벤토리 슬롯이 아닌 첫 빈 슬롯을 사용하므로 현재 개별 드롭 대상 강조와 동작 방식이 다릅니다.
- <code>DemoScene Additive.unity</code>와 <code>ItemBox.prefab</code>은 사용자 커밋 이후 팀원 변경도 포함하므로 현재 파일 전체를 개인 작업으로 기록하면 안 됩니다.
- 기능 동결 전에는 새 구조 추가보다 기존 상태 전환, 드롭 확률, 프리팹 직렬화 값의 회귀 확인이 우선입니다.

## 배운 점

- 피격 피드백은 색상 플래시와 경직을 하나의 상태 변경으로 묶기보다 렌더링, 이동, 애니메이션 책임으로 분리해야 공격 흐름을 안전하게 유지할 수 있습니다.
- 공격 중 경직은 AI와 NavMeshAgent를 멈추기보다 애니메이터만 짧게 멈추는 편이 기존 콤보 정합성을 보존하기 쉽습니다.
- 디코이와 플레이어를 하나의 타겟 변수로 덮어쓰면 디코이 종료 후 추적 흐름이 끊길 수 있으므로 이동 우선 타겟과 전투 타겟을 분리해야 합니다.
- 다수 에너미의 겹침은 Agent Radius 하나만 키우기보다 접근 목적지 분산과 회피 우선순위 분산을 함께 사용해야 완화됩니다.
- 확률 상자와 튜토리얼 확정 상자는 같은 ItemBox를 사용하더라도 생성 정책과 프리팹 설정을 분리해야 안전합니다.
- UI 하이라이트는 별도의 유사 판정을 만들기보다 실제 드롭 이벤트가 선택한 대상을 그대로 표시해야 플레이어에게 정확한 정보를 줄 수 있습니다.
- 코드 변경 기록은 커밋 메시지만 사용하지 않고 실제 프리팹·씬 직렬화 값을 함께 확인해야 런타임 설정을 정확히 남길 수 있습니다.
- 긴 코드 전문은 인덱스와 파일별 하위 문서로 분리한 뒤 Git 원본과 재대조해야 누락 여부를 검증하기 쉽습니다.
