### <b>프로젝트 목표 및 결과</b>

---

1. <b>초기 목표</b>
   - 에피소드 단위로 퍼즐과 스토리를 연결해 “기억 회복” 경험을 만들기
   - AI NPC 상호작용을 포함한 힐링 포인트앤클릭/어드벤처 경험 구현
   - 팀원이 맡은 에피소드들을 하나의 프로젝트로 통합해 “완주 가능한 빌드”를 제출하기
2. <b>최종 결과물</b>
   - EP.3 구간(3-1/3-2/3-3) 퍼즐과 연출, 이동/문 상호작용 흐름을 연결해 플레이 가능한 빌드를 완성
   - 사운드 시스템을 SoundManager 중심으로 정리하고, UI/플레이어/오브젝트 상호작용 사운드 분리 적용
   - 최종 발표에서 EP.3-2 퍼즐 리뉴얼(리듬 퍼즐)과 동기화/판정 구조를 핵심 사례로 공유
3. <b>목표 대비 성과 (정량 / 정성 지표)</b>
   - 정량(예시):
     - EP.3 퍼즐 3개 구간(3-1/3-2/3-3) 완료 및 연출/이동까지 연결
     - 사운드 분류(BGM/Ambient/UI/SFX) 기반으로 적용 범위 확대
   - 정성:
     - “각 기능”이 아니라 “플레이 경험의 흐름”을 기준으로 마감/안정화에 집중하면서 완성도를 끌어올림
     - 리뉴얼/트러블슈팅 과정에서 시스템 구조를 문서화하고 재사용 가능한 체크리스트 형태로 정리

### <b>스크럼 회고</b>

---

1. <b>협업 방식 (스크럼 주기, 사용한 도구, 회의 운영 방식)</b>
   - Notion 기반으로 기획/진행 상황/회고 기록
   - GitHub로 협업(브랜치/머지) + Discord로 커뮤니케이션
   - 발표/FGT/최종 발표 일정 기준으로 기능 우선순위 조정 및 마감
2. <b>잘 진행된 점</b>
   - 에피소드 단위로 역할이 분리되어 있어, 병렬로 개발한 뒤 통합하는 방식이 명확했다.
   - 문서화(사운드 구조, EP.3 퍼즐 흐름/연출, 트러블슈팅)가 잘 되어 통합/마감 단계에서 커뮤니케이션 비용이 줄었다.
3. <b>개선이 필요했던 점</b>
   - 마감 직전에는 시스템 간 연결(퍼즐/컷씬/세이브/사운드)이 강하게 얽혀 있어서, 작은 변경도 연쇄 이슈를 만들 수 있었다.
   - “플레이 테스트로 끝까지 검증” 루틴을 더 앞 단계부터 강제했으면, 마지막에 발견되는 오류(세이브/상호작용 충돌)를 줄일 수 있었을 것 같다.

### <b>프로젝트 기여</b>

---

1. <b>담당 기능 / 모듈</b>
   - <b>EP.3-1 (Melody)</b>
     - 악보 조각 수집 퍼즐 흐름 구현(랜덤 스폰, 수집 판정, 완료 후 피아노 상호작용/연출 연결)
   - <b>EP.3-2 (Rhythm)</b>
     - 점프맵 → <b>탑다운 5레인 리듬 퍼즐</b>로 리뉴얼
     - 채보/입력/판정/점수/라이프 규칙 및 UI, 클리어 후 이동 연출 연결
     - 음악 싱크 보정(초반 구간 보정, 판정 윈도우 조정 등) 중심 트러블슈팅
   - <b>EP.3-3 (Harmony)</b>
     - 테이블/하모니 심볼/피아노/문 상호작용 동선 재정리
     - 기억 회복 흐름이 마지막 연출로 자연스럽게 이어지도록 연결
   - <b>사운드 시스템</b>
     - SoundManager 중심으로 구조 정리(BGM/Ambient/UI/SFX)
     - PlayerSound / UISoundTrigger / SoundTrigger로 역할 분리하여 유지보수성 개선
     - 씬별 기본 사운드 적용 구조를 점검하고(일부 switch-case 등) 딕셔너리 기반 리팩토링 방향 정리
   - <b>마감 안정화</b>
     - 상호작용 우선순위 충돌, 씬 전환 연출 연결, 세이브 플래그 누락/직렬화 충돌 이슈 점검 및 수정
2. <b>사용한 기술 스택</b>
   - Unity(프로젝트 기준 2022 LTS 계열 사용), C#
   - Cinemachine(연출/컷씬), JSON 기반 데이터(세이브 등)

3. <b>핵심 코드 또는 산출물 (스크린샷·코드블록 첨부)</b>

### <b>트러블슈팅 모음</b>

---

1\) <b>EP.3-2 리듬 퍼즐 싱크/판정 안정화</b>

1. 문제 상황 파악
   - 입력 타이밍과 음악/비트맵 기준 시간이 어긋나 체감 싱크가 깨지는 구간이 발생
2. 문제 발생 조건 파악
   - 재생 시작 시점/초반 구간 보정 부족, 판정 윈도우(허용 범위) 설정이 플레이 체감과 맞지 않음
3. 결과 검증, 해결
   - 초반 구간 기준 시점 보정 + 판정 윈도우 재조정
   - 플레이 테스트로 체감 싱크를 반복 검증하며 안정화

2\) <b>세이브 데이터 누락/덮어쓰기(초기화처럼 보이는 현상)</b>

1. 문제 상황 파악
   - 특정 플래그가 파일에 저장되지 않아 진행 상태가 되돌아가는 것처럼 보임
   - 씬에 직렬화된 예전 데이터가 런타임 세이브를 덮어써 초기화처럼 보이는 케이스 발생
2. 문제 발생 조건 파악
   - 저장 경로에서 누락된 상태값 존재
   - 씬에 남아 있는 직렬화 데이터와 현재 저장 데이터의 우선순위 충돌
3. 결과 검증, 해결
   - 누락 플래그를 저장 대상에 포함하도록 보완
   - 씬 직렬화 데이터가 현재 세이브를 덮어쓰지 않도록 처리해 데이터 신뢰성 확보

3\) <b>시스템 연결부(상호작용 우선순위/연출 트리거)에서 발생하는 연쇄 이슈</b>

1. 문제 상황 파악
   - 퍼즐/컷씬/문 활성화/사운드가 연결된 구간에서 한쪽 수정이 다른 쪽 동작을 깨는 문제 발생
2. 문제 발생 조건 파악
   - 상호작용 조건(선행 퍼즐 완료 여부)과 트리거 호출 타이밍이 구간별로 분산되어 있음
3. 결과 검증, 해결
   - 흐름을 “조건 → 행동 → 연출” 순으로 재정리하고, 연결 지점을 체크리스트화하여 회귀 테스트

---

1. <b>Keep — 계속 가져갈 점</b>
   - 기능을 “경험의 흐름”으로 연결해 완성하는 관점
   - 시스템 구조(사운드/퍼즐/세이브)를 문서화하고 팀이 공유 가능한 형태로 남기는 습관
   - 마감 직전이라도 플레이 테스트로 끝까지 검증하는 루틴
2. <b>Problem — 아쉽거나 문제였던 점</b>
   - 마지막 구간에서 통합/마감 이슈가 한꺼번에 몰리며 디버깅 비용이 커졌다.
   - 플랫폼/씬/직렬화 등 “한 번 꼬이면 추적이 어려운 영역”을 더 일찍부터 관리했으면 좋았을 것 같다.
3. <b>Try — 다음 프로젝트에서 시도할 점</b>
   - 상태/세이브/연출 트리거를 더 명확히 분리하고, 변경에 강한 구조(데이터 드리븐/테스트 시나리오)를 초반부터 설계
   - 기능 완료 기준에 “회귀 테스트 체크리스트 통과”를 포함

---

1. <b>새로 학습한 기술</b>
   - 리듬 퍼즐(비트맵/입력/판정/점수) 구조 설계 및 싱크 보정 접근
