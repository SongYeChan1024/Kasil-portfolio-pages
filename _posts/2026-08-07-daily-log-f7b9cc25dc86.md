## 진행한 작업

### 1. 튜토리얼 구현 명세 완성

- TUT-00 기상부터 TUT-08 게이트 폐쇄와 현실 복귀까지 장면 목표, 공간 연출, 성공 트리거와 재시도 규칙을 상세화했습니다.
- 기억 투영형 도깨비와 영혼 주입형 도깨비의 행동·연출·드롭을 분리했습니다.
- 보스 <code>사람을 죽인 도깨비 — 월도</code>를 세 페이즈와 결박핵 해체·영혼 안정화 과정으로 구성했습니다.
- 토벌팀 5인의 시체·기록·장비가 게이트 진입과 전멸 과정을 공간적으로 설명하도록 배치했습니다.
- 수납 모듈 파괴 중에도 폐쇄 인증과 영혼 결박 파편이 보호되는 진행 불가 방지 규칙을 정했습니다.
- A\~G 레벨 구역을 그레이박스 요구, 전투 역할과 체크포인트 단위로 분해했습니다.

### 2. Unity 게임 저장소 출범

- 비공개 GitHub 저장소 [ERGOSQUARE-ARCHITECT](https://github.com/SongYeChan1024/ERGOSQUARE-ARCHITECT)를 생성했습니다.
- 로컬 <code>C:\GitHubProjects\ERGOSQUARE-ARCHITECT</code>에 Unity <code>6000.3.7f1</code> 프로젝트를 만들었습니다.
- <code>main</code> 브랜치에 첫 커밋 <code>8911e12 chore: initialize Unity project</code>를 생성하고 원격 저장소에 푸시했습니다.
- Unity 전용 <code>.gitignore</code>와 <code>.gitattributes</code>를 적용해 <code>Library</code>, <code>Temp</code>, <code>Logs</code>, <code>UserSettings</code>와 IDE 생성 파일을 제외했습니다.
- 프로젝트 README에 첫 프로토타입 범위와 [문서 저장소](https://github.com/SongYeChan1024/Document_ERGOSQUARE-ARCHITECT)를 연결했습니다.

### 3. Codex 프로젝트 구성

- Unity 저장소를 Codex 프로젝트의 <b>기본 폴더</b>로 변경했습니다.
- 문서 저장소는 <b>보조 폴더</b>로 유지해 하나의 작업에서 기획과 구현을 함께 확인할 수 있게 했습니다.
- 새 작업의 기본 Git·작업트리·PR 대상은 Unity 저장소가 되고, 두 저장소는 각자의 Git 이력을 유지합니다.

### 4. Git과 작업트리 운영 판단

- 초기에는 영구 작업트리를 만들지 않고 짧은 기능 브랜치를 하나씩 개발합니다.
- <code>main</code>은 언제든 Unity에서 열 수 있는 안정 상태로 유지합니다.
- 첫 구현 브랜치는 <code>codex/tutorial-foundation</code>을 후보로 정했습니다.
- 장기 병렬 실험이 필요할 때만 영구 작업트리를 도입합니다.
- Unity 작업트리마다 <code>Library</code>가 따로 생성되어 디스크와 임포트 비용이 증가하는 점을 고려합니다.

### 5. Unity 구조 방향

```txt
Assets/_ERGOSQUARE/
├─ Core/          부트스트랩·이벤트·저장·공통 유틸리티
├─ Gameplay/      플레이어·전투·AI·에르고스퀘어·아이템·게이트
├─ Content/       도깨비 튜토리얼과 개별 게이트
├─ Presentation/  카메라·UI·VFX·오디오
├─ Editor/        프로젝트 전용 에디터 도구
└─ Tests/         EditMode·PlayMode 테스트
```

- 외부 에셋은 <code>Assets/ThirdParty</code>로 분리합니다.
- 공용 시스템과 <code>Content/Tutorial_Dokkaebi</code>의 전용 콘텐츠를 분리합니다.
- 최초 씬은 <code>Bootstrap</code>, <code>CombatSandbox</code>, <code>Tutorial_Dokkaebi</code>를 기준으로 합니다.

## 문제와 판단

### 기획 문서만으로 구현 착수가 어려운 문제

시나리오와 세계관은 정리됐지만 트리거, 드롭, AI, 실패 처리와 체크포인트가 흩어져 있었습니다. 상세 플롯, 아이템·드롭, 몬스터·보스를 독립 명세로 만들고 상위 문서는 링크와 책임만 유지했습니다.

### 문서와 게임 소스를 한 저장소에서 관리할 때의 충돌

문서와 Unity 프로젝트는 추적 대상과 변경 주기가 다릅니다. 두 GitHub 저장소로 분리하고 README와 Codex 다중 폴더로 연결했습니다.

### 영구 작업트리를 지금 만들지 여부

영구 작업트리는 장기 병렬 작업에는 유용하지만 Unity 캐시가 작업트리마다 생깁니다. 현재는 한 방향의 튜토리얼 프로토타입이 우선이므로 로컬 기능 브랜치 방식으로 시작합니다.
