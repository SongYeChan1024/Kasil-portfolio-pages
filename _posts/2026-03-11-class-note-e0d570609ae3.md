### 다형성과 오버라이드 개념

- <b>다형성(Polymorphism) 활용</b>: 모든 생명체는 데미지를 입고 체력이 감소하며 사망하는 공통 기능을 부모 클래스에 구현 [^{{notes}}]
- 상속받는 자식 클래스는 부모의 기능을 물려받음 [^{{notes}}]
- 플레이어와 좀비 몬스터처럼 서로 다른 타입을 하나의 타입(Living Entity)으로 묶어서 관리 [^{{notes}}]
- <b>오버라이드를 통한 확장</b>: 부모 클래스의 기본 메서드를 자식 클래스에서 확장하여 추가 기능 구현   

### Enemy 스크립트 초기 설정

- Enemy 스크립트에서 Head Target까지 구현 완료 
- Setup 메서드로 적 AI의 초기 스펙 결정  
- 랜덤 값으로 체력, 공격력, 이동속도, 색깔 등을 다르게 설정   
- 랜덤 설정으로 강한 좀비(높은 체력, 빠른 속도, 강한 공격력)가 생성될 수 있음 

### Update 코루틴 구현

- Update 밑에 코루틴 추가: <code>UpdatePath()</code>  
- 0.25초 간격으로 살아있는 동안 반복 실행  
- Animator와 AudioSource 컴포넌트 설정  
- Hash 값으로 Animator 파라미터 참조: <code>hashDie</code>, <code>hashIsTarget</code> 등   

### Skinned Mesh Renderer 처리

- 좀비는 Mesh Renderer가 아닌 Skinned Mesh Renderer 사용   
- Skinned Mesh Renderer는 4-5년 전에 많이 사용되었던 컴포넌트 
- 자식 오브젝트에 있으므로 <code>GetComponentInChildren</code> 사용  

### NavMesh와 AI 구현

- <b>NavMesh(내비메시)</b>: 에이전트가 걸어다닐 수 있는 표면 [^{{notes}}]
- <b>NavMesh Agent</b>: 내비메시 위에서 경로를 계산하고 이동하는 컴포넌트 [^{{notes}}]
- <b>NavMesh Obstacle</b>: 에이전트 경로를 막는 장애물 [^{{notes}}]
- <b>Off-mesh Link</b>: 끊어진 내비메시 영역을 연결 (울타리 타고 오르기 등) [^{{notes}}]

### 추적 대상 찾기 구현

- <code>Physics.OverlapSphere</code>로 반경 20 내의 플레이어 탐지   
- What Is Target에 Player 레이어 설정  
- Player Character에 Player 레이어 부여  
- 네트워크 게임에서는 플레이어가 여러 명일 수 있으므로 배열로 처리 
- Collider 배열을 순회하며 Living Entity 컴포넌트 검색   
- 하나의 추적 대상만 찾으면 루프 탈출하여 왔다갔다 하는 현상 방지  

### Target Entity 초기화 과정

- Target Entity는 명시적 초기화 없이 런타임에 결정됨  
- <code>OverlapSphere</code>로 플레이어를 찾은 후 Living Entity를 Target Entity에 할당   

### NavMesh Agent 경로 설정

- <code>agent.destination</code> 또는 <code>agent.SetDestination()</code> 메서드 사용 가능  
- destination은 Property이며 둘 다 같은 기능  
- <code>SetDestination</code> 메서드의 반환값은 bool 타입 
- 추적 대상이 없으면 이동 멈춤  

### OnDamage 오버라이드

- 베이스 OnDamage는 데미지 감소와 체력 감소만 처리 
- 오버라이드된 OnDamage에서 <b>Blood Impact 효과</b> 추가 
- Blood Spray Hit 파티클 효과 재생   
- Hit Sound 재생  
- <code>Quaternion.LookRotation</code>으로 타겟 방향 바라보기  
- Hit Normal 계산: 발사 위치에서 맞은 위치를 뺀 벡터 

### Quaternion vs Euler 각도

- <b>Quaternion.LookRotation</b>: 그쪽 방향으로 계속 바라보는 회전   
- <b>Euler 각도</b>: 딱딱 정해진 각도로 회전 (예: 45도씩 회전)   

### Die 메서드 구현

- 사망 시 모든 Collider 비활성화   
- Collider 복수 처리를 위해 <code>GetComponents&lt;Collider&gt;()</code> 사용 (배열 반환)  
- Box Collider와 Capsule Collider 모두 비활성화 
- NavMesh Agent 정지: <code>agent.isStopped = true</code>  
- Die 애니메이션 재생: <code>animator.SetTrigger(hashDie)</code> 
- Death Sound 재생 

### OnTriggerStay 공격 구현

- Box Collider 안에 머물러 있을 때 공격 실행   
- 공격 간격 체크: <code>Time.time &gt; lastAttackTime + timeBetAttack</code>   
- Target Entity와 Attack Target 비교  
- 충돌 지점 계산: <code>Vector3 hitPoint = other.ClosestPoint(transform.position)</code>  
- 충돌 방향 계산: <code>transform.position - other.transform.position</code>  
- <code>attackTarget.OnDamage</code> 호출하여 데미지와 충돌 정보 전달  

### 이벤트와 액션 델리게이트

- 이벤트를 사용하여 강한 커플링 해소하고 코드 간결화 [^{{notes}}]
- <b>Action 델리게이트 선언</b>: <code>public event Action onDie;</code>   
- Action은 반환형이 void이고 매개변수가 없는 델리게이트의 간단한 표현 
- 기존 delegate 방식: <code>public delegate void OnDieDelegate(); public event OnDieDelegate onDie;</code> 

### 입력 시스템 변경 (키보드 → 마우스)

- 기본 설정: AD 키로 좌우 회전 
- 마우스 회전으로 변경: Player Input의 Look을 Mouse Delta로 설정  
- Input System에서 Player Input 컴포넌트 설정 
- <code>OnLook</code> 메서드 추가하여 Look 입력 처리  

### Layer 설정

- Player Character에 Player 레이어 설정   
- Zombie의 What Is Target을 Player 레이어로 지정  
- Layer Mask를 통해 특정 레이어만 감지 

### UI 슬라이더

- UI 슬라이더 사용 예정 (향후 구현) [^{{notes}}]

### 코드 구조 및 주의사항

- 괄호 짝 맞추기: 괄호 클릭 시 짝이 하이라이트됨 
- 자동완성 시 복수형(s) 주의: <code>GetComponents</code> (배열 반환) vs <code>GetComponent</code> (단일 반환)  
- 느낌표(!)로 부정 표현: <code>!dead</code>는 살아있다는 의미  
- <code>GetComponentInChildren</code> 사용 시 자식 오브젝트의 컴포넌트 검색

### 익명 함수 (Anonymous Functions)

- <b>익명 함수</b>: 이름이 없는 함수로, 한 번 잠깐 쓰려고 만들 때 자주 사용  
- <b>두 가지 주요 형태</b>:
  - <b>delegate</b> (옛날 스타일): <code>button.onClick.AddListener(delegate () { Debug.Log("클릭"); });</code>
  - <b>람다식</b> <code>=&gt;</code> (최근 스타일): <code>button.onClick.AddListener(() =&gt; { Debug.Log("클릭"); });</code>  
- Unity에서 버튼 클릭, 이벤트 등록, 간단한 콜백 처리에 많이 사용됨
- 람다식은 수학식에서 따온 개념으로, 이름 없이 한 번 쓰고 버릴 때 사용 

### Mathf.Lerp (Linear Interpolation)

- <b>Lerp</b>: Linear Interpolation의 줄임말로, 두 값 사이를 비율만큼 보간 
- <b>형태</b>: <code>Mathf.Lerp(a, b, t)</code> (a: 시작값, b: 끝값, t: 0\~1 사이 비율)
- <b>예시</b>: <code>Mathf.Lerp(0f, 10f, 0.5f)</code> = 5 (중간값)
- <b>t 값의 의미</b>:
  - t = 0: 시작값 반환
  - t = 1: 끝값 반환
  - t = 0.5: 중간값 반환
- <b>중요 포인트</b>: Lerp는 "속도"가 아니라 "비율"임 - 전체 구간의 비율만큼 이동
- <b>활용 예시</b>: 체력바 부드럽게 줄이기, 카메라 부드럽게 따라오기, 오브젝트 천천히 이동, 볼륨 조절, 회전/크기 값 부드럽게 변경
- 반복 적용 시 목표값에 점점 가까워지는 효과 (처음 1만큼 증가 → 0.9 증가 → 0.81 증가...)

## <code>Mathf.Lerp</code>란?

<code>Lerp</code>는 <b>Linear Interpolation</b>의 줄임말

뜻은 두 값 사이를 <b>비율만큼 보간한다</b>는 뜻

형태:

```cs
Mathf.Lerp(a, b, t);
```

- <code>a</code> : 시작값
- <code>b</code> : 끝값
- <code>t</code> : 0 \~ 1 사이 비율

예시:

```cs
float result = Mathf.Lerp(0f, 10f, 0.5f);
Debug.Log(result);
```

<br />이건 <code>0</code>에서 <code>10</code> 사이의 <b>50% 지점이라는 뜻</b>

결과:

```cs
5
```

# <code>t</code> 값에 따라 결과가 어떻게 바뀌냐

```txt
Mathf.Lerp(0f,10f,0f);// 0
Mathf.Lerp(0f,10f,0.25f);// 2.5
Mathf.Lerp(0f,10f,0.5f);// 5
Mathf.Lerp(0f,10f,1f);// 10
```

즉:

- <code>t = 0</code> 이면 시작값
- <code>t = 1</code> 이면 끝값
- <code>t = 0.5</code> 이면 중간값

# 어디에 쓰냐

유니티에서는 이런 데 자주 씀

- 체력바가 부드럽게 줄어들 때

- 오브젝트가 천천히 이동할 때
- 볼륨이 서서히 커지거나 작아질 때
- 회전값, 크기값을 부드럽게 바꿀 때

# 중요한 포인트

## <code>Lerp</code>는 “속도”가 아니라 “비율”

많이 헷갈리는 부분

```cs
Mathf.Lerp(0f,10f,0.1f);
```

이건 0에서 10으로 <b>0.1만큼 이동</b>이 아니라,

<b>전체 구간의 10% 지점</b>으로 가는 것

결과는 <code>1</code> .

# 한 줄 요약

<code>Mathf.Lerp(a, b, t)</code>는

<b>시작값 a에서 끝값 b까지 t 비율만큼의 값을 반환하는 함수.</b>

a는 시작값, b는 목표값, t는 비율 이라고 생각하면<br />a = 10, b= 20, t = 0.1 일 때 처음은 1만큼 증가 남은거리 9 그래서 0.9 증가 그이후 남은거리 8.1 그래서 0.81 만큼 증가 이런식으로 20에 가까워지게 된다

# 카메라 Rendering Path

카메라의 <b>Rendering Path</b>는 화면을 렌더링하는 방식을 결정한다.

## 1. Use Graphics Settings

프로젝트의 <b>Graphics Settings 설정을 따라 자동으로 렌더링 방식이 결정</b>된다.

일반적으로 기본 설정은

```txt
Forward Rendering
```

이다.

---

## 2. Forward Rendering

특징

- 렌더링 방식이 <b>가볍고 성능이 좋다</b>
- <b>모바일 게임에서 많이 사용</b>
- 하지만 <b>조명 표현이 제한적</b>이다.

즉

```txt
성능 좋음
하지만 라이팅 표현이 단순함
```

---

## 3. Deferred Shading

특징

- <b>조명과 색 표현이 더 정확하다</b>
- <b>라이트가 많은 환경에서 유리하다</b>
- 대신 <b>메모리 사용량이 많고 성능이 무겁다</b>

Deferred Rendering의 동작 방식

```txt
1. 오브젝트 정보 먼저 저장
2. 조명 계산
3. 최종 화면 출력
```

즉

```txt
오브젝트 정보 → 조명 계산 → 화면 출력
```
