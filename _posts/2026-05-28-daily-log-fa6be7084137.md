## 오늘 진행한 내용(상세)

### 1) Firebase 연동 준비(빌드/패키지/필수 패키지)

- Android로 빌드 타겟을 잡고 Package Name을 설정해 Firebase 콘솔과 연결할 준비를 했다.
- Firebase를 Unity와 붙일 때 필요한 핵심 포인트를 정리했다.
  - <code>UnityMainThreadDispatcher</code>
    - Firebase 콜백은 백그라운드 스레드에서 오는 경우가 있어서, <b>Unity UI/GameObject 조작을 메인 스레드로 넘겨야</b> 크래시를 피할 수 있음
  - <code>Newtonsoft.Json (Json.NET)</code>
    - Firebase와 주고받는 데이터가 JSON 기반이라 <b>직렬화/역직렬화</b>가 필요함

### 2) UI 세팅: Canvas Scaler + Anchor로 반응형 UI 만들기

- Canvas Scaler의 목적: 해상도가 달라도 UI의 크기/비율이 망가지지 않게 전체 스케일을 잡는 것.
- 가장 자주 쓰는 모드: <b>Scale With Screen Size</b>
- Screen Match Mode 개념을 다시 정리했다.
  - Match Width or Height: 가로/세로 중 어느 쪽 기준으로 스케일을 맞출지 슬라이더로 조절
  - Expand: 잘림(Clipping) 방지, 대신 여백이 생길 수 있음
  - Shrink: 화면에 구겨 넣는 방식이라 실무에선 거의 안 씀
- UI 요소들은 Middle Center만 믿지 말고, Top Right/Top Middle 같은 <b>Anchor를 명확히 잡아야</b> 해상도 바뀔 때 위치가 유지된다.

### 3) 2D 실습 프로젝트 기획(눈 피하기)

- 게임 핵심 규칙
  - 플레이어: 가로 이동
  - 위에서 떨어지는 눈(장애물) 회피
  - 체력 100, 피격 시 데미지 20 → 5번 맞으면 Game Over
- Firebase에 저장할 데이터(방향)
  - 게임 재화(코인/돈)
  - 스코어(Score)
  - 플레이어 종류(5\~6종)

## 이슈/메모

- ScriptableObject는 “기본 데이터” 관리에는 좋지만, 플레이어 진행 상황 저장은 Firebase/별도 저장 시스템으로 가져가야 한다는 구분이 더 명확해졌다.
