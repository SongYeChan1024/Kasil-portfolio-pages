# 일일회고록

## 1) 오늘 한 일 (정리)

- <b>FGT 발표 준비</b>
  - 내가 맡은 파트(사운드 시스템 / 에피소드 3 퍼즐 구현) 기준으로 PPT 흐름 재정리
  - 팀 프로필 소개 문구, 발표 대사 다듬기
  - 슬라이드별로 “어떤 순서로 설명할지” 발표용 문장 정리
- <b>FGT 발표 진행</b>
  - <b>플레이 흐름 / 에피소드 3 / 사운드 기능</b> 중심으로 설명
- <b>사운드 시스템 발표 내용 요약</b>
  - <code>SoundManager</code> 중심으로 전체 사운드 통합 관리
  - 역할 분리 구조
    - <code>SoundProfile</code>, <code>SoundController</code>
    - <code>PlayerSound</code>, <code>UISoundTrigger</code>, <code>SoundTrigger</code>
  - 씬 기본 사운드 / 플레이어 사운드 / UI 사운드 / 오브젝트 상호작용 사운드를 분리 관리
  - 적용 흐름 & 체크 포인트
    - SoundProfile 설정 → SoundController 연결 → 클립 등록 → <code>Play()</code> 호출 여부 확인
- <b>에피소드 3 퍼즐 발표 내용 요약</b>
  - 공연장 내 <b>악보 조각 10개 랜덤 생성</b> 탐색형 퍼즐
  - <b>음악 BPM 기반 비트맵</b>을 만들고 발판이 순차 생성되는 <b>음악 점프맵</b> 퍼즐
  - 주요 스크립트 역할 정리
    - <code>PieceSpawner</code>, <code>PieceCollect</code>
    - <code>Ep3_1Manager</code>
    - <code>RhythmAudioManager</code>, <code>RhythmBeatWindowManager</code>
    - <code>RhythmPuzzleManager</code>, <code>RhythmScoreManager</code>
- <b>다른 팀 발표 청취 & 참고사항</b>
  - LLM 기반 신분 심사 게임 발표를 들으며 인상 깊었던 점 정리
    - 프롬프트 구조화
    - 카드형 정보 디자인
    - 캐릭터 페르소나 유지
    - UI 애니메이션, 감정 피드백 등
  - “개별 기능”보다 <b>게임 루프가 분명하고, 연출/피드백이 경험과 연결된 완성도</b>가 특히 좋다고 느꼈음
- <b>질의응답 피드백 정리</b>
  - 사운드 구조
    - 현재처럼 <code>Don't Destroy On Load</code> 기반 싱글톤 구조 유지 가능
    - 추후 사운드 종류가 많아지면 Dictionary 방식이 유지보수에 유리할 수 있다는 조언
  - 에피소드 3 퍼즐
    - 사운드 연출/스토리 연결을 더 강화하는 방향으로 설명
  - 오디오 기본값 초기화 기능
    - 아직 우선순위상 구현하지 못한 상태 공유
- <b>FGT 이후 팀원 작업 현황 정리</b>
  - 성혁 레이서님: 빌드 버전관리, 아이콘 관련 작업 진행 중
  - 남해 레이서님: NPC AI, 호감도 증가 시 출력 이펙트 작업 진행 중
  - 대식 레이서님: 작업 내용 추가 확인 필요
  - 나: 사운드 초기화/기본값 세팅 + 추가 다듬을 부분 정리 중

---

## 2) 느낀 점

- 오늘은 “준비”에서 끝난 게 아니라 <b>발표 → 피드백 → 다음 작업 방향 정리</b>까지 자연스럽게 이어져서 의미가 컸다.
- 기능을 구현하는 것과, 그 기능을 <b>다른 사람에게 이해되게 설명하는 일</b>은 완전히 다른 작업이라는 걸 다시 체감했다.
- 발표 준비 과정에서 사운드 시스템과 에피소드 3 퍼즐 구조를 다시 정리하면서, 내가 만든 흐름과 역할이 더 명확해졌다.
- 다른 팀 발표를 보며, 완성도 높은 프로젝트는 기능 하나하나보다도 <b>전체 루프/피드백/연출/분위기의 연결감</b>이 중요하다는 걸 느꼈다.
- 우리 팀도 퍼즐·이야기·사운드·연출이 더 강하게 연결되면 플레이어 몰입감이 크게 올라갈 것 같다.

---

## 3) 아쉬운 점

- 발표에서 설명이 길어지거나 기술적인 내용에 치우친 부분이 있었다.
  - 구조 설명도 중요하지만, 듣는 사람 입장에서는 “왜 이렇게 만들었는지”와 “그래서 경험이 어떻게 좋아졌는지”가 먼저 전달되어야 한다는 걸 느꼈다.
  - 다음에는 발표 문장을 더 짧고 직관적으로 정리해야겠다.
- 사운드 구조는 지금도 동작하지만, 프로젝트 규모가 더 커질 경우를 생각하면 보완 여지가 남아 있다.
  - 초기화 기능, 기본값 세팅, 유지보수성 관점의 구조 정리가 앞으로 계속 필요
- 팀원별 작업 현황을 정리하면서, 대식 레이서님의 작업 내용이 아직 불명확해서 전체 진행 상황을 한 번 더 맞출 필요가 있다.

## 4) 다음 주 할 일 (계획)

- <b>사운드 파트</b>
  - 초기화 기능과 기본값 세팅을 더 정리
  - 씬 전환 이후에도 사운드가 의도한 상태로 유지되는지 점검
  - 기본값 복원/적용 흐름이 자연스럽게 이어지도록 확인 및 보완
- <b>에피소드 3 파트</b>
  - 퍼즐과 연출이 자연스럽게 이어지도록 흐름 점검
  - 플레이어가 진행하면서 느끼는 연결감이 약한 부분 찾기
  - 필요 시 사운드 연출/컷신 연결 수정으로 퍼즐 경험과 이야기 흐름 강화
- <b>팀 공통</b>
  - 빌드 파일 공유, 피드백 정리, 최종 발표 버전 대비 기획/개발 지속
  - 작업 현황 공유를 다시 정리하고, 남은 구현/보완 사항을 우선순위로 정리하기
