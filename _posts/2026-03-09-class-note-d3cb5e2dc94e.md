### PBR(Physically Based Rendering) 렌더링 기술

- PBR은 빛이 실제 세계에서 물체와 상호작용하는 방식을 수학적으로 모델링하여 시뮬레이션하는 렌더링 방식 
- 과거에는 아티스트가 눈대중으로 색상과 반사광을 조절했지만, PBR은 실제 물리 법칙에 기반한 수치를 사용 
- 어떤 조명 환경에서도 물체가 사실적으로 보임 

<b>PBR의 주요 장점:</b> 

- <b>일관성</b>: 한 번 잘 만든 재질은 낮, 밤, 실내 등 어떤 조명 아래서도 자연스럽게 보임
- <b>워크플로우 표준화</b>: Unity, Unreal Engine, 3ds Max 등 대부분의 툴이 동일한 PBR 파라미터를 사용하여 협업과 에셋 공유가 용이
- <b>사실감</b>: 복잡한 수치 계산을 엔진이 대신 처리하므로 아티스트는 시각적 완성도에 더 집중 가능 

### 립싱크(Lip Sync) 기술

<b>립싱크 기술의 정의와 발전:</b> 

- 캐릭터의 입모양을 음성 데이터나 텍스트 소리에 맞춰 동기화하는 기술
- 과거에는 애니메이터가 수작업으로 입모양을 잡았으나, 최근에는 AI 딥러닝을 통해 실시간으로 정교한 연출 가능

<b>립싱크 구현의 핵심 3단계:</b> 

- <b>음소 추출(Phoneme Extraction)</b>: 입력된 오디오 데이터에서 '아, 에, 이, 오, 우' 같은 개별 발음 단위(음소)를 분석
- <b>비제임 매핑(Viseme Mapping)</b>: 분석된 각 음소에 가장 적합한 입 모양 이미지나 3D 모델의 데이터(Viseme)를 연결
- <b>보간 및 합성(Interpolation)</b>: 3D 캐릭터의 경우 블렌드 셰이프(Blend Shape)를 활용하여 자연스러운 움직임 구현

<b>최신 기술 트렌드:</b>  

- <b>Audio-to-Face</b>: 오디오 파일 하나만 입력하면 AI가 자동으로 3D 캐릭터의 얼굴 애니메이션(눈 깜빡임, 눈썹 움직임 포함) 생성
- <b>다국어 자동 대응</b>: 한국어 음성을 입력해도 영어, 일본어 입 모양으로 자연스럽게 변환
- <b>실시간 라이브 립싱크</b>: 버추얼 유튜버(VTuber)나 메타버스 아바타처럼 실시간 마이크 입력에 맞춰 0.1초 내외의 지연시간으로 입 모양 생성

### 디지털 휴먼 기술

<b>3D 캐릭터와의 차이점:</b> 

- 기존 3D 캐릭터는 정해진 애니메이션 기반의 제한적인 표현
- 디지털 휴먼은 AI를 통해 감정, 표정, 상호작용이 가능한 자연스러운 표현 구현
- 상황에 따라 표정, 입술 근육, 눈가 주위의 표정 등을 자연스럽게 표현

<b>디지털 휴먼의 주요 특징:</b> 

- 고품질 PBR 쉐이더를 통해 피부, 머리카락, 눈 등의 디테일 극대화
- HDRP를 활용한 사실적인 조명과 라이팅
- 블렌드 스페이스로 얼굴 근육의 미세한 움직임까지 표현 가능 

<b>적용 사례:</b>

- 게임: The Last of Us - NPC 또는 플레이어 캐릭터로 사용되어 사실적인 대화와 행동 구현, 현실적인 감정 표현을 통한 스토리텔링과 몰입감 극대화  
- 영화: 아바타 - 모션캡처와 디지털 휴먼 기술을 활용하여 배우의 연기를 가상 캐릭터로 변환 
- 광고: 버추얼 인플루언서 - 디지털 휴먼 기술로 제작된 가상 인물이 브랜드 이미지 전달 

### Unity 디지털 휴먼 구현

<b>모델링과 스킨 어태치먼트:</b>  

- 3D 모델 기반으로 동작
- 스킨 어태치먼트를 사용해 눈, 치아, 혀 등 개별 파츠를 본체에 자연스럽게 부착하고 동기화된 움직임 구현
- 아이 스킨 어태치먼트, 티스 스킨 어태치먼트, 텅 스킨 어태치먼트로 구분

<b>전용 쉐이더 시스템:</b> 

- 디지털 휴먼 스킨(피부)
- 디지털 휴먼 아이즈(눈)
- 디지털 휴먼 티스(치아)
- 디지털 휴먼 헤어(머리카락)

<b>주요 텍스처 종류:</b> 

- <b>알베도 맵(Albedo Map)</b>: 표면의 기본 색상 정보(피부톤, 의상 색상)
- <b>노말 맵(Normal Map)</b>: 표면의 디테일한 입체감(피부 모공, 천의 주름)
- <b>서브서페이스 맵(Sub-surface Map)</b>: 반투명한 재질에서 빛이 통과하는 효과(피부를 통한 빛의 투과)

<b>블렌드 셰이프(Blend Shape):</b>  

- 3D 모델의 정점(Vertex)을 이동시켜 모양을 변형하는 방식
- 베이스 셰이프(기본 표정)와 타겟 셰이프(특정 표정) 사이를 슬라이더처럼 조절
- 표정 변화를 자연스럽게 구현하기 위한 핵심 기술

### 헤어 시스템 (Hair System)

<b>Unity Hair 시스템 특징:</b> 

- 헤어 쉐이더와 물리 효과를 적용하여 사실적인 움직임 구현
- 디지털 휴먼의 생동감을 높이는 중요한 요소

<b>Hair Physics 주요 설정:</b>   

- <b>Hair System Settings</b>: 전반적인 동작 제어, 시뮬레이션 성능, 기본 설정 관리
- <b>Blending Settings</b>: 머리카락 밀도, 길이, 물리적 반응 조정
- <b>Volume Settings</b>: 머리카락 전체 볼륨과 밀도 조절
- <b>Stiffness(탄성)</b>: 머리카락의 탄성과 바람 등 외부 힘에 대한 반응
- <b>Velocity</b>: 외부 힘에 반응할 때 속도와 방향성 조절
- <b>Gravity</b>: 중력값 설정으로 무게감 표현

<b>실습 내용:</b>  

- Unity Asset Store 또는 GitHub에서 Hair System 패키지 다운로드
- Package Manager를 통해 Git URL로 설치 가능
- Alembic 파일 형식을 사용하여 애니메이션 데이터와 시뮬레이션 결과 캐시 처리
- 실시간 렌더링 지원

### AI와 게임 개발의 미래

<b>1인 개발자 시대:</b>  

- 기존에는 기획자, 아티스트, 프로그래머가 필요했으나, AI 툴의 발전으로 1인 개발이 가능해질 전망
- AI를 활용하여 3D 캐릭터, 2D 이미지 에셋, 렌더링 리소스를 3일 정도에 제작 가능

<b>AI 활용 방안:</b>  

- 디자인과 기획은 AI 에이전트 툴 활용 (제미나이, ChatGPT 등)
- 프로그래밍은 기본 지식과 검수 능력 필요 - GitHub Copilot으로 단순 반복 작업 자동화
- 로직과 코드 검수는 여전히 개발자의 역량 필요

<b>AI와 게임 엔진의 관계:</b>  

- AI 발전으로 Unity나 Unreal Engine이 사라지는 것이 아니라, AI가 엔진 안에 통합될 것
- 서드파티처럼 AI가 엔진 내부에 탑재
- 툴 조작은 여전히 인간이 수행해야 하며, AI가 완전히 대체하기까지는 시간 필요

### Unity 실습 프로젝트 설정

<b>프로젝트 생성:</b> 

- Unity 2022 버전 사용
- Built-in Render Pipeline
- 프로젝트명: Human System

<b>패키지 설치 방법:</b>   

- Window → Package Manager에서 Hair System 검색 후 Install
- 또는 Package Manager에서 '+' 클릭 → "Add package from git URL" 선택 후 URL 입력

<b>그래픽 설정 확인:</b>  

- Edit → Project Settings → Graphics
- Scriptable Render Pipeline Settings 확인
- HD Render Pipeline이 설치되어 있어야 함 

<b>데모 씬 실행:</b>   

- Demo Scene을 더블클릭하여 열기
- Play 버튼으로 실행하여 디지털 휴먼 시연 확인
- 포커스, 라이팅 등 다양한 설정 조정 가능

### 교육적 고려사항

<b>Unity 에셋 사용 제한:</b>  

- 디지털 휴먼 패키지는 교육 및 비상업적 목적으로만 사용 가능
- 상업적 사용 시 별도 라이선스 필요

<b>권장 학습 경로:</b> 

- Unity를 2-3년 정도 학습한 후 Unreal Engine도 학습하면 경력 스펙에 큰 도움
- 두 엔진 모두 다룰 수 있으면 취업 시장에서 경쟁력 향상


## 메모


<b>PBR은 Physically Based Rendering(물리 기반 렌더링)의 약자로,</b>

빛이 실제 현실 세계에서 물체와 상호작용하는 방식을

수학적으로 모델링하여 시뮬레이션하는 렌더링 방식입니다.

<b>과거에는 아티스트가 눈대중으로 색상과 반사광을 조절했다면,</b>

PBR은 실제 물리 법칙에 기반한 수치를 사용하기 때문에

어떤 조명 환경에서도 물체가 사실적으로 보이게 됩니다.

<b>PBR 사용의 장점</b>

<b>일관성: 한 번 잘 만들어진 재질은 낮, 밤, 실내 등</b>

어떤 조명 아래서도 어색함 없이 자연스럽게 보입니다.

워크플로우 표준화: 유니티(Unity), 언리얼 엔진(Unreal Engine), 3ds Max 등

대부분의 툴이 동일한 PBR 파라미터를 사용하므로 협업과 에셋 공유가 쉽습니다.

<b>사실감: 복잡한 수치 계산을 엔진이 대신해주므로 아티스트는 시각적 완성도에 더 집중할 수 있습니다.</b>

<b>립싱크 기술의 핵심 단계</b>

<b>립싱크가 자연스럽게 구현되려면 보통 세 가지 단계를 거칩니다.</b>

<b>음소 추출 (Phoneme Extraction): 입력된 오디오</b>

데이터에서 ‘아, 에, 이, 오, 우’ 같은 개별 발음 단위(음소)를 분석해냅니다.

<b>비제임 매핑 (Viseme Mapping): 분석된 각 음소에</b>

가장 적합한 입 모양 이미지나 3D 모델의 데이터(Viseme)를 연결합니다.

<b>보간 및 합성 (Interpolation): 입 모양이 끊기지 않도록</b>

부드럽게 이어주는 단계입니다.

3D 캐릭터라면 리깅된 ‘블렌드 셰이프(Blend Shape)’를 활용해 자연스러운 움직임을 만듭니다.

<b>최신 기술 트렌드</b>

최근에는 게임 엔진과

생성형 AI의 결합으로

훨씬 강력한 기능들이 제공되고 있습니다.

<b>Audio-to-Face: 오디오 파일 하나만 넣으면 AI가 알아서</b>

3D 캐릭터의 얼굴 애니메이션(눈 깜빡임, 눈썹 움직임 포함)을 생성합니다.

<b>다국어 자동 대응: 한국어 음성을 넣어도 영어,</b>

일본어 입 모양으로 자연스럽게 변환하는 기술입니다.

<b>실시간 라이브 립싱크: 버추얼 유튜버(VTuber)나</b>

메타버스 아바타처럼 실시간 마이크

입력에 맞춰 0.1초 내외의 지연시간으로 입 모양을 생성합니다.

노션 ai가 이 회의를 기록하고 있습니다. 라는것입니다. 자 그 다음에 다음번에 뵙도록 하겠습니다.

### 글로벌 일루미네이션 (GI) 개념

<b>Realtime Global Illumination (실시간 GI)</b>  

- 게임 실행 중 빛의 세기와 방향 변화를 간접광에 실시간 반영 
- 장점: 동적인 조명 연출 가능, 시간 변화 표현 가능
- 단점: 계산량이 많아 성능 부담이 큼
- 사용 사례: 시간 변화가 있는 게임, 조명 변화가 잦은 게임

<b>Baked Global Illumination (베이크된 GI)</b> 

- 미리 계산해서 텍스처(라이트맵)에 저장 
- 실행 중 빛의 변화가 간접광에 반영되지 않음 
- 장점: 성능이 좋음, 고품질 조명 표현 가능
- 단점: 조명 실시간 변경 어려움, 베이크 재작업 필요

<b>프로젝트 적용</b>  

- Mixed Lighting 모드 사용 (실시간 + 베이크 혼합)
- Shadow Mask 방식 적용
- Indirect Resolution: 0.5로 설정 (로우폴리 모델이라 품질 저하 티 안남)

<b>애니메이터 설정</b>

<b>IK (Inverse Kinematics) 개념</b>  

- FK (Forward Kinematics): 어깨 → 팔꿈치 → 손목 → 손가락 순서
- IK (Inverse Kinematics): 손가락 → 손목 → 팔꿈치 → 어깨 역순으로 동작
- 총을 정확하게 잡기 위해 IK 사용

### 입력 시스템 구현

<b>Player Input 컴포넌트</b>  

- Create Actions로 액션 생성
- OnMove, OnFire 이벤트 추가 
- WASD 키로 이동, 마우스로 발사 설정

<b>MovementInput 스크립트</b>  

- Player Input의 이벤트를 받아 처리
- moveInput 벡터로 입력값 저장 
- UnityEvent로 이벤트 등록 방식 사용 

<b>입력과 액터 분리 개념</b> 

- 입력 처리와 캐릭터 동작을 별도 스크립트로 분리
- 재활용 가능성 증가
- 네트워크 게임 개발 시 특히 중요

<b>이동 구현</b>  

- FixedUpdate에서 물리 기반 이동 처리
- A/D 키: 좌우 회전 (Rotate)
- W/S 키: 전진/후진 (Translate)
- 애니메이터 파라미터 연동

<b>FixedUpdate vs Update</b> 

- FixedUpdate: 속도가 중요한 FPS/TPS 게임에 적합
- Update: 부드러운 애니메이션/움직임에 적합

### 인터페이스와 느슨한 커플링

<b>느슨한 커플링(Loose Coupling) 개념</b>  

- 아이템이 정확히 무엇인지 구분하지 않고 인터페이스만 확인
- 코드량 감소 및 확장성 증가
- 아이템이 40-50개로 늘어나도 코드 추가 불필요

<b>나쁜 예시 (타이트 커플링)</b>  

```javascript
if (item is AmmoBox) { }
else if (item is HealthPack) { }
else if (item is Coin) { }
// 아이템 추가 시마다 계속 코드 추가 필요
```

<b>좋은 예시 (느슨한 커플링)</b> 

```javascript
IItem item = ...;
item.Use(target);
// 아이템 종류 관계없이 동일 처리
```

<b>인터페이스 구현</b>  

- IItem 인터페이스: Use(GameObject target) 메서드 선언만
- AmmoBox, HealthPack, Coin 등이 IItem 상속
- 각 아이템이 Use() 메서드 구현 강제

<b>IDamageable 인터페이스</b>  

- OnDamage(float damage, Vector3 hitPoint, Vector3 hitNormal) 선언
- 모든 생명체(플레이어, 적)가 상속
- 중복 코드 제거 목적

## : 미리 구워서 저장해 둔 조명을 사용

실시간 런타임 중에 빛의 세기와 뱡향이 달라져도<br />그 변화를 간접광에 실시간으로 반영하지 못함.

조명 결과를 <b>미리 계산해서 텍스처(라이트맵)</b> 에 저장해 두는 방식.<br />게임 플레이 중에는 그 계산 결과를 그냥 가져다 씀.<br />즉, 실행 중에 빛을 다시 계산하는 게 아니라<br /><b>이미 구워 놓은 조명 정보</b>를 보여주는 것.

예를 들면:

- 벽에 비친 부드러운 빛
- 방 안 구석의 간접광
- 물체 아래 자연스러운 그림자 느낌

이런 걸 미리 계산해서 저장해 둡니다.

### 장점

- 성능이 좋음
- 고품질 조명 표현 가능
- 정적인 배경에 아주 유리함

### 단점

- 조명이 실시간으로 크게 바뀌기 어려움
- 움직이는 오브젝트에는 그대로 적용하기 어려움
- 베이크를 다시 해야 수정사항이 반영됨

## 한 줄 비교

### Realtime GI

- <b>실행 중 계산</b>
- 조명 변화 가능
- 무거움

### Baked GI

- <b>미리 계산</b>
- 조명 변화 어려움
- 가벼움

## 언제 쓰면 좋냐

### Realtime GI가 어울리는 경우

- 시간 변화가 있는 게임
- 조명이 자주 켜지고 꺼지는 연출
- 동적인 환경이 중요한 게임

### Baked GI가 어울리는 경우

- 맵 구조와 조명이 거의 고정된 게임
- 실내 배경
- 성능 최적화가 중요한 프로젝트

<b>유니티 실무에서는 보통 이렇게 사용</b>

- <b>정적인 배경 → Baked GI</b>
- <b>플레이어 / 움직이는 오브젝트 → Light Probe</b>
- <b>실시간 조명 → Realtime Light</b>

즉, 대부분 프로젝트는

<b>Realtime + Baked를 섞어서 사용하는 경우가 많음.</b>

# FK (Forward Kinematics) 정운동학

## : 부모 관절부터 차례로 움직이는 방식

캐릭터의 <b>루트(부모) 관절부터 자식 관절 방향으로 움직이는 방식</b>입니다.

즉, <b>위에서 아래로 움직임이 전달됩니다.</b>

예를 들어 <b>팔을 움직일 때</b>

```txt
어깨 → 팔 → 손목 → 손
```

이 순서로 회전을 조절합니다.

### 예시

팔을 들어 올리려면

1. 어깨를 회전
2. 팔을 회전
3. 손목을 회전

이렇게 하나씩 조정해야 합니다.

### 특징

- 관절을 <b>직접 회전시켜서 움직임을 만든다</b>
- 애니메이션을 만들 때 기본적으로 많이 사용됨

### 장점

- 자연스러운 회전 표현 가능
- 계산이 단순함
- 애니메이션 제작에 유리

### 단점

- 목표 위치에 맞추기 어렵다

# IK (Inverse Kinematics) 역운동학

## : 목표 위치를 먼저 정하고 관절을 계산하는 방식

IK는 <b>끝 관절(End Effector)</b> 의 위치를 먼저 정합니다.

그리고 엔진이 <b>그 위치에 맞게 중간 관절을 자동 계산</b>합니다.

예를 들어 <b>손을 문 손잡이에 가져가야 할 때</b>

```txt
손 위치 지정 → 팔과 어깨 각도 자동 계산
```

### 예시

- 캐릭터가 <b>문 손잡이를 잡음</b>
- 발이 <b>계단 위에 정확히 올라감</b>
- 캐릭터가 <b>벽을 짚음</b>

이런 상황에서 사용됩니다.

### 특징

- 목표 위치 중심
- 관절 회전을 자동 계산

### 장점

- 정확한 위치 맞추기 가능
- 발 위치 보정 등에 매우 유용

### 단점

- 계산이 복잡함
- 잘못 설정하면 어색한 포즈 발생

---

# FK vs IK 한눈에 보기

| 구분 | FK | IK |
| --- | --- | --- |
| 방식 | 부모 → 자식 | 끝 → 부모 |
| 제어 | 관절 회전 직접 제어 | 목표 위치 기반 |
| 계산 | 단순 | 복잡 |
| 사용 | 일반 애니메이션 | 손/발 위치 맞추기 |

---

# 쉽게 기억하는 방법 🧠

### FK

👉 <b>어깨를 움직이면 손이 따라간다</b>

```txt
어깨 → 팔 → 손
```

### IK

👉 <b>손 위치를 정하면 팔이 따라 맞춰진다</b>

```txt
손 → 팔 → 어깨
```

# 게임에서 실제 사용 예

<b>FK</b>

- 캐릭터 기본 애니메이션
- 달리기
- 공격 모션
- 점프

<b>IK</b>

- 발이 계단에 맞게 올라가기
- 손으로 벽 짚기
- 총 잡는 위치 보정
- 무기 조준
