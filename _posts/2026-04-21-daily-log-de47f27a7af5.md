# 일일회고록

## 1) 오늘 한 일

- <b>프로젝트 사운드 구조 점검 및 리팩토링 방향 확정</b>
  - 기존 구조가 <code>List 등록 + Dictionary 조회 + switch(scene.name) 분기 + 일부 AudioClip 직접 참조</code>가 섞인 <b>혼합 구조</b>임을 다시 정리했다.
  - <code>enum</code>은 “사운드 종류를 구분하는 이름표”, <code>Dictionary</code>는 “enum 키로 사운드를 빠르게 찾는 매핑”이라는 역할로 개념을 명확히 잡았다.
  - <code>switch</code> 분기와 <code>Dictionary</code> 기반 데이터 구조를 비교하며, <b>확장성/유지보수성이 필요한 공용 영역은 딕셔너리가 더 적합</b>하다는 결론을 문서화했다.
- <b>씬별 자동 사운드 재생 구조 리팩토링(핵심)</b>
  - 기존 <code>OnSceneLoaded()</code>의 <code>switch(scene.name)</code> 기반 하드코딩을 정리하고,
    <p>
    <code>Dictionary&lt;string, SoundProfile&gt;</code>로 <b>씬 이름 → SoundProfile</b>을 조회해 적용하는 흐름으로 바꾸는 방향을 구체화/적용했다.
    </p>
  - <code>SoundProfile</code>을 “사운드를 재생하는 객체”가 아니라 <b>씬에서 사용할 사운드 세트를 담는 ScriptableObject(데이터)</b>로 정의해 역할을 정리했다.
  - 최종 흐름을 아래처럼 통일했다.
    - 씬 로드 → <code>scene.name</code>으로 <code>sceneSoundDict</code> 조회 → <code>SoundProfile</code> 적용 → BGM / Ambient / PlayerSound 반영
  - <code>SoundManager.prefab</code>에서 씬-프로필 매핑을 인스펙터로 관리하도록 해서, 새 씬이 추가되어도 코드에 case를 늘리지 않게 만들었다.
- <b>SoundController 구조 정리(일원화)</b>
  - 씬에 있던 <code>SoundController</code> 프리팹/스크립트를 제거하는 방향으로 정리하고,
  - 씬 사운드 책임을 <code>SoundManager</code>로 모아 구조를 단순화했다.
  - 엔딩 씬도 별도 <code>SoundController</code> 없이 <code>EndingManager</code>가 <code>SoundProfile</code>을 적용하도록 통일했다.
- <b>리팩토링 이후 로그/오류 점검 및 정리</b>
  - <code>Episode0</code> BGM 클립 미등록 경고: <code>SoundManager.prefab</code>에서 슬롯이 비어 있던 문제로 확인 → 메인 테마 클립 연결로 수정
  - <code>The referenced script (Unknown) on this Behaviour is missing!</code>:
    - 에피소드 1 컷씬 프리팹 2개가 예전 GUID 참조 중인 문제로 확인 → 현재 <code>CutsceneImagePlayer</code> 스크립트 GUID로 재연결
  - <code>ServerChat</code> OpenAI 응답 파싱 오류:
    - 사운드 리팩토링과 별개 이슈로 분리
    - JSON이 아니라 HTML 응답이 돌아온 상황으로 판단하고 원인 추적을 분리하기로 했다.

---

## 2) 느낀 점

- “코드를 고친다”보다 먼저, <b>구조를 이해하고 책임을 나누는 과정</b>이 리팩토링의 핵심이라는 걸 다시 느꼈다.
- <code>enum</code> / <code>Dictionary</code> / <code>SoundProfile</code> / <code>SoundManager</code>의 역할을 분리해서 정의하니, 이전에 헷갈리던 부분이 확실히 정리됐다.
- 특히 <b>하드코딩 분기(switch)를 데이터 중심 구조로 바꾸는 것</b>이 유지보수에서 얼마나 큰 차이를 만드는지 체감했다.
  - 씬이 늘어나도 “코드 수정”이 아니라 “데이터 추가/연결”로 해결되는 방향이 가장 마음에 들었다.

---

## 3) 아쉬운 점

- 리팩토링을 진행하면서 사운드와 직접 관련 없는 오류(Missing Script, ServerChat 응답 문제)도 같이 드러나서, 점검 범위가 넓어지며 집중이 분산될 위험을 느꼈다.
- 아직 프로젝트 안에는
  - <b>공용 시스템으로 관리할 사운드</b>와
  - <b>개별 연출용으로 직접 참조할 사운드</b>

  <p>
  를 더 명확히 나누는 기준이 필요하다.
  </p>

---

## 4) 내일(다음) 할 일

- 씬별 <code>SoundProfile</code> 매핑이 실제 씬들에서 누락 없이 잘 연결되어 있는지 전체 점검
- 리팩토링 이후 발생 가능한 예외 케이스(프로필 없음, 클립 누락 등) 처리 로직/로그 메시지 정리
- ServerChat 파싱 오류는 사운드 이슈와 분리해서 재현 조건 및 서버 응답 형태부터 확인
