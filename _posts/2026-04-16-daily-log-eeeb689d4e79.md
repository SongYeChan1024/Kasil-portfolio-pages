- 컷씬 공통 기능 통일

  - 하이라키의 <code>Button-next</code>, <code>Button-skip</code>을 실제 컷씬 제어 버튼으로 연결
  - 시작 컷씬 즉시 스킵 시 카메라가 플레이어 시점으로 자연스럽게 복귀하도록 수정

  - 악보 상호작용 후 흐름을 “컷씬 재생 → 음악 시작 → 문 열림”으로 변경
  - <code>CutsceneImagePlayer</code> 데이터에 자막 2묶음 세팅

  - 피아노 컷씬 하얀 화면 이슈: 표시용 <code>Image</code> 참조를 더 정확히 찾도록 로직 수정 방향 반영
- 문구/이미지 연출 정리
  - ‘기억이 되살아난 뒤 같은 로비가 다르게 보이게’ 되는 흐름을 인트로/조사 문구에 반영
  - 머그컵/사진 등 오브젝트 조사 시 플레이어 독백형 문장 정리
  - 피아노 엔딩 컷씬 이미지 방향: NPC+플레이어가 함께 피아노 앞에 앉아 있는 회상 장면 중심

## 배운 것(개념/정리)

- 장면/연출은 단독으로 예쁜 것보다 “전후 씬과 맞물리는 흐름”이 완성도를 좌우한다.
- 조사형 연출은 자동 재생보다, 상호작용 입력을 통해 수동 재생으로 설계할 때 몰입/가독성이 좋아진다.
- 컷씬 시스템은 입력/버튼/UI가 에피소드별로 분리되면 유지보수가 어려워, 공통 입력으로 통일하는 게 안정적이다.
- Unity에서 ‘하얀 화면’은 대개 기본 활성 UI/잘못된 참조로 발생하므로, 초기 활성 상태와 참조 탐색 로직을 우선 점검한다.

  - 다음 액션: 클리어→컷씬→문 상호작용까지 전체 플로우에서 저장/상태값 타이밍 재점검

  - 해결/시도: 실제 표시용 <code>Image</code>를 더 정확히 찾도록 로직 수정 방향 반영
  - 다음 액션: 에디터에서 실제 재생으로 “이미지 표시→자막→음악→문 열림”까지 최종 확인
- 내용: 3-3 로비 인트로에서 음악가 이름이 이상하게 출력
  - 원인/가설: 별도 컷씬 컨트롤러가 자동 재생되며 데이터가 섞임
