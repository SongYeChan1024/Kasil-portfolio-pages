## 오늘의 목표

새 장비·에르고 스퀘어 UI에서 성장과 조합을 편집하고, VARCO 3D 플레이어의 전투·애니메이션을 실제 데이터에 연결합니다. 테스트 캐릭터와 데모 플레이어를 분리하고 맵·플레이어·몬스터를 조립하는 구조로 정리합니다.

## 오늘 한 일

### 에르고 스퀘어 성장과 조합

- 최초 지급은 3×3, 추가 생성은 1×1로 정정했습니다. 레벨업마다 기존 스퀘어 한 행·열 확장 또는 새 공간 생성 중 하나를 선택합니다.
- 중앙 플레이어 고정 칸과 역할 강제 구분을 제거했습니다. 첫 3×3에 빗자루와 코어를 같이 배치하고 Q 스킬을 사용합니다.
- 이후 무기를 다른 스퀘어로 옮겨 코어·보조 파츠를 조합해 강화하거나 소환으로 변형합니다. 최초 발동 비용·로컬 출력·열 부하·냉각을 연결하고 이동·키 변경·구역 전환 시 상태를 보존합니다.

### 새 UI와 장비

- 왼쪽 가방, 가운데 장비·에르고 스퀘어 탭, 오른쪽 설명의 새 UI를 사용합니다. 격자 확대·축소와 이동, 아이템별 점유 크기·회전·겹침 방지를 반영했습니다.
- 성장 선택·스퀘어 전환·배치·키 배정·조합을 같은 새 UI에서 수행합니다.
- 검을 가방에서 주무기 슬롯으로 드래그하면 장착하고, 월드와 인벤토리 미리보기에 실제 검과 정수 그립을 표시하도록 연결했습니다.

### FSM과 실제 Animator

- 이동·기본 공격 3타·스킬·집중·사망을 실제 게임플레이 상태와 Animator에 연결했습니다. 보행은 방향 기준과 반복 구간을 맞췄습니다.
- 통째로 재구성한 베기 대신 보존된 VARCO 원래 3타를 복원하고, 검 궤적에 필요한 오른쪽 전완·손목 회전만 보정했습니다.
- 재생 전에도 루트의 Demo Player Rig에서 연결된 FSM·Animator·컴포넌트를 확인하고 그래프를 열 수 있게 했습니다.

### 독립 데모 플레이어와 구역 조립

- Player\_Test는 원본으로 보존하고 VARCO 모델 기반 Player\_Architect\_Demo를 별도 일반 프리팹으로 만들었습니다. 게임플레이 컴포넌트와 설정을 새 루트에 이관했습니다.
- 동굴·보스·귀환과 본부에서 같은 데모 플레이어를 사용합니다.
- 맵·플레이어·몬스터·UI·시스템·진행기를 분리하고 구역 조립 프리팹과 로더에서 연결합니다. 기존 비동기 씬 전환을 유지하며 Additive 스트리밍은 아직 적용하지 않았습니다.

## 발견한 문제와 해결

- 테스트 플레이어에 외형만 덧붙이는 구조가 의도와 달랐습니다. 테스트 자산과 분리된 데모 프리팹을 만들어 참조를 이관했습니다.
- 재생 전 Animator 연결이 보이지 않고 장비 표시와 실제 동작이 어긋났습니다. 직렬화된 연결·루트 진단 인스펙터·실제 장비 상태를 기준으로 확인 경로를 통일했습니다.
- 검 동작을 과하게 재구성하면서 원래 모션이 달라졌습니다. 원본 몸 동작과 공격 데이터를 보존하고 필요한 관절 회전만 수정하는 기준으로 되돌렸습니다.

## 검증 결과

최종 독립 데모 플레이어 기준으로 별도 Unity 6000.3.7f1에서 다음 검사를 통과했습니다.

- 프리팹 생성·참조 이관 27개, 최종 편집·빌드 의존성 25개. 활성 빌드 씬 7개에서 Player\_Test 의존성 없음.
- 실제 튜토리얼·보스·귀환 진행 72개, 장비 드래그 17개.
- Animator·FSM·공격 210개 및 69프레임 기록, 스퀘어·조합·소환·본부 인계 80개.
- 전달 파일 22개 일치, Player\_Test와 메타 및 원래 모션·Controller·데이터 31개 파일 보존 확인. 검사 대상 최종 로그의 C# 컴파일 오류 0건.

반복 프레임 검사를 포함한 자동 기능 검증입니다. 메인 Unity 창에서 전체 튜토리얼을 수동 완주한 결과는 아닙니다. 열린 씬의 미저장 변경은 자동 저장하거나 폐기하지 않았습니다. 분리 자체의 성능 개선율은 측정하지 않았습니다.

## 오늘의 결정과 후속 범위

커스터마이징을 고려해 현재 데모 외형을 출발점으로 둡니다. 향후 의상이 없는 기본 신체와 분리 의상을 공통 골격에 연결하고, 외형 교체 시 플레이어 루트·FSM·장비·스퀘어 상태를 유지합니다. 월드와 인벤토리 미리보기는 같은 외형 데이터를 반영해야 합니다.

현재 캐릭터는 단일 스킨 메시이며 기본 신체·교체 의상·외형 교체 UI·영구 저장은 아직 없습니다. 이번에는 제작·연결 계약과 후속 수용 기준을 기획서·기술 명세·결정 기록에 반영했습니다.
