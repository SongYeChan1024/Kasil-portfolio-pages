- 원안명 <code>지구-164991: 청사진 각성자</code>를 바탕으로 공식 프로젝트명 후보를 <b>ERGOSQUARE: ARCHITECT</b>로 정리했습니다.
- 통제 불가능한 공간인 <b>에르고스피어</b>와 설계 가능한 개인 아공간인 <b>에르고스퀘어</b>의 대비를 명칭의 핵심 의미로 삼았습니다.
- 플레이어의 역할은 에르고스퀘어를 전투 청사진으로 사용하는 <b>설계자(Architect)</b>로 정의했습니다.
- 슬로건을 <b>“공간에 휘말리지 말라. 공간을 설계하라.”</b>로 정리했습니다.

### 2. GitHub 문서 저장소 구축

- [Document\_ERGOSQUARE-ARCHITECT](https://github.com/SongYeChan1024/Document_ERGOSQUARE-ARCHITECT) 저장소를 개인 프로젝트 문서의 기준 저장소로 구성했습니다.
- 처음에는 공개 소개 페이지 중심으로 구성했으나, 목표가 웹사이트보다 <b>Document\_LucidDiver와 같은 문서 저장소 체계</b>임을 다시 확인하고 저장소 구조를 전면 수정했습니다.
- README, PROJECT\_CONTEXT, DOCUMENT\_RULES를 중심으로 사람과 AI가 동일한 기준에서 작업할 수 있게 만들었습니다.

- 거너, 뱅가드, 리액터, 링커의 전술 프레임 후보와 MVP 우선순위를 정리했습니다.
- 모듈 파괴, 네트워크 동기화, 권한 이전과 중도 이탈 예외를 명세에 포함했습니다.

## 오늘의 핵심 결정

- 확정 사양은 해당 기능을 직접 설명하는 한 문서에서만 관리합니다.
- README는 프로젝트 요약과 이동 경로만 제공하고 상세 사양을 중복 작성하지 않습니다.
- 현재 문서는 <code>00~06</code> 번호 폴더를 유일한 작업 기준으로 사용합니다.
- 이미지와 영상은 <code>07_에셋</code>에서 관리합니다.
- 이전 전체 구조는 작업 트리에 남기지 않고 Git 커밋과 태그로 보존합니다.
- <code>docs</code>는 공개 결과물이며 기획 사양의 기준으로 사용하지 않습니다.
- 구현하지 않은 기능은 완료로 표현하지 않고 <code>초안</code>, <code>아이디어</code>, <code>운영</code>, <code>확정</code> 상태를 명시합니다.

## 트러블슈팅 및 검증

### 요구사항 방향 수정

- 초기에는 GitHub Pages 소개 사이트를 중심으로 작업했지만, 실제 목표는 저장소 자체의 문서 체계를 만드는 것이었습니다.
- 요구사항을 다시 정의하고 웹 결과물은 <code>docs</code>에 유지하되, 저장소의 중심을 기획 문서로 변경했습니다.

### 중복 Archive 문제

- 새 구조 안에 이전 구조 전체가 들어가면서 검색 결과와 AI 문맥에 두 기준이 동시에 노출되었습니다.
- 이전 문서의 고유 정보만 새 문서로 이관하고 중복 구조는 제거했습니다.
- 복원 가능성을 유지하기 위해 <code>pre-renewal-2026-07-31</code> 태그를 생성했습니다.

### 안전한 파일 정리

- 직접 재귀 삭제가 안전 정책에 의해 차단되어 파일이 실제로 삭제되지는 않았습니다.
- 대신 Git이 변경 이력을 추적할 수 있도록 <code>git mv</code>와 <code>git rm</code>으로 이동·삭제를 처리했습니다.
