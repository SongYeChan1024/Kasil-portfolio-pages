# Kasil Devlog

송예찬(Kasil)의 게임 기획·개발 일지, 배우고 있는 기술, 개인 개발 기록을 모으는 블로그입니다.
[Chirpy](https://github.com/cotes2020/jekyll-theme-chirpy) 테마(Jekyll)로 만들고 GitHub Pages로 배포합니다.

- 사이트: https://songyechan1024.github.io/Kasil_DevLog/

## 폴더 구조

```text
Kasil_DevLog/
├─ _posts/       개발일지 (YYYY-MM-DD-영문-슬러그.md)
├─ _tabs/        사이드바 메뉴: 카테고리 · 태그 · 아카이브 · 기술 스택 · 개인 개발 · 소개
├─ _data/        연락처·공유 버튼 설정
├─ _config.yml   사이트 설정 (제목, 언어, 주소 등)
├─ _legacy/      예전 HTML 포트폴리오 (보관용, 사이트에 나오지 않음)
└─ .github/      GitHub Actions 배포 설정
```

## 글 쓰기

사이트의 **글쓰기** 메뉴 또는 `/Kasil_DevLog/admin/`에서 작성할 수 있습니다. Decap CMS 3.17.3과 GitHub backend를 사용합니다.

- GitHub Fine-grained token을 생성하고 `Kasil_DevLog` 저장소에만 `Contents: Read and write` 권한을 줍니다. Metadata는 기본 읽기 권한을 유지합니다.
- 관리자 화면에 토큰을 입력합니다. 기본은 페이지 메모리에서만 사용합니다. 개인 PC에서는 **이 브라우저에 로그인 유지**를 선택하면 다음 접속 때 자동 로그인합니다. 이 경우 토큰은 이 사이트의 브라우저 저장소에 보관되며, 로그아웃하거나 인증에 실패하면 제거됩니다. 공용 PC에서는 선택하지 마세요. 만료·폐기된 토큰은 새로 입력해야 합니다. Decap의 기본 사용자 기록에는 토큰을 넣지 않습니다.
- **블로그 글 → 새 글**에서 제목·날짜·카테고리·태그·본문·이미지를 입력하고 저장/발행합니다. `main`에 커밋된 뒤 기존 GitHub Actions가 사이트를 배포합니다.
- 이미지는 `assets/img/uploads`에 저장합니다. Markdown 본문의 이미지 경로는 `/assets/img/uploads/파일명`으로 씁니다. Chirpy 테마가 GitHub Pages의 baseurl을 자동으로 붙이므로 이미지 경로 앞에 `/Kasil_DevLog`를 다시 붙이지 않습니다. 전체 HTTPS 주소도 사용할 수 있습니다.
- 캡처한 이미지는 본문의 원하는 위치를 클릭하고 **Ctrl+V**로 붙여 넣습니다. Rich Text·Markdown 모드 모두 지원하며 PNG·JPEG·WebP·GIF를 한 장당 10MB까지 받을 수 있습니다. 파일 이름은 자동으로 생성하고, 글을 저장할 때 이미지도 함께 업로드합니다. 이미지 추가 후에도 글 저장이 필요합니다.
- 날짜가 미래이면 예약된 시각에 자동으로 빌드되지는 않습니다. 공개할 시각 또는 지난 시각을 입력하세요.
- 토큰을 저장소·본문·채팅에 넣지 마세요. 토큰을 잃거나 만료되면 GitHub에서 새 토큰을 만듭니다.

관리자 UI와 backend 확장은 `admin/`에 있습니다. 기존의 Markdown 파일 작성 방식도 그대로 사용할 수 있습니다.

편집기 회귀 검사는 `node --test tools/editor-regression.test.mjs tools/cache-regression.test.mjs`로 실행합니다. `node tools/editor-preview-server.mjs`로 띄운 로컬 검증 화면은 Decap의 메모리 테스트 백엔드를 사용하여 실제 GitHub에 글이나 이미지를 올리지 않습니다.

`assets/js/dist/sw.min.js`는 Chirpy의 같은 경로를 덮어쓰고 `/sw.min.js`로 출력되는 서비스 워커입니다. 인증·관리자 요청을 캐시하지 않고, 글 목록과 검색 색인은 온라인에서 최신 내용을 우선 가져옵니다. 테마·Decap 버전을 변경하면 이미지 삽입/미리보기/실행 취소/저장과 로그인 복원·로그아웃, 오프라인 캐시를 다시 확인해 주세요.

`_posts/2026-10-23-slug.md` 파일을 만들고 맨 위에 아래 머리말을 붙입니다.

```yaml
---
title: "[프로젝트] 제목"
date: 2026-10-23 23:00:00 +0900
categories: [개발일지, 프로젝트 이름]
tags: [태그1, 태그2]
---
```

- 프로젝트 **일일개발일지**는 구현한 기능, 변경 내용, 확인한 결과와 남은 작업을 중심으로 씁니다. 카테고리 첫 칸은 `개발일지`, 둘째 칸은 프로젝트 이름으로 둡니다. After Seconds 글은 `categories: [개발일지, After Seconds]`를 사용하며 기존 **개인 프로젝트 → After Seconds** 메뉴에 모읍니다.
- **데일리 로그**는 하루 동안 배운 점과 이해가 바뀐 과정을 1인칭 일기 형식으로 씁니다. `categories: [데일리 로그]`를 사용하며 독립된 **데일리 로그** 메뉴에 모읍니다. 같은 날의 프로젝트 일지와 함께 쓰더라도 구현 내역을 반복하기보다 학습 과정에 초점을 맞춥니다.
- 작성자의 요청에 따라 기존의 "날것의 기록은 노션 데일리로그에 둔다" 원칙에서 공개 가능한 학습 일기는 블로그의 **데일리 로그**에도 작성합니다. 개인적인 원문과 비공개 기록은 노션에 둡니다.
- 비공개 내용(연락처, 공개 전 팀 기획의 세부, 내부 문서 링크)은 올리지 않습니다.

## 로컬에서 미리 보기

### 홈 화면과 카테고리 관리

홈은 글 목록과 **오른쪽 카테고리**로 구성합니다. 오른쪽의 **수정** 또는 배너의 **꾸미기 · 관리**를 누르면 인증 후 블로그 관리 화면으로 이동합니다.

- **기본 설정**: 홈 화면 제목, 소개, 별명, 프로필 소개글.
- **꾸미기 설정**: 배너·프로필 이미지와 강조 색상.
- **메뉴 관리**: 메뉴 이름, 순서, 상단·오른쪽 표시 여부, 첫 화면, 포함할 카테고리. 여러 카테고리를 한 메뉴에 묶을 수 있습니다.
- **하위 카테고리**: 메뉴를 선택한 뒤 **＋ 하위 카테고리**로 추가합니다. 기존 메뉴도 **상위 카테고리**에서 옮길 수 있습니다. 오른쪽 목록에서 접기·펼치기를 지원하며 상위 항목은 하위 글까지 중복 없이 모읍니다. 순서 이동은 같은 상위 항목 안에서 적용하고, 메뉴를 제외하면 그 하위 메뉴는 한 단계 위로 옮깁니다.
- **태그 검색**: 글쓰기의 **태그** 칸에 이름을 쉼표로 구분해 넣습니다. 홈의 **태그로 찾기** 검색창(자동완성) 또는 글 목록의 `#태그`를 누르면 선택한 카테고리 안에서 태그 이름으로 검색합니다. 태그 검색은 부분 일치·대소문자 무시 방식이며 글 검색과 함께 적용할 수 있습니다. `?tab=메뉴ID&tag=태그` 주소로 결과를 공유할 수 있습니다.
- 메뉴에서 카테고리를 제외해도 게시글이나 글의 원래 카테고리는 바뀌지 않습니다. 새 이름을 직접 입력하는 경우 글에 지정한 카테고리 이름과 같아야 합니다.
- 변경 후 상단 **게시** 버튼으로 저장하면 `_data/blog_ui.json`을 저장하고 기존 배포가 실행됩니다. 작성 중인 변경은 공개 화면에 바로 적용되지 않습니다.
- 각 카테고리는 전체 공개 글을 대상으로 검색하고 10개씩 나눠 보여 줍니다. `?tab=메뉴ID` 주소를 공유할 수 있고 메뉴 이름을 바꿔도 ID는 유지합니다.

관리 화면은 기존 Decap의 인증·저장·이미지 선택 기능을 사용합니다. 별도 관리용 토큰을 만들 필요가 없습니다. 네이버의 관리자 메뉴 구성을 참고했으며, 네이버 계정 설정이나 게시글은 변경하지 않습니다.

**글쓰기**는 바로 새 글 편집기로 이동합니다. **이 브라우저에 로그인 유지**로 저장한 유효한 토큰이 있으면 자동 로그인하고, 없거나 인증에 실패하면 입력 화면을 표시합니다. 관리 화면과 글쓰기 화면 모두 왼쪽 위 **← 블로그 홈**으로 돌아올 수 있습니다.

로컬 검증: `tools/category-preview`에서 `pnpm install --frozen-lockfile` 후 저장소 루트에서 `node tools/category-preview/server.mjs`를 실행합니다. `http://127.0.0.1:4176/Kasil_DevLog/`에서 확인할 수 있습니다. 이 서버의 관리 화면은 메모리 테스트 백엔드로만 저장하며, 종료하거나 새로고침하면 검증용 변경은 사라집니다. 공개된 테마 파일을 사용하므로 인터넷 연결이 필요합니다. Liquid 미리보기이며 아래의 Jekyll 전체 빌드 검사를 대체하지 않습니다.

메뉴·분류·페이지 나눔·템플릿 검사는 `node --test tools/category-regression.test.mjs`로 실행합니다.

### Jekyll 전체 사이트

Ruby와 Bundler가 필요합니다.

```bash
bundle install
bundle exec jekyll serve
```

브라우저에서 `http://127.0.0.1:4000/Kasil_DevLog/`를 엽니다.

## 배포

`main`에 push하면 GitHub Actions(`.github/workflows/pages-deploy.yml`)가 사이트를 만들어 배포합니다.
저장소 Settings → Pages → Source를 **GitHub Actions**로 바꿔 둬야 합니다.
